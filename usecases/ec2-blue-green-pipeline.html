EC2のアプリをCI/CDでBlue/Greenデプロイする

最終更新:2026-10-26

1. やりたいこと#

  • GitHubへのプッシュをきっかけに、ビルド・テストから本番デプロイまでを自動化したい。
  • 本番の前に、人の確認を入れたい。
  • 本番の切り替えはダウンタイムなしで行い、問題があればすぐ戻したい。

2. 構成を組み立てる#

① buildspec.yml に従ってビルド・テストするものは?

  • AWS CodeBuildサーバーを用意せずに、buildspec.yml の手順でビルドとテストを実行します。
  • AWS CodeArtifactライブラリなどのパッケージを保管するサービスで、ビルドは実行しません。
  • AWS CloudFormationインフラを作るサービスで、アプリのビルド・テストはしません。

② 新しいAuto Scalingグループに配置し、ALBの向き先を切り替えるものは?

  • AWS CodeDeploy(Blue/Green)新しい環境(Green)に appspec.yml の手順で配置し、ALBの通信を切り替えます。旧環境(Blue)を残せるので戻しやすいです。
  • EC2 Image BuilderAMIを作るサービスで、通信の切り替えはしません。
  • Systems Manager Run Commandコマンドを一括実行できますが、Blue/Greenの切り替えや自動ロールバックの仕組みはありません。

③ 本番の前に人の確認を入れるには?

  • CodePipelineに手動承認のアクションを入れる承認されるまでパイプラインが止まり、承認者にはSNSで通知できます。
  • CodeBuildのテストを増やす自動のテストで、人の確認にはなりません。
  • 本番だけ手作業でデプロイする自動化の要件に合わず、手順のばらつきも出ます。

3. 構成図#

CodePipelineがSource → CodeBuild → 手動承認 → CodeDeployの順に進めます。Blue/Greenは旧環境を残せるのでロールバックが容易です。リソースを増やしたくない場合はIn-placeも選べますが、更新中は台数が減ります(デプロイ戦略)。

4. 使うサービスと役割#

  • AWS CodePipeline:Source → Build → Approval → Deploy の流れを自動化する
  • AWS CodeBuild:buildspec.ymlに従ってビルド・テストする
  • AWS CodeDeploy:appspec.ymlに従ってEC2にデプロイし、Blue/Greenで切り替える
  • Elastic Load Balancing:BlueとGreenの切り替え
  • Amazon CloudWatch:アラームによる自動ロールバック

5. 構築の流れ#

  1. ソースにbuildspec.yml(ビルド手順)とappspec.yml(デプロイ手順・フック)を置く
  2. CodeDeployのアプリケーションとデプロイグループを作成し、デプロイ方式をBlue/Greenにする
  3. CodePipelineでSource(GitHub)・Build(CodeBuild)・Approval(手動承認)・Deploy(CodeDeploy)のステージを作る
  4. CloudWatchアラーム(エラー率など)をデプロイグループに設定し、自動ロールバックを有効にする

6. ポイント・注意点#

  • 本番前に人の確認を入れる → Manual Approval Action。
  • Blue/Greenは旧環境(Blue)を残しておけるので、ロールバックが非常に容易(デプロイ戦略)。
  • デプロイ後の動作確認は、appspec.ymlの ValidateService などのフックで行う。
  • リソースを増やしたくない場合はIn-place(OneAtATimeなど)も選べるが、更新中は台数が減る。
