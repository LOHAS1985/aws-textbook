「AccessDenied」の原因を調べ、最小権限に直す

最終更新:2026-10-26

1. やりたいこと#

  • アプリのロールにS3の権限を付けたのに、オブジェクトの取得で AccessDenied になる。
  • どの呼び出しが拒否されたかを記録から調べたい。
  • 広すぎる権限のロールを、実際に使っている権限だけに絞りたい。

2. 構成を組み立てる#

① 拒否されたAPIの呼び出しと呼び出し元を記録しているものは?

  • AWS CloudTrailerrorCode が AccessDenied のイベントから、誰がどの操作で拒否されたかが分かります。
  • VPCフローログIPアドレスとポートの通信の記録で、IAMの拒否は記録しません。
  • AWS Configリソースの設定の履歴で、APIの呼び出しの結果は記録しません。

② 実際の利用の記録から、必要な権限だけのポリシーを作るものは?

  • IAM Access AnalyzerCloudTrailの記録からポリシーを生成し、使っていないアクセスも見つけます。
  • AWS Trusted Advisorベストプラクティスのチェックで、ロールごとの必要な権限は作りません。
  • Amazon GuardDuty脅威を検出するサービスで、ポリシーは作りません。

③ S3の権限はあるのに、KMSで暗号化されたオブジェクトだけ読めない原因は?

  • KMSキーの kms:Decrypt の権限がないSSE-KMSのオブジェクトは、S3の権限に加えてキーの権限も必要です(暗号化)。
  • バケットのバージョニングが無効読み取りの権限には関係ありません。
  • リージョンが違うリージョンが違っても、エラーの種類は AccessDenied になりません。

④ IAMで許可しているのに拒否されるとき、ほかに確認するものは?

  • SCP・アクセス許可の境界・バケットポリシーの明示的なDenyどこか1つでも明示的なDenyがあれば拒否されます(IAMポリシーと評価ロジック)。
  • インスタンスタイプ権限の判定には関係ありません。
  • CloudWatchアラーム権限の判定には関係ありません。

3. 構成図#

CloudTrailの拒否の記録から操作と呼び出し元を特定し、SCP・許可境界・リソースベースのポリシー・KMSキーポリシーの順に確かめます。直したあとは、Access Analyzerのポリシー生成や、IAMの最終アクセス情報で、使っていない権限を外します。

4. 使うサービスと役割#

  • AWS CloudTrail:拒否されたAPI呼び出し(errorCode: AccessDenied)と呼び出し元の記録
  • AWS IAM:ポリシーシミュレーター、IAM Access Analyzer(ポリシーの生成・未使用のアクセスの検出・外部アクセスの検出)、最終アクセス情報
  • AWS Organizations:SCP・RCPによる制限の確認
  • AWS KMS:暗号化されたデータを読むためのキーポリシー

5. 構築の流れ#

  1. CloudTrailのイベント履歴(またはAthena)で、拒否されたAPI・呼び出し元のロール・対象のリソースを特定する。エラーメッセージにどの種類のポリシーで拒否されたかが出ることもある
  2. ポリシーシミュレーターで、そのロールが該当の操作を許可されているかを確認する
  3. ポリシーの評価順に確認する:SCP・RCPに拒否はないか → 許可境界・セッションポリシーで制限されていないか → バケットポリシーに明示的なDenyはないか → SSE-KMSのキーポリシーで kms:Decrypt が許可されているか
  4. 原因のポリシーを直す。別のアカウントのリソースなら、IAMポリシーとリソースベースのポリシーの両方で許可する
  5. Access Analyzerで、CloudTrailの記録から実際に使った操作だけのポリシーを生成し、未使用の権限・ロールを見つけて削除する

6. ポイント・注意点#

  • 評価の原則:明示的なDenyが最優先、何も許可がなければ暗黙的に拒否。
  • IAMポリシーで許可しても、SCP・許可境界の範囲外なら拒否される(実際の権限は重なった部分だけ)。
  • KMSで暗号化されたS3のオブジェクトは、S3の権限に加えてKMSキーの権限が必要。
  • クロスアカウントのアクセスは、呼び出し元のIAMポリシーと、相手側のリソースベースのポリシー(またはロールの信頼ポリシー)の両方が必要。
  • 最小権限への絞り込み → Access Analyzerのポリシー生成・未使用のアクセスの検出、IAMの最終アクセス情報。

あわせて読む:iam:PassRoleとサービスにリンクされたロール
