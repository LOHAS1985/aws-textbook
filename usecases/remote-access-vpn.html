社員の端末からVPCの社内システムに安全に接続する

最終更新:2026-10-26

1. やりたいこと#

テレワーク中の社員が、自宅のPCからVPC内の社内システムや、オンプレミスのファイルサーバーを使えるようにしたい。ログインは社内のIDでシングルサインオンにし、部署ごとにアクセスできるネットワークを分けたい。インターネットの閲覧まですべてVPN経由にはしたくない。

2. 構成図#

3. 使うサービスと役割#

  • AWS Client VPN:エンドポイント、SAML認証、認可ルール、ルートテーブル、スプリットトンネル、接続ログ
  • AWS Certificate Manager:エンドポイントのサーバー証明書
  • AWS IAM Identity Center:SAMLのIdP(外部のIdPでもよい)
  • AWS Transit Gateway/AWS Site-to-Site VPN:VPCからオンプレミスへの経路
  • Amazon CloudWatch:接続ログ

4. 構築の流れ#

  1. サーバー証明書をACMに用意し、IdPとSAMLで連携するためのIAMのSAMLプロバイダーを作る
  2. Client VPNエンドポイントを作る:クライアントCIDR(VPCやオンプレミスと重ならない範囲)、認証方法(SAML)、接続ログ、スプリットトンネルを設定する
  3. 2つのAZのサブネットをターゲットネットワークとして関連付け、エンドポイントにセキュリティグループを付ける
  4. 認可ルールで、IdPのグループごとにアクセスできる宛先のCIDRを決める(例:経理グループ → 経理システムのサブネット)
  5. オンプレミス宛ての経路をエンドポイントのルートテーブルに追加し、VPC側のルートテーブル・セキュリティグループでもクライアントからの通信を許可する

5. ポイント・注意点#

  • 社員の端末からのリモートアクセス → Client VPN。拠点どうしの接続 → Site-to-Site VPN。
  • VPN以外の通信までVPN経由になる → スプリットトンネルを有効にする。
  • 接続はできるのに目的のサーバーに届かない → 認可ルール、エンドポイントのルートテーブル、宛先側のセキュリティグループ・ルートの順に確認する。
  • クライアントCIDRは、接続先のネットワークと重ならないようにする(作成後は変更できない)。
  • 関連付けたサブネットの数と接続時間で料金がかかる。可用性のため2つのAZに関連付ける。

この構成を組み立てる演習#

  • 社員の端末からVPCに接続する構成を組み立てるテレワーク中の社員を、社内のIDで認証し、部署ごとに許された宛先だけにつなぐ
