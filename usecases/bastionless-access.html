踏み台サーバーなしでプライベートなEC2を操作する

最終更新:2026-10-26

1. やりたいこと#

  • インターネットに出られないプライベートサブネットのEC2に、シェルで接続したい。
  • 踏み台サーバーやSSHの22番ポートは使わない。
  • 誰がいつ何をしたかの記録を残したい。

2. 構成を組み立てる#

① ポートを開けずに、ブラウザやCLIからシェルを開くものは?

  • Systems Manager Session ManagerEC2のSSM Agentが外向きのHTTPSでつなぐため、受信のポートは不要です。接続できる人はIAMで制御します。
  • パブリックサブネットの踏み台サーバー要件で使わないと決めています。22番を開け、鍵も管理する必要があります。
  • AWS Client VPNVPCにつなぐことはできますが、その先はSSHなどのポートが必要です。

② インターネットに出られないEC2から、Systems Managerにつなぐ経路は?

  • インターフェイス型VPCエンドポイントssm・ssmmessages などのエンドポイントを作り、プライベートなまま接続します(VPCエンドポイント)。
  • インターネットゲートウェイパブリックIPが必要になり、プライベートなままでは使えません。
  • VPCピアリングVPC同士をつなぐもので、AWSのサービスへの経路にはなりません。

③ EC2のロールに付けるポリシーは?

  • AmazonSSMManagedInstanceCoreEC2をSystems Managerの管理対象にするための最小限の権限です。
  • AmazonEC2FullAccessEC2の操作の権限で、Systems Managerへの接続には足りず、広すぎます。
  • 何も付けなくてよいロールがないと、Systems Managerに登録されません。

3. 構成図#

EC2のSSM AgentがVPCエンドポイント経由でSystems Managerにつなぎ、運用担当者はSession Managerからシェルを開きます。操作はS3やCloudWatch Logsに記録でき、セッションの開始・終了はCloudTrailに残ります。SSHの鍵を配らずにSSHで接続したい場合は、EC2 Instance Connectも使えます。

4. 使うサービスと役割#

  • AWS Systems Manager:Session Managerでブラウザ/CLIからシェル接続する
  • Amazon VPC:インターネットに出られないサブネットから、インターフェイス型エンドポイント(ssm・ssmmessages・ec2messages)でSystems Managerに接続する
  • AWS IAM:EC2のロール(AmazonSSMManagedInstanceCore)と、利用者が接続できる範囲の制御
  • Amazon S3/CloudWatch Logs:セッションの操作ログの保存先
  • AWS CloudTrail:セッションの開始・終了の記録

5. 構築の流れ#

  1. EC2のIAMロールに AmazonSSMManagedInstanceCore を付け、SSM Agentが動いていることを確認する
  2. プライベートサブネットに、ssm・ssmmessages・ec2messages のインターフェイス型VPCエンドポイントを作成する(エンドポイントのSGで443番を許可)
  3. EC2のセキュリティグループから22番ポートのインバウンドルールを削除する
  4. Session Managerの設定で、操作ログの保存先(S3・CloudWatch Logs)を指定する
  5. 運用担当者のIAMポリシーで、接続してよいインスタンスを(タグなどで)制限する

6. ポイント・注意点#

  • 22番ポートを開けずに接続 → Session Manager。SSHの鍵を配らずにSSH接続 → EC2 Instance Connect。
  • Session Managerで接続できない → SSM Agent、IAMロール、Systems Managerへの経路(NATまたはVPCエンドポイント)を確認する。
  • ポートフォワーディングで、手元のPCからプライベートなRDSなどに接続することもできる。
