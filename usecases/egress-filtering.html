外向きの通信を許可したドメインだけに制限する

最終更新:2026-10-26

1. やりたいこと#

  • プライベートサブネットのサーバーが、NAT経由でインターネットのどこにでもつながってしまう。
  • OSのアップデートなど、必要なドメインだけに外向きの通信を絞りたい。
  • 不正なドメインは、名前解決の段階でも止めたい。

2. 構成を組み立てる#

① 許可したドメイン以外への外向きの通信を止めるものは?

  • AWS Network Firewallステートフルルールのドメインリストで、TLSのSNIやHTTPのHostヘッダーから宛先のドメインを判定します。
  • セキュリティグループIPアドレスとポートでしか制御できず、ドメイン名では絞れません(ネットワークACLとセキュリティグループ)。
  • AWS WAF外から来るWebのリクエストを守るもので、サーバーから外への通信は制限しません。

② 不正なドメインの名前解決を止めるものは?

  • Route 53 Resolver DNS FirewallAWS管理のドメインリストなどで、マルウェアのドメインの名前解決をブロックします(DNS)。
  • Route 53のプライベートホストゾーンVPCの中だけで使う名前を定義するもので、外部のドメインのブロックはしません。
  • Amazon GuardDuty不審な通信を検出しますが、名前解決は止めません。

③ Network Firewallで通信を検査するために必要な設定は?

  • ルートテーブルで、通信がファイアウォールのエンドポイントを通るようにするルートで通さないと検査されません。行きと戻りの経路を同じにします(ルートテーブル)。
  • ファイアウォールを作るだけでよいルートを変えないと、通信はファイアウォールを通りません。
  • EC2にエージェントを入れるNetwork Firewallはエージェントを使いません。

3. 構成図#

DNS Firewallで不正なドメインの名前解決を止め、Network Firewallで許可したドメイン以外への通信を止めます。インスタンスが外部のDNSサーバーを直接使うとDNS Firewallを迂回されるので、53番の外向きの通信もファイアウォールで止めます。エンドポイントはAZごとに置きます(アウトバウンド通信)。

4. 使うサービスと役割#

  • AWS Network Firewall:ステートフルルールのドメインリスト(TLSのSNI・HTTPのHostヘッダーで判定)で許可リスト方式の制限
  • Route 53 Resolver DNS Firewall:AWS管理のドメインリストで、マルウェアなどのドメインの名前解決をブロック
  • Amazon VPC:ファイアウォール用サブネットとルートテーブル、NATゲートウェイ
  • Amazon CloudWatch:ファイアウォールのアラートログ・Resolverクエリログの保存と検索
  • Amazon GuardDuty:不審な通信の検出

5. 構築の流れ#

  1. 各AZにファイアウォール用のサブネットを作り、Network Firewallのエンドポイントを置く
  2. ルートテーブルを設定する:ワークロード → NATゲートウェイ → ファイアウォールエンドポイント → インターネットゲートウェイの順に通り、戻りの通信もファイアウォールを通るようにする
  3. ステートフルルールグループに、許可するドメイン(例:.amazonaws.com、OSのリポジトリ)の許可リストを作り、それ以外を拒否する
  4. DNS FirewallのルールグループにAWS管理のドメインリスト(マルウェア・ボットネット)をブロックとして設定し、VPCに関連付ける
  5. アラートログとResolverクエリログをCloudWatch Logsに出し、ブロックされた通信を確認しながら許可リストを調整する

6. ポイント・注意点#

  • ドメイン名で外向きの通信を絞る、IDS/IPS → Network Firewall。DNSの問い合わせの段階で止める → DNS Firewall。
  • Network Firewallは、ルートテーブルで通信をエンドポイントに通さないと検査されない。行きと戻りの経路を対称にする。
  • セキュリティグループ・ネットワークACLはIPアドレスとポートでしか制御できず、ドメイン名では絞れない。
  • DNS Firewallは、インスタンスが外部のDNSサーバーを直接使うと迂回される。53番ポートの外向き通信もファイアウォールで止める。
  • ファイアウォールのエンドポイントはAZごとに置き、そのAZのサブネットの通信は同じAZのエンドポイントを通す。
