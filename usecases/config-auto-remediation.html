公開されたS3バケットを検出して自動で修復する

最終更新:2026-10-26

1. やりたいこと#

誰かが誤ってS3バケットを公開してしまっても、すぐに検出して自動で非公開に戻したい。違反の状況はSecurity Hubで一覧にし、担当者にも通知したい。

2. 構成図#

3. 使うサービスと役割#

  • AWS Config:設定レコーダーで変更を記録し、Configルールで評価し、修復アクションを起動する
  • AWS Systems Manager:Automationランブックで設定を修正する
  • AWS Security Hub:セキュリティ基準のチェック結果を集約する
  • Amazon EventBridge/Amazon SNS:検出結果の通知
  • AWS CloudTrail:誰が公開設定にしたかを調べる

4. 構築の流れ#

  1. AWS Configの設定レコーダーを有効にする
  2. S3のパブリックアクセスを禁止するAWSマネージドルールを追加する
  3. ルールに修復アクション(SSM Automationのランブック)を設定し、自動修復を有効にする。Automationが使うIAMロールも用意する
  4. Security Hubを有効にし、EventBridgeルールで重要な検出結果をSNSに通知する

5. ポイント・注意点#

  • 「設定が要件を満たしているか」を継続的に評価 → Config。「誰が変更したか」→ CloudTrail。
  • 非準拠の自動修復 → 修復アクション+SSM Automation。
  • 複数のルールと修復をまとめて展開 → Conformance Packs。
  • そもそも公開させない予防策として、アカウント単位のS3ブロックパブリックアクセスや、SCPでの禁止も併用する。

この構成を組み立てる演習#

  • 公開されたS3バケットを自動で修復する構成を組み立てる設定のルール違反を検出し、人手を介さずに元に戻して、担当者にも知らせる
