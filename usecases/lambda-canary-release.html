Lambdaを段階的にリリースする

最終更新:2026-10-26

1. やりたいこと#

  • Lambda関数の新しいバージョンを、まず一部の通信だけに流して様子を見たい。
  • エラーが増えたら、自動で元のバージョンに戻したい。

2. 構成を組み立てる#

① 通信の割合を段階的に移し、アラームで戻すものは?

  • AWS CodeDeploySAMの DeploymentPreference で、Canary・Linearの移し方とロールバックのアラームを指定します。
  • AWS CodeBuildビルドとテストを行うもので、通信の割合は変えません。
  • API Gatewayのステージステージのカナリア設定もありますが、この構成ではLambdaのエイリアスを使って切り替えます。

② 旧・新のバージョンに通信を配分する、名前の付いた向き先は?

  • Lambdaのエイリアス(live)エイリアスは2つのバージョンに重みを付けて通信を分けられます。イベントソースはエイリアスのARNを指定しておきます。
  • $LATEST常に最新のコードを指すだけで、割合で分けられません。
  • Lambdaレイヤー共通のライブラリを分けて配る仕組みで、通信の配分とは関係ありません。

③ 「最初に10%を5分間、問題なければ残りを一気に」の移し方は?

  • Canary最初に一部だけ流して確かめ、そのあと一気に移します。
  • Linear一定の間隔で、同じ割合ずつ少しずつ移す方法です。
  • AllAtOnce一度に全部を移すので、様子を見られません(デプロイ戦略)。

3. 構成図#

SAMでデプロイすると、CodeDeployがエイリアスの向き先を少しずつ新しいバージョンへ移し、アラームが鳴れば自動で戻します。切り替えの前後にテスト用の関数を実行する PreTraffic・PostTraffic フックも設定できます。

4. 使うサービスと役割#

  • AWS SAM:AutoPublishAlias と DeploymentPreference で段階的デプロイを設定する
  • AWS CodeDeploy:Canary/Linearでトラフィックを移す
  • AWS Lambda:バージョンとエイリアス
  • Amazon CloudWatch:エラー数などのアラームでロールバックを判断する

5. 構築の流れ#

  1. SAMテンプレートの関数に AutoPublishAlias: live を設定する
  2. DeploymentPreference に Type: Canary10Percent5Minutes と、監視するCloudWatchアラームを設定する
  3. 初回デプロイ後、コードを修正して再度 sam deploy する
  4. CodeDeployがトラフィックを段階的に移し、問題なければ100%に、アラームが鳴ればロールバックする

6. ポイント・注意点#

  • 最初に少しだけ流してから一気に → Canary、一定間隔で少しずつ → Linear。
  • イベントソースはエイリアスのARNを指定しておく(バージョンのARNだと切り替わらない)。
  • 切り替えの前後にテスト用のLambdaを実行する PreTraffic/PostTraffic フックも設定できる。
