複数アカウントへのログインをシングルサインオンにまとめる

最終更新:2026-10-26

1. やりたいこと#

  • 20個のアカウントにそれぞれIAMユーザーを作っていて、退職者の消し忘れが起きている。
  • 社内のIDで一度ログインすれば、権限のあるアカウントを使えるようにしたい。
  • 長期のアクセスキーもなくしたい。

2. 構成を組み立てる#

① 社内のIdPと連携し、アカウントごとの権限を割り当てるものは?

  • AWS IAM Identity Centerグループごとに「どのアカウントで、どの権限を使えるか」を割り当て、一時的な認証情報でログインさせます。
  • Amazon Cognito自社のアプリの利用者のログイン向けで、社員のAWSアカウントへのログインには使いません。
  • AWS Directory ServiceActive Directoryを用意するサービスで、それだけではアカウントへの権限の割り当てはできません。

② アカウントで使える権限を定義する単位は?

  • パーミッションセット割り当てると、各アカウントにIAMロールが自動で作られます。そのロールは直接編集しません。
  • 各アカウントのIAMユーザーアカウントごとに管理が必要になり、今の問題が解決しません。
  • SCP組織の権限の上限を決めるもので、権限を与えるものではありません(IAMポリシーと評価ロジック)。

③ 退職者がすべてのアカウントに入れないようにするには?

  • 社内のIdPでユーザーを無効にするSCIMで同期されるので、すべてのアカウントへのアクセスがまとめて止まります。
  • 20個のアカウントで順にロールを削除する手間がかかり、消し忘れの問題が残ります。
  • パスワードポリシーを厳しくする退職者のアクセスは止まりません。

3. 構成図#

IAM Identity Centerを社内のIdPとつなぎ、グループにパーミッションセットを割り当てます。CLIも aws sso login で一時的な認証情報を使えるので、長期のアクセスキーが不要になります(IAMロールと一時的な認証情報)。組織全体で禁止したい操作は、SCPで制限します。

4. 使うサービスと役割#

  • AWS IAM Identity Center:シングルサインオン、パーミッションセット、アカウントへの割り当て、MFA
  • AWS Organizations:対象のアカウント群。Identity Centerは管理アカウント(または委任管理者)で有効化
  • AWS IAM:パーミッションセットから自動で作られるロール
  • AWS CloudTrail:誰がどのアカウントで何をしたかの記録

5. 構築の流れ#

  1. Organizationsの管理アカウントでIdentity Centerを有効にし、日常の管理は委任管理者アカウントで行う
  2. IDソースを決める:Identity Center内のディレクトリ、Active Directory、または外部のIdP(SAML 2.0で連携し、SCIMでユーザー・グループを自動同期)
  3. パーミッションセット(AWS管理ポリシー・カスタマー管理ポリシー・インラインポリシー、セッションの長さ)を作る
  4. 「グループ × アカウント × パーミッションセット」の割り当てを作る(例:開発者グループ → 本番は読み取り専用、開発は管理者)
  5. MFAを必須にし、各アカウントのIAMユーザーとアクセスキーを廃止する。CLIは aws configure sso と aws sso login で一時的な認証情報を使う

6. ポイント・注意点#

  • 多数のアカウントへのシングルサインオンと権限の一元管理 → IAM Identity Center。
  • 権限はパーミッションセットで定義し、割り当てると各アカウントにIAMロールが自動で作られる。そのロールを直接編集しない(パーミッションセットの更新で上書きされる)。
  • 退職者はIdPで無効にすれば、すべてのアカウントに入れなくなる。
  • アカウントごとのリソースのARNを含むポリシーは、カスタマー管理ポリシーを各アカウントに同じ名前で用意して参照する。
  • 組織全体で禁止したい操作は、Identity CenterではなくSCPで制限する。
