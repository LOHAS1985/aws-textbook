Webアプリを攻撃や大量アクセスから守る

最終更新:2026-10-26

1. やりたいこと#

  • SQLインジェクションを狙うリクエストや、ログイン画面への大量の試行が来ている。
  • アプリを改修せずに、前段で攻撃を止めたい。DDoSにも備えたい。
  • ブロックしたリクエストの記録を残したい。

2. 構成を組み立てる#

① SQLインジェクションなどアプリ層の攻撃を、前段で止めるものは?

  • AWS WAFWeb ACLのマネージドルールで、SQLインジェクションや既知の悪い入力をブロックします。
  • AWS Shield Standardネットワーク層(L3・L4)のDDoS対策で、SQLインジェクションは止めません。
  • ネットワークACLIPアドレスとポートでしか判定できず、リクエストの中身は見られません。

② 同じIPアドレスからの大量のログイン試行を止めるルールは?

  • レートベースルール一定時間内のリクエスト数が上限を超えたIPアドレスを、一時的にブロックします。
  • ジオマッチルール国や地域で判定するもので、同じ国からの大量の試行は止められません。
  • セキュリティグループで443を閉じるすべての利用者がアクセスできなくなります。

③ CloudFrontに関連付けるWeb ACLを作るリージョンは?

  • us-east-1(バージニア北部)CloudFrontはグローバルなサービスなので、us-east-1で作ります。ALB用はALBと同じリージョンで作ります(サービスの範囲)。
  • アプリと同じリージョンCloudFront用のWeb ACLは、そのリージョンでは作れません。
  • どこでもよい関連付けられるのは、対象に合ったリージョン(スコープ)のWeb ACLだけです。

④ WAFを迂回して、ALBに直接アクセスされないようにするには?

  • ALBへの経路をCloudFrontからだけに絞るCloudFrontのマネージドプレフィックスリストをセキュリティグループに使い、カスタムヘッダーの確認も組み合わせます。
  • ALBを削除するアプリにつながらなくなります。
  • NLBに変える迂回の対策にならず、WAFも付けられなくなります。

3. 構成図#

CloudFrontにAWS WAFのWeb ACLを関連付け、マネージドルールとレートベースルールで攻撃を止めます。DDoSはShield Standardで自動的に守られ、大規模な攻撃への支援が必要ならShield Advancedを使います。ブロックの記録はWAFのログに残します。

4. 使うサービスと役割#

  • AWS WAF:マネージドルール(SQLインジェクション・既知の悪い入力・IP評価リスト)、レートベースルール、ジオマッチ、ログ
  • AWS Shield:Standard(自動)によるL3/L4のDDoS対策、必要ならAdvanced
  • Amazon CloudFront:エッジでの受付とキャッシュ
  • Elastic Load Balancing:オリジンのALB
  • Amazon CloudWatch:ルールごとのブロック件数の監視

5. 構築の流れ#

  1. CloudFront用のWeb ACLを作る(CloudFront用はus-east-1で作成)
  2. AWSマネージドルール(コアルールセット・SQLデータベース・既知の悪い入力・Amazon IP評価リスト)を追加する
  3. ログインのパスに、IPごとのレートベースルールを追加する。必要に応じて国のジオマッチやBot Controlを加える
  4. まずは新しいルールを Count で動かし、正常な通信を誤ってブロックしていないかログで確かめてから Block にする
  5. ALBのセキュリティグループで、CloudFrontのマネージドプレフィックスリストからの通信だけを許可する(またはCloudFrontのVPCオリジンを使う)
  6. WAFのログを有効にし(ロググループ名は aws-waf-logs- で始める)、ブロック件数にアラームを設定する

6. ポイント・注意点#

  • アプリ層の攻撃(SQLi・XSS)→ WAF。同じIPからの大量アクセス → レートベースルール。
  • CloudFrontのWeb ACLはus-east-1で作る。ALB用はALBと同じリージョン。
  • WAFは NLB・EC2に直接付けられない。CloudFront・ALB・API Gatewayなどの前段に付ける。
  • オリジンに直接アクセスされるとWAFを迂回されるので、ALBへの経路をCloudFrontからだけに絞る。
  • 大規模なDDoSへの24時間の支援や費用の保護が必要 → Shield Advanced。複数アカウントへ同じルールを展開 → Firewall Manager。
