手作業による設定変更(ドリフト)を見つけて戻す

CloudFormationのドリフト検出とConfigルールで、テンプレートと実際の設定のずれを定期的に見つける

最終更新:2026-10-25

1. やりたいこと#

CloudFormationで作った環境なのに、障害対応のときにコンソールでセキュリティグループのルールやインスタンスタイプを手で変えた人がいる。テンプレートと実際の設定が食い違うと、次のスタックの更新で失敗したり、変更が消えたりする。ずれ(ドリフト)を定期的に見つけて、どちらかに合わせたい。

2. 構成図#

3. 使うサービスと役割#

  • AWS CloudFormation:ドリフト検出(スタック・StackSets)、リソースのインポート
  • AWS Config:マネージドルール cloudformation-stack-drift-detection-check による定期的な確認
  • Amazon EventBridge/Amazon SNS:非準拠の通知
  • AWS IAM/AWS Organizations:本番環境のコンソールでの変更そのものを制限する

4. 構築の流れ#

  1. CloudFormationのコンソールまたはCLI(detect-stack-drift)でドリフト検出を実行し、DRIFTED のリソースと、期待値・実際の値の差分を確認する
  2. Configのルール cloudformation-stack-drift-detection-check を有効にし、ドリフト検出を定期的に実行させる
  3. 非準拠になったらEventBridge経由でSNSに通知する
  4. ずれを解消する:手作業の変更を残すべきならテンプレートを修正して更新する。不要な変更なら、リソースの設定をテンプレートどおりに戻す
  5. 再発を防ぐため、本番環境ではIAMやSCPで手作業の変更を制限し、変更はテンプレート経由で行う運用にする

5. ポイント・注意点#

  • テンプレートと実際の設定のずれを見つける → ドリフト検出。定期的に自動で → Configルール。
  • ドリフト検出は見つけるだけで、自動では直さない。テンプレートか実際のリソースのどちらかに合わせる。
  • テンプレートで明示的に指定したプロパティだけが比較の対象。ドリフト検出に対応していないリソースタイプもある。
  • CloudFormationの外で作ったリソースをスタックの管理下に入れる → リソースのインポート。
  • 複数アカウント・リージョンに展開したスタックは、StackSetsのドリフト検出でまとめて確認できる。
