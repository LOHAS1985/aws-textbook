機密データを保存するS3を暗号化・監査する

最終更新:2026-10-26

1. やりたいこと#

  • 個人情報を含むファイルをS3に保存する。保存時に暗号化したい。
  • 「いつ・誰がキーを使ってデータにアクセスしたか」を監査したい。
  • 想定外の場所に個人情報が置かれていないかを、定期的に点検したい。

2. 構成を組み立てる#

① S3の中の個人情報などの機密データを見つけるものは?

  • Amazon MacieS3のオブジェクトを分析し、個人情報などの機密データを検出します。
  • Amazon GuardDuty不正なアクセスなどの脅威を検出するもので、データの中身は調べません(セキュリティ検出のサービスの選び方)。
  • Amazon Inspectorソフトウェアの脆弱性を見つけるもので、S3のデータは調べません。

② キーの利用まで監査できる暗号化の方式は?

  • SSE-KMS(カスタマー管理キー)キーの利用がCloudTrailに記録され、キーポリシーで使える人も制御できます(暗号化)。
  • SSE-S3S3が管理するキーで暗号化されますが、キーの利用の記録は追えません。
  • 暗号化しない要件を満たしません。

③ オブジェクトの取得・削除をCloudTrailに記録するには?

  • 証跡でS3のデータイベントを有効にする既定で記録されるのは管理イベント(バケットの作成など)だけです。
  • S3のバージョニングを有効にする過去のバージョンが残るだけで、操作の記録にはなりません。
  • 何もしなくても記録されるオブジェクトの操作は、データイベントを有効にしないと記録されません。

3. 構成図#

SSE-KMSで暗号化し、キーの利用とS3のデータイベントをCloudTrailで記録し、Macieで個人情報の置き場所を点検します。読み取る側にも kms:Decrypt の権限が必要です。KMSのリクエストの料金は、S3バケットキーを有効にすると抑えられます。

4. 使うサービスと役割#

  • Amazon S3:SSE-KMSによる暗号化、バケットポリシーでのアクセス制御
  • AWS KMS:カスタマー管理キー(キーポリシーで利用者を制御、利用を監査)
  • AWS CloudTrail:KMSキーの利用と、S3のデータイベント(オブジェクトの取得・削除)を記録する
  • Amazon Macie:S3内の機密データ・個人情報を検出する

5. 構築の流れ#

  1. KMSでカスタマー管理キーを作成し、キーポリシーで利用できるロールを限定する
  2. S3バケットのデフォルト暗号化をSSE-KMS(作成したキー)にする
  3. バケットポリシーで、HTTPS以外の通信や、指定した暗号化方式以外のアップロードを拒否する
  4. CloudTrailの証跡で、このバケットのデータイベントを有効にする
  5. Macieを有効にし、バケットを定期的に分析するジョブを作成する

6. ポイント・注意点#

  • 鍵の利用を監査したい → SSE-KMS(SSE-S3ではキーの利用履歴を追えない)。
  • 読み取る側にも kms:Decrypt の権限が必要。
  • S3のオブジェクト操作の記録にはデータイベントの有効化が必要(管理イベントだけでは記録されない)。
  • S3の個人情報の検出 → Macie、不正アクセスなどの脅威検出 → GuardDuty。
  • KMSのリクエスト料金を抑えるには、S3バケットキーを有効にする。
