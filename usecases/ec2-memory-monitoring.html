EC2のメモリ・ディスク使用率を監視する

最終更新:2026-10-26

1. やりたいこと#

  • Amazon LinuxのEC2(複数台)のメモリ使用率とディスク使用率を監視したい。
  • メモリ使用率が80%以上の状態が5分続いたら、担当者にメールで知らせたい。
  • 収集の設定は全台で共通にし、変更するときも1か所を直すだけにしたい。

2. 構成を組み立てる#

① 全台で共通の収集の設定を置く場所は?

  • Systems Manager Parameter StoreCloudWatchエージェントは、Parameter Storeに置いた設定を fetch-config で取得できます。設定を1か所で管理し、全台に同じ設定を配れます。
  • AWS Secrets Managerパスワードなどの機密情報を保管し、ローテーションするためのサービスです。機密でない設定の置き場所には向きません(機密情報・設定値の保存先の選び方)。
  • 各インスタンスのユーザーデータユーザーデータは起動時に1回実行されるだけで、インスタンスごとに書くため、あとから全台の設定をまとめて変えられません。

② EC2の中でメモリ・ディスクの使用率を集めて送るものは?

  • CloudWatchエージェントメモリやディスクの使用率はOSの中の値なので、AWSの外側からは見えません。エージェントをインストールして、カスタムメトリクスとして送ります。
  • EC2の詳細モニタリング標準のメトリクスの間隔が5分から1分になるだけで、メモリやディスクの使用率は含まれません。
  • SSM AgentSystems Managerからの操作(Run Command・Session Managerなど)を受けるためのエージェントで、メトリクスは送りません。CloudWatchエージェントのインストールに使うことはできます。

③ アラームから担当者にメールで知らせるものは?

  • Amazon SNSアラームのアクションにSNSトピックを指定し、メールアドレスをサブスクリプションとして登録します。
  • Amazon SQSメッセージをためておくキューで、人に通知する仕組みはありません(メッセージングサービスの選び方)。
  • Amazon SESアプリからメールを送るサービスで、アラームのアクションには直接指定できません。

④ EC2に付けるIAMロールのポリシーは?

  • CloudWatchAgentServerPolicyメトリクス・ログの送信(cloudwatch:PutMetricData など)と、Parameter Storeの AmazonCloudWatch- で始まる設定の読み取りが許可された、エージェント用のAWS管理ポリシーです。
  • CloudWatchReadOnlyAccess読み取りの権限だけなので、メトリクスを送れません。
  • AdministratorAccess動きはしますが、必要以上の権限を与えることになり、最小権限の原則に反します。

⑤ エージェントが送ったメトリクスは、CloudWatchのどの名前空間に入る?(既定の設定)

  • CWAgentエージェントのメトリクスは既定で CWAgent 名前空間に入ります(メモリ使用率は mem_used_percent)。アラームはここのメトリクスで作ります。
  • AWS/EC2AWSが自動で集める標準のメトリクス(CPU使用率など)の名前空間です。エージェントの値はここには入りません。
  • AWS/CloudWatchこのような名前空間には入りません。AWS/ で始まる名前空間は、AWSのサービスが送る標準のメトリクス用です。

3. 構成図#

メモリ・ディスクの使用率はOSの中の値なので、CloudWatchエージェントでカスタムメトリクスとして送ります。設定はParameter Storeに置いて全台で共有し、EC2には CloudWatchAgentServerPolicy を付けたIAMロールを付けます。

アラームは CWAgent 名前空間の mem_used_percent で作り、「期間1分・5個中5個」のように評価の設定で「5分続いたら」を表します(CloudWatchアラームの状態と評価)。通知はアラームのアクションでSNSトピックに送ります。

台数が多い場合は、Systems Managerの State Manager でエージェントのインストールと設定の取得を全台に自動で行うと、新しく起動したインスタンスにも漏れなく設定できます。

4. 使うサービスと役割#

  • Amazon CloudWatch:エージェントでメトリクスを収集し、アラームでしきい値を監視する
  • AWS IAM:EC2のロールに CloudWatchAgentServerPolicy を付ける
  • AWS Systems Manager:エージェントの一括インストールや、設定ファイルをParameter Storeで共有する
  • Amazon SNS:アラーム発生時のメール通知

5. 構築の流れ#

  1. EC2のIAMロールに CloudWatchAgentServerPolicy をアタッチする
  2. CloudWatchエージェントをインストールする(多数のEC2にはSystems ManagerのRun CommandやDistributorで一括導入)
  3. 設定ファイル(JSON)に mem_used_percent・disk_used_percent を指定する(Parameter Storeに置くと全EC2で同じ設定を使える)
  4. エージェントを起動し、メトリクスがCloudWatchに届くことを確認する
  5. メトリクスにアラーム(例:80%以上が5分間)を作成し、通知先にSNSトピックを指定する

6. ポイント・注意点#

  • メモリ・ディスク使用率は詳細モニタリングを有効にしても取れない。エージェントが必要。
  • メトリクスが届かない → IAMロール、エージェントの起動状態、設定ファイルを確認する。
  • エージェントのメトリクスは、標準とは別の名前空間(CWAgent)に入る。
  • 同じエージェントでアプリのログファイルもCloudWatch Logsに送れる。
