VPCのIPアドレスを重ならずに払い出す構成を組み立てる

組織全体のVPCに、決めた範囲から重ならないCIDRを自動で割り当てる

最終更新:2026-10-26

1. 要件#

  • チームが自由にVPCを作った結果、CIDRが重なり、つなげないVPCが出てきた。
  • これから作るVPCには、決めた範囲から重ならないCIDRを自動で割り当てたい。
  • 使用状況を1か所で把握したい。

2. 構成を組み立てる#

① 組織全体のIPアドレスのプールを管理し、重複を防ぐものは?

  • Amazon VPC IP Address Manager(IPAM)プールの階層と割り当てのルールを決め、使用状況や重複を監視します(CIDR)。
  • Amazon Route 53DNSのサービスで、IPアドレスの範囲は管理しません。
  • Transit GatewayVPC同士をつなぐもので、CIDRが重ならないようにはしません。

② プールをほかのアカウントに共有するものは?

  • AWS Resource Access Manager(RAM)プールをOUやアカウントに共有し、各アカウントがVPCの作成時に使えるようにします。
  • CloudFormation StackSetsテンプレートを展開するもので、プールの共有はしません(VPCの作成には使えます)。
  • VPCピアリングVPC同士の接続で、プールの共有ではありません。

③ 既存のVPCのCIDRについて正しいものは?

  • CIDRは後から追加できるが、元のCIDRは変更できないセカンダリCIDRで範囲は広げられますが、重なりは作り直さないと解消できません。作る前の計画が大切です。
  • 元のCIDRをいつでも変更できるVPCの元のCIDRは変更できません。
  • 重なっていてもTransit Gatewayで問題なくつなげる重なった範囲は正しくルーティングできません。

3. 解説#

解説を見る(答え合わせのあとに読む)

委任管理者のアカウントでIPAMとプールを作り、RAMで本番のOUに共有します。各アカウントはVPCの作成時にプールを指定するだけで、重ならないCIDRが割り当てられます。プールの使用率はCloudWatchで監視し、枯渇の前に範囲を追加します。
