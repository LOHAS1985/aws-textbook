開発環境を夜間・休日に自動で停止して費用を下げる

最終更新:2026-10-26

1. やりたいこと#

  • 開発環境のEC2とRDSを、平日の20時(日本時間)に停止し、平日の9時に起動したい。
  • 対象は Env=dev のタグが付いたものだけにしたい(台数は今後増える)。
  • この処理のために、常に動かしておくサーバーは増やしたくない。

2. 構成を組み立てる#

① 決まった時刻に処理を起動するものは?

  • Amazon EventBridge Schedulerサーバーなしで、cron式・rate式のスケジュールでターゲットを起動できます。タイムゾーンを指定できるのも利点です。
  • 管理用のEC2で動かすcronそのEC2を常に動かしておく必要があり、「サーバーを増やさない」という要件に反します。
  • CloudWatchアラームメトリクスがしきい値を超えたときに動く仕組みで、時刻を決めて起動することはできません。

② EC2とRDSを停止・起動する手順を実行するものは?

  • Systems Manager AutomationAWSが用意したランブック(AWS-StopEC2Instance、AWS-StopRdsInstance など)で、APIを使って停止・起動できます。タグで対象を選ぶこともできます。
  • Systems Manager Run Commandインスタンスの中でコマンドを実行する機能です。RDSは操作できず、インスタンスの停止・起動にも向きません。
  • AWS Backupバックアップの取得と保管のサービスで、インスタンスの停止・起動はしません。

③ 「平日の20時(日本時間)」のスケジュールの指定として正しいものは?

  • タイムゾーンを Asia/Tokyo にして cron(0 20 ? * MON-FRI *)EventBridge Schedulerはタイムゾーンを指定できるので、日本時間のまま書けます。「日」と「曜日」のどちらかは ? にします(cron式とrate式)。
  • タイムゾーンを指定せずに cron(0 20 ? * MON-FRI *)UTCとして扱われ、日本時間の翌朝5時に実行されてしまいます。
  • rate(1 day)作成した時刻から1日ごとの実行になり、時刻も曜日も指定できません。

④ 停止・起動する対象の選び方は?

  • Env=dev のタグで選ぶ台数が増えても、タグを付けるだけで対象に加わります(タグ)。
  • インスタンスIDを1つずつ列挙する台数が増減するたびにスケジュールの設定を書き換える必要があり、漏れが起きやすくなります。
  • アカウントのすべてのインスタンスを対象にする本番環境まで止めてしまうおそれがあります。

⑤ RDSを停止するときの注意点として正しいものは?

  • 停止したDBインスタンスは7日たつと自動で起動するそのため、長期間止めておく場合も、毎日の停止の処理で止め直す必要があります。停止中は、インスタンスの料金はかからず、ストレージとバックアップの料金はかかります。
  • 一度停止すれば、起動するまでずっと止まったままになるRDSは最大7日で自動的に起動します。
  • 停止中もインスタンスの料金がかかり続ける停止中はインスタンスの時間料金はかかりません。かかるのはストレージとバックアップの料金です。

3. 構成図#

EventBridge Schedulerが日本時間で指定した時刻にSSM Automationを起動し、Env=dev のタグが付いたEC2・RDSを停止・起動します。どちらもサーバーを用意する必要がなく、Automationに渡すIAMロールには停止・起動に必要な権限だけを与えます(iam:PassRole)。

Auto Scalingグループに属するEC2は、個別に停止してもヘルスチェックで入れ替えられてしまうので、グループのスケジュールされたアクションで台数を0にします。

4. 使うサービスと役割#

  • Amazon EventBridge:Scheduler(cron式・タイムゾーン指定)で決まった時刻に処理を起動
  • AWS Systems Manager:Automationランブック(AWS-StopEC2Instance・AWS-StartEC2Instance・AWS-StopRdsInstance など)をタグの対象に実行
  • Amazon EC2/Amazon RDS:停止・起動の対象
  • Amazon EC2 Auto Scaling:スケジュールされたアクションで希望容量を変更
  • AWS Cost Explorer:タグ別の費用で効果を確認

5. 構築の流れ#

  1. 対象のリソースにタグ(例:Schedule=office-hours)を付ける
  2. Automationの実行用IAMロール(EC2・RDSの停止・起動の権限)を作る
  3. EventBridge Schedulerで、平日20時(タイムゾーンを Asia/Tokyo に指定)に停止のランブックを、タグを対象に実行するスケジュールを作る。同様に9時の起動も作る
  4. Auto Scalingグループは、ランブックではなくスケジュールされたアクションで、夜間は最小・希望容量を0、朝に元の値へ戻す(グループ内のインスタンスを直接止めると、Auto Scalingが置き換えてしまう)
  5. Cost Explorerでタグ別の費用を確認し、効果を測る

6. ポイント・注意点#

  • 決まった時刻に処理を起動 → EventBridge Scheduler(cron式とタイムゾーン)。
  • Auto Scalingのインスタンスを止めたい → インスタンスを止めるのではなく、スケジュールされたアクションで台数を変える。
  • RDSを停止できるのは最大7日。7日を過ぎると自動で起動するので、長く止めるなら毎週止め直すか、スナップショットを取って削除する。
  • EC2を停止しても、EBSボリュームとElastic IPの料金はかかる。インスタンスストアのデータは消える。
  • 多数のアカウントでまとめて管理したいなら、AWSが公開している Instance Scheduler on AWS のソリューションも使える。
