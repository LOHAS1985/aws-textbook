DBのパスワードを自動でローテーションする

最終更新:2026-10-26

1. やりたいこと#

  • DBのパスワードを、コードや設定ファイルに書かずに管理したい。
  • 30日ごとに自動でパスワードを変更し、その間もアプリの接続を止めたくない。

2. 構成を組み立てる#

① パスワードを保管し、自動のローテーションもできるものは?

  • AWS Secrets ManagerシークレットをKMSで暗号化して保管し、決めた間隔で自動でローテーションします。
  • Systems Manager Parameter Store暗号化して保管できますが、自動のローテーションの機能はありません(機密情報・設定値の保存先の選び方)。
  • Amazon S3に置いたファイルファイルに書くのと同じで、ローテーションの仕組みもありません。

② ローテーションのときに、DBとシークレットのパスワードを変更するものは?

  • ローテーション用のLambda関数Secrets Managerが起動し、DBのパスワードとシークレットの値を更新します。RDS用にはAWSが用意した関数があります。
  • AWS CodeDeployアプリをデプロイするもので、パスワードは変更しません。
  • Patch ManagerOSのパッチを当てるもので、パスワードは変更しません。

③ アプリのロールに必要な権限は?

  • secretsmanager:GetSecretValue と、キーの kms:DecryptシークレットはKMSで暗号化されているので、取得には両方が必要です。
  • rds:ModifyDBInstanceDBの設定を変える権限で、アプリには不要です。
  • AdministratorAccess最小権限に反します。

3. 構成図#

アプリは接続のたびにSecrets Managerから認証情報を取得し、ローテーションはLambdaが行うので、アプリのコードを変える必要はありません。接続を切らしたくない場合は、2つのユーザーを交互に使う「交代ユーザー方式」にします。ローテーション用のLambdaをVPCに置く場合は、Secrets ManagerのVPCエンドポイントかNATが必要です。

4. 使うサービスと役割#

  • AWS Secrets Manager:認証情報の保管・取得(GetSecretValue)・自動ローテーション
  • AWS KMS:シークレットの暗号化
  • AWS Lambda:ローテーション処理の実行
  • Amazon RDS:パスワードを変更する対象のDB
  • AWS IAM:アプリに secretsmanager:GetSecretValue と kms:Decrypt を許可する

5. 構築の流れ#

  1. Secrets ManagerにDBの認証情報(ユーザー名・パスワード・ホスト)を保存する
  2. ローテーションを有効にし、間隔(例:30日)と方式(シングルユーザー/交代ユーザー)を選ぶ
  3. アプリのIAMロールにシークレットの取得とKMSの復号を許可する
  4. アプリを、起動時や接続時にシークレットを取得するように変更する

6. ポイント・注意点#

  • 自動ローテーションが必要 → Secrets Manager(Parameter Storeにはない)。
  • ローテーション中も接続を切らしたくない → 交代ユーザー方式。
  • ローテーション用LambdaをVPC内に置く場合は、Secrets ManagerへのVPCエンドポイントかNATゲートウェイが必要。
  • CloudFormationからはダイナミックリファレンスで参照し、テンプレートにパスワードを書かない。
