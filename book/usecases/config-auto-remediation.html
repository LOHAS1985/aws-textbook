公開されたS3バケットを検出して自動で修復する

最終更新:2026-10-26

1. やりたいこと#

  • 社内のルールで、S3バケットのパブリックアクセスを禁止している。
  • 誤って公開されたバケットを自動で見つけ、人手を介さずに設定を元に戻したい。
  • 見つかったことは、担当者にもメールで知らせたい。

2. 構成を組み立てる#

① バケットの設定がルールに違反していないかを評価するものは?

  • AWS Configのルールマネージドルール(例:s3-bucket-level-public-access-prohibited)で設定を評価し、違反を NON_COMPLIANT と判定します。修復アクションも設定できます。
  • AWS CloudTrail誰がいつ設定を変えたかを記録するサービスで、設定がルールに合っているかは評価しません(監視・記録のサービスの選び方)。
  • Amazon InspectorEC2・コンテナイメージ・Lambdaの脆弱性を見つけるサービスで、S3バケットの設定は評価しません。

② Configの修復アクションとして、設定を直す処理を実行するものは?

  • Systems Manager AutomationのランブックConfigの修復アクションに指定できるのは、SSM Automationのランブックです。ブロックパブリックアクセスを有効にするAWS提供のランブックがあります。
  • Lambda関数(修復アクションに直接指定)修復アクションにLambda関数を直接は指定できません。独自の処理が必要なら、ランブックの中からLambdaを呼びます。
  • S3のライフサイクルルール古いオブジェクトの移動や削除を自動で行う機能で、公開の設定は直せません。

③ 違反が見つかったことを受け取り、SNSに渡すものは?

  • Amazon EventBridgeのルールConfigの「準拠状況の変化」のイベントをイベントパターンで選び、SNSトピックに送ります(イベント駆動の自動修復)。
  • CloudWatch Logsログを保存するサービスで、Configのイベントを受けて通知する役割はありません。
  • Amazon SQSキューにためるだけで、人への通知はできません。

④ 「人手を介さずに直す」ための修復アクションの設定は?

  • 自動修復を有効にする(再試行の回数も設定)違反と判定されるたびに自動でランブックが実行されます。
  • 手動修復にして、担当者がコンソールから実行する人の操作が必要なので、要件を満たしません。まず手動で動きを確かめてから自動に切り替える使い方はあります。
  • Configの記録を停止して、違反が出ないようにする違反が見えなくなるだけで、バケットは公開されたままです。

⑤ ランブックが設定を変更するときに使う権限は?

  • 修復に必要な権限だけを与えたIAMロール(AutomationAssumeRole に指定)最小権限で修復させます。このロールを設定する人には iam:PassRole の権限が必要です(iam:PassRoleとサービスにリンクされたロール)。
  • Configのサービスにリンクされたロールの権限で自動的に実行されるサービスにリンクされたロールは、Configが設定を記録するためのもので、修復の権限は含みません。
  • ルートユーザーの権限で実行するルートユーザーは日常の作業や自動化に使いません(ルートユーザーとアカウントの保護)。

3. 構成図#

Configのルールで違反を検出し、修復アクション(自動)でSSM Automationのランブックを実行して設定を直します。違反のイベントはEventBridgeのルールでSNSに送り、担当者に知らせます。

そもそも公開できないようにする予防の対策として、アカウントのブロックパブリックアクセスを有効にし、SCPで無効化を禁止する方法もあります。「検出して直す」と「最初から防ぐ」を組み合わせるのが確実です。

4. 使うサービスと役割#

  • AWS Config:設定レコーダーで変更を記録し、Configルールで評価し、修復アクションを起動する
  • AWS Systems Manager:Automationランブックで設定を修正する
  • AWS Security Hub:セキュリティ基準のチェック結果を集約する
  • Amazon EventBridge/Amazon SNS:検出結果の通知
  • AWS CloudTrail:誰が公開設定にしたかを調べる

5. 構築の流れ#

  1. AWS Configの設定レコーダーを有効にする
  2. S3のパブリックアクセスを禁止するAWSマネージドルールを追加する
  3. ルールに修復アクション(SSM Automationのランブック)を設定し、自動修復を有効にする。Automationが使うIAMロールも用意する
  4. Security Hubを有効にし、EventBridgeルールで重要な検出結果をSNSに通知する

6. ポイント・注意点#

  • 「設定が要件を満たしているか」を継続的に評価 → Config。「誰が変更したか」→ CloudTrail。
  • 非準拠の自動修復 → 修復アクション+SSM Automation。
  • 複数のルールと修復をまとめて展開 → Conformance Packs。
  • そもそも公開させない予防策として、アカウント単位のS3ブロックパブリックアクセスや、SCPでの禁止も併用する。
