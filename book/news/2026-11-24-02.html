Systems Manager:Automation で Azure・Google Cloud の運用作業も自動化

Systems Manager Automation のランブックが、AWS だけでなく Azure と Google Cloud のリソースも対象にできるようになりました。

最終更新:2026-11-24

1. 発表の内容#

Systems Manager Automation(手順書=ランブックを作り、運用作業を自動で実行する機能)が、Microsoft Azure と Google Cloud のリソースを操作できるようになりました。誤った設定の修正や使われていないリソースの片付けなどを、クラウドごとに別のツールや認証情報を用意せず、1か所から実行できます。

Azure や Google Cloud の API を呼ぶ、リソースの状態を確認する、操作の完了を待つ、という6つの新しいアクションが加わりました。対象は、Azure ならサブスクリプション・リージョン・リソースグループ・種類・タグ、Google Cloud ならプロジェクト・ゾーン・アセットの種類・ラベルで絞れます。コードを書く場合の aws:executeScript には両クラウドの Python SDK が入り、一時的な認証情報は Systems Manager の Cloud Connector から渡されるので、ランブックに秘密情報を保存しません。段階的な実行、承認での一時停止、エラーが多いときの中断も従来どおり使えます。

説明の中心 成功・推奨・正常 利用者・外部・送信元

何がうれしいか
複数のクラウドを使う環境でも、承認・段階実行・エラー時の中断といった安全な仕組みをそのまま使えます。AWS が用意したランブックで、Azure や Google Cloud の仮想マシンへ SSM Agent や Amazon Inspector のエージェントも入れられます。
試験・実務への影響
Automation のランブックは運用の自動化と自動修復の中心です。対象が AWS の外にも広がったと押さえておきましょう。利用できるのは Cloud Connector を作れるリージョンです。
