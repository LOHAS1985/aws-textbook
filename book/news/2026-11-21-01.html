Route 53:プライベートなエンドポイントにもヘルスチェックが可能に

インターネットに公開していない内部のサーバーにも Route 53 のヘルスチェックを使え、異常時の DNS フェイルオーバーが自動でできるようになりました。

最終更新:2026-11-21

1. 発表の内容#

Route 53 のヘルスチェックは、対象が正常かを定期的に確認し、異常なら DNS の応答を正常な宛先へ切り替える(DNS フェイルオーバー)仕組みです。これまでは、インターネットから到達できる宛先しか確認できませんでした。そのため、内部の API やデータベース、プライベートサブネット内のサーバーでは、CloudWatch アラーム・Lambda 関数・Route 53 の API を組み合わせた自前の仕組みが必要で、切り替えに数分かかっていました。

今回の「プライベートエンドポイントのヘルスチェック」では、VPC から到達できる宛先なら、IP アドレス・ドメイン名・ポートを指定して HTTP・HTTPS・TCP で確認できます。プライベートホストゾーンのレコードに関連付ければ、異常な宛先を外す切り替えを Route 53 が自動で行います。Direct Connect や Site-to-Site VPN の先にあるオンプレミスの宛先も対象で、Transit Gateway や Cloud WAN をはさんだリージョン間の災害対策にも使えます。

説明の中心 成功・推奨・正常 失敗・非推奨・障害 その他の構成要素

説明の中心 成功・推奨・正常 失敗・非推奨・障害 利用者・外部・送信元 点線の矢印(使われない・切り替え前・補足)

何がうれしいか
自前の監視と切り替えの仕組みが要らなくなり、運用の手間が減ります。切り替えも速くなります。インターネットへの公開も不要です。
試験・実務への影響
「内部のリソースの DNS フェイルオーバーを、管理の手間を増やさず行いたい」という場面の答えになります。ヘルスチェックはこれまで公開エンドポイントが前提だった、という違いを押さえましょう。
