Secrets Manager:アカウントをまたぐレプリケーションに対応

Secrets Manager のシークレットを、別の AWS アカウントへ自動で複製できるようになりました。

最終更新:2026-11-14

1. 発表の内容#

AWS Secrets Manager は、パスワードや API キーなどの秘密情報(シークレット)を安全に保管し、ローテーション(定期的な更新)も自動化するサービスです。これまでもリージョンをまたぐ複製はできましたが、今回、アカウントをまたぐレプリケーションに対応しました。元のシークレット(プライマリ)を持つアカウントとは別のアカウントに、同じ内容のコピー(レプリカ)を作り、値が変わるたび(ローテーションを含む)自動で同期されます。

レプリカは独立したリソースで、レプリカ側のアカウントが持つカスタマー管理の KMS キーで暗号化されます。そのため、KMS キーの共有や、アカウント間のシークレットポリシーの設定は要りません。セキュリティ担当のアカウントで一元的にシークレットを管理しつつ、利用側の各アカウントはすぐ近くのコピーを読めます。また、ランサムウェアやアカウント侵害に備え、復旧専用の別アカウントに最新のコピーを置く使い方もできます。必要ならレプリカを単独のシークレットに昇格できます。

説明の中心 成功・推奨・正常 利用者・外部・送信元 その他の構成要素

何がうれしいか
鍵やポリシーをアカウント間で共有せずに、最新のシークレットを各アカウントへ配れます。復旧用の隔離アカウントへのバックアップにも使えます。
試験・実務への影響
「リージョン間の複製」に加え「アカウント間の複製」が選択肢になりました。マルチアカウント構成での機密情報の配布や、事業継続の設計で押さえておきたい機能です。
