EventBridge:カスタムイベントバスが Webhook を直接受け取れるように

拡張カスタムイベントバスに Webhook イベントの受信口ができ、自前の API エンドポイントなしで外部からイベントを受け取れます。

最終更新:2026-11-23

1. 発表の内容#

Webhook は、外部のサービスが出来事(出荷状況の更新など)を HTTPS で相手のURLへ知らせる仕組みです。これまで、AWS で Webhook を受けるには、API Gateway と Lambda などで受け口を作って運用する必要がありました。

今回、EventBridge の拡張カスタムイベントバスに「Webhook イベントソース」を作ると、EventBridge が HTTPS のURLを用意します。届いたリクエストは、HMAC 署名・固定トークン・基本認証のいずれかで検証され、通ったものだけがバスに入ります。その後は、ルールにあたるサブスクライバーが絞り込んで配信するのは、これまでのイベントと同じです。

説明の中心 成功・推奨・正常 利用者・外部・送信元 その他の構成要素

何がうれしいか
受け口用の API とコンピューティングを作って運用する手間がなくなります。Webhook の分の追加料金はなく、通常のカスタムイベントバスへの入力として課金されます。
試験・実務への影響
「外部のSaaSからのイベントを、運用の手間を増やさずに取り込む」という場面で、選べる構成が増えました。疎結合なイベント駆動の構成の一部として押さえておきましょう。
