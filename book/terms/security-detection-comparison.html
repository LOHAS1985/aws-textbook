セキュリティ検出のサービスの選び方

GuardDuty・Inspector・Macie・Config・Security Hub CSPMなどを「何を見つけるか」で使い分ける

最終更新:2026-10-26

1. 詳しい説明#

AWSには、セキュリティ上の問題を見つけるサービスが複数あります。名前からは役割が分かりにくいですが、見つけるもので整理すると区別できます。不正なアクセスなどの「脅威」、ソフトウェアの「脆弱性」、S3の中の「機密データ」、リソースの「設定の不備」です。それぞれの検出結果をSecurity Hub CSPMに集めて、EventBridgeで通知や自動対応につなげるのが基本の形です。

比較表#

サービス見つけるもの対象データの取り方
GuardDuty脅威(不正アクセス、乗っ取られたEC2、暗号資産のマイニング、マルウェアなど)アカウント・EC2・S3・EKSなどCloudTrail・VPCフローログ・DNSログを自動で分析。設定やエージェントは不要
Inspectorソフトウェアの脆弱性(CVE)、意図しないネットワークの公開EC2・ECRのコンテナイメージ・LambdaEC2はSSMエージェント(またはエージェントレスのスキャン)。継続的に再スキャン
Macie機密データ(個人情報・認証情報など)、公開されたバケットS3S3のオブジェクトの中身を機械学習とパターンで調べる
AWS Configルールに違反した設定ほぼすべてのリソース設定の変更を記録し、ルールで評価する
Security Hub CSPMセキュリティ基準(AWS基礎セキュリティのベストプラクティス、CISなど)への違反。他サービスの結果の集約アカウント全体(組織全体も可)Configのルールでチェックし、各サービスの結果を共通の形式で集める
Amazon Detective検出結果の原因と影響範囲(調査用)GuardDutyなどの検出結果ログから関係をグラフにして、調査を助ける
IAM Access Analyzer外部のアカウントに公開されたリソース、使われていない権限S3・IAMロール・KMSキーなどポリシーを分析する
Trusted Advisorベストプラクティスからの逸脱(全ポートを開けたSG、ルートユーザーのMFAなど)アカウント定期的にチェックする(全項目はBusiness以上のサポートプラン)

2025年に、従来のSecurity Hubは「Security Hub CSPM」という名前になりました。「Security Hub」の名前は、GuardDuty・Inspector・Macie・Security Hub CSPMの結果を関連付けてリスクを分析する新しいサービスに使われています。

見つけたあとの対応#

検出サービスは問題を見つけるだけで、多くは自分では直しません。対応は、検出結果のイベントをEventBridgeで受けて、Lambdaや Systems Manager Automationで自動化します。たとえば、GuardDutyが乗っ取られたEC2を見つけたら、隔離用のセキュリティグループに付け替えます(運用シナリオ「乗っ取られたEC2を自動で隔離する」)。Configのルール違反には、Configの自動修復を設定できます。

選び方のポイント#

  • 不審なAPI呼び出しや、EC2が怪しいIPと通信しているのを見つけたい → GuardDuty。
  • EC2やコンテナイメージの脆弱性(CVE)を見つけたい → Inspector(運用シナリオ「脆弱性を継続的に検出し、パッチ適用まで自動化する」)。
  • S3に個人情報が保存されていないかを調べたい → Macie(運用シナリオ「機密データを保存するS3を暗号化・監査する」)。
  • 「暗号化されていないEBSがないか」など、自社の設定ルールを継続的にチェックしたい → AWS Config。
  • CISなどのセキュリティ基準にどれだけ準拠しているかを点数で見たい・複数のサービスの結果を1か所で見たい → Security Hub CSPM。
  • GuardDutyの検出結果について、原因や影響範囲を詳しく調べたい → Detective。
  • S3バケットやIAMロールが外部のアカウントに公開されていないかを知りたい → IAM Access Analyzer。
  • InspectorでEC2がスキャンされない → SSMエージェントが動いていて、Systems Managerの管理対象になっているかを確認する。
  • 組織の全アカウントでまとめて有効にしたい → Organizationsで委任管理者のアカウントを決め、そこから全アカウントに有効化する(GuardDuty・Inspector・Macie・Security Hub CSPMとも対応)。

2. 関連する用語#

  • 監視・記録のサービスの選び方:GuardDutyが分析するログ(CloudTrail・VPCフローログ)
  • VPCフローログ:IP通信の記録
  • IAMポリシーの評価:Access Analyzerが分析するポリシー
  • 暗号化:Configのルールで確認する代表的な設定

3. 関連サービス#

  • Amazon GuardDuty:脅威の検出
  • Amazon Inspector:脆弱性の検出
  • Amazon Macie:S3の機密データの検出
  • AWS Config:設定の記録とルールでの評価
  • AWS Security Hub:検出結果の集約とセキュリティ基準のチェック
  • AWS IAM:IAM Access Analyzer
  • AWS Trusted Advisor:ベストプラクティスのチェック
  • Amazon EventBridge:検出結果を通知・自動対応に振り分ける

この用語が出てくるページ#

  • Amazon GuardDutyサービスログを機械学習と脅威インテリジェンスで分析し、不正アクセスやマルウェアを検出
  • Amazon InspectorサービスEC2・コンテナイメージ・Lambdaのソフトウェアの脆弱性とネットワークの露出を継続的にスキャン
  • Amazon MacieサービスS3の機密データや個人情報(PII)を検出・分類
  • AWS Security Hubサービスセキュリティ検出結果を集約し、基準への準拠状況を一元管理
  • AWS Trusted AdvisorサービスAWS環境を自動チェックし、ベストプラクティスに沿った改善を提案
