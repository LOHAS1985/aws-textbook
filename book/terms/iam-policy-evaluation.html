1. 詳しい説明#

AWSでは、APIの呼び出し(リクエスト)のたびに、関係するすべてのポリシーを調べて「許可するか拒否するか」を決めます。ポリシーの書き方と、この判断の順番(評価ロジック)を知っておくと、「なぜ権限エラーになるのか」を自分で切り分けられるようになります。

ポリシーの書き方#

ポリシーはJSONで書きます。次の例は「特定のバケットのオブジェクトの読み取りを、会社のIPアドレスからだけ許可する」ポリシーです。

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["s3:GetObject"],
      "Resource": "arn:aws:s3:::my-bucket/*",
      "Condition": {
        "IpAddress": { "aws:SourceIp": "203.0.113.0/24" }
      }
    }
  ]
}
要素意味例
Effect許可か拒否かAllow/Deny
Action対象の操作(サービス:API名)s3:GetObject、ec2:*(ワイルドカード)
Resource対象のリソース(ARNで指定)arn:aws:s3:::my-bucket/*
Condition適用する条件(省略可)送信元IP、MFAの有無、リージョン、タグ
Principal誰に対するものか(リソースベースのポリシーだけで使う)別アカウントのロールのARN、"Service": "lambda.amazonaws.com"

よく使う条件キー:aws:SourceIp(送信元IP)、aws:MultiFactorAuthPresent(MFAで認証したか)、aws:RequestedRegion(操作対象のリージョン)、aws:PrincipalOrgID(呼び出し元が自組織のアカウントか)、aws:SecureTransport(HTTPSか)、aws:ResourceTag/キー(リソースのタグ)。

ポリシーの種類#

種類付ける場所役割
アイデンティティベースのポリシーIAMユーザー・グループ・ロール「このユーザーは何ができるか」を許可する。AWS管理ポリシー(AWSが用意)、カスタマー管理ポリシー(自分で作って再利用)、インラインポリシー(1つのユーザー・ロールに直接埋め込む)がある
リソースベースのポリシーS3バケット、SQSキュー、KMSキー、Lambda関数など「このリソースを誰が使えるか」を許可する。Principal で相手を指定するので、他のアカウントやAWSサービスにも許可できる
アクセス許可の境界(Permissions Boundary)IAMユーザー・ロールそのユーザー・ロールが持てる権限の上限。権限を与えるものではない
SCP・RCPOrganizationsのルート・OU・アカウント組織のアカウント内のプリンシパル(SCP)・リソース(RCP)に対する権限の上限
セッションポリシーAssumeRoleなどで一時的な認証情報を作るときそのセッションだけ権限をさらに絞る

「上限」を決めるポリシー(境界・SCP・RCP・セッションポリシー)は、それだけでは何も許可しません。上限の範囲内で、アイデンティティベースまたはリソースベースのポリシーが許可した操作だけが実行できます。

評価ロジック(許可か拒否かの決まり方)#

  1. 最初はすべて拒否(暗黙的な拒否)の状態から始まる。
  2. 関係するポリシーのどこかに、そのリクエストに当てはまる明示的な Deny があれば、ほかでどれだけ許可していても拒否(明示的な拒否が最優先)。
  3. SCP・RCP・アクセス許可の境界・セッションポリシーがある場合、そのすべてで許可されている範囲に入っていなければ拒否。
  4. アイデンティティベースまたはリソースベースのポリシーに、当てはまる Allow があれば許可。どこにもなければ拒否(暗黙的な拒否のまま)。

同じアカウントと別のアカウント#

  • 同じアカウント内:アイデンティティベースとリソースベースのどちらか一方で許可されていれば実行できる(KMSのキーポリシーのように、リソース側の許可が必須なものもある)。
  • 別のアカウントへのアクセス:相手のリソースベースのポリシー(または引き受けるロールの信頼ポリシー)と、自分のアカウントのアイデンティティベースのポリシーの両方で許可されている必要がある。

権限の確認・見直しに使う機能#

機能できること
IAM Access Analyzer外部(他のアカウントや公開)からアクセスできるリソースを検出する。未使用の権限・ロールの検出、ポリシーの文法チェック、CloudTrailの記録からのポリシー生成もできる
認証情報レポートアカウント内の全IAMユーザーの、パスワード・アクセスキー・MFAの状態と最終使用日を一覧(CSV)にする
最終アクセス情報ユーザー・ロールが各サービスを最後に使った日時を表示する。使われていない権限を削る判断に使う
ポリシーシミュレーターあるユーザー・ロールが特定の操作を実行できるかを、実際に操作せずに試す

エラーメッセージが暗号化されている(Encoded authorization failure message)場合は、aws sts decode-authorization-message でデコードすると、どのポリシーで拒否されたかの手がかりが得られます。

2. 関連する用語#

  • ARN:ポリシーの Resource や Principal の指定に使う
  • OIDC:外部のIDプロバイダーで認証してロールを引き受ける
