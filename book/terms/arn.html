ARN

AWSのリソースを世界で一意に指し示す名前(Amazon Resource Name)

最終更新:2026-10-25

1. 詳しい説明#

ARN(Amazon Resource Name)は、AWSのリソースを一意に識別するための名前です。IAMポリシーで「どのリソースへの操作を許可するか」を書くときや、CLI・API・CloudFormationで別のリソースを指定するときに使います。

形式#

arn:パーティション:サービス:リージョン:アカウントID:リソース
例:arn:aws:lambda:ap-northeast-1:123456789012:function:MyFunction
部分意味例
パーティションAWSの大きな区分通常は aws(中国は aws-cn、米国政府向けは aws-us-gov)
サービスサービスの名前空間s3、ec2、iam、lambda
リージョンリソースがあるリージョンap-northeast-1。グローバルなリソースでは空欄
アカウントIDリソースを所有する12桁のアカウントID123456789012。S3バケットなどでは空欄
リソースリソースの種類と名前・IDinstance/i-0abc…、role/MyRole、my-bucket/*

よく見るARNの例#

リソースARNポイント
S3バケットarn:aws:s3:::my-bucketバケット名が世界で一意なので、リージョンとアカウントIDは空欄
S3のオブジェクトarn:aws:s3:::my-bucket/*バケット内の全オブジェクト。バケット自体の操作(s3:ListBucket)とオブジェクトの操作(s3:GetObject)でARNが違う点に注意
IAMロールarn:aws:iam::123456789012:role/MyRoleIAMはグローバルなのでリージョンは空欄
EC2インスタンスarn:aws:ec2:ap-northeast-1:123456789012:instance/i-0abc123すべての部分が埋まる
Lambda関数のエイリアスarn:aws:lambda:ap-northeast-1:123456789012:function:MyFunction:prod末尾にエイリアス名やバージョン番号を付けると、その版を指す

ポリシーでの使い方#

  • IAMポリシーの Resource にARNを書いて、操作の対象を絞る。
  • *(任意の文字列)や ?(任意の1文字)のワイルドカードを使える。例:arn:aws:s3:::logs-*/* は「logs- で始まるすべてのバケットのオブジェクト」。
  • リソースベースのポリシーでは、Principal に相手のアカウントやロールのARNを書く。

S3で「バケットの一覧は見られるのにオブジェクトが取得できない」(またはその逆)というときは、Resource に arn:aws:s3:::my-bucket(バケット)と arn:aws:s3:::my-bucket/*(オブジェクト)の両方が正しく書かれているかを確認します。

2. 関連する用語#

  • IAMポリシーと評価ロジック:ARNを使ってポリシーを書く
  • リージョンとアベイラビリティーゾーン:グローバルなリソースはARNのリージョンが空欄になる

3. 関連サービス#

  • AWS IAM:ポリシーの Resource・Principal
  • Amazon S3:バケットとオブジェクトでARNが異なる
  • AWS Lambda:バージョン・エイリアスのARN
  • AWS CloudFormation:!GetAtt などでリソースのARNを取得する
