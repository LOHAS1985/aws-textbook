1. 詳しい説明#

インスタンスプロファイルは、EC2インスタンスにIAMロールを渡すための入れ物(コンテナ)です。EC2にはIAMロールを直接付けることはできず、「インスタンス → インスタンスプロファイル → IAMロール」の形で付けます。インスタンス上のアプリやAWS CLIは、このロールの一時的な認証情報を自動で受け取るため、アクセスキーをインスタンスに保存する必要がありません。

ロールとインスタンスプロファイルの関係#

項目内容
入れられるロールの数1つのインスタンスプロファイルにロールは1つだけ
インスタンスに付けられる数1つのインスタンスにインスタンスプロファイルは1つだけ。複数の権限が必要なら、1つのロールに複数のポリシーを付ける
ロールの信頼ポリシー"Service": "ec2.amazonaws.com" を許可する(EC2がロールを引き受けられるようにする)
付け替え起動中のインスタンスでも、停止せずに付ける・外す・入れ替える(replace-iam-instance-profile-association)ことができる
ロールの権限の変更ロールのポリシーを変えると、付け替えなくても反映される(反映まで少し時間がかかることがある)

作り方:コンソールとCLI・IaCの違い#

マネジメントコンソールでEC2用のロールを作ると、同じ名前のインスタンスプロファイルが自動で作られます。そのため普段は意識しませんが、AWS CLI・CloudFormation・Terraformでは、ロールとは別にインスタンスプロファイルを作り、ロールを入れる必要があります。

aws iam create-role --role-name AppRole --assume-role-policy-document file://ec2-trust.json
aws iam create-instance-profile --instance-profile-name AppProfile
aws iam add-role-to-instance-profile --instance-profile-name AppProfile --role-name AppRole
aws ec2 associate-iam-instance-profile --instance-id i-0123456789abcdef0 \
    --iam-instance-profile Name=AppProfile

CloudFormationでは AWS::IAM::Role とは別に AWS::IAM::InstanceProfile を定義し、EC2や起動テンプレートの IamInstanceProfile にはインスタンスプロファイルの名前(またはARN)を指定します。ここにロール名を書いてしまうのはよくある間違いです(コンソールで作った場合は名前が同じなので動いてしまい、気づきにくい)。

インスタンスにロールを付けるときの権限#

インスタンスにインスタンスプロファイルを付ける人(またはAuto Scalingなどのサービス)には、EC2の操作権限に加えて、中のロールに対する iam:PassRole の権限が必要です。これがないと、強い権限のロールを付けたインスタンスを起動して、その権限を使うことができてしまうためです。

認証情報の取得とIMDSv2#

インスタンス上では、ロールの認証情報が http://169.254.169.254/latest/meta-data/iam/security-credentials/ロール名 から取得できます。AWS CLIやSDKは認証情報を探す順番の最後にここを見に行くため、プログラムで設定する必要はありません。

  • IMDSへのアクセスは、トークンを使うIMDSv2を必須にする(SSRFの脆弱性から認証情報を盗まれにくくする)
  • 環境変数や ~/.aws/credentials にアクセスキーが残っていると、そちらが優先される
  • インスタンス上で aws sts get-caller-identity を実行すると、どのロールで動いているか確認できる
