Amazon VPC

AWS上に論理的に分離された仮想ネットワークを作るサービス

1. サービス概要

Amazon VPC(Virtual Private Cloud)は、AWS上に論理的に分離された仮想ネットワークを構築するサービスです。

  • AWS内に自分専用のネットワーク空間を作成できる
  • IPアドレス範囲(CIDR)を自由に定義できる
  • サブネット単位でリソースを配置する

2. 主な機能・特徴

構成要素

構成要素役割
サブネットVPC内のネットワークの分割単位
ルートテーブル通信経路の制御
インターネットゲートウェイVPCとインターネットを接続(パブリックサブネットで利用)
NATゲートウェイプライベートサブネットからインターネットへのアウトバウンド通信のみ許可(外部からのアクセスは不可)
VPCエンドポイントインターネットを経由せずにVPCからAWSサービスへプライベート接続する
セキュリティグループアクセス制御。インスタンス単位、許可のみ設定可能
ネットワークACLアクセス制御。サブネット単位、許可/拒否の両方を設定可能

セキュリティグループはステートフル(戻りの通信は自動で許可)、ネットワークACLはステートレス(戻りの通信も明示的に許可が必要)です。

「パブリックサブネット」とは、ルートテーブルにインターネットゲートウェイへの経路(0.0.0.0/0 → IGW)があるサブネットのことです。

3. ユースケース

  • Webサーバーはパブリックサブネット、DBはプライベートサブネットに配置する多層構成
  • プライベートサブネットのサーバーからNATゲートウェイ経由でOSアップデートを取得
  • VPCエンドポイントでS3などにインターネットを経由せずアクセス

4. 料金の考え方

VPC・サブネット・ルートテーブル・セキュリティグループ自体は無料です。NATゲートウェイ(時間+処理データ量)、インターフェース型VPCエンドポイント、パブリックIPv4アドレスなどは有料です。

5. 関連サービス

  • Amazon EC2:VPC内に配置する代表的なリソース
  • Elastic Load Balancing:パブリックサブネットに置く入り口
  • Amazon S3:VPCエンドポイントの接続先
  • Amazon Route 53:プライベートホストゾーンでVPC内の名前解決
  • AWS Resource Access Manager:サブネットの共有
  • AWS Transit Gateway:多数のVPC・オンプレミスをハブ&スポークで接続
  • AWS Site-to-Site VPN/AWS Direct Connect:オンプレミスとの接続
  • VPCフローログ:VPC内の通信の記録
  • 関連する用語:CIDR、ルートテーブル、ネットワークACLとセキュリティグループ、ENIとElastic IP、VPCエンドポイント、VPCピアリング、リージョンとアベイラビリティーゾーン

6. 試験・実務でのポイント

  • プライベートサブネットから外へ出たいが外から入らせない → NATゲートウェイ。
  • 特定のIPを拒否したい → ネットワークACL(セキュリティグループは許可のみ)。
  • インスタンス単位の制御 → セキュリティグループ、サブネット単位 → ネットワークACL。
  • インターネットを経由せずAWSサービスへ → VPCエンドポイント。

7. まとめ

  • VPCはAWS上の自分専用ネットワーク。CIDRとサブネットで設計する。
  • 経路はルートテーブル、出入口はIGW/NAT/エンドポイント。
  • アクセス制御はセキュリティグループ(許可のみ)とネットワークACL(許可/拒否)。
