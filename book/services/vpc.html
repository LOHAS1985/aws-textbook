Amazon VPC

AWS上に論理的に分離された仮想ネットワークを作るサービス

1. サービス概要

Amazon VPC(Virtual Private Cloud)は、AWS上に論理的に分離された仮想ネットワークを構築するサービスです。

  • AWS内に自分専用のネットワーク空間を作成できる
  • IPアドレス範囲(CIDR)を自由に定義できる
  • サブネット単位でリソースを配置する

2. 主な機能・特徴

構成要素

構成要素役割
サブネットVPC内のネットワークの分割単位
ルートテーブル通信経路の制御
インターネットゲートウェイVPCとインターネットを接続(パブリックサブネットで利用)
NATゲートウェイプライベートサブネットからインターネットへのアウトバウンド通信のみ許可(外部からのアクセスは不可)
VPCエンドポイントインターネットを経由せずにVPCからAWSサービスへプライベート接続する
セキュリティグループアクセス制御。インスタンス単位、許可のみ設定可能
ネットワークACLアクセス制御。サブネット単位、許可/拒否の両方を設定可能

セキュリティグループはステートフル(戻りの通信は自動で許可)、ネットワークACLはステートレス(戻りの通信も明示的に許可が必要)です。

「パブリックサブネット」とは、ルートテーブルにインターネットゲートウェイへの経路(0.0.0.0/0 → IGW)があるサブネットのことです。

サブネットの予約IPと「1サブネット=1AZ」

サブネットは必ず1つのアベイラビリティーゾーン(AZ)の中だけに作られ、複数のAZにまたがることはできません。そのため、複数AZで冗長化したい場合は、AZごとにサブネットを用意します(例:パブリックサブネットとプライベートサブネットをそれぞれ2つのAZに1つずつ、計4つ)。

サブネットのCIDRは /16〜/28 の範囲で指定します。各サブネットでは、先頭4つと末尾1つの計5つのIPアドレスがAWSに予約されていて、リソースには割り当てられません。

アドレス(10.0.0.0/24の例)用途
10.0.0.0ネットワークアドレス
10.0.0.1VPCルーター
10.0.0.2DNSサーバー(Amazonが提供するDNS。VPCのCIDRの先頭+2)
10.0.0.3将来の利用のための予約
10.0.0.255ブロードキャストアドレス(VPCはブロードキャストに対応していないが予約される)

たとえば /24(256個)のサブネットで使えるのは251個、最小の /28(16個)では11個です。必要なIP数を見積もるときは、この5個を差し引いて考えます。CIDRの読み方は用語ページ「CIDR」を参照してください。

Elastic IP

EC2インスタンスに自動で付くパブリックIPv4アドレスは、インスタンスを停止・起動すると変わります。固定のパブリックIPが必要な場合は、Elastic IPアドレス(アカウントに確保する静的なパブリックIPv4アドレス)を取得してインスタンスやENIに関連付けます。

  • 関連付け先を別のインスタンスに付け替えられるため、障害時に予備のインスタンスへIPごと切り替える、といった使い方ができる
  • NATゲートウェイのパブリックIPにも使われる(外部の接続先に、送信元IPとして固定のIPを許可してもらえる)
  • リージョンごとに既定で5個までの上限(引き上げ申請が可能)
  • パブリックIPv4アドレスは、使用中・未使用にかかわらず1時間ごとに課金される。使わなくなったElastic IPは解放する

ENIとの関係は用語ページ「ENIとElastic IP」を参照してください。

VPCピアリング

VPCピアリングは、2つのVPCを1対1でつなぎ、プライベートIPのまま通信できるようにする機能です。別のアカウントや別のリージョンのVPCともつなげます。

  • つなぐVPC同士のCIDRが重なっていてはいけない
  • 接続を作るだけでは通信できない。両方のVPCのルートテーブルに、相手のCIDR → ピアリング接続(pcx-…)の経路を追加し、セキュリティグループでも許可する
  • 推移的なルーティングはできない:A–B、B–Cをピアリングしても、AからCへはBを経由して通信できない。AとCも直接ピアリングが必要
  • つなぐVPCが多くなると接続数が急増するため、その場合はTransit Gatewayでハブ&スポーク型にまとめる

詳しくは用語ページ「VPCピアリング」を参照してください。

VPCエンドポイントの2種類

種類対応サービス仕組み料金
ゲートウェイ型S3とDynamoDBのみルートテーブルに、サービスへの経路(プレフィックスリスト → エンドポイント)が追加される無料
インターフェース型(AWS PrivateLink)SQS・SNS・KMS・Systems Manager・CloudWatchなど多数(S3も可)サブネットにENI(プライベートIP)が作られ、セキュリティグループで制御する時間料金+データ処理量

オンプレミスやピアリング先のVPCから使えるのはインターフェース型だけです。エンドポイントポリシーなどの詳細は用語ページ「VPCエンドポイント」を参照してください。

NATゲートウェイはAZごとに作る

NATゲートウェイは、作成した1つのAZの中で冗長化されたサービスです。AZ自体に障害が起きると、そのAZのNATゲートウェイも使えなくなります。1つのNATゲートウェイを全AZのプライベートサブネットで共有していると、そのAZの障害で全AZのサーバーが外に出られなくなります。

そのため、可用性を高めるにはAZごとにNATゲートウェイを作り、各AZのプライベートサブネットのルートテーブルを、同じAZのNATゲートウェイに向けます。AZをまたぐデータ転送料金がかからなくなる利点もあります。

NATゲートウェイは自動でスケールし、セキュリティグループは付けられません(通信の制御はネットワークACLとインスタンス側のセキュリティグループで行う)。

セキュリティグループ同士の参照

セキュリティグループのルールでは、送信元(または送信先)にIPアドレスの範囲ではなく別のセキュリティグループのIDを指定できます。「そのセキュリティグループが付いているリソースからの通信を許可する」という意味になります。

セキュリティグループインバウンドルール
ALB用(sg-alb)HTTPS(443) 送信元 0.0.0.0/0
Web用(sg-web)HTTP(80) 送信元 sg-alb
DB用(sg-db)MySQL(3306) 送信元 sg-web

Auto ScalingでWebサーバーが増減してIPアドレスが変わっても、ルールを書き換える必要がありません。多層構成で「前の層からの通信だけを許可する」ときの定番の書き方です。同じリージョンのピアリング先VPCのセキュリティグループも参照できます。

エフェメラルポート(ネットワークACLの戻り通信)

クライアントがサーバーに接続するとき、送信先ポートは443などの決まった番号ですが、送信元ポート(=戻りの通信の宛先ポート)にはOSが一時的に選ぶ番号が使われます。これをエフェメラルポートと呼びます。

ネットワークACLはステートレスなので、インバウンドで443を許可するだけでは足りず、アウトバウンドでエフェメラルポート宛ての戻り通信も許可する必要があります。逆に、サブネット内のサーバーが外部へ接続する場合は、インバウンドでエフェメラルポートを許可します。

使われる範囲はOSや経路によって異なります(Linuxの多くは 32768〜61000、Windowsは 49152〜65535、NATゲートウェイやELBは 1024〜65535)。どの相手からの通信でも通るように、通常は 1024〜65535 を許可します。セキュリティグループはステートフルなので、この設定は不要です。

Reachability Analyzer(到達性の分析)

VPC Reachability Analyzerは、送信元(EC2インスタンス、ENI、インターネットゲートウェイなど)と送信先を指定すると、その間の経路で通信が届くかどうかを設定から分析する機能です。実際にパケットは送りません。

  • 届く場合:通過するルートテーブル・セキュリティグループ・ネットワークACLなどの経路を1つずつ表示する
  • 届かない場合:どのコンポーネントが原因で止まっているか(例:セキュリティグループにルールがない、ルートテーブルに経路がない)を示す
  • 「EC2に接続できない」といったトラブルの原因調査や、設定変更後の確認に使う。分析1回ごとに課金される

実際の通信の記録を見たい場合はVPCフローログを使います。Reachability Analyzerは「設定上届くか」、フローログは「実際に何が通ったか(ACCEPT/REJECT)」を確認するものです。

3. ユースケース

  • Webサーバーはパブリックサブネット、DBはプライベートサブネットに配置する多層構成
  • プライベートサブネットのサーバーからNATゲートウェイ経由でOSアップデートを取得
  • VPCエンドポイントでS3などにインターネットを経由せずアクセス

4. 料金の考え方

VPC・サブネット・ルートテーブル・セキュリティグループ自体は無料です。NATゲートウェイ(時間+処理データ量)、インターフェース型VPCエンドポイント、パブリックIPv4アドレスなどは有料です。

5. 関連サービス

  • Amazon EC2:VPC内に配置する代表的なリソース
  • Elastic Load Balancing:パブリックサブネットに置く入り口
  • Amazon S3:VPCエンドポイントの接続先
  • Amazon Route 53:プライベートホストゾーンでVPC内の名前解決
  • AWS Resource Access Manager:サブネットの共有
  • AWS Transit Gateway:多数のVPC・オンプレミスをハブ&スポークで接続
  • AWS Site-to-Site VPN/AWS Direct Connect:オンプレミスとの接続
  • VPCフローログ:VPC内の通信の記録
  • 関連する用語:CIDR、ルートテーブル、ネットワークACLとセキュリティグループ、ENIとElastic IP、VPCエンドポイント、VPCピアリング、リージョンとアベイラビリティーゾーン

6. 試験・実務でのポイント

  • プライベートサブネットから外へ出たいが外から入らせない → NATゲートウェイ。
  • 特定のIPを拒否したい → ネットワークACL(セキュリティグループは許可のみ)。
  • インスタンス単位の制御 → セキュリティグループ、サブネット単位 → ネットワークACL。
  • インターネットを経由せずAWSサービスへ → VPCエンドポイント。S3・DynamoDBだけなら無料のゲートウェイ型、オンプレミスから使うならインターフェース型。
  • サブネットで使えるIP数 = CIDRのアドレス数 − 5(先頭4つと末尾1つは予約)。
  • NATゲートウェイの可用性を高めたい → AZごとにNATゲートウェイを作り、各AZのルートテーブルで同じAZのものを指定する。
  • VPCピアリングは推移的ではない・CIDRの重複不可。多数のVPCをつなぐならTransit Gateway。
  • ネットワークACLでインバウンドを許可したのに通信できない → アウトバウンドのエフェメラルポート(1024〜65535)が許可されていない。
  • Auto Scalingで増減するサーバーからの通信を許可したい → 送信元にセキュリティグループIDを指定する。
  • どの設定が原因で通信が届かないかを特定したい → Reachability Analyzer。
  • 停止・起動してもパブリックIPを変えたくない → Elastic IP。

7. まとめ

  • VPCはAWS上の自分専用ネットワーク。CIDRとサブネットで設計する。
  • 経路はルートテーブル、出入口はIGW/NAT/エンドポイント。
  • アクセス制御はセキュリティグループ(許可のみ)とネットワークACL(許可/拒否)。
