AWS Batch

必要なコンピューティング容量を自動調整してバッチジョブを実行するサービス

最終更新:2026-11-07

内容の確認:2026年11月7日

1. サービス概要#

AWS Batchは、コンテナ化されたバッチ処理を登録・スケジュールし、必要な計算資源を自動的に用意して実行するサービスです。ジョブの量や要求リソースに応じて容量を調整し、EC2、Fargate、ECS、EKSなどの実行基盤を利用します。

2. 主な機能・特徴#

ジョブ実行の構成要素#

  • ジョブ定義:コンテナイメージ、vCPU・メモリ、環境変数、再試行などを定義する。
  • ジョブキュー:投入されたジョブの優先度や実行順序を管理する。
  • コンピューティング環境:ジョブを実行するEC2やFargateなどの容量を指定する。
  • ジョブ間の依存関係や配列ジョブを使い、大量の独立した処理をまとめて実行する。

説明の中心 成功・推奨・正常 利用者・外部・送信元 その他の構成要素

パイプラインとの使い分け#

Batchはコンテナ化された計算ジョブのスケジューリングと実行を担います。複数サービスをまたぐ処理の順序・分岐・エラー制御はStep FunctionsやMWAAなどで管理できます。ジョブのスケジュールをEventBridgeから起動する構成もあります。

3. ユースケース#

  • 大量のファイル変換や定期的な集計を並列に実行する。
  • 必要なCPU・メモリに応じたコンテナジョブを優先度付きで処理する。
  • ピーク時だけ計算容量を増やし、処理終了後に容量を減らす。

4. 料金の考え方#

AWS Batch自体に追加料金がない場合でも、ジョブを実行するEC2、Fargate、EKSなどの計算資源、ストレージ、ログ、データ転送に料金が発生します。実行時間、リソース要求、再試行、Spot利用の可否を見積もります。

5. 関連サービス#

  • Amazon ECS/Amazon EKS:コンテナ実行基盤
  • AWS Lambda:短時間のイベント駆動処理
  • AWS Step Functions:処理ステップの制御
  • Amazon MWAA:Airflowによるデータパイプライン管理
  • Amazon EventBridge:スケジュール起動

6. 試験・実務でのポイント#

  • コンテナ化されたバッチジョブをキューで管理し、実行容量を自動調整 → AWS Batch。
  • ジョブのコンテナ・リソース定義はジョブ定義、投入順序はジョブキュー、計算資源はコンピューティング環境で設定する。
  • 処理フローの分岐・状態管理はワークフローサービス、計算処理の実行はBatchと役割を分ける。

7. まとめ#

  • AWS Batchはバッチジョブをキューイングし、実行に必要な容量を調整する。
  • ジョブ定義・キュー・コンピューティング環境を組み合わせる。
