1. サービス概要#

AWS CodeBuildは、CI/CDパイプラインでビルド・テストを実行するフルマネージドなサービスです。ビルドサーバーを自分で用意する必要がありません。

2. 主な機能・特徴#

ビルドの手順(buildspec)#

ビルドの内容は buildspec.yml に記載します。

  1. 依存関係のインストール
  2. ビルド前処理
  3. コンパイル・テスト
  4. 後処理
  5. 成果物(アーティファクト)の出力

buildspec.ymlはソースのルートディレクトリに置くのが標準です。主な項目は次のとおりです。

項目役割
env環境変数。variables(平文)、parameter-store、secrets-manager(機密情報の参照)
phasesinstall→pre_build→build→post_buildの各フェーズ。installではruntime-versionsで言語のバージョンを指定できる。各フェーズに失敗時の動作(on-failure)とfinallyを書ける
artifacts成果物として出力するファイルの指定
cacheキャッシュするフォルダ(paths)の指定
reportsテストレポートにするファイルの指定

環境変数と機密情報#

環境変数は、プロジェクトの設定とbuildspec.ymlのenvのどちらでも指定できます。buildspec.ymlの値は優先順位が最も低く、ほかの場所で指定した値が優先されます。平文の環境変数はコンソールやCLIで値が見えてしまうため、パスワードやAPIキーはSecrets ManagerまたはParameter Storeから参照します(secrets-manager・parameter-store)。保存先の選び方は用語ページ「機密情報・設定値の保存先の選び方」を参照してください。

キャッシュ(S3とローカル)#

前回のビルドの依存ファイルなどを再利用すると、ダウンロードや再ビルドの時間を減らせます。キャッシュは2種類から選びます。

種類保存先向いている場面
Amazon S3キャッシュS3バケット。複数のビルドホストで共有できる小さめから中くらいのサイズで、作るより取得するほうが速い成果物
ローカルキャッシュビルドを実行したホストの上。そのホストだけで使える中くらいから大きな成果物。ビルドの頻度が低い場合には向かない

ローカルキャッシュには3つのモードがあります。ソースキャッシュはGitのメタデータを保存し、次のビルドでは差分だけを取得します。DockerレイヤーキャッシュはDockerイメージの層を再利用します(Linuxのみで、特権モードが必要)。カスタムキャッシュは、buildspec.ymlで指定したフォルダを保存します。ローカルキャッシュは、VPC内でビルドする場合には使えません。

テストレポート#

buildspec.ymlのreportsで、テスト結果のファイルとレポートグループを指定すると、ビルドの結果でテストの成功・失敗を確認できます。対応する形式は、JUnit XML、Cucumber JSON、NUnit XML、NUnit3 XML、TestNG XML、Visual Studio TRX などです。

ビルド環境と実行時間#

  • コンピュートタイプ:CPU・メモリ・OSの組み合わせを選ぶ。オンデマンドでは BUILD_GENERAL1_SMALL などの定義済みのタイプから選ぶ
  • 特権モード:Dockerイメージをビルドするときに有効にする。Dockerレイヤーキャッシュも特権モードが必要
  • タイムアウト:既定は60分。5分から36時間(2,160分)の範囲で設定し、超えるとビルドは停止する
  • サービスロール:ビルドがS3やECRなどのAWSリソースを操作するための権限。IAMロールで付与する

サービスロールの仕組みは用語ページ「IAMロールと一時的な認証情報」を参照してください。

3. ユースケース#

  • CodePipelineのBuildステージでのコンパイル・単体テスト
  • DockerイメージをビルドしてECRへプッシュ
  • テスト結果のレポート化

4. 料金の考え方#

選んだコンピュートタイプごとに、ビルドを実行した時間(分単位)に応じて課金されます。ビルドしていない時間は料金がかかりません。キャッシュでビルド時間を短くするとコストも下がります。無料利用枠は、オンデマンドの general1.small または arm1.small で月100分のビルド時間です。

5. 関連サービス#

  • AWS CodePipeline:パイプラインのBuildステージ
  • AWS CodeDeploy:ビルド後のデプロイ
  • Amazon ECR:イメージのプッシュ先
  • AWS CodeArtifact:依存パッケージの取得元
  • Amazon S3:成果物の保存先
  • AWS Secrets Manager:ビルドで使う機密情報の参照元
  • AWS Systems Manager:Parameter Storeのパラメータの参照元
  • 関連する用語:IAMロールと一時的な認証情報、機密情報・設定値の保存先の選び方

6. 試験・実務でのポイント#

  • ビルド手順の定義ファイル → buildspec.yml(CodeDeployのappspecと混同しない)。
  • ビルドが遅い → キャッシュ。複数のビルドホストで共有するならS3キャッシュ、大きなソースならローカルキャッシュ(VPC内のビルドでは使えない)。
  • テスト結果の可視化 → テストレポート(JUnit XMLなどの形式で出力)。
  • Dockerイメージをビルドする → 特権モードを有効にして、ECRへプッシュする。
  • パスワードやAPIキーをビルドで使う → 平文の環境変数ではなく、Secrets ManagerやParameter Storeから参照する。
  • ビルドが終わらず長時間続く → タイムアウト(既定60分)で停止させる。
  • 料金 → 実行したビルド時間で課金される。キャッシュで時間を短くすると、料金も下がる。

7. まとめ#

  • CodeBuildはマネージドなビルド・テスト実行サービス。手順はbuildspec.ymlに書く。

このサービスが登場する運用シナリオ#

  • EC2のアプリをCI/CDでBlue/Greenデプロイする
