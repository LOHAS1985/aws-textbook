AWS CodeBuild

CI/CDパイプラインのビルド・テストを実行するサービス

最終更新:2026-10-24

1. サービス概要#

AWS CodeBuildは、CI/CDパイプラインでビルド・テストを実行するフルマネージドなサービスです。ビルドサーバーを自分で用意する必要がありません。

2. 主な機能・特徴#

ビルドの手順(buildspec)#

ビルドの内容は buildspec.yml に記載します。

  1. 依存関係のインストール
  2. ビルド前処理
  3. コンパイル・テスト
  4. 後処理
  5. 成果物(アーティファクト)の出力

buildspec.ymlのフェーズ名は install → pre_build → build → post_build で、成果物は artifacts、キャッシュは cache セクションで指定します。ファイルはソースのルートディレクトリに置くのが標準です。

ローカルキャッシュ#

前回のビルドの依存ファイルや中間成果物を再利用してビルドを高速化します。buildspec.ymlにキャッシュするフォルダのパスを追加します。

テストレポート#

テストの結果を可視化できます。

3. ユースケース#

  • CodePipelineのBuildステージでのコンパイル・単体テスト
  • DockerイメージをビルドしてECRへプッシュ
  • テスト結果のレポート化

4. 料金の考え方#

選んだコンピューティングタイプでビルドを実行した時間(分単位)に応じて課金されます。ビルドしていない時間は料金がかかりません。キャッシュでビルド時間を短くするとコストも下がります。

5. 関連サービス#

  • AWS CodePipeline:パイプラインのBuildステージ
  • AWS CodeDeploy:ビルド後のデプロイ
  • Amazon ECR:イメージのプッシュ先
  • AWS CodeArtifact:依存パッケージの取得元
  • Amazon S3:成果物の保存先

6. 試験・実務でのポイント#

  • ビルド手順の定義ファイル → buildspec.yml(CodeDeployのappspecと混同しない)。
  • ビルドが遅い → ローカルキャッシュを設定。
  • テスト結果の可視化 → テストレポート。

7. まとめ#

  • CodeBuildはマネージドなビルド・テスト実行サービス。手順はbuildspec.ymlに書く。
