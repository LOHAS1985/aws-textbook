1. サービス概要#

Amazon DevOps Guruは、機械学習でアプリケーションの運用データ(メトリクス・ログ・イベント)を分析し、いつもと違う動き(異常)を自動で見つけて、原因の候補と対策を知らせるサービスです。

CloudWatchのアラームでは、監視するメトリクスとしきい値を自分で決める必要があります。DevOps Guruは、有効にするだけで対象のリソースの「普段の状態」を学習し、しきい値を設定しなくても異常を検知します。関連する複数の異常やデプロイなどのイベントをまとめて、1つのインサイトとして示します。

2. 主な機能・特徴#

インサイトの種類#

インサイト内容例
リアクティブインサイトいま起きている問題。関連する異常なメトリクス・ログ・イベントと、推奨される対策を示すデプロイの直後からLambdaのエラーとAPI Gatewayのレイテンシーが同時に増えた
プロアクティブインサイトこれから起きそうな問題を、影響が出る前に知らせるDynamoDBの消費キャパシティやディスクの使用量が増え続け、近いうちに上限に達しそう

インサイトには、異常なメトリクスのグラフ、同じ時間帯の関連イベント(CloudTrailに記録されたデプロイや設定変更など)、ログの異常(CloudWatch Logsの急なエラーの増加など)、そして推奨事項(何を確認・変更すればよいか)がまとめて表示されます。

分析の範囲(カバレッジ)#

どのリソースを分析するかは、次の3つから選びます。分析するリソースの数で料金が決まるため、範囲を絞ることもできます。

範囲の決め方内容
アカウント全体そのアカウント・リージョンの、対応しているすべてのリソースを分析する
CloudFormationスタック指定したスタックに含まれるリソースだけを分析する。スタックが1つのアプリとして扱われる
タグキーが devops-guru- で始まるタグ(例:devops-guru-app = shop)を付けたリソースを、値ごとに1つのアプリとして分析する

Lambda・API Gateway・DynamoDB・RDS/Aurora・ECS・EKS・SQS・SNS・Kinesis・ELB・Auto Scalingグループ・Step Functionsなど、多くのサービスに対応しています。分析に使うのは、主にCloudWatchのメトリクス、CloudTrailのイベント、CloudWatch Logsのログです。

通知と連携#

  • Amazon SNS:インサイトの作成・終了などを通知する(通知先のトピックを1つ指定する)。
  • Amazon EventBridge:インサイトをイベントとして受け取り、LambdaやSystems ManagerのAutomationで自動対応する。
  • Systems Manager OpsCenter:インサイトごとにOpsItemを自動で作り、運用チームの対応を管理する。
  • PagerDutyなどの外部の運用ツールとも連携できる。
  • Organizationsと連携し、委任管理者のアカウントから組織全体のインサイトをまとめて見られる。

DevOps Guru for RDS#

RDS・Auroraのデータベースの性能の問題に特化した機能です。Performance Insightsのデータを使い、DBの負荷の急な増加などの異常を見つけて、原因になったSQLや待機イベントと、対策(インデックスの追加、パラメータの見直しなど)を示します。利用するには、DBインスタンスでPerformance Insightsを有効にしておく必要があります。

似た機能との違い#

機能何をするか
DevOps Guruアプリ全体の多数のメトリクス・ログ・イベントを機械学習でまとめて分析し、関連する異常をインサイトにまとめ、原因の候補と推奨を示す
CloudWatchの異常検出(アラーム)1つのメトリクスごとに、過去の傾向から「正常な範囲(バンド)」を作り、外れたらアラームにする
CloudWatch Logsの異常検出ロググループのログのパターンの変化を見つける
AWS DevOps Agentアラームやチケットをきっかけに、AIエージェントが監視データ・コード・デプロイ履歴を調べて原因の調査と対応策の提示を行う
AWS Compute Optimizer異常ではなく、使用状況から適切なサイズを推奨する(コストと性能の最適化)

3. ユースケース#

  • サーバーレスアプリ(API Gateway+Lambda+DynamoDB)の異常を、アラームを1つずつ作らずに検知する
  • デプロイの直後に起きた性能の悪化を、原因になったデプロイのイベントと一緒に把握する
  • 容量の不足やクォータの上限に達しそうなことを、障害になる前に知る(プロアクティブインサイト)
  • Auroraの遅いSQLや負荷の急増の原因を、DevOps Guru for RDSで特定する

4. 料金の考え方#

分析したリソースの数×時間(リソース時間)で課金されます。料金はリソースの種類によって異なり、DevOps Guru for RDSはDBのvCPUの数×時間で課金されます。このほか、DevOps GuruのAPIの呼び出しにも料金がかかります。分析の範囲をCloudFormationスタックやタグで絞ると、費用を抑えられます。従量課金の仕組みは用語ページ「料金の基本」を参照してください。

5. 関連サービス#

  • Amazon CloudWatch:分析に使うメトリクス・ログ
  • AWS CloudTrail:デプロイや設定変更などのイベント
  • AWS CloudFormation:分析の範囲をスタックで指定する
  • Amazon SNS・Amazon EventBridge:インサイトの通知と自動対応
  • AWS Systems Manager:OpsCenterのOpsItemの作成
  • Amazon RDS・Amazon Aurora:DevOps Guru for RDSの対象
  • AWS Organizations:複数アカウントのまとめての管理
  • AWS DevOps Agent:AIエージェントによる障害の原因調査

6. 試験・実務でのポイント#

  • 「機械学習で運用上の異常を自動で検知」「しきい値を設定せずに」「原因の候補と推奨を提示」→ DevOps Guru。
  • いま起きている問題 → リアクティブインサイト。これから起きそうな問題 → プロアクティブインサイト。
  • 分析の範囲は、アカウント全体・CloudFormationスタック・タグ(devops-guru- で始まるキー)から選ぶ。
  • インサイトを通知 → SNS。自動で対応 → EventBridge。運用の課題として管理 → OpsCenterのOpsItem。
  • RDS・Auroraの性能の異常と原因のSQL → DevOps Guru for RDS(Performance Insightsの有効化が必要)。
  • 1つのメトリクスの正常な範囲から外れたら通知 → CloudWatchの異常検出。サイズの最適化 → Compute Optimizer。

7. まとめ#

  • DevOps Guruは、機械学習で運用データの異常を見つけ、原因の候補と推奨をインサイトとして示すサービス。
  • インサイトはリアクティブ(いまの問題)とプロアクティブ(これからの問題)の2種類。
  • 範囲はアカウント・スタック・タグで決め、通知はSNS・EventBridge、RDSにはDevOps Guru for RDSがある。
