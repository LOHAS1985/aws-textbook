Amazon Managed Service for Prometheus

Prometheus互換の監視をマネージドで提供(AMP)

最終更新:2026-10-24

1. サービス概要#

Amazon Managed Service for Prometheus(AMP)は、オープンソースの監視ツールPrometheusのサーバー管理をAWSが担当するサービスです。

  • サーバーの可用性維持
  • 保存領域の管理
  • スケーリング
  • パッチ適用

2. 主な機能・特徴#

Prometheusとは#

オープンソースのモニタリング・アラートツールキットです。

  • 用途:インフラ監視(CPU使用率・メモリ使用量)、アプリ監視(リクエスト数・レスポンスタイム)、Kubernetesクラスターの監視
  • 時系列データベースに特化
  • プル型のデータ収集:監視対象が /metrics エンドポイントでメトリクスを公開し、Prometheusサーバーが定期的に取りに行く
  • 独自のクエリ言語 PromQL

AMPワークスペース#

メトリクスを管理するためのワークスペースです。エンドポイントには、remote_write(メトリクス送信用)、クエリ(PromQL実行用)、ルールやアラートの管理用があります。

Prometheus Remote Write:Prometheusが収集したメトリクスを、外部のリモートストレージ(AMP)に保存する仕組みです。

アラート・通知・自動修復#

  • Recording rule:クエリ結果を新しいメトリクスとして事前計算する
  • Alerting rule:条件を満たしたときにアラートを発生させる。Alertmanagerがアラートを送る。

例:10分間にコンテナが3回を超えて再起動し、その状態が5分以上続いたらアラート

groups:
  - name: kubernetes-alerts
    rules:
      - alert: HighPodRestartRate
        expr: increase(kube_pod_container_status_restarts_total[10m]) > 3
        for: 5m
        labels:
          severity: warning

自動修復の流れ:AMP Alertmanager → SNS/EventBridge → Lambda/SSM Automation → Kubernetes API/AWS API

AWSサービスとの統合#

目的サービス
メトリクス収集Prometheus、EKS
ダッシュボードManaged Grafana
通知SNS
自動修復EventBridge、Lambda、Systems Manager Automation
認証IAM、AWS SigV4、IAM Identity Center

3. ユースケース#

  • EKSクラスターのコンテナ監視
  • 既存のPrometheus環境のストレージをマネージドに置き換え(Remote Write)
  • Pod再起動の多発を検知して自動修復

4. 料金の考え方#

取り込んだメトリクスのサンプル数、保存量、クエリで処理したサンプル数に応じて課金されます。

5. 関連サービス#

  • Amazon EKS:主な監視対象
  • Amazon Managed Grafana:可視化
  • Amazon SNS/Amazon EventBridge:通知・自動化
  • Amazon CloudWatch:AWS標準の監視サービス

6. 試験・実務でのポイント#

  • Prometheus互換・PromQL・Kubernetes監視 → AMP。
  • メトリクスの送信 → remote_writeエンドポイント。
  • アラートの送信 → Alertmanager。事前計算 → Recording rule。
  • 可視化はManaged Grafanaと組み合わせる。

7. まとめ#

  • AMPはPrometheusのサーバー管理をAWSに任せられるサービス。
  • Remote Writeで送信し、PromQLでクエリ、Alertmanagerで通知する。

このサービスが登場する運用シナリオ#

  • コンテナ(ECS・EKS)の性能を監視する
