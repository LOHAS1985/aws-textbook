1. サービス概要#

AWS Network Firewallは、VPCに出入りする通信をまとめて検査・フィルタリングするマネージド型のファイアウォールです。セキュリティグループやネットワークACLより細かい条件(ドメイン名、通信の中身のパターン、プロトコルなど)で通信を制御でき、侵入検知・防止(IDS/IPS)にも使えます。

ファイアウォールの台数や冗長化はAWSが管理し、通信量に合わせて自動でスケールします。

2. 主な機能・特徴#

構成要素#

要素説明

ファイアウォールポリシーどのルールグループをどの順で使うか、既定の動作を決める

通信を検査させる方法(ルートテーブル)#

Network Firewallは、ルートテーブルで通信をファイアウォールエンドポイントに向けることで初めて検査されます。例えばインターネットとの通信を検査するには、次のように設定します。

  • ワークロードのサブネット:0.0.0.0/0 の宛先をファイアウォールエンドポイントにする
  • ファイアウォールのサブネット:0.0.0.0/0 の宛先をインターネットゲートウェイにする
  • インターネットゲートウェイのルートテーブル(エッジの関連付け):ワークロードのサブネット宛てをファイアウォールエンドポイントにする(戻りの通信も検査するため)

主な使いどころ#

  • ドメインでの送信先の制限:許可したドメイン(例:.amazonaws.com、パッケージのリポジトリ)以外への外向きの通信をブロックする。
  • IDS/IPS:既知の攻撃パターンに一致する通信を検出・遮断する(AWSマネージドの脅威シグネチャも使える)。
  • TLSの中身の検査(TLSインスペクション)。
  • Transit Gatewayと組み合わせた検査用VPCで、複数VPCの通信を集中して検査する。

ログ#

アラートログ(ルールに一致した通信)・フローログ・TLSログを、S3・CloudWatch Logs・Data Firehose に出力できます。

3. ユースケース#

  • プライベートサブネットのサーバーが、許可したドメイン以外のインターネットにつながらないようにする
  • 複数VPC・オンプレミスとの通信を、Transit Gateway経由で1か所で検査する
  • 規制のために、IDS/IPSによる通信の監視が必要な環境

4. 料金の考え方#

ファイアウォールエンドポイントごとの時間料金と、処理したデータ量(GB)に応じて課金されます。AZごとにエンドポイントを置くので、AZ数に比例して時間料金が増えます。

5. 関連サービス#

  • Amazon VPC/ルートテーブル:配置と通信の誘導
  • AWS Transit Gateway:検査用VPCへの集約
  • AWS WAF:HTTPのアプリケーション層の保護
  • Route 53 Resolver DNS Firewall:DNSの問い合わせのフィルタリング
  • ネットワークACLとセキュリティグループ

6. 試験・実務でのポイント#

  • 「VPC全体の通信の検査」「IDS/IPS」「ドメイン名で外向きの通信を制限」→ Network Firewall。
  • 検査されないときはルートテーブルを確認する。行きと戻りの両方がエンドポイントを通る必要がある。
  • HTTPのSQLインジェクション対策ならWAF、IP・ポートだけならセキュリティグループ/ネットワークACLで足りる。
  • DNSの問い合わせだけを止めたいなら、より手軽な DNS Firewall も候補。

7. まとめ#

  • Network FirewallはVPCの通信をまとめて検査するマネージド型ファイアウォール。
  • ルートテーブルで通信をファイアウォールエンドポイントに通して使う。

このサービスが登場する運用シナリオ#

  • 外向きの通信を許可したドメインだけに制限するNetwork FirewallとRoute 53 Resolver DNS Firewallで、サーバーから不正な宛先への通信と名前解決を止める
