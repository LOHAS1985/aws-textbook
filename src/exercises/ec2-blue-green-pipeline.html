1. 要件

  • GitHubへのプッシュをきっかけに、ビルド・テストから本番デプロイまでを自動化したい。
  • 本番の前に、人の確認を入れたい。
  • 本番の切り替えはダウンタイムなしで行い、問題があればすぐ戻したい。

2. 構成を組み立てる

① buildspec.yml に従ってビルド・テストするものは?

  • AWS CodeBuildサーバーを用意せずに、buildspec.yml の手順でビルドとテストを実行します。
  • AWS CodeArtifactライブラリなどのパッケージを保管するサービスで、ビルドは実行しません。
  • AWS CloudFormationインフラを作るサービスで、アプリのビルド・テストはしません。

② 新しいAuto Scalingグループに配置し、ALBの向き先を切り替えるものは?

  • AWS CodeDeploy(Blue/Green)新しい環境(Green)に appspec.yml の手順で配置し、ALBの通信を切り替えます。旧環境(Blue)を残せるので戻しやすいです。
  • EC2 Image BuilderAMIを作るサービスで、通信の切り替えはしません。
  • Systems Manager Run Commandコマンドを一括実行できますが、Blue/Greenの切り替えや自動ロールバックの仕組みはありません。

③ 本番の前に人の確認を入れるには?

  • CodePipelineに手動承認のアクションを入れる承認されるまでパイプラインが止まり、承認者にはSNSで通知できます。
  • CodeBuildのテストを増やす自動のテストで、人の確認にはなりません。
  • 本番だけ手作業でデプロイする自動化の要件に合わず、手順のばらつきも出ます。

3. 解説

解説を見る(答え合わせのあとに読む)

CodePipelineがSource → CodeBuild → 手動承認 → CodeDeployの順に進めます。Blue/Greenは旧環境を残せるのでロールバックが容易です。リソースを増やしたくない場合はIn-placeも選べますが、更新中は台数が減ります(デプロイ戦略)。
