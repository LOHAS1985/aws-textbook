1. 要件

  • EC2・EBS・RDS・EFSのバックアップを、サービスごとではなく一元管理したい。
  • 新しく作ったリソースも、自動で対象にしたい。
  • リージョンの障害に備えて、別のリージョンにもコピーを残したい。

2. 構成を組み立てる

① スケジュール・保持期間・コピー先をまとめて決めるものは?

  • AWS Backupのバックアッププラン複数のサービスのバックアップを、1つのプランでスケジュール・保持期間・別リージョンへのコピーまで決められます。
  • Data Lifecycle ManagerEBSのスナップショットとAMIだけが対象で、RDSやEFSは管理できません。
  • S3のライフサイクルルールS3のオブジェクトの移動・削除の設定で、ほかのサービスのバックアップは取りません。

② 新しく作ったリソースも自動で対象にするには?

  • リソースの割り当てをタグで指定するBackup=daily のタグを付けるだけで対象になります(タグ)。
  • リソースのARNを1つずつ指定する新しいリソースのたびに設定の追加が必要です。
  • リソースごとに手動でバックアップを取る一元管理にも自動化にもなりません。

③ バックアップを誰にも削除させないようにするには?

  • ボールトロックを設定する保持期間中は、管理者を含めて誰もバックアップを削除できなくなります。
  • バックアップの保持期間を長くする期間が延びるだけで、手動の削除は防げません。
  • ボールトを暗号化する中身を守る対策で、削除は防げません。

3. 解説

解説を見る(答え合わせのあとに読む)

AWS Backupのバックアッププランで、タグの付いたリソースを毎日バックアップし、別リージョンのボールトにコピーします。Organizationsのバックアップポリシーを使うと、組織の全アカウントに同じプランを適用できます。これはDR戦略の「バックアップと復元」にあたります(DR戦略)。
