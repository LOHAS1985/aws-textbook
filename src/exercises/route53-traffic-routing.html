1. 要件

  • 東京とバージニア北部の2リージョンで動かしている。利用者を応答の速いほうへ振り分けたい。
  • 片方が落ちたら、もう片方だけに送りたい。
  • 新しいバージョンの環境に、まず通信の10%だけを流したい。

2. 構成を組み立てる

① 利用者からの遅延が小さいリージョンを返すものは?

  • Route 53のレイテンシーベースルーティング利用者からの遅延が最も小さいリージョンのレコードを返します。
  • Route 53の位置情報ルーティング国や地域で決めるもので、実際の速さでは選びません。
  • Application Load Balancerリージョンの中の振り分けで、リージョンは選べません。

② 異常なリージョンを応答から外すものは?

  • Route 53のヘルスチェックレコードに関連付けると、異常と判定されたレコードは返されなくなり、もう一方に切り替わります。
  • AWS CloudTrail操作の記録で、異常の判定はしません。
  • TTLを長くする古い応答が長く使われ、切り替えが遅くなります。

③ 新しい環境に通信の10%だけを流すルーティングは?

  • 加重ルーティングレコードごとの重みの割合で応答を分けます(例:90と10)。
  • フェイルオーバールーティング正常時はプライマリだけを返すもので、割合では分けません。
  • シンプルルーティング1つのレコードを返すだけで、割合は決められません(DNSレコードタイプ)。

3. 解説

解説を見る(答え合わせのあとに読む)

レイテンシーベースルーティングとヘルスチェックで、速いほうへ振り分けつつ、異常なリージョンを自動で外します。割合で分けたいときは加重ルーティングを使います。DNSのTTLとヘルスチェックの間隔の分だけ切り替えに時間がかかるので、すぐに切り替えたい場合はGlobal Acceleratorも候補です。
