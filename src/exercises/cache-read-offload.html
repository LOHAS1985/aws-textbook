1. 要件

  • セール中は同じ商品情報を何度もDBから読むため、RDSのCPUが上がって遅くなる。
  • DBを大きくせずに、よく読まれるデータをキャッシュしたい。
  • 画像などの静的なファイルは、利用者の近くから返したい。

2. 構成を組み立てる

① 静的なファイルを利用者の近くのエッジから返すものは?

  • Amazon CloudFront世界中のエッジロケーションでキャッシュして返します。キャッシュできない要求だけを後ろのアプリに送ります。
  • AWS Global AcceleratorAWSのネットワークで通信の経路を速くするもので、コンテンツをキャッシュしません。
  • Network Load Balancerリージョンの中で通信を振り分けるもので、キャッシュの機能はありません。

② アプリがDBの前に読む、インメモリのキャッシュは?

  • Amazon ElastiCacheメモリ上でデータを保持し、マイクロ秒〜ミリ秒で返します。DBの読み取りの回数を減らせます。
  • DynamoDB Accelerator(DAX)DynamoDB専用のキャッシュで、RDSの前には置けません。
  • Amazon EFS共有のファイルストレージで、キャッシュではありません。

③ 遅延読み込み(必要になったらキャッシュする)の弱点は?

  • 初回は必ずミスし、データが古くなることがあるTTLで古いデータを消すか、更新時にキャッシュも書き換える(ライトスルー)と組み合わせます(キャッシュの選び方)。
  • 使われないデータまでキャッシュされるライトスルーの弱点です。遅延読み込みは必要なデータだけをキャッシュします。
  • DBへの書き込みができなくなる書き込みはこれまでどおりDBに行います。

3. 解説

解説を見る(答え合わせのあとに読む)

静的なコンテンツはCloudFrontで、くり返し読まれるデータはElastiCacheで返し、DBにはキャッシュにないときだけ読みに行きます。ElastiCacheの Evictions が多いときはメモリ不足なので、ノードを大きくするかシャードを増やします。
