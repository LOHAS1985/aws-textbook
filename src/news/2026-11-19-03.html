1. 発表の内容

RDS でポイントインタイムリストア(ある時点の状態へ戻す復元)、リードレプリカの作成、Single-AZ から Multi-AZ への変換を行うと、スナップショットから新しいストレージボリュームが作られ、データブロックが Amazon S3 から裏でダウンロードされます。この初期化が終わるまでは、まだ取り込まれていないブロックに触れるたびに I/O の遅延が増えることがありました。しかも、初期化の速さはワークロード次第で、いつ完全な性能になるか分かりませんでした。

今回の変更で、インスタンスごとに、gp3 と io2 のボリューム全体で最大毎時4TiB の速さで初期化されます。アカウント全体で同時に初期化する量が帯域を超える場合は、残りを可能な範囲で処理するため、以前より遅くなることはありません。初期化中も DB インスタンスは使えます。既定で有効なので設定は不要で、追加料金もありません。進み具合は、コンソールや DescribeDBInstances API の StorageOperationStatus と StorageOperationPercentProgress で確認できます。

何がうれしいか
障害後の復元や読み取りを増やすためのレプリカ追加のあと、通常の性能に戻るまでの見通しが立てやすくなります。
試験・実務への影響
信頼性・事業継続の分野では、復元や Multi-AZ 変換のあとの性能と、スナップショットのブロックが後から取り込まれる仕組みを理解しておくと、設計の判断に役立ちます。
