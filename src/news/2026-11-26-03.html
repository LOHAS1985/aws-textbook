1. 発表の内容

RDS for SQL Server で、1つの DB インスタンスに置けるデータベースの数が、これまでの100個から500個になりました。顧客ごとにデータベースを分ける SaaS やマルチテナントのアプリでは、データベースを複数の DB インスタンスに分けていましたが、少ないインスタンスにまとめられます。管理・監視・パッチ適用の対象が減り、ライセンスとインフラのコストも下がります。

対象は vCPU が4つ以上(xlarge 以上。バースト可能なクラスを除く)の DB インスタンスで、SQL Server の全バージョンが使えます。シングル AZ の各エディションと、Always On 可用性グループを使うマルチ AZ の Enterprise などで使えます。データベースミラーリングを使うマルチ AZ、Standard エディションのマルチ AZ、小さいインスタンスは、従来の上限のままです。

何がうれしいか
インスタンス数を減らして運用とコストを抑えられます。すべての RDS for SQL Server のリージョンで使えます。
試験・実務への影響
数を集約すると、1つのインスタンスの障害の影響が広がります。可用性の設計(マルチ AZ の方式)と、リソースの競合の監視も合わせて考えましょう。
