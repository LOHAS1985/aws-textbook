1. 発表の内容

信頼できるアイデンティティの伝播(Trusted identity propagation、TIP)は、「誰の操作か」という身元を、リクエストと一緒に AWS サービスへ引き継ぐ仕組みです。引き継いだ身元は、IAM ポリシーの条件でのアクセス制御や、AWS CloudTrail で操作の元の人・ワークロードを見分けるのに使えます。

今回、TIP は IAM フェデレーション(SAML や OIDC で外部の ID を使ってサインインする方法)と IAM Roles Anywhere(AWS の外のワークロードが X.509 証明書で IAM ロールを使う仕組み)にも拡大しました。フェデレーションでは、SAML アサーションや OIDC トークンにある身元と、リスクスコアや CI/CD のワークフロー名といった任意の情報を、ロールセッションに対応付けられます。IAM Identity Center では、IAM Identity Center が作るユーザー ID に加えて、ID ソース側のユーザー名も一緒に引き継ぎ、アプリへのアクセスでも AWS アカウントへのアクセスでも同じ形で扱えるようになりました。

身元は、IAM ロールや AWS サービスの間を移っても保たれ、ロールごとに信頼ポリシーを直す必要はありません。あわせて、IAM の外部向けフェデレーションでは、TIP のセッションの身元を含む、AWS が署名した JWT(JSON Web Token)を発行でき、外部のサービスも元の利用者を判別できます。

何がうれしいか
共有のロールを使っても、操作した人やワークロードを CloudTrail で特定でき、ポリシーの条件で人ごとに制御できます。ロールごとの信頼ポリシーの更新も不要です。すべての商用リージョンなどで使えます。
試験・実務への影響
ロールを引き受けると「誰が操作したか」が分かりにくくなる点が課題でした。身元をセッションに引き継ぐ考え方と、監査には CloudTrail を使うことを押さえましょう。
