2. 注目の発表

Security Hub:SBOMインベントリ

SBOM(Software Bill of Materials)は、あるシステムにどんなソフトウェア部品(パッケージ)がどのバージョンで入っているかを書き出した「部品表」です。脆弱性が見つかったとき、「その部品を使っているのはどこか」をすぐ調べるために使います。Security Hubは、InspectorがEC2インスタンス・ECRのコンテナイメージ・Lambda関数について作るSBOMを集め、組織全体のパッケージ一覧として表示します。パッケージごとにバージョン・種類・入っているリソースの数が分かり、アカウントやリージョンで絞り込めます。リソースの詳細画面では、そのリソースに入っているソフトウェアを一覧でき、検出結果の優先度を判断する材料になります。APIでも取得できます。

何がうれしいか
新しい脆弱性が公表されたとき、該当のパッケージを使っているリソースを、アカウントをまたいで1か所で探せます。
試験・実務への影響
Security Hub Essentialsに追加料金なしで含まれ、新しい有効化の操作は要りません。Inspectorが有効なところで自動的に表示されます。「脆弱性のスキャンはInspector、結果の集約はSecurity Hub」という役割分担を押さえておきましょう。

EC2:ImdsV1EnabledメトリクスでIMDSv2への移行を追跡

EC2のインスタンスメタデータサービス(IMDS)は、インスタンスが自分の情報や一時的な認証情報を取得する窓口です。IMDSv1は単純なリクエストだけで取得でき、アプリの脆弱性を突かれると認証情報を盗まれるおそれがあるため、トークンを使うIMDSv2への移行が推奨されています。今回、IMDSv1がまだ有効なインスタンスを示す ImdsV1Enabled というCloudWatchメトリクスが追加されました。ダッシュボードやアラームで、移行が済んでいないインスタンスを追跡できます。

何がうれしいか
アカウントやリージョンをまたいで、独自のツールを作らずに移行の漏れを見つけ、優先順位を付けられます。
試験・実務への影響
すべてのリージョンで追加料金なしで使えます。「IMDSv2を必須にする」設定とあわせて、セキュリティ対策の定番として覚えておきましょう。

Lambda耐久関数:既定の上限を引き上げ

Lambdaの耐久関数(durable functions)は、最長1年かかる複数ステップの処理を、途中経過の保存(チェックポイント)や自動リトライを使って確実に進める機能です。待っている間は計算料金がかかりません。今回、既定のクォータ(上限)が引き上げられました。米国東部(バージニア北部)・米国西部(オレゴン)・欧州(アイルランド)以外のリージョンでの新しい値は次のとおりで、この3リージョンはその2倍です。

何がうれしいか
注文処理や文書処理などで、申請なしにより多くの実行を並行して進められます。状態の確認・一覧・履歴取得・停止のAPIも10倍の頻度で呼べるので、ダッシュボードやスクリプトでの監視がしやすくなります。
試験・実務への影響
実行中の数は100万から500万、チェックポイントの取得などは毎秒1,000から10,000、コールバック関連は毎秒300から3,000に上がりました。クォータが原因のスロットリングは、Service Quotasで確認して調整するのが基本です。

AWS assistant:Amazon Q Developerの名称変更

AWSマネジメントコンソールとコンソールのモバイルアプリで使えた Amazon Q Developer が、AWS assistant という名前になりました。アカウントの状況に合わせた案内や操作の支援といった機能は同じで、名前だけを分かりやすくしたものです。現在は無料で提供され、すでにPro階層を契約している人は、そのままPro階層の機能が使えます。世界中で利用できます。

何がうれしいか
コンソールの中の「AWSの運用を手伝ってくれる機能」だと、名前から分かるようになります。
試験・実務への影響
古い教材や設問の「Amazon Q Developer」は、コンソール内ではこのAWS assistantを指します。サービス名の変更は出題文の読み替えで迷いやすいので、覚えておくと安心です。
