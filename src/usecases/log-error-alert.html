1. やりたいこと

アプリケーションのログに「ERROR」が出力されたら、すぐに開発者へメールで知らせたい。原因調査のために、過去のログを条件で検索できるようにもしたい。

2. 構成図

3. 使うサービスと役割

  • Amazon CloudWatch:Logs(ログの保存)、メトリクスフィルター(ログの数値化)、アラーム、Logs Insights(検索・分析)
  • Amazon SNS:アラーム時のメール通知
  • AWS Lambda:ログを自動でCloudWatch Logsに出力する(EC2はエージェントで送る)

4. 構築の流れ

  1. アプリのログをCloudWatch Logsのロググループに送る(Lambdaは自動、EC2はCloudWatchエージェント)
  2. ロググループにメトリクスフィルターを作成し、フィルターパターンに ERROR を指定する
  3. フィルターが作ったメトリクスにアラーム(例:1分間に1件以上)を作成し、SNSトピックを通知先にする
  4. ロググループの保持期間を設定する(デフォルトは無期限)

5. ポイント・注意点

  • ログの特定の文字列でアラーム → メトリクスフィルター。
  • ログを即座に別の処理(Lambda・Firehoseなど)へ流したい → サブスクリプションフィルター。
  • 過去ログをSQLライクに調べる → Logs Insights。
  • 保持期間はデフォルト無期限。長期保存はS3に移してコストを下げる。
  • ログに機密情報が含まれる場合は、データ保護ポリシーでマスキングできる。
