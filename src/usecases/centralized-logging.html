1. やりたいこと

組織内の複数アカウントのアプリログやAPI操作の記録(CloudTrail)を、ログ集約用のアカウントに集めて長期保存したい。監査のときにはSQLで横断的に検索したい。

2. 構成図

3. 使うサービスと役割

  • Amazon CloudWatch:サブスクリプションフィルターでログをリアルタイムに転送する
  • Amazon Kinesis(Data Firehose):ログをS3へ配送する
  • AWS CloudTrail:組織全体のAPI操作を1つの証跡で記録する
  • Amazon S3:ログの長期保存(ライフサイクルでGlacierへ)
  • Amazon Athena:S3のログをSQLで分析する
  • AWS Organizations:組織の証跡、アカウントの管理

4. 構築の流れ

  1. 集約アカウントにログ用のS3バケットを作り、バケットポリシーで各アカウントからの書き込みを許可する
  2. 管理アカウントでCloudTrailの組織の証跡を作成し、保存先に集約バケットを指定する
  3. Data Firehoseの配信ストリームを作り、各アカウントのロググループにサブスクリプションフィルターを設定する
  4. S3のライフサイクルルールで、古いログをGlacierなどへ移す
  5. Athenaでテーブルを定義し、SQLで検索する

5. ポイント・注意点

  • 短期・頻繁に検索するログはCloudWatch Logs、長期・たまに検索するログはS3。
  • CloudTrailのログの改ざん検知 → ログファイルの整合性検証。
  • Athenaのコスト削減 → パーティション分割・列指向形式。
  • ログを削除させないために、S3オブジェクトロックやバケットポリシーで削除を制限する。
