1. やりたいこと

GitHubへのプッシュをきっかけに、ビルド・テストから本番デプロイまでを自動化したい。本番への切り替えはダウンタイムなしで行い、問題があればすぐ元に戻したい。

2. 構成図

3. 使うサービスと役割

  • AWS CodePipeline:Source → Build → Approval → Deploy の流れを自動化する
  • AWS CodeBuild:buildspec.ymlに従ってビルド・テストする
  • AWS CodeDeploy:appspec.ymlに従ってEC2にデプロイし、Blue/Greenで切り替える
  • Elastic Load Balancing:BlueとGreenの切り替え
  • Amazon CloudWatch:アラームによる自動ロールバック

4. 構築の流れ

  1. ソースにbuildspec.yml(ビルド手順)とappspec.yml(デプロイ手順・フック)を置く
  2. CodeDeployのアプリケーションとデプロイグループを作成し、デプロイ方式をBlue/Greenにする
  3. CodePipelineでSource(GitHub)・Build(CodeBuild)・Approval(手動承認)・Deploy(CodeDeploy)のステージを作る
  4. CloudWatchアラーム(エラー率など)をデプロイグループに設定し、自動ロールバックを有効にする

5. ポイント・注意点

  • 本番前に人の確認を入れる → Manual Approval Action。
  • Blue/Greenは旧環境(Blue)を残しておけるので、ロールバックが非常に容易(デプロイ戦略)。
  • デプロイ後の動作確認は、appspec.ymlの ValidateService などのフックで行う。
  • リソースを増やしたくない場合はIn-place(OneAtATimeなど)も選べるが、更新中は台数が減る。
