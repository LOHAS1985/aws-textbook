1. やりたいこと

  • 数百台のEC2に、毎週決まった時間帯にOSのセキュリティパッチを自動で適用したい。
  • 本番と開発で、適用のタイミングを分けたい。
  • パッチが適用されているかを、一覧で確認したい。

2. 構成を組み立てる

① 業務時間外の決まった時間帯に、パッチの適用を起動するものは?

  • Systems Managerのメンテナンスウィンドウスケジュール(cron式・タイムゾーン)と所要時間を決め、その間にタスクを実行します(cron式とrate式)。
  • CloudWatchアラームメトリクスのしきい値で動くもので、時間帯を決めた実行はできません。
  • Amazon Inspector足りないパッチ(脆弱性)を見つけますが、パッチを当てる時間帯は決めません。

② どのパッチを承認して当てるかを決めるものは?

  • パッチベースライン重要度・分類や、公開から何日後に承認するかなどを決めます。
  • 起動テンプレートEC2の起動の設定で、パッチの承認とは関係ありません。
  • SCP組織の権限の上限を決めるもので、パッチは選びません。

③ 本番と開発で適用の対象を分けるには?

  • タグでパッチグループを分け、別々のメンテナンスウィンドウを割り当てる台数が増えても、タグを付けるだけで正しいグループに入ります(タグ)。
  • 本番のインスタンスだけ手作業で適用する自動化の要件に合いません。
  • アカウントを分けないと分けられない同じアカウントでも、タグで分けられます。

3. 構成図

メンテナンスウィンドウの時刻に、パッチベースライン(当てるパッチ)とパッチグループ(当てる対象)に従ってPatch Managerが適用し、結果をコンプライアンスで確認します。まず「スキャンのみ」で足りないパッチを把握し、同時実行数とエラーのしきい値を決めて少しずつ適用すると安全です。

4. 使うサービスと役割

  • AWS Systems Manager:Patch Manager、Maintenance Windows、Run Command、コンプライアンス
  • AWS IAM:EC2のロールに AmazonSSMManagedInstanceCore を付ける
  • Amazon EC2:SSM Agentが動く管理対象ノード(オンプレミスはハイブリッドアクティベーションで登録)

5. 構築の流れ

  1. EC2にSSM AgentとIAMロールを用意し、Systems Managerの管理対象になっていることを確認する
  2. パッチベースラインで、承認するパッチ(例:重要度Critical、リリース7日後に自動承認)を定義する
  3. EC2にタグを付けてパッチグループ(例:本番・開発)に分ける
  4. メンテナンスウィンドウで実行日時を決め、ターゲットとタスク(パッチ適用のRun Command)を登録する
  5. コンプライアンスの画面で、適用できなかったノードを確認する

6. ポイント・注意点

  • EC2がSystems Managerに表示されない → SSM Agent・IAMロール・アウトバウンド通信(またはVPCエンドポイント)を確認。
  • 業務時間外に実行 → メンテナンスウィンドウ。対象の分類 → パッチグループ(タグ)。
  • まずは「スキャンのみ」で不足パッチを把握し、その後「インストール」を実行するのが安全。
  • 一度に全台へ適用せず、同時実行数とエラーのしきい値を設定して少しずつ進める。
