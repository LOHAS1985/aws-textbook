1. やりたいこと

アプリのコードや設定ファイルにDBのパスワードを書かずに管理したい。セキュリティ規定に従って、30日ごとにパスワードを自動で変更し、その間もアプリの接続を止めたくない。

2. 構成図

3. 使うサービスと役割

  • AWS Secrets Manager:認証情報の保管・取得(GetSecretValue)・自動ローテーション
  • AWS KMS:シークレットの暗号化
  • AWS Lambda:ローテーション処理の実行
  • Amazon RDS:パスワードを変更する対象のDB
  • AWS IAM:アプリに secretsmanager:GetSecretValue と kms:Decrypt を許可する

4. 構築の流れ

  1. Secrets ManagerにDBの認証情報(ユーザー名・パスワード・ホスト)を保存する
  2. ローテーションを有効にし、間隔(例:30日)と方式(シングルユーザー/交代ユーザー)を選ぶ
  3. アプリのIAMロールにシークレットの取得とKMSの復号を許可する
  4. アプリを、起動時や接続時にシークレットを取得するように変更する

5. ポイント・注意点

  • 自動ローテーションが必要 → Secrets Manager(Parameter Storeにはない)。
  • ローテーション中も接続を切らしたくない → 交代ユーザー方式。
  • ローテーション用LambdaをVPC内に置く場合は、Secrets ManagerへのVPCエンドポイントかNATゲートウェイが必要。
  • CloudFormationからはダイナミックリファレンスで参照し、テンプレートにパスワードを書かない。
