1. やりたいこと

ALB+Auto Scalingで3つのAZにまたがるWebアプリを動かしている。あるAZだけでネットワークが不安定になり、ヘルスチェックは通るのにエラーや遅延が増える「部分的な障害(グレー障害)」が起きた。そのAZを一時的に切り離し、残りのAZだけで処理を続けたい。

2. 構成図

3. 使うサービスと役割

  • Amazon Application Recovery Controller(ARC):ゾーンシフト(手動・一時的)、ゾーンオートシフト(AWSが自動で実行)
  • Elastic Load Balancing:複数AZへの振り分けとヘルスチェック
  • Amazon EC2 Auto Scaling:複数AZへのインスタンスの配置と台数の維持
  • Amazon CloudWatch:AZ別のエラー率・レイテンシーの監視

4. 構築の流れ

  1. アプリを3つ以上のAZに配置し、1つのAZが使えなくても残りで処理できる台数(静的安定性)を確保する
  2. CloudWatchで、ALBのメトリクスをAZ別に見て、特定のAZだけエラーや遅延が多くないかを監視する
  3. ALBとAuto ScalingグループをARCのゾーンシフトの対象として有効にする
  4. 特定のAZの問題が分かったら、そのAZへのゾーンシフトを開始する(有効期限を指定。最長3日で延長可)。問題が解消したら終了する
  5. AWS側の障害に自動で対応させたい場合はゾーンオートシフトを有効にし、定期的に行われる練習の実行で問題がないことを確認する

5. ポイント・注意点

  • 1つのAZの障害から通信を一時的に移す → ゾーンシフト。AWSの判断で自動で → ゾーンオートシフト。
  • ゾーンシフトは一時的な措置。期限が切れるか終了すると元に戻る。
  • 切り離した後も処理できるよう、残りのAZに事前に容量の余裕を持たせておく(障害時にスケールアウトが間に合うとは限らない)。
  • ヘルスチェックで分からない部分的な障害も、ゾーンシフトなら人の判断で切り離せる。
  • リージョン全体の障害への備えは、マルチリージョン構成とRoute 53・ARCのリージョンスイッチで行う。
