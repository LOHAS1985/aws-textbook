1. やりたいこと

顧客の個人情報を含むファイルをS3に保存する。保存時の暗号化に加えて、「いつ・誰が鍵を使ってデータにアクセスしたか」を監査できるようにし、想定外の場所に個人情報が置かれていないかも定期的にチェックしたい。

2. 構成図

3. 使うサービスと役割

  • Amazon S3:SSE-KMSによる暗号化、バケットポリシーでのアクセス制御
  • AWS KMS:カスタマー管理キー(キーポリシーで利用者を制御、利用を監査)
  • AWS CloudTrail:KMSキーの利用と、S3のデータイベント(オブジェクトの取得・削除)を記録する
  • Amazon Macie:S3内の機密データ・個人情報を検出する

4. 構築の流れ

  1. KMSでカスタマー管理キーを作成し、キーポリシーで利用できるロールを限定する
  2. S3バケットのデフォルト暗号化をSSE-KMS(作成したキー)にする
  3. バケットポリシーで、HTTPS以外の通信や、指定した暗号化方式以外のアップロードを拒否する
  4. CloudTrailの証跡で、このバケットのデータイベントを有効にする
  5. Macieを有効にし、バケットを定期的に分析するジョブを作成する

5. ポイント・注意点

  • 鍵の利用を監査したい → SSE-KMS(SSE-S3ではキーの利用履歴を追えない)。
  • 読み取る側にも kms:Decrypt の権限が必要。
  • S3のオブジェクト操作の記録にはデータイベントの有効化が必要(管理イベントだけでは記録されない)。
  • S3の個人情報の検出 → Macie、不正アクセスなどの脅威検出 → GuardDuty。
  • KMSのリクエスト料金を抑えるには、S3バケットキーを有効にする。
