1. やりたいこと

アカウントごとにチームが自由にVPCを作った結果、CIDRが重なり、Transit GatewayやオンプレミスとつなげないVPCが出てきた。これから作るVPCは、決められたアドレス範囲から重ならないCIDRを自動で割り当て、使用状況も1か所で把握したい。

3. 使うサービスと役割

  • Amazon VPC IP Address Manager(IPAM):プールの階層、割り当てルール、使用状況・重複の監視
  • AWS Organizations:IPAMの委任管理者、組織全体のリソースの検出
  • AWS RAM:プールの共有
  • AWS CloudFormation:VPCのテンプレートでIPAMプールを指定(StackSetsで各アカウントへ展開)
  • Amazon CloudWatch:プールの使用率のアラーム

4. 構築の流れ

  1. Organizationsの管理アカウントで、IPAMの委任管理者アカウントを指定する(高度なティアを使う)
  2. 委任管理者でIPAMを作り、管理するリージョンを指定する。最上位のプール(例:10.0.0.0/8)の下に、リージョン・環境ごとのプールを作る
  3. 各プールに割り当てルール(CIDRのサイズの最小・最大・既定、必須のタグ)を設定する
  4. RAMで、プールを対象のOU・アカウントに共有する
  5. 各アカウントでは、VPCの作成時(またはCloudFormationの Ipv4IpamPoolId)にプールとネットマスクを指定する。既存のVPCの重複や非準拠は、IPAMのリソースの一覧で確認する

5. ポイント・注意点

  • 組織全体のVPCのCIDRの重複を防ぐ・一元管理する → IPAM。他のアカウントへのプールの共有 → RAM。
  • CIDRが重なったVPCどうしは、ピアリングやTransit Gatewayで正しくルーティングできない。後から直すのは大変なので、作る前に計画する。
  • プールの使用率をCloudWatchで監視し、枯渇の前にCIDRを追加する。
  • VPCのCIDRは後から追加(セカンダリCIDR)できるが、元のCIDRは変更できない。
  • プライベートのプールや他のアカウントへの割り当てには、IPAMの高度なティアが必要。
