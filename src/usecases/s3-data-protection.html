1. やりたいこと

  • 誤って上書き・削除しても、元に戻せるようにしたい。
  • リージョンの障害に備えて、別のリージョンにもコピーを置きたい。
  • 一定期間は誰も消せないようにしたい。古いバージョンの費用も抑えたい。

2. 構成を組み立てる

① 決めた期間、誰もオブジェクトを消せないようにする機能は?

  • S3 Object Lock(コンプライアンスモード)保持期間中は、ルートユーザーも含めて誰も削除・上書きできません。
  • MFA Delete削除にMFAが必要になるだけで、権限のある人は期間に関係なく削除できます。
  • バケットポリシーで削除を拒否ポリシーを書き換えられる管理者なら削除できてしまいます。

② 増え続ける古いバージョンを整理するものは?

  • ライフサイクルルール(非現行バージョン)古いバージョンを一定日数後に安いストレージクラスへ移したり、削除したりします。
  • S3 Intelligent-Tieringアクセスの頻度で自動的に階層を変えますが、古いバージョンを削除はしません。
  • Transfer Acceleration遠くからのアップロードを速くする機能です。

③ クロスリージョンレプリケーションに必要な設定は?

  • 両方のバケットでバージョニングを有効にするレプリケーションにはバージョニングが必要です。既存のオブジェクトはバッチレプリケーションで複製します。
  • コピー先のバケットを公開する公開は不要です。レプリケーション用のIAMロールで複製します。
  • 同じバケット名にするバケット名は世界で一意なので、同じ名前にはできません。

④ バージョニングが有効なバケットで削除したオブジェクトを戻すには?

  • 削除マーカーを削除する通常の削除では削除マーカーが付くだけなので、マーカーを消すと元のバージョンが見えるようになります。
  • バージョニングを停止する今後のバージョンが作られなくなるだけで、戻りません。
  • レプリカからコピーし直すしかないバージョニングがあれば、同じバケットの中で戻せます。

3. 構成図

バージョニングで上書き・削除を戻せるようにし、クロスリージョンレプリケーションで別リージョンにコピーします。コピー先にはObject Lockで消せない期間を設け、古いバージョンはライフサイクルルールで整理します。特別な権限があれば解除できるようにしたいときは、Object Lockのガバナンスモードを使います。

4. 使うサービスと役割

  • Amazon S3:バージョニング、レプリケーション(CRR/SRR)、Object Lock、ライフサイクルルール、MFA Delete
  • AWS IAM:レプリケーション用のIAMロール
  • AWS KMS:暗号化されたオブジェクトのレプリケーション
  • AWS Backup:S3のバックアップ(特定時点への復元)

5. 構築の流れ

  1. コピー元・コピー先の両方のバケットでバージョニングを有効にする(レプリケーションの前提)
  2. レプリケーションルールを作り、コピー先のバケットとIAMロールを指定する。必要ならS3 Replication Time Control(15分以内の複製を目標)を有効にする
  3. 既にあるオブジェクトもコピーするなら、S3バッチレプリケーションを実行する(ルールの作成後に追加されたものだけが自動で複製される)
  4. 改ざん・削除を防ぐ必要があるバケットは、Object Lock(コンプライアンスモード/ガバナンスモード)と保持期間を設定する
  5. ライフサイクルルールで、古いバージョン(非現行バージョン)を一定日数後に安いストレージクラスへ移す・削除する

6. ポイント・注意点

  • 誤削除・上書きからの復旧 → バージョニング。削除は「削除マーカー」が付くだけなので、マーカーを消すと元に戻る。
  • レプリケーションには両方のバケットのバージョニングが必要。既存のオブジェクトはバッチレプリケーションで複製する。
  • 既定では削除マーカーは複製されない(ルールで有効にできる)。バージョンIDを指定した削除は複製されないので、コピー元での悪意ある削除からは守られる。
  • 誰も(rootユーザーも)消せないようにする → Object Lockのコンプライアンスモード。特別な権限があれば解除できる → ガバナンスモード。
  • バージョニングを有効にすると旧バージョンにも料金がかかる → 非現行バージョンのライフサイクルルールで整理する。
