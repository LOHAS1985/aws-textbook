1. 詳しい説明

HTTPの応答には3桁のステータスコードが付きます。1桁目で大きく分かれ、4xxは利用者(リクエスト)側の問題、5xxはサーバー側の問題を表します。障害の調査では、まず「何番が」「どこから」返っているかを確かめます。

分類意味例
2xx成功200 OK
3xxリダイレクト(別のURLへ)301・302(CloudFrontやALBでHTTPからHTTPSへの転送)
4xxリクエストの誤り・権限がない400・403・404・429
5xxサーバー側のエラー500・502・503・504

よく出るステータスコード

コード意味AWSでのよくある原因
400 Bad Requestリクエストの形式が不正パラメータの誤り、ヘッダーが大きすぎる
401 Unauthorized認証されていないトークンがない・期限切れ(Cognito・API Gatewayのオーソライザー)
403 Forbiddenアクセスが許可されていないS3のバケットポリシー・OACの設定漏れ、WAFでブロック、CloudFrontの地理的制限、API Gatewayの存在しないパス(Missing Authentication Token)
404 Not Found対象がないオブジェクトのキーやパスの誤り
429 Too Many Requestsリクエストが多すぎるAPI Gatewayのスロットリング、WAFのレートベースルール(スロットリングとリトライ)
500 Internal Server Errorサーバー内部のエラーアプリの例外
502 Bad Gateway中継先から不正な応答が返ったターゲットが接続を切った・応答の形式が不正、Lambdaの戻り値の形式の誤り、CloudFrontとオリジンのTLSの不一致(証明書の名前が合わない)
503 Service Unavailable処理できる相手がいない・混んでいるALBのターゲットグループにターゲットが登録されていない、S3の Slow Down
504 Gateway Timeout中継先から時間内に応答がないターゲットの処理が遅い(アイドルタイムアウト超え)、セキュリティグループでオリジンへの通信が止められている、API Gatewayの統合のタイムアウト(既定29秒)

ALBは、ターゲットグループのすべてのターゲットがヘルスチェックに失敗しているときは、全ターゲットにリクエストを送ります(フェイルオープン)。そのため「全台が異常」でも503にならず、ターゲット自身のエラー(5xx)やタイムアウトとして見えることがあります。

どこで返されたかを見分ける

CloudFront・ALB・API Gatewayのような中継役は、自分自身でエラーを返すことも、後ろのサーバーが返したエラーをそのまま中継することもあります。どちらなのかで、調べる場所が変わります。

場所中継役自身のエラー後ろが返したエラー
ALBHTTPCode_ELB_5XX_Count(ALBが作った5xx)HTTPCode_Target_5XX_Count(ターゲットが返した5xx)
CloudFront標準ログ・リアルタイムログの x-edge-detailed-result-type などオリジン(ALB・S3)のメトリクスやログ
API Gateway4XXError・5XXError と実行ログIntegrationLatency、Lambdaのエラー数・ログ

ALBのアクセスログには、ALBが返したコード(elb_status_code)とターゲットが返したコード(target_status_code)が別々に記録されます。ターゲット側のコードが「-」なら、ターゲットから応答が返っていません。

2. 関連する用語

  • スロットリングとリトライ:429・503のときの対処
  • TLS終端と証明書の配置:TLSの不一致による502
  • ネットワークACLとセキュリティグループ:通信が止められて504になる
  • CloudWatchアラームの状態と評価:5xxの数のアラーム
