1. 詳しい説明

責任共有モデルは、AWSを使うときのセキュリティと運用の責任を、AWSと利用者で分け合う考え方です。AWSは「クラウドのセキュリティ」(クラウドそのものを守る)を、利用者は「クラウドにおけるセキュリティ」(クラウドの上に置いたものを守る)を受け持ちます。

担当範囲例
AWSクラウドのセキュリティデータセンターの建物・入退室管理、電源・空調、サーバー・ストレージ・ネットワークの機器、仮想化の基盤(ハイパーバイザー)、マネージドサービスの基盤のソフトウェア
利用者クラウドにおけるセキュリティデータ(暗号化・バックアップ)、IAMの権限、ネットワークの設定(セキュリティグループ・ネットワークACL)、EC2のOSとアプリ、ログの確認

サービスによって境界が変わる

AWSが管理してくれる範囲が広いサービスほど、利用者の責任は小さくなります。

作業EC2RDSLambda
OSのパッチ利用者(Patch Managerなど)AWS(適用する時間帯はメンテナンスウィンドウで利用者が選ぶ)AWS
DBエンジン・ランタイムの更新利用者AWSが提供し、メジャーバージョンの更新は利用者が実施AWS(サポートが終わるランタイムからの移行は利用者)
バックアップの設定利用者自動バックアップの保持期間は利用者が設定コードとデータの管理は利用者
ネットワークの制限利用者(セキュリティグループ)利用者(セキュリティグループ・公開するか)利用者(VPCに接続するか・権限)
データの暗号化利用者が設定利用者が設定(作成時に指定)利用者が設定

両方で受け持つもの

  • パッチの管理:AWSは基盤のパッチ、利用者はOSとアプリのパッチ
  • 設定の管理:AWSは基盤の設定、利用者はOS・データベース・アプリの設定
  • 教育:AWSは自社の社員、利用者は自社の社員

反対に、データセンターの物理的なセキュリティや環境(電源・空調)は、利用者がAWSからそのまま引き継ぐもので、利用者が手を出すことはできません。監査で求められる証明書類はAWS Artifactから入手します。

試験では「誰がやるべきか」が問われます。EC2のOSのパッチは利用者、RDSのOSのパッチはAWS(適用の時間帯は利用者が選ぶ)、どのサービスでもデータの暗号化・IAMの権限・バックアップの設定は利用者、と整理しておきます。

2. 関連する用語

  • マネージドサービスとサーバーレス:AWSに任せる範囲が広いサービス
  • コンプライアンスとAWS Artifact:AWS側の責任を証明する書類
  • 保存時の暗号化と転送時の暗号化:利用者が設定する暗号化
  • AWS Well-Architected フレームワーク:セキュリティの柱

3. 関連サービス

  • Amazon EC2:OSから上が利用者の責任
  • Amazon RDS:OS・DBエンジンのパッチをAWSが行う
  • AWS Lambda:実行環境をAWSが管理する
  • AWS Systems Manager:EC2のパッチの適用(Patch Manager)
  • AWS IAM:権限の管理は利用者の責任
