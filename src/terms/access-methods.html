1. 詳しい説明

AWSの操作は、画面(マネジメントコンソール)・コマンド(CLI)・プログラム(SDK)・テンプレート(IaC)のどれで行っても、最後はAWSのAPI(HTTPSのリクエスト)の呼び出しになります。そのため、権限(IAM)・記録(CloudTrail)・上限(スロットリング)の考え方はどの方法でも同じです。

4つの方法の使い分け

方法向いている場面認証
マネジメントコンソール状態の確認、初めての設定、たまにしかしない操作Identity Centerのポータル、IAMユーザー、フェデレーション
AWS CLIくり返しの操作、スクリプトでの自動化、一括の確認プロファイル(Identity Centerのログイン・ロール)、EC2のロール
CloudShellCLIをインストールせずに、ブラウザからすぐコマンドを使うコンソールにログインしているユーザーの権限がそのまま使われる
SDKアプリケーションの中からAWSを使う実行環境のIAMロール(EC2・Lambda・ECS)
IaC(CloudFormation・CDK・Terraform)環境の構築・変更を再現できる形で管理する実行する人やCIのロール、CloudFormationのサービスロール

認証情報が使われる順番や、長期のアクセスキーを使わない方法は「IAMロールと一時的な認証情報」で説明しています。

AWS CLIの基本

# プロファイルの作成(IAM Identity Centerでログインする場合)
aws configure sso
aws sso login --profile dev

# 使うプロファイルとリージョンを指定して実行
aws ec2 describe-instances --profile dev --region ap-northeast-1

# 必要な項目だけを表形式で取り出す(--query)
aws ec2 describe-instances \
  --query "Reservations[].Instances[].[InstanceId,State.Name]" --output table

# 今どの権限で動いているかを確認
aws sts get-caller-identity
設定・オプション意味
プロファイル(--profile)~/.aws/config に名前を付けて保存した設定(アカウント・ロール・リージョン)。複数のアカウントを切り替えて使う
リージョン(--region)操作するリージョン。指定がないとプロファイルや環境変数 AWS_REGION の値を使う。「リソースが見つからない」ときはリージョンの違いを疑う
出力形式(--output)json(既定)・table・text・yaml
--query結果から必要な項目だけを取り出す(JMESPathという書き方)
--dry-runEC2などで、実際には実行せずに権限があるかだけを確かめる

エンドポイント

APIの送り先のURLをエンドポイントと呼び、多くはリージョンごとに サービス名.リージョン.amazonaws.com(例:ec2.ap-northeast-1.amazonaws.com)の形です。インターネットに出られないプライベートサブネットからAPIを呼ぶには、VPCエンドポイントか、NATゲートウェイが必要です。

コンソールの操作も、CloudTrailにはAPIの呼び出しとして記録されます。誰が何をしたかを調べるときは、操作した方法に関係なくCloudTrailを見ます。また、コンソールで「権限がありません」と出る操作は、CLIやSDKでも同じ理由で失敗します。
