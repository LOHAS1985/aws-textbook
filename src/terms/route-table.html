1. 詳しい説明

ルートテーブル(Route Table)は、通信をどこへ転送するかを決めるルール表です。AWSでは主にVPC内のサブネットに関連付けて使います。「この宛先IPアドレスなら、このターゲットへ送る」という対応表だと考えると分かりやすいです。

基本構造

項目意味
Destination(宛先)通信の宛先となるIPアドレス範囲(CIDR)
Target(ターゲット)その宛先へ通信を転送する先
DestinationTarget意味
10.0.0.0/16LocalVPC内の 10.0.0.0/16 宛てはVPC内で通信
172.16.0.0/16VPC Peering172.16.0.0/16 宛てはVPCピアリング経由

Destination(宛先)

どのIPアドレス範囲への通信かをCIDR形式で指定します。例えば 172.16.0.0/16 なら 172.16.0.0〜172.16.255.255 が対象です。宛先がプライベートかグローバルかに関係なく、CIDRで範囲を指定します。

CIDR意味
10.0.0.0/8プライベートIPv4アドレス範囲
172.16.0.0/12プライベートIPv4アドレス範囲
192.168.0.0/16プライベートIPv4アドレス範囲
0.0.0.0/0すべてのIPv4アドレス

Target(ターゲット)

  • Local:同じVPC内
  • Internet Gateway:インターネットとの通信
  • NAT Gateway:プライベートサブネットからインターネットへの通信
  • VPC Peering:別のVPCとの通信
  • Transit Gateway:複数のVPC・オンプレミスなどを接続
  • Virtual Private Gateway:VPN経由の通信

ルートの選び方(ロンゲストマッチ)

複数のルートに当てはまる場合、AWSは宛先IPに最も具体的に一致するルート(Longest Prefix Match)を選びます。

10.0.0.0/16 → Local
10.0.1.0/24 → 別のターゲット

10.0.1.50 宛ての通信はどちらにも含まれますが、/24 のほうが /16 より具体的なので、10.0.1.0/24 のルートが選ばれます。

デフォルトルート

0.0.0.0/0 はすべてのIPv4アドレスに一致するルートです。0.0.0.0/0 → Internet Gateway とすると、より具体的なルートがない宛先への通信はインターネットゲートウェイへ送られます。

ただし、インターネットゲートウェイへのルートがあるだけで、EC2がインターネットと通信できるとは限りません。EC2のパブリックIP、セキュリティグループ、ネットワークACLなども関係します。

セキュリティグループ・NACLとの違い

機能役割判断するもの

2. 関連する用語

  • VPCフローログ:経路やSG・NACLのトラブル調査に使う通信の記録
  • ネットワークACLとセキュリティグループ:通信の許可・拒否を判断する仕組み
  • アウトバウンド通信/インバウンド通信:ルートテーブルのターゲットごとの通信パターン
