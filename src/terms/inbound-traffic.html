1. 詳しい説明

インバウンド通信は、外部からVPC内のリソースへ入ってくる通信です。送信元の種類によって通る入口が異なり、いずれの場合もルートテーブルに経路があることに加えて、セキュリティグループとNACLで許可されていることが必要です。

① インターネット → パブリックサブネットのインスタンス(IGW)

  • 経路:インターネット → IGW → インスタンス
  • ルート:パブリックサブネットのルートテーブルで 0.0.0.0/0(IPv6は ::/0)→ IGW
  • 条件:IPv4ではパブリックIPv4アドレスまたはElastic IPが必要。IPv6ではグローバルに一意なIPv6アドレスで受信できる。
  • 特徴:インスタンスを直接公開するため、セキュリティグループで受け付けるポートを絞る。

② インターネット → プライベートサブネットのインスタンス(ALB/NLB)

  • 経路:インターネット → IGW → ALB/NLB → インスタンス
  • 配置:ロードバランサーはパブリックサブネット、インスタンスはプライベートサブネットに置く。
  • 特徴:インスタンスにパブリックIPを持たせずに公開できる。インスタンスのSGでは、ロードバランサーのSGからの通信だけを許可する。

③ オンプレミス → プライベートサブネット(Site-to-Site VPN/Direct Connect)

  • 経路:オンプレミス → Site-to-Site VPN または Direct Connect → インスタンス
  • 終端:仮想プライベートゲートウェイ(VGW)または Transit Gateway
  • 特徴:インターネットを経由せずプライベートIPで通信する。VPNはインターネット上を暗号化して通り、Direct Connectは専用線で接続する。
  • ルート:サブネットのルートテーブルに、オンプレミスのCIDR向けの経路(またはVGWのルート伝播)が必要。

④ 他のVPC → プライベートサブネット(VPCピアリング/Transit Gateway)

  • 経路:他のVPC → VPCピアリング または Transit Gateway → インスタンス
  • 特徴:プライベートIPでVPC間を接続する。VPCピアリングは1対1で推移的なルーティングはできない。Transit Gatewayは多数のVPCやオンプレミスをハブ&スポークで接続できる。
  • 条件:双方のルートテーブルに相手側CIDR向けの経路が必要。CIDRが重複していると接続できない。

比較

送信元入口経由するもの宛先パブリックIP
インターネットIGWなしパブリックサブネットのインスタンス必要
インターネットIGWALB/NLBプライベートサブネットのインスタンス不要
オンプレミスVPN/Direct Connectなしプライベートサブネットのインスタンス不要
他のVPCVPCピアリング/Transit Gatewayなしプライベートサブネットのインスタンス不要

押さえておきたいポイント

  • SGはステートフルなので、許可したインバウンド通信の応答(アウトバウンド)は自動的に許可される。
  • NACLはステートレスなので、インバウンドと応答のアウトバウンド(エフェメラルポート)の両方を明示的に許可する必要がある。
  • 通信が届かないときの確認順:ルートテーブル → IGWなどのアタッチ状態 → セキュリティグループ → NACL → パブリックIPの有無。
  • インターネットから直接受けたくないリソースはプライベートサブネットに置き、ロードバランサーを前段に配置する。

2. 関連する用語

  • アウトバウンド通信:VPC内から外へ出ていく通信
  • ルートテーブル:経路を決めるルール表
  • ネットワークACLとセキュリティグループ:通信の許可・拒否

3. 関連サービス

  • Amazon VPC:IGW・サブネット・ピアリング
  • Elastic Load Balancing:プライベートなインスタンスの公開
  • AWS Transit Gateway:多数のVPC・オンプレミスの接続
  • AWS Site-to-Site VPN/AWS Direct Connect:オンプレミスからの接続
  • AWS Resource Access Manager:Transit Gatewayの共有
