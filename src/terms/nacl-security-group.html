1. 詳しい説明

VPCでのネットワークアクセス制御には、主にネットワークACL(NACL)とセキュリティグループ(SG)があります。

  • ネットワークACL:サブネット単位で通信を制御する
  • セキュリティグループ:ENI(Elastic Network Interface)に関連付けて、リソース単位で通信を制御する

ネットワークACL(NACL)

  • サブネットに関連付けるアクセス制御リスト。
  • ステートレスなので、戻りの通信も別途許可する必要がある。
  • ルールには番号があり、番号の小さい順に評価され、最初に一致したルールが適用される。
  • ALLOW と DENY の両方を設定でき、特定のIPやCIDRからの通信を明示的に拒否したい場合に有用。

例:Webサーバー用サブネットで、10.0.0.0/16 からのTCP 80を許可、203.0.113.0/24 からのTCP 80を拒否、その他を拒否。拒否ルールが許可ルールより先に評価されるよう、ルール番号を小さくする必要があります。

セキュリティグループ(SG)

  • EC2などのリソースに紐づく仮想ファイアウォール。
  • ステートフルなので、許可した通信の戻りの通信は自動的に許可される。
  • ALLOW ルールのみ設定でき、DENY ルールは設定できない。
  • 1つのENIに複数のSGを関連付けられ、いずれかのSGで許可されれば通信が許可される。
  • 別のセキュリティグループを送信元として指定することもできる。

例:TCP 443を 0.0.0.0/0 から許可、TCP 22を管理用IP 203.0.113.10/32 から許可 → HTTPSは全世界から、SSHは管理端末からだけ接続できる。

ステートフルとステートレスの違い(試験で重要)

SG = 戻りの通信を意識しなくてよい、NACL = 戻りの通信もルールで考える と覚えるとよいでしょう。

試験でよく問われるポイント

  • 特定のIPアドレスからの通信だけを明示的に拒否したい → ネットワークACL。
  • EC2へのHTTPSを許可したとき、戻りの通信のルールは必要か → SGなら不要(ステートフル)。
  • サブネット全体に対してアクセス制御したい → ネットワークACL。
  • SGで明示的なDENYルールを設定したい → できない(許可ルールのみ)。
  • NACLで許可したのに通信できない → SG、NACLの反対方向のルール、ルートテーブル、ゲートウェイなども確認する。

2. 関連する用語

  • ルートテーブル:通信の経路を決める(許可・拒否はしない)
  • VPCフローログ:SG・NACLで許可(ACCEPT)・拒否(REJECT)された通信の記録
  • インバウンド通信/アウトバウンド通信:SG・NACLが関わる通信パターン
