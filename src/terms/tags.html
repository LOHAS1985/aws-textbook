1. 詳しい説明

タグは、リソースに付けるキーと値の組のラベルです(例:Environment = prod、Project = shop)。名前を付けて見分けるだけでなく、費用の集計・権限の制御・自動化の対象の指定に使えるため、運用の基本になります。

  • キーと値は大文字・小文字を区別する(env と Env は別のタグ)
  • 1つのリソースに付けられるタグは最大50個
  • aws: で始まるタグはAWSが付けるもので、利用者は作成・変更できない
  • EC2の Name タグは、コンソールの「名前」の列に表示される

タグの使い道

使い道仕組み例
費用の集計コスト配分タグとして有効にすると、Cost ExplorerやCURでタグごとに集計できるプロジェクト・部署ごとの請求額
権限の制御(ABAC)IAMポリシーの条件で、ユーザーとリソースのタグが一致するときだけ許可する自分のチームのタグが付いたEC2だけ停止できる
自動化の対象Systems Managerやスケジュールの処理で、タグで対象を選ぶPatch Group タグでパッチの適用先を分ける、AutoStop=true のインスタンスを夜間に止める
リソースの整理Resource Groups・Tag Editorでタグごとにまとめて検索・一括で編集する本番環境のリソースの一覧
バックアップの対象AWS Backupのバックアッププランで、タグでリソースを選ぶBackup=daily のリソースを毎日バックアップ

コスト配分タグ

  • 利用者が付けたタグは、請求とコスト管理のコンソールでコスト配分タグとして有効化しないと、費用の集計には使えない(管理アカウントで有効化する)
  • 有効化したあとの費用から集計される。過去の分にはさかのぼらない
  • AWSが付ける aws:createdBy(作成者)も、有効化するとコスト配分タグとして使える

ABAC(属性ベースのアクセス制御)

次のポリシーは、「呼び出した人の Team タグと、EC2インスタンスの Team タグが同じときだけ、停止・起動を許可する」という意味です。チームやリソースが増えても、タグを付けるだけでよく、ポリシーを書き換えずに済みます。

{
  "Effect": "Allow",
  "Action": ["ec2:StopInstances", "ec2:StartInstances"],
  "Resource": "*",
  "Condition": {
    "StringEquals": { "aws:ResourceTag/Team": "${aws:PrincipalTag/Team}" }
  }
}
条件キー意味
aws:ResourceTag/キー操作するリソースに付いているタグ
aws:RequestTag/キー作成・タグ付けのリクエストで付けようとしているタグ(作成時にタグを必須にする)
aws:TagKeysリクエストに含まれるタグのキーの一覧(付けてよいキーを制限する)
aws:PrincipalTag/キー呼び出したユーザー・ロールに付いているタグ

タグを付け忘れないようにする

  • CloudFormationのスタックに付けたタグは、スタックの中のリソースにも付く
  • Auto Scalingグループのタグは、「起動時に伝播」を有効にすると、起動するEC2インスタンスにも付く
  • EC2の起動テンプレートでは、インスタンスとEBSボリュームの両方にタグを指定できる

試験では「部署ごとの費用を出したい」にはコスト配分タグの有効化、「タグのないリソースを見つけたい」には Config の required-tags、「チームごとに操作できるリソースを分けたい」には ABAC が答えになることが多いです。
