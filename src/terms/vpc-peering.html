1. 詳しい説明

VPCピアリングは、2つのVPCを1対1で接続し、お互いのリソースがプライベートIPアドレスのまま通信できるようにする仕組みです。通信はAWSのネットワーク内を通り、インターネットには出ません。

  • 同じアカウント・別のアカウント、同じリージョン・別のリージョンのどちらのVPCともつなげる。
  • ゲートウェイのような機器はなく、帯域の上限や単一障害点もない。
  • VPCピアリング接続自体の時間料金はかからない。データ転送料金はかかる(同じAZ内の通信は無料、AZ間・リージョン間は有料)。

設定の流れ

  1. 片方のVPCからピアリング接続をリクエストする
  2. 相手側のVPCの所有者が承認(Accept)する
  3. 両方のVPCのルートテーブルに、相手のCIDR → ピアリング接続(pcx-)の経路を追加する
  4. セキュリティグループ・ネットワークACLで、相手のCIDRからの通信を許可する(同じリージョンなら、相手VPCのセキュリティグループを参照して許可することもできる)

「ピアリング接続はアクティブなのに通信できない」→ ほとんどの場合、片方のルートテーブルに経路がないか、セキュリティグループ・ネットワークACLで許可されていません。経路は往復分(両側)必要です。

制約(重要)

  • CIDRが重なっているVPC同士はつなげない。
  • 推移的なルーティングはできない:AとB、BとCをつないでも、AからBを経由してCへは行けない。AとCも通信させたいなら、AとCの間にもピアリングを作る。
  • 相手のVPCの出入口は使えない:相手VPCのインターネットゲートウェイ・NATゲートウェイ・VPN・Direct Connectを経由して外に出ることはできない。

Transit Gatewayとの使い分け

項目VPCピアリングTransit Gateway
つなぎ方1対1(VPCの数が増えると接続数が急増)ハブ&スポーク(接続はVPCの数だけ)
推移的なルーティングできないできる
オンプレミスとの接続できないVPN・Direct Connectもまとめてつなげる
料金データ転送料金のみアタッチメントの時間料金+データ処理料金
向いている場面少数のVPC同士の接続、通信量が多い接続多数のVPC・オンプレミスを含むネットワーク

2. 関連する用語

  • CIDR:重なっているとピアリングできない
  • ルートテーブル:両側にピアリング接続への経路を追加する
  • ネットワークACLとセキュリティグループ:相手VPCからの通信の許可
  • VPCエンドポイント:VPC全体ではなく、特定のサービスだけをプライベートに公開する方法

3. 関連サービス

  • Amazon VPC:ピアリング接続を作成する
  • AWS Transit Gateway:多数のVPCをつなぐ場合の選択肢
  • Amazon Route 53:プライベートホストゾーンを相手のVPCにも関連付けて名前解決する
