1. 詳しい説明

DR(Disaster Recovery:災害復旧)戦略は、リージョン全体の障害や、誤操作・ランサムウェアによるデータ破損などの災害に備えて、別の場所(DRサイト)をどの程度準備しておくかの方式です。準備を厚くするほど早く復旧できますが、コストが上がります。

RTOとRPO

どの戦略を選ぶかは、業務が許容できる2つの値で決まります。

  • RTO(目標復旧時間):障害が起きてから、サービスを再開するまでに許容できる時間。「何時間止まってよいか」。
  • RPO(目標復旧時点):どの時点までのデータを取り戻せればよいか。「何時間分のデータを失ってよいか」。バックアップやレプリケーションの間隔で決まる。

RPOとRTOは別々に決まります。例えば、1時間ごとにバックアップしていればRPOは最大1時間ですが、そのバックアップから環境を作り直すのに4時間かかれば、RTOは4時間です。

バックアップと復元

データのバックアップを別リージョンにコピーしておき、障害が起きたら、バックアップとインフラのコード(CloudFormationなど)から環境を作り直す方式です。最も安い一方で、作り直す時間がRTOになります。

  • AWS Backupのクロスリージョンコピー、S3のクロスリージョンレプリケーション、EBSスナップショットやAMIのリージョン間コピーを使う。
  • 作り直しを手作業にするとRTOが延びるため、CloudFormationなどで環境をコード化しておく。
  • ランサムウェアや誤削除への備えとしては、どの戦略を選んでも必要になる(レプリケーションは誤った変更もそのまま複製するため)。

パイロットライト

「種火」の意味で、データベースなどのデータ層だけを常に同期しておき、アプリのサーバーは止めておく方式です。障害時にアプリのサーバーを起動・増設してから切り替えます。

  • データはAuroraグローバルデータベース、DynamoDBグローバルテーブル、RDSのクロスリージョンリードレプリカなどで同期する。
  • アプリ層は、Auto Scalingグループを台数0で用意しておく、AMIだけを用意しておく、などで待機させる。
  • 切り替えるまでリクエストを処理できない点が、ウォームスタンバイとの違い。

ウォームスタンバイ

本番と同じ構成を、小さい規模で常に動かしておく方式です。障害時はDR側をスケールアウトし、DNSなどでトラフィックを切り替えます。常に動いているため、切り替え前から動作を確認できます。

  • DR側のAuto Scalingグループは最小台数を小さくしておき、切り替え時に希望台数を増やす。
  • Route 53のフェイルオーバールーティングやARC(Application Recovery Controller)で切り替える。

マルチサイト(アクティブ/アクティブ)

複数のリージョンで、本番と同じ規模の環境を動かし、どちらでもリクエストを処理する方式です。片方が止まっても、もう片方がそのまま処理を続けます。

  • Route 53のレイテンシーや加重ルーティング、Global Acceleratorで両方のリージョンに振り分ける。
  • どちらのリージョンでも書き込める必要があるため、DynamoDBグローバルテーブルのようなマルチリージョンで書き込めるデータストアが向いている。
  • 片方のリージョンを読み取り専用で待機させる方式は、アクティブ/パッシブ(ホットスタンバイ)と呼ばれる。

高可用性とDRの違い

マルチAZ構成(RDSのマルチAZ、複数AZにまたがるAuto Scalingグループなど)は、1つのAZの障害に自動で備える高可用性の仕組みです。DR戦略は、リージョン全体の障害やデータの破損に備えるもので、目的が違います。試験では「リージョン障害に備える」と書かれていればDR戦略、「AZ障害に備える」と書かれていればマルチAZを選びます。

戦略の選び方とDR訓練

  • 要件(RTO・RPO)を満たす戦略のうち、最もコストが低いものを選ぶ。
  • 切り替え手順は、実際に試さないと動くか分からない。AWS Fault Injection Service(FIS)で障害を起こす訓練や、AWS Backupの復元テストで、定期的に確かめる。
  • サーバーをブロック単位で別リージョンへ複製し続けるAWS Elastic Disaster Recovery(DRS)を使うと、オンプレミスやEC2のサーバーを、少ない待機コストで短いRTO・RPOで復旧できる。
  • 関連する運用シナリオ:バックアップを一元管理して別リージョンに保管する、リージョン障害に備えて別リージョンへ切り替える、誤操作したRDSのデータを特定の時点に戻す

2. 関連する用語

  • 高可用性とスケーリング:AZ障害への備え(マルチAZ)
  • リージョンとAZ:障害の範囲を分ける単位
  • SLAと可用性:可用性の目標値
  • デプロイ戦略:Blue/Greenなど、新旧環境の切り替え方式
  • サーキットブレーカー:障害を広げないための設計パターン

3. 関連サービス

  • AWS Backup:別リージョン・別アカウントへのバックアップコピー、復元テスト
  • Amazon Aurora:グローバルデータベース
  • Amazon DynamoDB:グローバルテーブル
  • Amazon RDS:クロスリージョンリードレプリカ、自動バックアップのリージョン間レプリケーション
  • Amazon S3:クロスリージョンレプリケーション
  • Amazon Route 53:フェイルオーバールーティング
  • Amazon Application Recovery Controller:リージョンの切り替えの管理
  • AWS CloudFormation:DRサイトの環境をコードから作る
  • Amazon EC2 Auto Scaling:DR側のサーバーの増設
