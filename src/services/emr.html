1. サービス概要

Amazon EMRは、Apache Spark、Hadoop、HiveなどのビッグデータフレームワークをAWS上で実行するマネージドサービスです。大規模なデータ処理や分析に必要なクラスターを作成し、S3などのデータを並列に処理します。

2. 主な機能・特徴

実行方式

  • EMR on EC2:クラスターのEC2インスタンスとソフトウェア構成を管理し、柔軟なカスタマイズを行う。
  • EMR Serverless:クラスターを常時管理せず、SparkやHiveのジョブ実行に必要なリソースを利用する。
  • EMR on EKS:Amazon EKS上でEMRの処理を実行し、既存のKubernetes基盤と共存させる。

分散処理

処理対象を複数のノードに分け、並列に読み込み・変換・集計します。S3をデータレイクとして使う処理では、クラスターディスクにすべてのデータを置かずに済みます。HDFSを使う構成では、クラスター内の一時・分散ストレージの容量と耐障害性を考慮します。

Glueとの使い分け

AWS Glueはサーバーレスなデータ統合・ETLを簡潔に実行したい場合に向きます。EMRはフレームワークや実行環境の選択、クラスター構成、ライブラリなどを細かく制御したい大規模処理に向きます。どちらもSparkを使えるため、既存コード・運用負荷・処理時間・コストで選びます。

3. ユースケース

  • 大量のログやイベントをSparkで集計・変換する。
  • 複雑なデータ処理や機械学習向け前処理を分散実行する。
  • 既存のHadoop/SparkアプリケーションをAWS上で実行する。
  • データレイクのデータを変換し、分析用の保存先へ出力する。

4. 料金の考え方

実行方式により、EC2インスタンスの稼働、EMRの利用、ジョブ処理に使うリソースなどが主な課金要因です。EMR on EC2では未使用ノードを停止し、ジョブに適したインスタンスタイプとクラスターサイズを選びます。S3、EKS、データ転送などの料金は別に確認します。

5. 関連サービス

  • Amazon S3:データレイクと処理結果の保存
  • AWS Glue:サーバーレスETLとData Catalog
  • AWS Lake Formation:データレイクの細粒度アクセス制御
  • Amazon Redshift:分析データウェアハウス
  • Amazon EKS:EMR on EKSの実行基盤

6. 試験・実務でのポイント

  • SparkやHadoopなどのOSSフレームワークを大規模分散実行 → Amazon EMR。
  • インフラ管理を避けてジョブ単位で処理する → EMR Serverless。
  • ノードやソフトウェアを柔軟に制御する → EMR on EC2。
  • 既存のKubernetes基盤を使う → EMR on EKS。
  • GlueはサーバーレスETL、EMRはOSS処理基盤の柔軟な実行を軸に比較する。

7. まとめ

  • EMRは、SparkやHadoopなどをマネージドなクラスター環境で実行する。
  • EC2、Serverless、EKSの実行方式から、制御性と管理負荷に合わせて選ぶ。
