1. サービス概要

Amazon API Gatewayは、APIの作成・公開・管理のためのサービスです。クライアントからのリクエストを受け付け、LambdaやHTTPサーバー、他のAWSサービスへ中継します。

2. 主な機能・特徴

APIの種類

  • HTTP API:シンプルで低コストなAPI(実体はHTTPS)。
  • REST API:多機能なAPI。
    • ステージ変数:API Gateway内部だけで使う変数。バックエンドや呼び出し先URL、環境固有の設定値を切り替える。${stageVariables.xxx} で値を参照する。
      例:prodステージは lambdaAlias="prod"、testステージは lambdaAlias="test" とし、arn:aws:lambda:ap-northeast-1:123456789012:function:MyFunction:${stageVariables.lambdaAlias} で呼び出し先を切り替える。
    • ステージレベルのキャッシュ:GET以外(POSTなど)にも対応。
  • WebSocket API:双方向通信。

リクエスト処理の流れ

  1. メソッドリクエスト:クライアントから受け取るリクエストの定義
  2. 統合リクエスト:バックエンドへ送る前の変換処理(Lambda・HTTPサーバー・他AWSサービス向けに変換)
  3. 統合レスポンス:バックエンドから返ってきたデータの変換処理
  4. メソッドレスポンス:クライアントへ返すレスポンスの仕様

オーソライザー

APIを呼び出してよいかを判定する認証・認可の機能です。キャッシュ機能があるため、直前の結果を引き継ぐ可能性があります。

3. ユースケース

  • API Gateway+Lambda(プロキシ統合)によるサーバーレスAPI
  • 既存のHTTPシステムの前段にAPIの入り口を置く(HTTP統合)
  • APIキーと使用量プランで、外部パートナーごとに利用量を制限
  • チャットなどのリアルタイム双方向通信(WebSocket API)

4. 料金の考え方

APIの呼び出し回数とデータ転送量で課金されます(WebSocketは接続時間とメッセージ数)。HTTP APIはREST APIより安価です。REST APIのキャッシュを有効にすると、キャッシュサイズに応じた時間料金が加わります。

5. 関連サービス

  • AWS Lambda:代表的なバックエンド、Lambdaオーソライザー
  • Amazon Cognito:ユーザー認証(Cognitoオーソライザー)
  • AWS IAM:SigV4によるIAM認証
  • Amazon CloudFront/AWS Certificate Manager:カスタムドメインと証明書
  • Amazon VPC:プライベートAPIのVPCエンドポイント
  • AWS X-Ray:リクエストのトレース

6. 試験・実務でのポイント

  • APIを変更したら再デプロイ(createDeployment)しないと反映されない。
  • APIキーは使用量プランに関連付け(createUsagePlanKey)て初めて使える。
  • 環境ごとにLambdaのエイリアスを切り替える → ステージ変数。
  • オーソライザーの結果はキャッシュされる。権限変更がすぐ反映されないときはキャッシュを疑う。
  • リクエストをそのまま渡す → プロキシ統合、変換が必要 → 非プロキシ+マッピングテンプレート。
  • VPC内からのみ使わせたい → プライベートAPI(VPCエンドポイント必須)。

7. まとめ

  • API GatewayはHTTP/REST/WebSocketのAPIを提供する。
  • 処理はメソッドリクエスト → 統合リクエスト → 統合レスポンス → メソッドレスポンス。
  • 認可はオーソライザー、利用制限はAPIキー+使用量プラン。
