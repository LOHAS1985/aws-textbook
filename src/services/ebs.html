1. サービス概要

Amazon EBS(Elastic Block Store)は、EC2にアタッチして使うブロックストレージサービスです。PCの内蔵ディスクのように使え、EC2を停止してもデータは残ります。

2. 主な機能・特徴

  • EC2を停止してもEBSのデータは残る(インスタンスストアとの違い)。
  • マルチアタッチ:同一AZの別のEC2インスタンスへもアタッチできる。
  • 暗号化に対応。
  • スナップショットを取得できる(S3に保存される)。
  • バーストクレジット:ベースラインの性能に加え、一時的にそれを超える性能を発揮するための「クレジット」が付与される仕組み。

EBSボリュームは特定のAZに作成され、同じAZのインスタンスにしかアタッチできません。マルチアタッチはプロビジョンドIOPS SSD(io1/io2)でのみ利用できます。別のAZで使う場合はスナップショットから復元します。

ボリュームの種類

種類媒体特徴主用途ポイント
gp3SSD汎用SSD。IOPS/スループットを容量と独立して調整可能Web、アプリ現在の標準推奨
gp2SSD旧世代の汎用SSD。IOPSがサイズに依存旧環境gp3への移行が推奨
io2SSD超高耐久・高IOPS高性能DBミッションクリティカル
io1SSD高IOPS高性能DBio2の旧世代
st1HDD高スループットビッグデータ、ログ順次読み書き向け
sc1HDD超低コストアーカイブ最低性能
standardHDD旧世代の磁気ディスクレガシーほぼ非推奨

CloudWatchメトリクス

観点メトリクス
IOPS(1秒あたりのI/O操作数)VolumeReadOps、VolumeWriteOps
スループット(1秒あたりの転送量、MiB/s)VolumeReadBytes、VolumeWriteBytes
レイテンシー1回のI/Oが完了するまでの時間
アイドル時間VolumeIdleTime

キューの深さ(完了待ちのI/O数)VolumeQueueLength

ストレージの最適化

RAIDを構成できます。ストライピング(RAID 0)はデータを複数ボリュームに分散して並列処理し、性能を上げます。

3. ユースケース

  • OSディスク(Windows/Linux)
  • データベースの保存領域(MySQL/PostgreSQL)
  • アプリケーションのログ保存
  • アップロードファイルなどの永続データ

4. 料金の考え方

プロビジョニングした容量(GB/月)に対して課金され、gp3やio1/io2では追加のIOPS・スループットにも料金がかかります。EC2が停止中でもボリュームの料金は発生します。スナップショットは保存量に応じて課金されます。

5. 関連サービス

  • Amazon EC2:EBSをアタッチするインスタンス
  • Amazon S3:スナップショットの保存先
  • Amazon EFS:複数インスタンス・複数AZで共有できるファイルストレージ
  • AWS Backup:スナップショットの一元管理
  • Amazon CloudWatch:メトリクスの監視

6. 試験・実務でのポイント

  • 迷ったらgp3。高IOPSのDB → io2。大量の順次読み書き → st1。
  • gp2で性能が落ちる → BurstBalance(バーストクレジット残量)を確認。
  • I/Oが詰まっている → VolumeQueueLength を確認。
  • 性能を上げたい → RAID 0(ストライピング)。
  • EBSはAZに紐づく。別AZへはスナップショット経由。

7. まとめ

  • EBSはEC2用の永続ブロックストレージ。停止してもデータは残る。
  • 標準はgp3、高性能はio2、HDDはst1/sc1。
  • 性能のトラブルはCloudWatchメトリクスで切り分ける。
