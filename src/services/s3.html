1. サービス概要

Amazon S3(Simple Storage Service)は、ファイルを「オブジェクト」として保存するオブジェクトストレージサービスです。データは「バケット」に格納し、アクセス頻度に応じてストレージクラスを選んでコストを最適化します。

2. 主な機能・特徴

バケット・キー・プレフィックス

S3のデータはバケット(入れ物)の中にオブジェクトとして保存します。オブジェクトはキー(名前)で識別され、データ本体とメタデータを持ちます。

  • バケット名は全世界(全アカウント・全リージョン)で一意。バケットはリージョンを指定して作る
  • 1オブジェクトの最大サイズは5TB(1回のPUTでは5GBまで。それ以上はマルチパートアップロード)
  • バケット内の容量・オブジェクト数に上限はない

S3の中身はフラットな構造で、フォルダは実在しません。logs/2026/10/app.log は「logs/2026/10/app.log という1つのキーを持つオブジェクト」です。キーの先頭部分(logs/2026/ など)をプレフィックスと呼び、コンソールは / 区切りのプレフィックスをフォルダのように見せているだけです。

プレフィックスは、ライフサイクルルールやレプリケーションの対象の絞り込み、IAMポリシーでのアクセス範囲の指定(arn:aws:s3:::my-bucket/user-a/*)などに使います。性能もプレフィックスごとに1秒あたりPUTなど3,500件・GETなど5,500件まで出せるので、プレフィックスを分けると全体の処理量を増やせます。

ストレージクラス

ブロックパブリックアクセス

ブロックパブリックアクセスは、バケットやオブジェクトが誤ってインターネットに公開されるのを防ぐ設定です。バケットポリシーやACLで公開する設定をしても、ブロックパブリックアクセスが有効ならその公開は無効になります。新しく作るバケットでは既定ですべて有効です。

設定効果
BlockPublicAcls公開するACLを新しく付けることをブロックする
IgnorePublicAcls既に付いている公開ACLを無視する
BlockPublicPolicy公開するバケットポリシーの設定をブロックする
RestrictPublicBuckets公開ポリシーを持つバケットへのアクセスを、AWSサービスとバケット所有者のアカウントに限定する

アカウント単位とバケット単位の両方で設定でき、どちらかで有効ならブロックされます。アカウント単位で有効にしておけば、どのバケットも公開できなくなります。静的ウェブサイトを直接公開する場合などは、そのバケットだけ無効にします。また、新しいバケットではACLも既定で無効(オブジェクト所有者=バケット所有者に強制)になっていて、アクセス制御はポリシーで行います。

暗号化

保存時の暗号化方式は、x-amz-server-side-encryption ヘッダーで指定します。

区分方式鍵の管理者特徴主な用途
サーバーSSE-S3AWSS3が自動で鍵管理・暗号化最も簡単・標準
サーバーSSE-KMSユーザー+AWS(KMS)AWS KMSで鍵管理し、監査可能(いつ・どこで・誰が利用したか確認できる)セキュリティ重視
サーバーSSE-Cユーザー鍵をリクエストごとに指定特殊要件
クライアントクライアントサイド暗号化ユーザー送信前にクライアント側で暗号化し、S3は暗号化データをそのまま保存高セキュリティ

S3ではすべての新しいオブジェクトが既定でSSE-S3で暗号化されます(2023年1月から)。ヘッダーを指定しなくても、暗号化されないオブジェクトは作られません。バケットの既定の暗号化をSSE-KMSに変えると、ヘッダーなしでアップロードされたオブジェクトもKMSキーで暗号化されます。

  • SSE-KMSを既定にする場合はS3バケットキーを有効にすると、KMSへのリクエスト数が減り、KMSの料金とスロットリングを抑えられる
  • 既定の暗号化を変えても、既存のオブジェクトは再暗号化されない(コピーやS3 Batch Operationsで暗号化し直す)
  • 「特定のKMSキー以外での暗号化を禁止する」ときは、バケットポリシーで条件(s3:x-amz-server-side-encryption-aws-kms-key-id)に合わないPUTをDenyする

暗号化の考え方は用語ページ「保存時の暗号化と転送時の暗号化」を参照してください。

アクセス制御

  1. IAMポリシー:IAMユーザー/ロールに付与し、操作単位(GetObject、PutObjectなど)で制御する。
    例:Cognito Identity Poolでユーザーに一時IAMロールを発行し、そのポリシーでS3の特定プレフィックスだけアクセスを許可する。
  2. バケットポリシー:どのバケットに誰がアクセスできるかをバケットに直接設定する。他アカウントからのアクセスはバケットポリシーで許可する(他アカウント側のIAMポリシーでの許可も必要)。
  3. ACL:現在は非推奨。
  4. 署名付きURL(Presigned URL):期限付きでアクセスさせるURL。

エンドポイント

  1. パブリックエンドポイント:インターネット経由でアクセス(例:https://bucket-name.s3.region.amazonaws.com)
  2. VPCエンドポイント:インターネットを経由せずにプライベート接続
    • ゲートウェイ型:VPCからのみ利用可能。無料。
    • インターフェイス型:オンプレミスやピアリングVPCからもアクセス可能。ENIにプライベートIPが割り当てられる。有料。

イベント通知

オブジェクトの状態変化をトリガーに、他サービスへ非同期にイベントを送る仕組みです。送信先はLambda・SNS・SQSです。

  • 作成:s3:ObjectCreated:Put/Post/Copy/CompleteMultipartUpload
  • 削除:s3:ObjectRemoved:Delete/DeleteMarkerCreated
  • 復元:s3:ObjectRestore:Post/Completed
  • レプリケーション:s3:Replication

読み取り操作(GetObject)やリスト操作(ListObjects)などは対象外です。

通知の送信先にはAmazon EventBridgeも選べます。バケットで「EventBridgeへの通知」をオンにすると、すべてのイベントがEventBridgeのデフォルトイベントバスに送られ、EventBridgeのルールで絞り込んで転送します。

項目S3のイベント通知(Lambda・SNS・SQS)EventBridge経由
送信先Lambda・SNS・SQSの3つStep Functions・Kinesis・API送信先など多数のターゲット
絞り込みキーのプレフィックス・サフィックスだけキー・サイズ・送信元IPなど、イベントの中身で細かく絞り込める
同じイベントを複数の送信先にプレフィックスが重なる同じイベントタイプの設定は作れない(SNSでファンアウトする)複数のルールで同じイベントを複数の送信先に送れる
その他—アーカイブと再実行、他アカウントのイベントバスへの転送ができる

バージョニング

バージョニングを有効にすると、同じキーへの上書きや削除をしても以前のバージョンが残り、誤操作から復元できます。バケットの状態は「無効(既定)」「有効」「停止」の3つで、一度有効にすると無効には戻せず、停止しかできません(停止しても既存のバージョンは残る)。

  • 上書き:新しいバージョンが作られ、古いバージョンは「非現行バージョン」として残る
  • 削除(バージョンIDを指定しない):オブジェクトは消えず、削除マーカーが最新バージョンとして置かれる。削除マーカーを削除すると元に戻る
  • バージョンIDを指定した削除:そのバージョンが完全に削除される
  • すべてのバージョンが保存料金の対象になるため、ライフサイクルルールで古いバージョンを削除する
  • MFA Deleteを有効にすると、バージョンの完全削除やバージョニングの状態変更にMFAが必要になる(ルートユーザーがCLIで設定)

バージョニングはレプリケーションやObject Lockの前提条件でもあります。

レプリケーション

  1. 送信元・送信先バケットのバージョニングを有効化
  2. レプリケーション専用のIAMロールを作成
  3. 送信元バケットにレプリケーションルールを設定(必要に応じてオーナーオーバーライドで所有権を移動)

ライフサイクルルール

ライフサイクルルールは、オブジェクトを日数に応じて自動で処理するルールです。バケット全体、またはプレフィックス・タグ・サイズで絞り込んだオブジェクトに適用します。

アクション内容例
移行(Transition)別のストレージクラスへ移す作成30日後にStandard-IA、90日後にGlacier Flexible Retrieval
有効期限(Expiration)オブジェクトを削除する(バージョニング有効時は削除マーカーを置く)作成365日後に削除
非現行バージョンの移行・削除古いバージョンを移す・削除する非現行になって30日後に削除
不完全なマルチパートアップロードの中止途中で止まったアップロードのパーツを削除する開始7日後に中止
期限切れの削除マーカーの削除古いバージョンがすべて消えて残った削除マーカーを消す—
  • StandardからStandard-IA・One Zone-IAへは作成から30日以上経たないと移行できない
  • 128KB未満の小さいオブジェクトは既定では移行されない(移行の料金の方が高くつくため)
  • 移行先の最低保存期間より前に削除・移行すると、残りの期間分の料金がかかる

Object Lock

S3 Object Lockは、オブジェクトのバージョンを一定期間、削除・上書きできなくする(WORM:Write Once Read Many)機能です。法令で定められた期間の記録保持や、ランサムウェア対策に使います。バージョニングが必須です。

保護の種類内容
ガバナンスモード(保持期間)通常のユーザーは削除・保持期間の短縮ができない。特別な権限(s3:BypassGovernanceRetention)を持つユーザーは解除できる。設定のテストや社内ルール向け
コンプライアンスモード(保持期間)ルートユーザーを含め誰も、保持期間が終わるまで削除できず、モードの変更や期間の短縮もできない。法令対応向け
リーガルホールド期限なしで削除を禁止する。外すまで有効(s3:PutObjectLegalHold の権限で付け外しする)。訴訟などで一時的に保全したいとき

バケットに既定の保持モードと期間を設定しておくと、新しいオブジェクトに自動で適用されます。Glacierのボールトに対する同様の機能は「Vault Lock」です。

静的ウェブサイトホスティング

静的ウェブサイトホスティングを有効にすると、バケットのHTML・CSS・画像などをWebサイトとして公開できます(サーバー側でプログラムを動かす動的なサイトは不可)。

  • インデックスドキュメント(index.html)とエラードキュメント(error.html)を指定する。別のURLへのリダイレクトも設定できる
  • ウェブサイトエンドポイント:http://バケット名.s3-website-リージョン.amazonaws.com(リージョンによっては s3-website.リージョン)
  • 公開するには、ブロックパブリックアクセスを無効にし、バケットポリシーで全員に s3:GetObject を許可する
  • ウェブサイトエンドポイントはHTTPのみ。HTTPSを使うにはCloudFrontを前に置く
  • 独自ドメインをRoute 53で直接向ける場合は、バケット名をドメイン名と同じにする

実務では、バケットは非公開のままにしてCloudFront+OAC(オリジンアクセスコントロール)から配信する構成がよく使われます。その場合、OACはバケットの通常のREST APIエンドポイントに対して使い、ウェブサイトエンドポイントは使いません。

マルチパートアップロード

マルチパートアップロードは、大きなファイルを複数のパーツに分けて並列にアップロードし、最後にS3側で1つのオブジェクトに結合する方法です。

  • 100MB以上のファイルで推奨、5GBを超えるファイルでは必須
  • パーツは5MB〜5GB(最後のパーツは5MB未満でもよい)、最大10,000パーツ
  • 並列に送るので速く、失敗したパーツだけ送り直せる
  • AWS CLIの aws s3 cp などは、大きいファイルで自動的にマルチパートアップロードを使う
  • 完了も中止もされていないアップロードのパーツは一覧に見えないまま保存料金がかかるため、ライフサイクルルールで「不完全なマルチパートアップロードの中止」を設定する

遠隔地からのアップロードを速くしたい場合は、Transfer Accelerationと組み合わせます。

CORS

ブラウザは、表示中のページと異なるオリジン(ドメイン・プロトコル・ポートの組み合わせ)へのJavaScriptからのリクエストを、相手が許可していない限りブロックします。CORS(Cross-Origin Resource Sharing)は、この許可をサーバー側で返す仕組みです。

https://www.example.com のページのJavaScriptから、S3のバケット(別オリジン)のファイルを読み込んだり直接アップロードしたりする場合は、バケットにCORS設定を書きます。

[
  {
    "AllowedOrigins": ["https://www.example.com"],
    "AllowedMethods": ["GET", "PUT"],
    "AllowedHeaders": ["*"],
    "ExposeHeaders": ["ETag"],
    "MaxAgeSeconds": 3000
  }
]

ブラウザのコンソールに「CORS policy によりブロックされた」というエラーが出る場合は、S3側のCORS設定(許可するオリジン・メソッド)を確認します。CORSはブラウザが行うチェックなので、CLIやサーバーからのアクセスには関係しません。

その他の機能

  • S3 Select:オブジェクト(CSV・JSON)からSQLで必要なデータだけを抽出する機能。2024年に新規の利用受付を終了しており、これから使う場合はAmazon AthenaなどでS3のデータをSQLで分析する。
  • S3 Batch Operations:大量のオブジェクトに対して一括で操作を実行。
  • S3 Transfer Acceleration:クライアントに近いCloudFrontのエッジロケーションでデータを受け取り、AWSのバックボーン経由でバケットに転送して高速化する。バケット単位で有効化。
  • S3 Object Lambda:データの取り出し時にデータを加工する(画像の動的リサイズ、機密データのマスキングなど)。

3. ユースケース

  • 静的ファイル・画像・ログ・バックアップの保存
  • 長期アーカイブ(Glacier系クラス)
  • アップロードをトリガーにしたLambda処理(イベント通知)
  • Athenaでのデータ分析の保存先(データレイク)

4. 料金の考え方

料金はストレージクラスによって大きく変わります。安いクラスほど最低保存期間や取り出しの時間・料金がかかります。

ストレージクラス主用途取り出し速度可用性最低保存期間コスト
Standard頻繁なアクセス即時高なし高
Standard-IA低頻度アクセス即時高30日安
One Zone-IA低頻度+単一AZ即時中30日さらに安
Express One Zone最高性能(ディレクトリバケットを使用)即時中なし保存:高/取得:安
Glacier Instant Retrievalアーカイブだが即時取得即時高90日安
Glacier Flexible Retrieval長期アーカイブ分〜時間高90日非常に安
Glacier Deep Archive超長期保存Standard:12時間/Bulk:48時間高180日最安
Intelligent-Tieringアクセス頻度が不明即時高30日自動最適化
OutpostsOutposts環境即時ローカル依存なし特殊

※ディレクトリバケット:単一AZに保存し、S3 Standardと比べてデータアクセスが10倍高速。

ストレージ料金のほか、リクエスト数やデータ転送(アウト)にも料金がかかります。ゲートウェイ型VPCエンドポイントは無料です。

6. 試験・実務でのポイント

基本・ストレージクラス

  • S3にフォルダは実在しない。キーの先頭部分(プレフィックス)で範囲を指定する。
  • Deep Archiveの取り出しはStandardで12時間、Bulkで48時間。
  • 古いデータを自動で安いクラスへ・自動削除 → ライフサイクルルール。不完全なマルチパートアップロードの中止もここで設定。
  • 遠隔地からのアップロード高速化 → Transfer Acceleration。取り出し時の加工 → Object Lambda。
  • 5GBを超えるファイルのアップロード → マルチパートアップロードが必須(100MB以上で推奨)。

アクセス制御・公開

  • 他アカウントへのアクセス許可 → バケットポリシー+相手側のIAMポリシー。
  • 一時的に外部へ共有 → 署名付きURL。
  • アカウント内のどのバケットも公開させない → アカウント単位のブロックパブリックアクセス。
  • VPCから無料でプライベート接続 → ゲートウェイ型。オンプレミスから → インターフェイス型。
  • 静的サイトをHTTPSで配信 → CloudFrontを前に置く(ウェブサイトエンドポイントはHTTPのみ)。
  • ブラウザから別ドメインのS3にアクセスするとエラー → バケットのCORS設定。

暗号化・データ保護

  • 鍵の利用を監査したい → SSE-KMS。暗号化方式は x-amz-server-side-encryption ヘッダーで指定。
  • 新しいオブジェクトは既定でSSE-S3で暗号化される。KMSを既定にするなら既定の暗号化をSSE-KMSに変え、バケットキーでKMSのコストを抑える。
  • 誤った上書き・削除から戻したい → バージョニング。削除は削除マーカーを消せば復元できる。有効にした後は「停止」しかできない。
  • 誰にも(ルートユーザーでも)削除させない保持 → Object Lockのコンプライアンスモード。特権ユーザーは解除できる → ガバナンスモード。期限なし → リーガルホールド。
  • レプリケーションには両バケットのバージョニングが必須。

イベント

  • イベント通知はGetObjectでは発火しない。
  • S3のイベントをStep Functionsなど多数の送信先へ・細かく絞り込みたい → EventBridgeへの通知を有効にする。

7. まとめ

  • S3はオブジェクトストレージ。ストレージクラスでコストと取り出し速度を選ぶ。
  • 暗号化はSSE-S3/SSE-KMS/SSE-C/クライアントサイドの4種類。
  • アクセス制御はIAMポリシー・バケットポリシー・署名付きURLが中心。
