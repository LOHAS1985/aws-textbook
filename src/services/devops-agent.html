1. サービス概要

AWS DevOps Agentは、経験のあるDevOpsエンジニアのように障害の原因を調べ、対応策を示し、再発防止策を提案する、いつでも動いているAIエージェントです。

アラームやチケットが上がると、すぐに調査を始めます。メトリクス・ログ・トレースなどの監視データ、コード、デプロイの履歴を突き合わせて、原因を絞り込みます。AWSだけでなく、他のクラウドやオンプレミスのアプリにも対応します。

2. 主な機能・特徴

本番運用の機能

機能内容
障害の自動調査アラートやチケットをきっかけに調査を始め、監視データ・コード・デプロイを関連付けて根本原因を特定する
対応策の提示復旧の手順、成功の確かめ方、必要なら変更の戻し方を示す。Kiroなど別のエージェントが実装できる形の指示も出せる
再発防止の提案(評価)過去の障害の傾向を分析し、監視・インフラ・デプロイパイプライン・アプリの回復力の改善点を提案する
連絡の自動化調査の結果や対応の手順を、Slack・ServiceNow・PagerDutyなどに送る
SRE作業の代行自然言語で、リソースの状態の確認やデプロイの追跡などを頼める
AWSサポートとの連携調査の内容を添えて、そのままサポートケースを作れる

このほか、本番に出す前の変更のリスクを確認するリリース管理の機能(リリースの準備状況のレビュー、変更に合わせたテストの自動実行)がプレビューとして提供されています。

しくみ

  • エージェントスペース:エージェントが調べてよい範囲を決める入れ物。AWSアカウント、外部ツールとの連携、アクセス権限をここで設定する。
  • トポロジー:アプリを構成するリソースとその関係を自動で見つけて地図にしたもの。調査のときに使われ、使うほど精度が上がる。
  • 管理者はAWSマネジメントコンソールでエージェントスペースを設定し、運用担当者は専用のWebアプリで調査の結果を見たりエージェントとやり取りしたりする。
  • 連携先:CloudWatch・Datadog・Dynatrace・New Relic・Splunk・Grafana・GitHub・GitLab・Azure DevOps など。MCPサーバーをつないで独自のシステムにも広げられる。
  • スキルとして、自社の手順書(ランブック)や設計の基準を登録できる。

3. ユースケース

  • 深夜のアラームで、担当者が起きる前に調査を進め、原因の候補と対応策をまとめておく
  • 直前のデプロイが原因の障害を特定し、ロールバックの手順を示す
  • 同じような障害が繰り返し起きていないかを分析し、監視やアーキテクチャの改善につなげる

4. 料金の考え方

エージェントが作業(調査・評価・SRE作業)をした時間に応じて秒単位で課金されます。待機中は課金されません。新規の利用者には2か月の無料試用があります。

5. 関連サービス

  • Amazon CloudWatch:アラームと監視データ
  • AWS X-Ray:トレース
  • AWS CodePipeline:デプロイの履歴
  • AWS Health Dashboard:AWS側の障害情報
  • Kiro:提案されたコードの改善の実装
  • AWS Security Agent:セキュリティのためのAIエージェント

6. 試験・実務でのポイント

  • 「障害の根本原因の調査をAIエージェントで自動化」「MTTRの短縮」→ DevOps Agent。
  • 調べる範囲(アカウント・連携先・権限)はエージェントスペースで決める。
  • エージェントは原因と対応策を示す。復旧の判断・操作は運用担当者が行う。
  • メトリクスの異常の検知そのものはCloudWatchのアラームや異常検出で行い、その後の調査をDevOps Agentが担う。

7. まとめ

  • DevOps Agentは、障害の調査・対応策の提示・再発防止の提案を行うAIエージェント。
  • 監視データ・コード・デプロイを突き合わせて、原因の特定を速くする。
