1. サービス概要

AWS Direct Connect(DX)は、オンプレミスのデータセンターとAWSを、インターネットを経由しない専用の回線で接続するサービスです。インターネットの混雑に左右されないため、帯域が安定し、レイテンシーも一定になります。

接続は、AWSが用意しているDirect Connectロケーション(データセンター事業者の施設)で、オンプレミス側の回線とAWSのネットワークをつなぐことで実現します。

2. 主な機能・特徴

接続の種類

種類内容
専用接続(Dedicated)1つの物理ポートを専有する。1/10/100/400Gbps
ホスト型接続(Hosted)Direct Connectパートナーが提供する回線を利用する。50Mbps〜25Gbps。小さい帯域から始められる

開通までに数週間〜数か月かかることがあります。すぐに接続したいときはSite-to-Site VPNを使います。

仮想インターフェイス(VIF)

1本の回線の上に、接続先ごとの論理的なインターフェイスを作ります。

VIF接続先
プライベートVIFVPC(VGWまたはDirect Connectゲートウェイ経由)。プライベートIPで通信する
パブリックVIFS3やDynamoDBなど、パブリックなエンドポイントを持つAWSのサービス
トランジットVIFTransit Gateway(Direct Connectゲートウェイ経由)

Direct Connectゲートウェイ

1つのDirect Connect接続から、複数のリージョン・複数のアカウントのVPC(VGWやTransit Gateway)へ接続するためのグローバルなリソースです。

冗長化

1本の回線だけでは、回線やロケーションの障害で通信が止まります。重要なシステムでは冗長化します。

  • 最大の回復性:2つのロケーションに、それぞれ2本ずつ接続する。
  • 高い回復性:2つのロケーションに、1本ずつ接続する。
  • VPNをバックアップにする:DX1本+Site-to-Site VPN。低コストだが、障害時は帯域が下がる。
  • LAG(リンクアグリゲーショングループ):同じロケーションの複数の接続を束ねて、1本の太い回線として使う。

暗号化

Direct Connectは専用線ですが、標準では通信は暗号化されません。暗号化が必要な場合は次のいずれかを使います。

  • MACsec:対応する専用接続(10/100/400Gbps)で、回線上の通信を暗号化する。
  • DXの上でSite-to-Site VPN:IPsecで暗号化する(パブリックVIF経由、またはTransit GatewayでのプライベートIP VPN)。

3. ユースケース

  • 大量のデータを継続的にオンプレミスとAWSの間で転送する
  • 帯域とレイテンシーが安定している必要がある業務システム(基幹系・金融など)
  • ハイブリッド構成で、データ転送料金を抑えたい

4. 料金の考え方

ポートの時間料金(接続の帯域で決まる)と、AWSから外へのデータ転送(アウト)料金がかかります。DX経由のデータ転送料金はインターネット経由より安く設定されています。ほかに、ロケーションまでの回線費用(通信事業者やパートナーへの支払い)が別にかかります。

5. 関連サービス

  • Amazon VPC:接続先のネットワーク(VGW)
  • AWS Transit Gateway:トランジットVIFで多数のVPCに接続
  • AWS Site-to-Site VPN:DXのバックアップ、DX上での暗号化
  • AWS DataSync:DX経由でのデータ転送
  • Amazon CloudWatch:ConnectionState などで接続の状態を監視

6. 試験・実務でのポイント

  • 「安定した帯域」「一定のレイテンシー」「インターネットを経由しない」→ Direct Connect。「すぐに」「安く」→ Site-to-Site VPN。
  • DXは標準では暗号化されない。暗号化が必要ならMACsecかDX上のVPN。
  • VPCへはプライベートVIF、S3などへはパブリックVIF、Transit GatewayへはトランジットVIF。
  • 複数リージョン・複数アカウントのVPCにつなぐ → Direct Connectゲートウェイ。
  • 低コストで冗長化 → DX+Site-to-Site VPN。高い可用性 → 複数ロケーションでDXを冗長化。
  • 開通まで時間がかかるため、急ぎの要件ではまずVPNを使う。
  • Site-to-Site VPN・Direct Connect・Client VPNの使い分け → オンプレミスとAWSをつなぐ方法の選び方。

7. まとめ

  • オンプレミスとAWSを専用線でつなぎ、安定した帯域とレイテンシーを得る。
  • VIF(プライベート・パブリック・トランジット)で接続先を分ける。
  • DXゲートウェイで複数リージョン・アカウントへ接続できる。
  • 標準では暗号化されない。冗長化(複数ロケーション、VPNのバックアップ)も考える。
