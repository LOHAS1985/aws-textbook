1. サービス概要

Amazon Cognitoは、Web/モバイルアプリに認証・認可の機能を提供するサービスです。「ユーザープール」と「IDプール」の2つの機能があります。

項目ユーザープールIDプール
役割認証(ログイン)認可(一時的なAWS権限の付与)
主な目的ユーザー管理AWSへのアクセス
機能サインアップ、ログイン、MFASTSの一時認証情報の取得
発行するものJWTトークンAWSクレデンシャル
内部連携アプリ認証IAMロール/STS

2. 主な機能・特徴

ユーザープール(ユーザー認証)

  • サインアップ・サインイン(ソーシャルサインイン:Facebook・Googleなど/SAML・OIDC IDプロバイダー経由)
  • ユーザーディレクトリ/プロファイル管理(ログイン情報+ユーザープロファイル+セキュリティ状態)
  • 多要素認証(MFA)などのセキュリティ機能

通常のサインインの流れ

  1. クライアントがユーザー名/メールアドレスとパスワードを送信
  2. Cognitoがユーザーディレクトリを参照
  3. 必要に応じてMFAなどを要求 → 認証成功
  4. トークンを発行(JWT=トークンのフォーマット)
    • IDトークン(JWT):ユーザー情報を含む(認証)
    • アクセストークン(JWT):スコープ・権限情報(認可)。API Gatewayに渡してアクセス可否を判断する
    • リフレッシュトークン(非JWT):ログインを維持する

ソーシャル/SAML/OIDCの流れ:クライアントがCognitoにログインを依頼 → Cognitoが外部IdPへリダイレクト → 外部IdPでログイン → 外部IdPがCognitoに結果を渡す → Cognitoがユーザーを紐付け/新規作成 → トークン発行

IDプール(AWSサービスの利用権限を付与)

  1. クライアントがログインしてトークンを取得
  2. クライアントがIDプールにトークンを渡す
  3. IDプールがトークンを検証(ユーザーを特定)
  4. IDプールがIAMロールを決定し、一時的なAWS資格情報を発行(トークン → AWS資格情報に変換)
  5. クライアントがそのロールでAWSリソースにアクセス

Lambdaトリガー

各処理の前後にLambdaを呼び出せます。

トリガータイミング用途例
Pre Authenticationログイン直前ログイン拒否、追加チェック
Post Authenticationログイン後ログイン履歴の記録など
Pre Sign-upサインアップ前メールドメインの制限、招待制の制御
Post Confirmationユーザー登録完了後初期データ作成、ウェルカムメール、DBユーザー作成
Pre Token Generationトークン発行前トークンにカスタムの属性を追加

3. ユースケース

  • モバイルアプリの会員登録・ログイン(ユーザープール)
  • Googleアカウントでのソーシャルログイン
  • ログインユーザーごとにS3の自分のフォルダ(プレフィックス)だけにアクセスさせる(IDプール+IAMポリシー)
  • API Gatewayの認可(Cognitoオーソライザー)

4. 料金の考え方

ユーザープールは月間アクティブユーザー(MAU)数に応じて課金され、一定数までは無料枠があります。IDプール自体は無料です。

5. 関連サービス

  • Amazon API Gateway:Cognitoオーソライザー
  • AWS STS/AWS IAM:IDプールの一時認証情報
  • Amazon S3:ユーザーごとのプレフィックス制御
  • AWS Lambda:トリガー
  • AWS Amplify:Cognitoを使った認証の組み込み
  • AWS AppSync:GraphQL APIの認証

6. 試験・実務でのポイント

  • ログイン(認証)→ ユーザープール、AWSリソースへの直接アクセス(認可)→ IDプール。
  • API Gatewayに渡すのはアクセストークン(またはIDトークン)。
  • サインアップを特定のメールドメインに制限 → Pre Sign-upトリガー。
  • 登録完了後の初期処理 → Post Confirmationトリガー。

7. まとめ

  • Cognitoはアプリの認証・認可サービス。
  • ユーザープール=ログインとJWT発行、IDプール=AWS資格情報の発行。
  • Lambdaトリガーで認証フローをカスタマイズできる。
