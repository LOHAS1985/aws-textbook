1. サービス概要

Amazon EKS(Elastic Kubernetes Service)は、Kubernetesをマネージドで運用できるサービスです。Kubernetesの頭脳にあたるコントロールプレーンをAWSが管理し、利用者はアプリ(Pod)の実行に集中できます。

2. 主な機能・特徴

基本用語

用語意味
クラスターKubernetes全体のまとまり。コントロールプレーンとノードで構成される
ノードPodを実行するサーバー。EKSではEC2インスタンス、またはFargate
PodKubernetesの最小のデプロイ単位。1つ以上のコンテナをまとめたもの。同じPod内のコンテナはIPアドレスとストレージを共有する
コンテナアプリケーションの実行単位。イメージ(ECRなどに保存)から起動される
名前空間(Namespace)クラスター内のリソースを論理的に分ける区画。環境やチームごとの分離に使う
マニフェストリソースの望ましい状態を書いたYAMLファイル。kubectl apply -f で適用する
etcdクラスターの状態(Pod/Deployment/Serviceの一覧、レプリカ数、イメージ、ConfigMap、Secret、ノード情報など)を保存するデータベース

アーキテクチャ

層内容管理者
コントロールプレーンAPIサーバー、etcdなど。複数AZに分散して配置されるAWS
データプレーンPodが動くコンピューティング(EC2またはFargate)利用者(Auto ModeではAWSが一部管理)

コントロールプレーンはAWSが管理するVPCに配置され、利用者のVPCとはENI経由で接続されます。

データプレーンの選択肢

種類概要向いているケース
マネージド型ノードグループノード(EC2)のプロビジョニングとライフサイクル管理をEKSが自動化標準的な運用。ノードの更新を楽にしたい
セルフマネージド型ノードEC2を自分で構築・管理AMIやノード構成を細かく制御したい
AWS FargateサーバーレスでPodを実行。ノード管理が不要ノード運用を避けたい
EKS Auto Modeノードの管理や一部のアドオンまでAWSに任せる運用負荷を最小限にしたい

Fargateの注意点:Fargateプロファイルで、Fargateで動かすPod(名前空間やラベル)を指定します。Podはプライベートサブネットで実行され、DaemonSetは使えず、特権コンテナも実行できません。

ネットワーク

  • Amazon VPC CNIプラグインにより、PodにはVPCのプライベートIPアドレスが割り当てられる。
  • Podが多いとサブネットのIPアドレスが枯渇しやすい。サブネットのサイズやCIDRの設計に注意する。
クラスターエンドポイントの設定動作
パブリックのみインターネットからAPIサーバーに接続できる(アクセス元のCIDRを制限可能)
パブリックとプライベートVPC内からはプライベート経由、外部からはパブリック経由で接続できる
プライベートのみVPC内(VPNやDirect Connectを含む)からのみ接続できる

認証と認可

  • 認証はIAMで行い、クラスター内での認可はKubernetesのRBACで決まる。IAMの権限があっても、クラスター側で許可されていなければ操作できない。
  • IAMプリンシパルとクラスター権限の対応付けには、アクセスエントリ(推奨)か、従来の aws-auth ConfigMapを使う。
Podに AWSの権限を与える方法概要
IRSA(IAM Roles for Service Accounts)OIDCプロバイダーを使い、サービスアカウントにIAMロールを紐付ける
EKS Pod Identityより簡単な設定で、PodにIAMロールを割り当てる

ノードのIAMロールに広い権限を付けるのではなく、Pod単位で最小権限を与えます。

kubectl

Kubernetesを操作するためのコマンドラインツールです。

  • kubectl get pods:Podの一覧を見る
  • kubectl apply -f app.yaml:YAMLの内容をクラスターに反映する
  • kubectl logs <Pod名>:ログを見る

ロードバランシング

AWS Load Balancer Controllerを導入すると、KubernetesのリソースからAWSのロードバランサーを作成できます。

Kubernetesのリソース作成されるロードバランサー
IngressALB
ServiceNLB

ストレージ

  • EBS CSIドライバー:EBSボリュームをPodの永続ボリュームとして使う。単一AZに紐付く。
  • EFS CSIドライバー:複数Pod・複数AZから共有できるファイルストレージとして使う。
  • CSIドライバーはEKSアドオンとして導入する。

3. ユースケース

  • 既存のKubernetes資産(マニフェスト・ツール)をAWSで動かしたい
  • マルチクラウドやオンプレミスとKubernetesで運用を揃えたい
  • 多数のマイクロサービスを名前空間で分けて運用したい

4. 料金の考え方

料金はクラスターごとの時間課金と、データプレーンのコンピューティング料金(EC2またはFargate)で構成されます。

5. 関連サービス

  • Amazon ECS:AWS独自のコンテナオーケストレーション
  • Amazon ECR:コンテナイメージの保存先
  • AWS IAM:クラスターの認証、IRSA/Pod Identity
  • Elastic Load Balancing:Ingress→ALB、Service→NLB
  • Amazon EBS/Amazon EFS:永続ボリューム
  • Amazon VPC:Pod IPの割り当て元

6. 試験・実務でのポイント

  • Podに権限を渡す → IRSAまたはEKS Pod Identity(ノードロールに広い権限を付けない)。
  • IAMで認証できても、RBAC/アクセスエントリで許可されていないと操作できない。
  • Podが増えてIPが足りない → VPC CNIの仕様。サブネットのCIDR設計を見直す。
  • FargateではDaemonSet・特権コンテナが使えない。
  • 複数AZのPodで共有したい → EFS CSIドライバー。EBSは単一AZ。
  • APIサーバーをVPC内からだけ使わせたい → エンドポイントをプライベートのみに。

7. まとめ

  • EKSはコントロールプレーンをAWSが管理するKubernetesサービス。
  • データプレーンはマネージド型ノードグループ/セルフマネージド/Fargate/Auto Modeから選ぶ。
  • 認証はIAM、認可はRBAC。Podの権限はIRSAかPod Identityで最小権限に。
