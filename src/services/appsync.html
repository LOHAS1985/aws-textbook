1. サービス概要

AWS AppSyncは、GraphQL APIを提供するマネージドサービスです。

通常のREST APIでは、例えば id: 1, name: aaa, email: a@ex.com のように、nameだけ欲しいのに不要な情報も返ってきます。必要な項目だけを取得したいときにGraphQLを使います。

2. 主な機能・特徴

  • クライアントが必要な項目だけを指定して取得できる(GraphQL)。
  • スキーマでデータの型を定義し、リゾルバーで各フィールドをデータソース(DynamoDB、Lambda、Aurora Serverless、Amazon OpenSearch Service、HTTPエンドポイントなど)に結びつける。
  • 操作は Query(取得)、Mutation(更新)、Subscription(リアルタイム通知)の3種類。
  • 認証はAPIキー、IAM、Cognitoユーザープール、OIDC、Lambdaに対応。

リクエストの流れとリゾルバー

クライアントがGraphQLのクエリを送ると、AppSyncはスキーマに従って、フィールドごとにリゾルバーを実行します。リゾルバーは、リクエストをデータソースへの操作に変換し、結果をGraphQLの応答の形に整えます。1つのデータソースへの操作を行うユニットリゾルバーと、複数の処理を順番につなぐパイプラインリゾルバーの2種類があります。

リゾルバーの処理は、公式ドキュメントでは現在 APPSYNC_JS ランタイム(JavaScript)で書くことが案内されています。

リアルタイム更新(Subscription)

クライアントはWebSocketでAppSyncに接続し、subscriptionを登録して待ちます。どのMutationの実行で通知するかは、スキーマの @aws_subscribe(mutations: [...]) で指定します。Mutation(例:sendMessage)が実行されると、AppSyncが購読中のクライアントに変更を送ります。1本のWebSocket接続で複数の購読を扱えます。

2025年3月からは、GraphQLのQuery・Mutation・Subscriptionとは別に、WebSocketでイベントを配信するAppSync Eventsも提供されています。

認証の設定

APIごとに既定の認証方式を1つ決め、必要に応じて追加の認証方式を組み合わせられます。

  • APIキー:認証なしのAPIの呼び出し回数(スロットリング)を制御する簡易な方式。
  • IAM:IAMユーザーやロールの認証情報で署名したリクエスト(SigV4)で認証する。用語ページ「IAMロールと一時的な認証情報」を参照してください。
  • Amazon Cognitoユーザープール・OIDC:ログインしたユーザーのトークンで認証する。OIDCは用語ページ「OIDC(OpenID Connect)」を参照してください。
  • Lambda:独自の認可ロジックをLambda関数で実装する。

キャッシュとWAF

APIごとに専用のキャッシュを有効にすると、クエリや更新の応答を速くできます。キャッシュはインスタンスタイプを選び、時間単位で課金されます。AWS WAFのWebACLをAPIに関連付けると、ルールに基づいて不正なリクエストを遮断できます。

制限

  • APIキーの有効期限は最長365日(延長も可能)。開発用や、公開しても安全なAPIに向く方式とされている。
  • Lambda認可は、1つのAPIにつき1つだけ設定できる。Lambda関数がリゾルバーに渡すコンテキストデータは5MBまで。
  • リアルタイム更新を受け取るには、クライアントが接続を維持しておく必要がある。

3. ユースケース

  • モバイルアプリで通信量を減らすため、必要なデータだけを取得
  • チャットやダッシュボードなどのリアルタイム更新(Subscription)
  • 複数のデータソースを1つのAPIにまとめる

4. 料金の考え方

クエリ・Mutationの実行回数と、リアルタイム更新のメッセージ数・接続時間に応じて課金されます。専用キャッシュを使う場合は、選んだインスタンスの時間料金が加わります。データ転送料金は、EC2のデータ転送と同じ料金体系です。

5. 関連サービス

  • Amazon API Gateway:REST/HTTP/WebSocket API
  • Amazon DynamoDB/AWS Lambda/Amazon Aurora:代表的なデータソース
  • Amazon OpenSearch Service:検索用のデータソース
  • Amazon Cognito:ユーザー認証
  • AWS WAF:APIへの不正なリクエストの遮断
  • AWS Amplify:AppSyncを使ったアプリ開発
  • 関連する用語:マネージドサービスとサーバーレス、キャッシュの選び方

6. 試験・実務でのポイント

  • 「GraphQL」「必要な項目だけ取得」→ AppSync。REST API → API Gateway。
  • リアルタイムのデータ同期・チャットの更新 → AppSyncのSubscription(WebSocket)。
  • 複数のデータソース(DynamoDB・Lambda・Aurora・OpenSearch)を1つのAPIにまとめる → リゾルバーで各フィールドをデータソースに結びつける。
  • Cognitoユーザープール・OIDC・IAMで利用者を認証する → 既定または追加の認証方式として設定する。
  • 開発用や公開APIの簡易な認証 → APIキー(有効期限は最長365日)。
  • APIへの不正なリクエストを遮断したい → AWS WAFのWebACLを関連付ける。
  • 同じクエリが多く、応答を速くしたい → APIごとの専用キャッシュ(時間単位の料金がかかる)。

7. まとめ

  • AppSyncはGraphQL APIのマネージドサービス。必要なデータだけを効率よく取得できる。
