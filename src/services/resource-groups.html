1. サービス概要

AWS Resource Groupsは、タグやCloudFormationのスタックを条件に、リソースをグループにまとめるサービスです。同じ条件のリソースを一覧にしたり、Systems Managerなどの操作の対象にしたりできます。

Tag Editorは、リージョンを指定してリソースを検索し、選んだ複数のリソースにタグをまとめて付ける・変える・外すための機能です。グループの条件になるタグは、まずTag Editorで付けておきます。

2. 主な機能・特徴

グループの種類

種類条件の決め方例
タグベース(TAG_FILTERS_1_0)リソースの種類(例: AWS::EC2::Instance)と、タグのキー・値で絞る。種類に AWS::AllSupported を指定すると、対応するすべての種類が対象になるStage=Test のEC2インスタンスとS3バケット
CloudFormationスタックベース現在のリージョンにある1つのスタックを選び、その中からリソースの種類で絞るスタック「web-prod」のEC2インスタンスとEBSボリューム
  • タグベースのグループには、条件に合うリソースが自動で入る。タグを付けたり外したりすると、メンバーが変わる。
  • スタックベースのグループは、1つのスタックだけを元にする。親スタックのグループには、子スタックが1つのメンバーとして入り、子スタックの中のリソースは展開されない。

Tag Editor

  • 検索:リソースの種類、タグのキーと値、リージョンで絞り込み、対象のリソースの一覧を作る。
  • 一括のタグ付け:一覧で選んだリソースに、キーと値をまとめて付ける。1つのリソースに付けられるタグは最大50個。
  • 対応範囲:Tag Editorとグループで扱えるリソースの種類は、サービスごとに異なる。対応していないサービスのリソースは、そのサービス独自のタグ操作を使う(例: aws iam tag-role)。
  • タグポリシーの準拠レポート:AWS Organizationsのタグポリシーに、各リソースが準拠しているかを報告させられる(Tagging APIの StartReportCreation)。

APIで使う

Resource Groupsには2つのAPIがあり、役割が違います。

API主な操作用途
Resource Groups APICreateGroup、SearchResources などグループの作成・更新・削除、グループへのタグ付け、クエリによるリソースの検索
Resource Groups Tagging APIGetResources、TagResources、UntagResources、GetTagKeys、GetTagValuesリソースのタグの検索・付与・削除。タグの一覧や値の一覧の取得
  • TagResourcesは、1回の呼び出しで最大20個のARNにタグを付けられる。
  • GetResourcesは、1回に指定できるARNが最大100個。結果はページ単位で返り、呼び出しの回数にはレート制限がある。
  • Tagging APIは、指定したリージョンのリソースだけを対象にする。

3. ユースケース

  • 本番環境のすべてのリソースに Environment=prod のタグを付け、そのタグで一覧を作る
  • 既存の多数のリソースに、部署のタグをTag Editorで一括で付ける
  • タグで作ったグループを対象に、Systems ManagerのRun CommandやAutomationで一括の操作を行う
  • CloudFormationのスタックごとにリソースをまとめて、スタックの単位で確認する

4. 料金の考え方

リソースグループとTag Editorの機能そのものに、単独の料金は設定されていません。料金は、タグを付けたリソース(EC2やS3など)の料金として発生します。タグは費用の集計にも使えます。コスト配分タグとして有効化すると、Cost Explorerでタグごとの費用を確認できます。

5. 関連サービス

  • AWS Systems Manager:リソースグループを対象に、Run CommandやAutomationを実行する
  • AWS CloudFormation:スタックベースのグループの元になるスタック
  • AWS Organizations:タグポリシーと、タグの準拠レポート
  • AWS Config:リソースの構成とタグの変更を記録する
  • AWS Backup:タグを条件に、バックアップの対象のリソースを指定する
  • AWS Cost Explorer:コスト配分タグで、タグごとの費用を分析する
  • AWS IAM:タグを条件にして、アクセスを許可・拒否する
  • 関連する用語:タグ

6. 試験・実務でのポイント

グループの作り方

  • 「タグの値で同じ役割のリソースをまとめたい」→ タグベースのリソースグループ。
  • 「CloudFormationのスタックごとにまとめたい」→ CloudFormationスタックベース(1つのスタック・現在のリージョンだけ)。
  • 親スタックのグループには、子スタックのリソースは入らない(子スタックが1つのメンバーとして入る)。

タグ付け

  • 既存のリソースに、まとめて同じタグを付ける → Tag Editor。
  • APIで一括で付ける → TagResources(1回の呼び出しで最大20個のARN)。
  • Tagging APIはリージョンごとに動く。別のリージョンのリソースは、そのリージョンを指定して操作する。
  • 対応していないサービスのリソースは、Tag Editorやグループの対象外。そのサービスのタグ操作を使う。

検索・監査

  • タグのキーや値の一覧を調べる → GetTagKeys・GetTagValues。
  • タグのルールを守れているかを確認する → Organizationsのタグポリシーと、準拠レポート(StartReportCreation)。

SOA-C03での位置づけ

  • タグで対象を指定して、Systems Managerなどで一括で操作する運用の基礎として扱う。

7. まとめ

  • AWS Resource Groupsは、タグかCloudFormationスタックを条件に、リソースをグループにまとめるサービス。
  • Tag Editorで既存のリソースに一括でタグを付け、そのタグを条件にグループを作る。
  • グループ用のResource Groups APIと、タグ用のResource Groups Tagging APIを使い分ける。
