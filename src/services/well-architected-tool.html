1. サービス概要

AWS Well-Architected Toolは、ワークロードの設計をAWS Well-Architected Frameworkに沿って評価し、リスクや改善計画を記録するサービスです。フレームワークの質問に答え、レンズやマイルストーンを使ってレビューを継続できます。

Well-Architected Toolはガイド付きの自己レビューを行うサービスです。AWS Well-Architected Agentのように、環境を自動分析して修正案を生成するものとは役割が異なります。

2. 主な機能・特徴

ワークロードのレビュー

  • ワークロード:業務価値を提供するシステムを登録し、レビュー対象をまとめる。
  • レンズ:AWS Well-Architected Frameworkや、業界・技術領域ごとの追加質問を使って評価する。
  • リスク:回答から高リスク・中リスクの項目を特定し、改善の優先順位を付ける。
  • マイルストーン:レビューの時点を保存し、改善前後を比較する。

フレームワークとの違い

AWS Well-Architected Frameworkは設計のベストプラクティス、Well-Architected Toolは質問への回答・レビュー記録・改善追跡のためのサービスです。Toolがワークロードの設定を自動変更するわけではありません。

3. ユースケース

  • データパイプラインやデータレイクの設計を、運用・セキュリティ・信頼性の観点で見直す。
  • 複数チームのレビューと改善計画を記録する。
  • 新しい構成や移行後のワークロードを定期的に評価する。

4. 料金の考え方

Well-Architected Tool自体は追加料金なしで利用できます。レビュー対象のAWSリソースや、改善で利用する各サービスにはそれぞれの料金が発生します。

5. 関連サービス

  • AWS Well-Architected フレームワーク:レビューの設計原則
  • AWS Trusted Advisor:ベストプラクティスに基づく自動チェック
  • Amazon CloudWatch:運用状態の監視
  • AWS Systems Manager:運用作業の自動化
  • 関連する用語:DEA-C01の学習範囲

6. 試験・実務でのポイント

  • 設計レビューの質問・リスク・改善計画を記録 → AWS Well-Architected Tool。
  • フレームワークはベストプラクティス、Toolはレビューと改善追跡を支援するサービス。
  • レビュー結果を基に実際の設定変更や運用改善を行うのは利用者の責任。

7. まとめ

  • Well-Architected Toolはワークロードの設計レビューと改善追跡を支援する。
  • 自動修復サービスではなく、フレームワークに沿った継続的な評価に使う。
