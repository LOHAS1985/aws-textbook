1. サービス概要

Amazon Application Recovery Controller(ARC)は、AZやリージョンに障害が起きたときに、アプリケーションの通信を正常なAZ・リージョンへ切り替えて、すばやく復旧するためのサービスです。旧称は Route 53 Application Recovery Controller です。

機能は、1つのAZの障害に備える「マルチAZの復旧」と、リージョンの障害に備える「マルチリージョンの復旧」の2つに分かれます。

2. 主な機能・特徴

分類機能内容
マルチAZゾーンシフト障害が起きたAZから、同じリージョンの正常なAZへ通信を手動で一時的に移す
ゾーンオートシフトAWSがAZの障害を検知すると、AWSが自動で通信を移す
マルチリージョンリージョンスイッチ複数アカウントにまたがるリソースのリージョン切り替えを、計画(プラン)として自動で実行する
ルーティングコントロールDNSのレコードを、オン/オフのスイッチで切り替えてリージョンをフェイルオーバーする
準備状況チェック切り替え先のクォータ・容量・ルーティングの設定を監視する(新規の利用受付は終了)

ゾーンシフトとゾーンオートシフト

  • 対象は、ALB・NLB(クロスゾーン負荷分散の有効・無効を問わない)、EC2 Auto Scalingグループ、EKS。シフトしたいAZと同じリージョンで開始する。
  • ゾーンシフトは手動で開始し、最長3日の有効期限(延長可)を付ける。悪いデプロイが1つのAZにだけ入った場合などにも使える。
  • ゾーンオートシフトを有効にするときは、残りのAZで全負荷をまかなえる容量を事前に用意しておく。AWSは定期的に練習の実行(実際にAZから通信を移す)を行い、移しても問題ないことを確かめる。

ルーティングコントロール

Route 53 のヘルスチェックと組み合わせ、ルーティングコントロールの状態(オン/オフ)でDNSの応答を切り替えます。5つのリージョンにまたがるクラスターで動いており、障害時でも確実に操作できるように作られています。安全ルールで「必ずどちらか一方だけをオンにする」といった誤操作の防止ができます。

リージョンスイッチ

EC2 Auto Scalingの容量の拡張、Auroraグローバルデータベースの切り替え、DNSの切り替えなど、リージョンを切り替える手順をプランとして定義しておき、障害時にまとめて実行します。実行の進み具合を確認でき、練習の実行もできます。

3. ユースケース

  • 1つのAZだけでエラー率が上がったときに、そのAZを切り離して影響を減らす
  • AZの障害時に、利用者が操作しなくても自動で正常なAZだけで動かす(ゾーンオートシフト)
  • アクティブ/スタンバイ構成の複数リージョンのアプリを、確実な手順でフェイルオーバーする

4. 料金の考え方

ゾーンシフトとゾーンオートシフトは追加料金なしで使えます。ルーティングコントロールはクラスターの時間料金、リージョンスイッチはプランの数に応じた料金がかかります。

5. 関連サービス

  • Elastic Load Balancing/Amazon EC2 Auto Scaling:ゾーンシフトの対象
  • Amazon Route 53:DNSのフェイルオーバー
  • Amazon Aurora:グローバルデータベースの切り替え
  • DR戦略/リージョンとAZ
  • マルチリージョンのフェイルオーバー(ユースケース)

6. 試験・実務でのポイント

  • 「1つのAZの障害から通信を一時的に移す」→ ゾーンシフト。AWSに自動で任せる → ゾーンオートシフト。
  • ゾーンオートシフトの前提は、残りのAZで処理しきれる容量を事前に確保しておくこと。
  • ゾーンシフトの対象は ALB・NLB・EC2 Auto Scalingグループ・EKS。
  • リージョンの切り替えを確実・自動で → ルーティングコントロール/リージョンスイッチ。

7. まとめ

  • ARCは、AZやリージョンの障害時に通信を切り替えて復旧するためのサービス。
  • マルチAZはゾーンシフト/オートシフト、マルチリージョンはリージョンスイッチ/ルーティングコントロール。
