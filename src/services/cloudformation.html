1. サービス概要

AWS CloudFormationは、AWSリソースをコード(テンプレート)として定義し、自動で構築・管理するサービスです(Infrastructure as Code)。

2. 主な機能・特徴

構成要素

  • テンプレート:インフラの設計図(YAML/JSON形式)
  • スタック:テンプレートから作られるリソースの集合(環境そのもののイメージ)
  • ネストスタック:スタックを入れ子構造にする

主な機能

  • 構文の拡張:サーバーレス用に AWS SAM がある。
  • Transformセクション:デプロイ前にテンプレートを別のテンプレートへ変換する。例:Transform: AWS::Serverless-2016-10-31(SAM)
  • カスタムリソース:実行時の独自処理を作成(ほとんどの場合Lambdaを使う)。例:RDSのDBユーザー作成、Slack通知のWebhook登録
  • DeletionPolicy:リソース削除時の扱い。Delete(削除する。デフォルト)/Retain(残す)/Snapshot(スナップショットを取ってから削除)
  • NoEcho:機密情報を画面・ログに表示しない
  • 変更セット:実行中のリソースに変更がどう影響するか(追加・変更・置き換え・削除)を事前に確認する。
  • Lambdaのコード更新の注意:Lambdaのコードを S3Bucket/S3Key で指定している場合、S3上のファイルを同じキーで上書きしただけでは、テンプレートに変化がないためCloudFormationはコードの変更を検知しない。S3のキー(ファイル名)か S3ObjectVersion を変えて更新する。
  • ドリフト検出:テンプレート(理想の状態)と実際のリソースのズレを検出
  • スタックポリシー:スタック更新時に特定のリソースの変更を禁止する
  • ダイナミックリファレンス:テンプレート内でSecrets Manager/Parameter Storeの値を実行時に参照し、秘密情報を直書きしない。記述は {{resolve:xxxx:...}}。xxxxは ssm(Parameter Store)、ssm-secure(SecureString)、secretsmanager(Secrets Manager)。
  • StackSets:複数のAWSアカウント・リージョンへスタックを一括展開する

AWS CLIのコマンドとオプション

コマンド内容
create-stack新規作成
update-stack更新
delete-stack削除
describe-stacks状態確認
deploy作成/更新

主なオプション:--template-file(テンプレート指定)、--stack-name(スタック名)、--parameter-overrides(パラメータ上書き)、--capabilities(IAMリソース作成の許可)、--tags、--region、--role-arn(実行ロール)、--disable-rollback(ロールバック無効)

テンプレートの例(S3バケットの作成)

  • Parameters:パラメータ(バケット名、バージョニングのON/OFF。AllowedValues で値の候補を限定)
  • Resources:本体(Properties で設定)
  • Conditions:条件分岐
  • Outputs:外部へ返す情報(!Ref などの組み込み関数で値を取得)
AWSTemplateFormatVersion: '2010-09-09'
Description: Create an S3 bucket with parameters and outputs

Parameters:
  BucketName:
    Type: String
  VersioningEnabled:
    Type: String
    AllowedValues: [true, false]
    Default: false

Conditions:
  EnableVersioning: !Equals [ !Ref VersioningEnabled, true ]

Resources:
  MyS3Bucket:
    Type: AWS::S3::Bucket
    Properties:
      BucketName: !Ref BucketName
      VersioningConfiguration:
        Status: !If [ EnableVersioning, Enabled, Suspended ]

Outputs:
  BucketNameOutput:
    Value: !Ref MyS3Bucket
  BucketURL:
    Value: !Sub "https://${MyS3Bucket}.s3.amazonaws.com"

3. ユースケース

  • 開発・ステージング・本番で同じ構成の環境を再現
  • 複数アカウントへ共通のセキュリティ設定を展開(StackSets)
  • 本番のDBを誤って削除しないよう保護(DeletionPolicy: Retain/Snapshot、スタックポリシー)

4. 料金の考え方

CloudFormation自体は(AWSリソースを扱う範囲では)無料です。作成されたリソースに料金がかかります。

5. 関連サービス

  • AWS CDK:プログラミング言語で書いてCloudFormationに変換
  • AWS SAM:サーバーレス向けの拡張
  • AWS Secrets Manager/Parameter Store:ダイナミックリファレンス
  • AWS Lambda:カスタムリソース
  • AWS Service Catalog:テンプレートを製品として配布
  • AWS CodePipeline:CI/CDでのデプロイ

6. 試験・実務でのポイント

  • スタック削除時にリソースを残す → DeletionPolicy: Retain(デフォルトはDelete)。
  • パスワードを直書きしない → ダイナミックリファレンス/NoEcho。
  • 変更の影響を事前確認 → 変更セット。手動変更によるズレ → ドリフト検出。
  • 複数アカウント・リージョンへ展開 → StackSets。
  • IAMリソースを作るテンプレート → --capabilities CAPABILITY_IAM が必要。
  • Lambdaのコードを更新したのに反映されない → S3キーかVersionIdを変える。

7. まとめ

  • CloudFormationはテンプレートからスタックを作るIaCサービス。
  • DeletionPolicy・変更セット・ドリフト検出・スタックポリシーで安全に運用する。
  • 秘密情報はダイナミックリファレンス、マルチアカウントはStackSets。
