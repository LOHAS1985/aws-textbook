1. サービス概要

AWS KMS(Key Management Service)は、データの暗号化に使う暗号化キーを安全に作成・管理・使用できるサービスです。S3・EBS・RDSなど多くのAWSサービスの暗号化に使われます。

2. 主な機能・特徴

キーの種類

  • KMSキー:データキーを生成・暗号化する、KMSの中で管理されるキー。以前はCMK(カスタマーマスターキー)と呼ばれていたため、古い資料ではこの名前で出てくる。
  • データキー:実データを暗号化する。
  • HMACキー:改ざん検知用の鍵。

暗号化の流れ(エンベロープ暗号化)

  1. アプリがKMSにデータキーの生成をリクエスト(GenerateDataKey API)
  2. KMSがデータキーを生成し、KMSキーでそのデータキーを暗号化
  3. KMSが平文のデータキーと暗号化されたデータキーをアプリに渡す
  4. アプリが平文のデータキーでデータを暗号化し、平文のデータキーは破棄
  5. 暗号化データと暗号化データキーを一緒に保存

※小さなデータ(4KBまで)は、KMSの Encrypt API で直接暗号化します。

復号の流れ

  1. アプリが保存先から暗号化データと暗号化データキーを取得
  2. アプリがKMSに復号をリクエスト(Decrypt API。入力=暗号化データキー)
  3. KMSがKMSキーで暗号化データキーを復号し、平文のデータキーを返す
  4. アプリが平文のデータキーでデータを復号し、平文のデータキーは破棄

キーポリシーとIAMポリシー

KMSキーへのアクセスは、キーポリシー(キーに付けるリソースベースのポリシー)で決まります。すべてのKMSキーには、必ず1つのキーポリシーがあります。ほかのサービスと違い、キーポリシーで許可していないと、IAMポリシーで許可しても使えません。

  • 既定のキーポリシーには、アカウント(ルート)を許可する文が入っている。これがあると、そのアカウントのIAMポリシーでキーの権限を与えられるようになる。
  • キーポリシーでは、キーを管理する人(キーの管理者:削除の予定・ポリシーの変更など)と、キーを使う人(キーのユーザー:Encrypt・Decrypt・GenerateDataKey)を分けて許可する。
  • 条件キー kms:ViaService を使うと、「S3を通したときだけ復号を許可する」のように、使えるサービスを絞れる。
  • グラント:キーポリシーを変えずに、特定のプリンシパルに一時的に権限を渡す仕組み。EBSやRDSなどのAWSサービスが、暗号化したボリュームを使うときに内部で使う。

別アカウントでの利用

別アカウントにキーを使わせるには、両方のアカウントで許可が必要です。

AWSマネージドキーはキーポリシーを変えられないため、別アカウントでは使えません。暗号化したEBSスナップショットやRDSスナップショットを別アカウントと共有するときは、カスタマーマネージドキーで暗号化しておきます。

キーのローテーション

  • カスタマーマネージドキー(対称キー)は、自動ローテーションを有効にすると、決めた間隔(90日〜2560日。既定は365日)でキーの中身(キーマテリアル)が新しくなる。すぐにローテーションすることもできる。
  • ローテーションしても、キーIDとARNは変わらず、古いキーマテリアルも残るため、以前に暗号化したデータはそのまま復号できる。アプリの変更はいらない。
  • AWSマネージドキーは、毎年自動でローテーションされる。
  • 自分で用意したキーマテリアルをインポートしたキーは自動ローテーションできない。新しいキーを作り、エイリアス(キーの別名)の向き先を変える手動ローテーションを行う。

キーの無効化と削除

カスタマーマネージドキーはすぐには削除できず、7〜30日(既定は30日)の待機期間を指定して削除を予定します。待機期間中は取り消せます。削除すると、そのキーで暗号化したデータは二度と復号できません。

  • まだ使われているか分からないときは、先にキーを無効化して様子を見る(無効化はいつでも元に戻せる)。
  • 削除の待機中のキーを使おうとした操作はCloudTrailに記録されるので、CloudWatchのメトリクスフィルターとアラームで検知できる。

マルチリージョンキー

マルチリージョンキーは、同じキーマテリアルとキーIDを持つキーを、複数のリージョンに置く仕組みです。あるリージョンで暗号化したデータを、別のリージョンでそのまま復号できます。DRで別リージョンにコピーしたデータを復号したい場合や、複数のリージョンでクライアント側の暗号化をする場合に使います。通常のKMSキーは、作ったリージョンの外では使えません。

リクエストの上限

KMSのAPIには、1秒あたりのリクエスト数の上限があります。超えると ThrottlingException になります。S3のSSE-KMSで大量のオブジェクトを読み書きすると上限に達しやすいため、S3バケットキーを有効にして、KMSへのリクエストを減らします(料金も下がります)。それでも足りなければ、Service Quotasで上限の引き上げを申請します。

キーの保管場所

キーマテリアルは通常、KMSのハードウェアセキュリティモジュール(HSM)の中で作られ、外に出ることはありません。規制のために専用のHSMが必要な場合は、CloudHSMのクラスターを使うカスタムキーストアや、AWSの外のキー管理システムを使う外部キーストアも選べます。

3. ユースケース

  • S3(SSE-KMS)・EBS・RDSなどの保存データの暗号化
  • アプリでの大きなデータのエンベロープ暗号化
  • 別アカウントと暗号化データを共有(カスタマー管理キー+キーポリシー)

4. 料金の考え方

AWS所有キーは無料、AWS管理キーは利用料(APIリクエスト)のみ、カスタマー管理キーはキーごとの月額料金+利用料がかかります。マルチリージョンキーは、リージョンごとのキーにそれぞれ月額料金がかかります。S3バケットキーを使うと、KMSへのリクエストが減り、利用料を下げられます。

5. 関連サービス

  • Amazon S3/Amazon EBS/Amazon RDS:KMSで暗号化するサービス
  • AWS Secrets Manager:シークレットをKMSで暗号化
  • AWS CloudTrail:キー利用の監査ログ
  • AWS IAM:kms:Decrypt などの権限
  • AWS Database Encryption SDK:KMSを使ったクライアント側暗号化
  • 関連する用語:保存時の暗号化と転送時の暗号化

6. 試験・実務でのポイント

キーと権限

  • 大きなデータ → GenerateDataKey でエンベロープ暗号化。4KB以下 → Encrypt。
  • キーポリシーの編集・クロスアカウント共有・キーの無効化が必要 → カスタマー管理キー。
  • IAMで許可したのにキーを使えない → キーポリシーで許可されているか確認する。
  • 別アカウントで使う → キーを持つ側のキーポリシーと、使う側のIAMポリシーの両方で許可する。
  • 復号には kms:Decrypt 権限が必要(S3のSSE-KMSオブジェクトの取得でも必要)。

運用

  • 自動ローテーションは対称キーのみ。ローテーションしてもキーIDは変わらず、古いデータも復号できる。
  • インポートしたキーマテリアルのローテーション → 新しいキーを作り、エイリアスを付け替える。
  • キーをすぐには消せない → 削除は7〜30日の待機期間のあと。迷ったら先に無効化。
  • 別リージョンで同じキーで復号したい → マルチリージョンキー。
  • SSE-KMSで ThrottlingException → S3バケットキーでKMSへのリクエストを減らす。
  • Secrets Manager・Parameter Store・AppConfig・KMSの使い分け → 機密情報・設定値の保存先の選び方。

7. まとめ

  • KMSは暗号化キーの管理サービス。キーはAWS所有・AWS管理・カスタマー管理の3種類。
  • KMSキーでデータキーを暗号化し、データキーで実データを暗号化する(エンベロープ暗号化)。
  • アクセスはキーポリシーが基本。別アカウントではキーポリシーとIAMポリシーの両方で許可する。
  • ローテーション・削除の待機期間・マルチリージョンキー・リクエストの上限を押さえる。
