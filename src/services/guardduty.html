1. サービス概要

Amazon GuardDutyは、AWSアカウント内のログやイベントを継続的に分析し、不正アクセス・認証情報の漏えい・マルウェア・暗号資産のマイニングなどの脅威を検出するサービスです。

悪意のあるIPアドレスやドメインのリスト(脅威インテリジェンス)と機械学習を使って、ふだんと違う怪しい動きを見つけます。エージェントのインストールやログの収集設定は不要で、有効化するだけで分析が始まります。

2. 主な機能・特徴

基本の分析対象(基盤データソース)

有効化すると、次の3つのログを自動で分析します。利用者が CloudTrail の証跡やフローログを作成しておく必要はありません(GuardDuty が独自に取得します)。

データソース見つけられる脅威の例
CloudTrail 管理イベントふだん使わない国からのAPI呼び出し、CloudTrailの停止、漏えいした認証情報の利用
VPCフローログ悪意のあるIPアドレスとの通信、ポートスキャン、EC2からの大量送信
DNSログマルウェアの指令サーバーや、マイニング用ドメインへの問い合わせ

保護プラン(追加で有効化する分析対象)

保護プラン分析するもの
S3 ProtectionS3のデータイベント(オブジェクトの取得・削除など)
EKS ProtectionEKSの監査ログ
Runtime MonitoringEC2・ECS(Fargate含む)・EKS上のOSレベルの動き(プロセス・ファイル・通信)。専用のセキュリティエージェントを使う
Malware Protection for EC2怪しい動きがあったEC2のEBSボリュームをスキャン
Malware Protection for S3S3に新しくアップロードされたファイルをスキャン
RDS ProtectionAurora・RDSへのログインの異常
Lambda ProtectionLambda関数のネットワーク通信

初めて有効化したときは、Runtime Monitoring 以外の保護プランが自動で有効になり、30日間の無料試用に含まれます。

Extended Threat Detection

1つひとつは小さな出来事でも、順番に起きると攻撃とみなせるもの(認証情報の窃取→権限の昇格→データの持ち出し など)を、複数段階の攻撃としてまとめて検出します。追加料金なしで自動的に有効です。

検出結果(Finding)

  • 種類は 脅威の目的:リソース/内容 の形の名前で表す(例:UnauthorizedAccess:EC2/SSHBruteForce、CryptoCurrency:EC2/BitcoinTool.B)。
  • 重要度は 低・中・高・重大 の4段階。
  • 信頼できるIPリスト(検出しない)・脅威リスト(必ず検出する)を自分で登録できる。
  • 抑制ルールで、問題ないと分かっている検出結果を自動でアーカイブできる。

複数アカウントの管理

Organizations と連携し、委任管理者アカウントで組織全体の GuardDuty を有効化・管理できます。有効化はリージョンごとに必要です。

3. ユースケース

  • 漏えいしたアクセスキーが使われたことを早期に発見する
  • EC2が乗っ取られてマイニングや外部攻撃の踏み台にされていないかを監視する
  • 検出結果をEventBridge+Lambdaで受けて、該当インスタンスを隔離用セキュリティグループに付け替える
  • S3にアップロードされたファイルのマルウェアチェック

4. 料金の考え方

分析したイベントやログの量(CloudTrailのイベント数、フローログ・DNSログのGB数など)と、有効にした保護プランの対象量に応じて課金されます。30日間の無料試用期間があり、その間にコンソールで月額の見込みを確認できます。

5. 関連サービス

  • AWS Security Hub:検出結果の集約
  • Amazon EventBridge:検出結果をトリガーにした通知・自動対応
  • Amazon Inspector:脆弱性の検出(GuardDutyは脅威の検出)
  • Amazon Macie:S3の機密データの検出
  • AWS CloudTrail/VPCフローログ:分析の元になるログ
  • AWS Organizations:委任管理者による一括管理

6. 試験・実務でのポイント

  • 「不正アクセス」「認証情報の悪用」「マイニング」「脅威の検出」→ GuardDuty。
  • CloudTrail・フローログ・DNSログを自分で有効化していなくても分析できる。
  • 脆弱性(CVE)は Inspector、機密データは Macie、脅威は GuardDuty と使い分ける。
  • 検出結果への自動対応 → EventBridgeルール+Lambda/SSM Automation。
  • 組織全体での有効化 → 委任管理者。リージョンごとに有効化が必要。
  • GuardDuty・Inspector・Macie・Security Hub CSPMの使い分け → セキュリティ検出のサービスの選び方。

7. まとめ

  • GuardDutyは、ログを自動で分析して脅威を検出するサービス。有効化するだけで使える。
  • 保護プランでS3・EKS・RDS・Lambda・実行時の動きまで分析対象を広げられる。
  • EventBridgeと組み合わせて、検出から対応までを自動化する。
