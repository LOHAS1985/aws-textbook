1. サービス概要

AWS Application Discovery Serviceは、オンプレミス環境のサーバーやデータベースの使用状況・構成・ネットワーク依存関係を収集し、AWSへの移行計画を支援するサービスです。AWS Migration Hubと連携し、検出したサーバーをアプリケーション単位にまとめて移行状況を追跡できます。

新規顧客は利用を開始できません。2025年11月7日以降、新規の利用開始は終了しています。既存顧客は継続して利用できます。新しい移行調査には、後継のAWS Transformを検討します。

2. 主な機能・特徴

サーバーの検出方法

  • Agentless Collector:VMware vCenterに仮想アプライアンスを配置し、対象サーバーの構成・使用状況を収集する。
  • Discovery Agent:個々のサーバーにエージェントを導入して、詳細な構成やネットワーク接続を収集する。
  • 収集したデータはMigration Hubのホームリージョンに保存される。
  • エクスポートしたデータをAmazon AthenaやAmazon Quickで分析できる。

検出と移行の違い

Application Discovery Serviceは、移行元の把握と計画のためのデータ収集を担います。サーバーの複製・起動は行いません。実際のサーバー移行にはAWS Transform MGN、データベース移行にはAWS DMSなどを要件に応じて使います。

3. ユースケース

  • 移行対象のサーバー台数・構成・リソース使用量を把握する。
  • サーバー間の通信を分析して、同時に移行するアプリケーション群を決める。
  • 収集データをコスト見積もりや移行先の設計に使う。

4. 料金の考え方

提供状況や利用できる機能が変更されているため、既存環境の料金と継続利用条件は公式情報で確認します。新規の調査ではAWS Transformなど現行の代替サービスと、その利用料金を確認します。

5. 関連サービス

  • AWS Transform MGN:検出後のサーバー複製・移行
  • AWS DMS:データベースの移行と継続レプリケーション
  • AWS DataSync:ファイル・オブジェクトの転送
  • Amazon Athena/Amazon Quick:収集データの分析
  • 関連する用語:DEA-C01の学習範囲

6. 試験・実務でのポイント

  • オンプレミス環境を検出して移行を計画 → Application Discovery Service。
  • 新規顧客は利用を開始できず、後継のAWS Transformが案内されている。
  • 検出・計画、サーバー移行、データベース移行はそれぞれ別の役割として整理する。

7. まとめ

  • Application Discovery Serviceは移行前のサーバー構成・依存関係を集める。
  • 新規利用は終了しているため、移行計画ではAWS Transformなどの現行サービスを検討する。
