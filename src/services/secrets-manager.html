1. サービス概要

AWS Secrets Managerは、アプリケーションで使う機密情報(DBのパスワードやAPIキーなど)を安全に保管・取得・ローテーションするサービスです。

2. 主な機能・特徴

  • 自動暗号化:保存時はKMS、転送時はHTTPSで暗号化される。
  • シークレットのレプリケーション:リージョンサービスのため、別リージョンへ自動でレプリケーションできる。
  • ローテーション:パスワードを定期的に自動変更できる。

3. ユースケース

アプリのDB接続情報の管理

  1. 事前準備:DB接続用の認証情報をSecrets Managerに保存(KMSで暗号化)
    {"username": "app_user", "password": "xxxxx", "host": "db.example.com"}
  2. ユーザーがアプリにログイン(ID/パスワードを入力)
  3. アプリがDB認証情報を取得(GetSecretValue API)
  4. アプリがその認証情報でDBに接続
  5. DBがユーザーテーブルと照合(DBにはハッシュ化されたパスワードが保存されており、入力値を同じ方法でハッシュ化して比較)
  6. アプリに結果を返す

「アプリのエンドユーザーのID/パスワードをSecrets Managerに保存すればよいのでは?」→ 非推奨。Secrets Managerは少数の機密情報を安全に運用するためのサービスで、ユーザーごとに保存するとコストが膨大になります。

4. 料金の考え方

シークレット1件ごとの月額料金と、APIの呼び出し回数で課金されます。

Parameter Storeは一部無料で使えるため、ローテーションが不要な設定値はParameter Storeが向いています。

5. 関連サービス

  • AWS KMS:シークレットの暗号化
  • Amazon RDS/Amazon Aurora:認証情報の自動ローテーション
  • AWS Systems Manager:Parameter Store
  • AWS Lambda:ローテーション処理の実行

6. 試験・実務でのポイント

  • DBパスワードの自動ローテーション → Secrets Manager(Parameter Storeは不可)。
  • ダウンタイムなしでローテーション → 交代ユーザー方式。
  • コストを抑えて設定値を管理 → Parameter Store。
  • シークレットの取得は secretsmanager:GetSecretValue(KMSの復号権限も必要)。
  • DRで別リージョンでも使いたい → シークレットのレプリケーション。

7. まとめ

  • Secrets Managerは機密情報の保管・取得・ローテーションのサービス。
  • ローテーションはシングルユーザーと交代ユーザーの2方式。
  • ローテーション不要の設定値はParameter Storeで十分。
