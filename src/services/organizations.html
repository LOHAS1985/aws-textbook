1. サービス概要

AWS Organizationsは、複数のAWSアカウントをまとめて管理するサービスです。アカウントをグループに分け、組織全体に共通のルールを適用できます。

2. 主な機能・特徴

用語

  • ルート:組織の階層の最上位。ルートにSCPを適用すると、組織内のすべてのアカウントが対象になる。
  • 管理アカウント:組織を作成したアカウント。メンバーアカウントの招待・作成や一括請求を行う。
  • メンバーアカウント:組織に所属する管理アカウント以外のアカウント。
  • OU(組織単位):アカウントのグループ。OUの中にOUを入れて階層にできる。
  • SCP(サービスコントロールポリシー):権限の制御(拒否が中心)。IAMで許可しても、SCPで拒否されていれば拒否される。

SCPの利用イメージ

Organizationsの管理アカウント側の管理者が設定します。

  • 組織全体の権限の管理 → SCP
  • 個々の権限の管理 → IAM
AWS Organizations
├── SCP
│    ├── 使用可能リージョンを制限
│    ├── CloudTrail停止を禁止
│    └── Organizations操作を禁止
├── IAM Identity Center
│    ├── 開発者 → Developer権限
│    ├── 運用者 → Administrator権限
│    └── 監査者 → ReadOnly権限
└── 各AWSアカウント
     ├── Production
     ├── Development
     └── Test

SCPは権限を「与える」ものではなく、上限(ガードレール)を決めるものです。実際の操作には、SCPで禁止されていないことに加えて、IAMでの許可が必要です。また、SCPは管理アカウントには適用されません。

3. ユースケース

  • 本番・開発・テストのアカウントを分けて管理
  • 全アカウントで使用できるリージョンを制限
  • CloudTrailの停止など、セキュリティ設定の変更を全アカウントで禁止
  • IAM Identity Centerで、複数アカウントへのログインを一元化

4. 料金の考え方

Organizations自体は無料です。複数アカウントの請求をまとめる一括請求(コンソリデーティッドビリング)により、ボリュームディスカウントやリザーブドインスタンスの共有の恩恵も受けられます。

5. 関連サービス

  • AWS IAM:個々の権限管理
  • AWS IAM Identity Center:組織内の複数アカウントへのシングルサインオン(パーミッションセット)
  • AWS CloudTrail:組織全体の証跡
  • AWS Config:組織全体のルール評価
  • AWS Resource Access Manager:組織内でのリソース共有
  • AWS Security Hub:組織全体のセキュリティ状況の集約
  • AWS Backup:組織全体のバックアップポリシー

6. 試験・実務でのポイント

  • IAMで許可してもSCPで拒否されたら拒否。
  • 全アカウントで特定の操作・リージョンを禁止 → SCPをOUやルートに適用。
  • アカウントのグループ化 → OU。

7. まとめ

  • Organizationsは複数アカウントの管理サービス。
  • OUでアカウントをまとめ、SCPで組織全体の権限の上限を決める。
