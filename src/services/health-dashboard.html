1. サービス概要

AWS Health Dashboardは、AWS側で起きている障害や、予定されているメンテナンスなどの情報(イベント)を確認できる画面です。裏側ではAWS Healthというサービスがイベントを提供しており、ダッシュボード・API・EventBridgeから利用できます。

CloudWatchが「自分のリソースの状態(CPU使用率など)」を監視するのに対し、AWS Healthは「AWSのサービスやインフラ側の状態」と、それが自分のリソースに与える影響を知らせます。「アプリが遅いのは自分の設定のせいか、AWS側の障害か」を切り分けるときに最初に確認する場所です。

2. 主な機能・特徴

2つの画面

画面内容見られる人
サービスの状態(Service health)全リージョン・全サービスの稼働状況。一般向けの障害情報誰でも(サインイン不要)
アカウントの状態(Your account health)自分のアカウントのリソースに影響するイベント。影響を受けるリソースのIDも表示されるサインインしたユーザー

以前は前者が「Service Health Dashboard」、後者が「Personal Health Dashboard」という別々の名前でしたが、現在はAWS Health Dashboardにまとめられています。

イベントの種類

種類内容例
未解決の問題(Issue)AWSのサービスで発生している障害・性能低下東京リージョンのあるAZでEC2のAPIエラーが増えている
予定された変更(Scheduled change)今後予定されているメンテナンスなどEC2インスタンスのリタイア(ハードウェアの廃止)、RDSのメンテナンス、古いバージョンのサポート終了
その他の通知(Account notification)アカウントに関するお知らせ証明書の期限切れ、アクセスキーの漏えいの検知

EventBridgeとの連携(自動対応)

AWS HealthのイベントはAmazon EventBridgeにも送られます(イベントの発生元は aws.health)。ルールを作れば、イベントをきっかけに通知や自動対応ができます。

  • 予定されたメンテナンスをSNSでメール・チャットに通知する
  • EC2のリタイア予定を受けて、Systems Manager Automationでインスタンスを停止・起動し、別のハードウェアへ移す
  • アクセスキーの漏えい(AWS_RISK_CREDENTIALS_EXPOSED)を受けて、Lambdaでキーを無効化する

EventBridgeへは、イベントが発生したリージョンに届きます。特定のリージョンに属さないグローバルなイベント(IAMなど)はus-east-1に届くため、ルールを作るリージョンに注意します。

組織ビュー

AWS Organizationsを使っている場合、管理アカウント(または委任された管理者アカウント)で組織ビューを有効にすると、すべてのメンバーアカウントのイベントをまとめて確認できます。

AWS Health API

イベントをプログラムから取得するためのAPIです。Business Support+ 以上のサポートプラン(Business Support+・Enterprise Support・Unified Operations。2026年までの旧プランではBusiness・Enterprise On-Ramp・Enterprise)が必要です。EventBridgeとの連携やダッシュボードは、サポートプランに関係なく使えます。

3. ユースケース

  • アプリの障害時に、AWS側の問題かどうかを確認する
  • EC2のリタイアやRDSのメンテナンスの予定を事前に把握し、業務時間外に対応する
  • メンテナンスや障害の通知をチームのメール・チャットに自動で流す
  • マルチアカウント環境で、全アカウントへの影響を一か所で確認する

4. 料金の考え方

AWS Health Dashboardと、EventBridgeへのイベント配信は無料です。通知や自動対応に使うSNS・Lambdaなどの料金はかかります。AWS Health APIを使うには、上記のサポートプランの契約が必要です。

5. 関連サービス

  • Amazon EventBridge:Healthのイベントを受け取り、通知・自動対応につなげる
  • Amazon SNS:イベントの通知
  • AWS Systems Manager:Automationでの自動対応
  • Amazon CloudWatch:自分のリソースの監視(Healthと役割が異なる)
  • AWS Trusted Advisor:ベストプラクティスに沿っているかのチェック
  • AWS Organizations:組織ビューで全アカウントのイベントを集約
  • 関連する用語:サポートプラン

6. 試験・実務でのポイント

  • AWS側の障害・メンテナンスが自分のリソースに影響するかを知りたい → AWS Health Dashboard(アカウントの状態)。
  • Healthのイベントで通知・自動対応したい → EventBridgeのルール(aws.health)→ SNS・Lambda・SSM Automation。
  • EC2のリタイア予定の通知 → 期限までにインスタンスを停止・起動して別のホストへ移す(再起動では移らない)。
  • 全アカウントのイベントをまとめて見たい → Organizationsの組織ビュー。
  • Health APIを使うには Business Support+ 以上のサポートプランが必要(サポートプラン)。
  • CloudWatch=自分のリソースの状態、Health=AWS側の状態、Trusted Advisor=ベストプラクティスのチェック、と区別する。
  • CloudWatch・CloudTrail・Config・X-Rayの使い分け → 監視・記録のサービスの選び方。

7. まとめ

  • AWS側の障害・予定されたメンテナンス・アカウントへの通知を確認できるダッシュボード。
  • 「サービスの状態」は全体の情報、「アカウントの状態」は自分のリソースへの影響。
  • EventBridgeと連携して、通知や自動対応ができる。
  • ダッシュボードは無料。APIはBusiness Support+ 以上のサポートプランが必要。
