1. サービス概要

AWS Transform MGNは、物理・仮想・クラウド上のサーバーをAWSへリホストするサービスです。旧AWS Application Migration Serviceと同じMGNの名称で、ソースサーバーのブロックデータを継続的に複製し、AWS上で起動できる形に変換します。

移行時の停止時間を抑えながら、複数サーバーをテスト・切り替えできます。データベースの論理的な移行や異種DB間のスキーマ変換が目的なら、AWS DMSなどと比較します。

2. 主な機能・特徴

継続レプリケーションと起動

  • ソースサーバーのブロックレベルの変更をステージング領域へ継続的に複製する。
  • レプリケーション設定テンプレートで、複製先のネットワークやディスクなどを定義する。
  • テスト起動で移行先の動作を確認した後、カットオーバーして本番利用へ切り替える。
  • 起動テンプレートやポスト起動アクションで、移行後のインスタンス設定や処理を管理する。

3. ユースケース

  • オンプレミスの物理・仮想サーバーを短い停止時間でAWSへ移行する。
  • 多数のサーバーをアプリケーションや移行ウェーブごとにまとめて移行する。
  • 本番切り替え前にテストインスタンスを起動し、移行後の動作を確認する。

4. 料金の考え方

レプリケーションに使うステージング用リソース、移行先のEC2などの実行料金、ストレージ、データ転送が費用に影響します。移行中のテスト起動や複製期間も含めて見積もります。

5. 関連サービス

  • AWS Application Discovery Service:移行前のサーバー調査
  • AWS DMS:データベースの移行・継続レプリケーション
  • AWS DataSync:ファイルやオブジェクトの転送
  • Amazon EC2:移行後のサーバー実行先
  • Amazon CloudWatch:移行後の監視

6. 試験・実務でのポイント

  • サーバーのブロックレベル複製とAWSへのリホスト → AWS Transform MGN。
  • テスト起動で検証してからカットオーバーする。
  • データベースの論理移行・継続レプリケーションは、サーバー単位のMGNとAWS DMSを使い分ける。

7. まとめ

  • AWS Transform MGNはサーバーを継続複製し、AWS上でテストして切り替える。
  • 試験ガイドの旧名称「AWS Application Migration Service」と同じMGNとして把握する。
