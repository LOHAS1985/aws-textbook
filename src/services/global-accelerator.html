1. サービス概要

AWS Global Acceleratorは、AWSのグローバルネットワークを使って、ユーザーからアプリケーションまでの通信経路を最適化するサービスです。

2. 主な機能・特徴

仕組み

  1. 2つの静的Anycast IPアドレスが割り当てられ、エッジロケーションで受け付ける。
    • Anycast IP:1つのIPアドレスを複数のエッジロケーションに設定する方式
    • 2つある理由:可用性(冗長性)のため
  2. ユーザーの通信は最寄りのエッジロケーションに入り、インターネットではなくAWSのバックボーンネットワークでリージョン内のエンドポイントへ転送される。
  3. エンドポイントのヘルスチェックを行い、異常時は正常なエンドポイントへ自動でフェイルオーバーする。

構成要素と2種類のアクセラレーター

アクセラレーターの中は、リスナー、エンドポイントグループ、エンドポイントの階層になっています。リスナーは受け付けるプロトコル(TCPまたはUDP)とポート範囲を指定します。エンドポイントグループはリージョンごとに作り、その中のエンドポイントは同じリージョンに置きます。

  • 標準アクセラレーター:利用者を、場所と健全性に応じて最適なリージョンのエンドポイントへ振り分ける
  • カスタムルーティングアクセラレーター:1人の利用者を、多数の宛先の中の特定の宛先に割り当てる。宛先はVPCのサブネット内のプライベートIPアドレス

対応エンドポイント

  • ALB/NLB
  • EC2インスタンス
  • Elastic IPアドレス

トラフィックダイヤルとエンドポイントの重み

標準アクセラレーターでは、エンドポイントグループごとにトラフィックダイヤル(0〜100%。既定は100%)で、そのリージョンへ向かう通信の割合を調整できます。メンテナンスの前にダイヤルを0%にすると、そのリージョンへの通信を止めて作業できます。

  • ダイヤルの変更は新しい接続から反映される。既存の接続は切れない
  • ヘルスチェックはダイヤルの影響を受けない
  • エンドポイントごとの重み(weight)で、同じエンドポイントグループの中の配分を調整できる

ヘルスチェック

エンドポイントグループごとにヘルスチェックを設定できます。EC2インスタンスとElastic IPアドレスは、Global Acceleratorのエンドポイントグループでヘルスチェックの設定を変えられ、ALBとNLBは Elastic Load Balancingのコンソールで設定します。正常なエンドポイントが1つもない場合は、リージョン内のすべてのエンドポイントへ振り分けます。

固定IPアドレス

アクセラレーターには固定IPアドレスが割り当てられ、アクセラレーターが存在する間は保持されます。無効化(disable)すると通信は受け付けなくなりますが、IPアドレスは残ります。アクセラレーターを削除すると固定IPアドレスも失われ、そのIPでは通信を受けられなくなります。

  • IPv4の固定IPアドレスは2つ。デュアルスタックの場合は、IPv6の2つを加えて計4つになる
  • IPv4は、自分が持つIP範囲(BYOIP)をアクセラレーターに使うこともできる
  • デュアルスタックで使うには、エンドポイントもデュアルスタックに対応している必要がある

制限(クォータ)

主な上限は次のとおりです。引き上げを申請するには、Service Quotasのコンソール(us-east-1リージョン)を使います。上限の考え方は用語ページ「サービスクォータ」を参照してください。

項目上限
標準アクセラレーター(1アカウントあたり)20
カスタムルーティングアクセラレーター(1アカウントあたり)10
リスナー(1アクセラレーターあたり)10
ポート範囲(1リスナーあたり)10
リスナー数 × エンドポイントグループ数42以下

リスナーを増やすほど、指定できるリージョンの数は減ります。

3. ユースケース

  • ゲーム・VoIP・IoTなど、TCP/UDPでレイテンシーを下げたいアプリ
  • 固定IPアドレスでの接続が必要(取引先のファイアウォールで許可リスト登録など)
  • 複数リージョン間のすばやいフェイルオーバー

4. 料金の考え方

アクセラレーターごとの時間料金と、転送データ量に応じた料金(DT-Premium)がかかります。

5. 関連サービス

  • Amazon CloudFront:HTTPのキャッシュ配信
  • Elastic Load Balancing/Amazon EC2:エンドポイント
  • Amazon Route 53:DNSベースのルーティング
  • Amazon Application Recovery Controller (ARC):ゾーンシフトで障害のあるAZから通信を逃がす(Global Acceleratorが対応)
  • 関連する用語:キャッシュの選び方、DR戦略、高可用性とスケーリング

6. 試験・実務でのポイント

  • 「静的IP」「TCP/UDP」「グローバルにレイテンシー改善」→ Global Accelerator。
  • 「キャッシュ」「HTTP」→ CloudFront。
  • DNSのキャッシュに左右されずにフェイルオーバーしたい → Global Accelerator。
  • 取引先のファイアウォールで接続元を許可リストに登録したい → Global Acceleratorの固定IPアドレス。
  • リージョンのメンテナンス中に通信を止めたい → トラフィックダイヤルを0%にする。
  • アクセラレーターを止めたいが、IPは残しておきたい → 無効化。削除すると固定IPは失われる。

7. まとめ

  • 2つの静的Anycast IP+AWSバックボーンで通信経路を最適化する。
  • CloudFrontはキャッシュ、Global Acceleratorは経路最適化。
