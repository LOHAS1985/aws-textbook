1. サービス概要

Amazon RDS(Relational Database Service)は、リレーショナルデータベース(SQL)の構築・運用を提供するマネージドサービスです。パッチ適用やバックアップなどの面倒な運用作業をAWSに任せられます。

対応DBエンジン:MySQL、PostgreSQL、MariaDB、Oracle Database、Microsoft SQL Server、Amazon Aurora

2. 主な機能・特徴

RDSが代行するDB運用タスク

  • プロビジョニング:DBサーバーの起動
  • パッチ適用:OS/DBエンジン
  • バックアップ
    • 自動バックアップ:保持期間は最大35日
    • 手動スナップショット:無期限(削除するまで残る)
    • ポイントインタイムリカバリ:特定時点のデータに復元
  • 障害時のフェイルオーバー:Multi-AZ構成
  • スケーリング:スペック変更、リードレプリカ(プライマリから非同期でレプリケーションするためわずかな遅延が発生)

Multi-AZは別AZにスタンバイを置く可用性のための仕組みで、スタンバイは読み取りに使えません(同期レプリケーション)。リードレプリカは読み取り性能を上げる仕組みです。目的の違いを区別しましょう。

RDS Proxy

大量のクライアントからのアクセスを、少数のDB接続に集約・再利用する仕組みです。

  • 前提:DBクエリの時間は短く、DB接続を行うのはアプリサーバー。
  • 例:アプリサーバーから1万人がDBにアクセスしても、実際に同時にクエリを投げているのは一部。RDS Proxyは50接続を1万人で使い回す。Proxyがないと1万接続を使い、接続数の上限を超える可能性が高い。

3. ユースケース

  • Webアプリの業務データベース
  • 既存のMySQL/Oracle/SQL ServerをAWSへ移行
  • Lambdaなど接続数が急増しやすい環境からのDB接続(RDS Proxy)

4. 料金の考え方

DBインスタンスの稼働時間(インスタンスクラス)、ストレージ容量、バックアップ容量、データ転送量で課金されます。Multi-AZはスタンバイ分の料金も加わります。リザーブドインスタンスで割引も可能です。

5. 関連サービス

  • Amazon Aurora:AWSが開発した高性能なRDSエンジン
  • Amazon DynamoDB:NoSQLの選択肢
  • Amazon ElastiCache:DBの前段のキャッシュ
  • AWS Lambda:RDS Proxyと相性の良い接続元
  • AWS Secrets Manager:DB認証情報の管理・ローテーション
  • AWS Backup:バックアップの一元管理

6. 試験・実務でのポイント

  • 自動バックアップは最大35日。それ以上残したい → 手動スナップショット。
  • 障害対策 → Multi-AZ、読み取り性能 → リードレプリカ(非同期なので遅延あり)。
  • 「DB接続数が多すぎる」「Lambdaから大量接続」→ RDS Proxy。
  • 特定時点に戻したい → ポイントインタイムリカバリ。

7. まとめ

  • RDSはリレーショナルDBのマネージドサービス。運用タスクをAWSが代行する。
  • バックアップは自動(最大35日)と手動(無期限)。
  • 可用性はMulti-AZ、読み取り拡張はリードレプリカ、接続集約はRDS Proxy。
