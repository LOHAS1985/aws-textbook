1. サービス概要

Amazon EFS(Elastic File System)は、Linux向けの共有ファイルストレージです。複数のサーバーから同時にマウントして、同じファイルを読み書きできます。Windows向けにはAmazon FSx for Windows File Serverを使います。

2. 主な機能・特徴

  • 共有ストレージ:EC2・ECS・EKS・Lambdaから同時にマウントできる。
  • オンプレミスからもDirect Connect・VPN経由で利用できる。接続方法の選び方は用語ページ「オンプレミスとAWSをつなぐ方法の選び方」を参照してください。

マウントターゲット

NFSで接続するための入り口で、実体はサブネット内のENIです。ENIの仕組みは用語ページ「ENIとElastic IP」を参照してください。1つのファイルシステムにつき、AZごとに1つまで作成できます。

マウントターゲットはAZ単位で作る、という点が試験で問われます。

  • マウントターゲットは1つのAZに1つ。そのAZの中のどれか1つのサブネットに作る(同じAZの別のサブネットのEC2も、そのマウントターゲットを使う)。
  • EC2から使うときは、同じAZのマウントターゲットに接続する。ファイルシステムのDNS名(fs-xxxx.efs.ap-northeast-1.amazonaws.com)を使うと、自動で同じAZのマウントターゲットのIPに解決される。別のAZのマウントターゲットを使うと、レイテンシーが上がり、AZ間のデータ転送料もかかる。
  • EC2を置くAZには、必ずマウントターゲットを作る。マウントターゲットがないAZのEC2から「DNS名が解決できない」「マウントがタイムアウトする」ときは、そのAZにマウントターゲットを追加する。
  • マウントターゲットのセキュリティグループで、EC2のセキュリティグループからのNFS(TCP 2049)を許可する。
  • One Zoneのファイルシステムは1つのAZにしかデータを置かないため、マウントターゲットもそのAZに1つだけ。ほかのAZから使うと、AZ間の通信になる。

パフォーマンスモード(作成後に変更不可)

最大I/Oは旧世代のモードで、操作ごとのレイテンシーが高くなります。IOPSやレイテンシーの見方は用語ページ「IOPS・スループット・レイテンシー」を参照してください。AWSはすべてのファイルシステムで汎用モードを推奨しており、高い性能が必要な場合は汎用モード+Elasticスループットを使います。

レイテンシー低い高い
IOPSの上限高い最高
用途基本はこちら(推奨)。Webサーバー、CMSなど旧世代。高いレイテンシーを許容できる、高度に並列化されたワークロード

暗号化(保存時の暗号化は作成後に変更不可)

EFSの保存時の暗号化は、ファイルシステムを作成するときにしか有効にできません。作成後に、暗号化されていないファイルシステムを暗号化に変えたり、暗号化をやめたりすることはできません。使うKMSキー(AWSマネージドキー aws/elasticfilesystem かカスタマーマネージドキー)も作成時に決めます。

暗号化設定するタイミング方法
保存時(データ・メタデータ)作成時のみ(後から変更不可)作成時に暗号化を有効にし、KMSキーを選ぶ(コンソールでは既定で有効)
転送中(EC2〜EFS間)マウントするとき(いつでも可)EFSマウントヘルパー(amazon-efs-utils)で mount -t efs -o tls fs-xxxx:/ /mnt/efs のように TLS を指定する

暗号化されていない既存のファイルシステムを暗号化したいときは、次の手順で移行します。

  1. 暗号化を有効にした新しいファイルシステムを作る
  2. AWS DataSync(またはAWS Backupの復元)で、古いファイルシステムのデータをコピーする
  3. アプリのマウント先を新しいファイルシステムに切り替え、古いものを削除する

組織のルールとして暗号化を強制したいときは、IAMポリシーやSCPで、条件キー elasticfilesystem:Encrypted が false の CreateFileSystem を拒否します。既存のファイルシステムの状態は、AWS Configのマネージドルール efs-encrypted-check で確認できます。転送中の暗号化を必須にするには、ファイルシステムポリシーで aws:SecureTransport が false の接続を拒否します。RDSやEBSでも同じく「暗号化は作成時に決める」ので、用語ページ「保存時の暗号化と転送時の暗号化」もあわせて確認してください。

3. ユースケース

  • 複数のWebサーバーでコンテンツを共有(CMSなど)
  • ECS/EKSの複数タスク・複数AZからの共有ボリューム
  • ビッグデータ分析・メディア処理

4. 料金の考え方

ストレージクラスでコストが変わります。

クラスAZ配置用途コスト・特徴
Standard複数頻繁にアクセス料金高・レイテンシー低
Standard-IA複数たまにアクセス料金安・読み取り時にアクセス料金
Archive複数ほとんどアクセスしない料金最安・アクセス料金はIAより高い
One Zone単一頻繁にアクセス+AZ障害を許容Standardより安い
One Zone-IA単一たまにアクセス+AZ障害を許容One Zoneよりさらに安い

スループットはElasticなら転送量、Provisionedなら確保した値に対して課金されます。

EFSは使った容量分だけ課金され、容量を事前に確保する必要はありません。ライフサイクル管理で、アクセスされないファイルを自動的にIA/Archiveへ移動できます。

5. 関連サービス

  • Amazon EC2/Amazon ECS/Amazon EKS/AWS Lambda:マウント元
  • Amazon EBS:単一インスタンス向けのブロックストレージ
  • Amazon FSx:Windows向けなどのファイルストレージ
  • AWS DataSync:EFSへのデータ転送

6. 試験・実務でのポイント

  • Linuxで複数インスタンス・複数AZから共有 → EFS。Windows → FSx for Windows。
  • マウントターゲットはAZ単位(1つのAZに1つ)。EC2は同じAZのマウントターゲットに接続し、EC2を置くAZには必ずマウントターゲットを作る。NFS(TCP 2049)をセキュリティグループで許可する。
  • 保存時の暗号化は作成後に有効にできない → 暗号化した新しいファイルシステムを作り、DataSyncでデータを移す。転送中の暗号化はマウント時に -o tls。
  • パフォーマンスモードは作成後に変更不可、スループットモードは変更可能。
  • 最大I/OモードではOne Zone・Elasticスループットが使えない。AWSの推奨は汎用モード。
  • スパイクがある負荷 → Elastic、小容量で高スループット → Provisioned。

7. まとめ

  • EFSはLinux向けの共有ファイルストレージ(NFS)。
  • 接続口はAZごとのマウントターゲット。
  • パフォーマンスモードと保存時の暗号化は後から変えられないので作成時に決める。
