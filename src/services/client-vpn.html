1. サービス概要

AWS Client VPNは、テレワーク中の社員などが自分のPCからVPCやオンプレミスのネットワークへ安全に接続するための、マネージド型のリモートアクセスVPNです。OpenVPNベースのクライアントソフト(AWS提供のクライアントなど)を使って、TLSで暗号化した接続を張ります。

拠点(ネットワーク)どうしをつなぐ Site-to-Site VPN に対し、Client VPN は個々の利用者の端末をつなぎます。

2. 主な機能・特徴

構成要素

要素説明
Client VPNエンドポイント接続を受け付ける本体。サーバー証明書(ACM)・認証方法・クライアントに割り当てるIPアドレス範囲(クライアントCIDR)を設定する
ターゲットネットワークエンドポイントを関連付けるVPCのサブネット。高可用性のために複数のAZのサブネットを関連付ける
認可ルールどの利用者(グループ)が、どの宛先ネットワークにアクセスできるかを決める
ルートテーブルエンドポイントから先の宛先(VPC・ピアリング先・オンプレミス・インターネット)への経路

認証の方法

  • 相互認証(証明書):クライアント証明書で認証する
  • Active Directory認証:AWS Directory Service経由でADのユーザーで認証する(MFAも可)
  • SAMLフェデレーション認証:IAM Identity Centerや外部のIdPでシングルサインオン

AD・SAMLを使うと、グループごとに認可ルールを分けられます。

スプリットトンネル

既定では、PCのすべての通信がVPNを通ります。スプリットトンネルを有効にすると、エンドポイントのルートにある宛先(VPCなど)だけをVPNに通し、それ以外のインターネットの通信はPCから直接出ます。VPNの通信量とデータ転送料を減らせます。

運用

  • 接続ログを CloudWatch Logs に出力できる(誰がいつ接続したか)。
  • クライアント接続ハンドラー(Lambda)で、接続時に独自のチェックを行える。
  • セキュリティグループをエンドポイントに適用して、VPC内の通信先を制限できる。
  • クライアントCIDRは、VPCのCIDRと重ならない範囲にする。

3. ユースケース

  • テレワークの社員が、VPC内の社内システムやオンプレミスのファイルサーバーにアクセスする
  • 踏み台サーバーを置かずに、管理者がプライベートサブネットのサーバーに接続する
  • 委託先の作業者に、特定のネットワークだけアクセスを許可する

4. 料金の考え方

エンドポイントを関連付けたサブネットごとの時間料金と、接続している利用者ごとの時間料金(接続数×時間)がかかります。関連付けるサブネットを増やすと可用性は上がりますが、費用も増えます。

5. 関連サービス

  • AWS Directory Service/IAM Identity Center:利用者の認証
  • Amazon CloudWatch:接続ログ

6. 試験・実務でのポイント

  • 「個々の社員のPCからVPCに接続」「リモートアクセスVPN」→ Client VPN。拠点間は Site-to-Site VPN。
  • VPC以外の通信までVPN経由になって遅い・費用が高い → スプリットトンネルを有効にする。
  • 接続できても目的のネットワークに届かない → 認可ルールとエンドポイントのルートテーブルの両方を確認する。
  • 可用性を上げるには、複数AZのサブネットをターゲットネットワークに関連付ける。
  • Site-to-Site VPN・Direct Connect・Client VPNの使い分け → オンプレミスとAWSをつなぐ方法の選び方。

7. まとめ

  • Client VPNは、利用者の端末からVPCやオンプレミスにつなぐマネージド型のVPN。
  • 証明書・AD・SAMLで認証し、認可ルールとルートで行き先を制御する。
