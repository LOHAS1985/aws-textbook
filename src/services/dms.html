1. サービス概要

AWS Database Migration Service (AWS DMS)は、リレーショナル・NoSQLデータベースやデータウェアハウスなどのデータ移行とレプリケーションを支援するサービスです。AWS内外のソースとターゲットを接続し、1回限りの移行や継続的な変更データキャプチャ(CDC)を実行します。

2. 主な機能・特徴

移行タスク

  • ソースとターゲットのエンドポイント、ネットワーク接続、認証情報を設定する。
  • 全件ロードを行い、その後に変更を継続複製して、切り替えまでデータを同期する。
  • 移行タスクの状態、遅延、エラーを監視して、再試行やリソース調整を行う。

データ移行とスキーマ変換

DMSはデータの移行・レプリケーションを担います。異なるデータベースエンジンへ移行する場合、AWS DMS Schema ConversionやAWS Schema Conversion Toolでスキーマやコードの互換性を評価・変換します。移行元と移行先の型・関数・制約が完全に一致するとは限らないため、変換結果を確認してテストします。

接続と整合性

ソース・ターゲットのセキュリティグループ、ルーティング、認証情報、ネットワーク到達性を確認します。移行中の更新量が大きい場合は、レプリケーション遅延を監視します。切り替え前には件数・チェックサム・業務上の重要な値を比較します。

3. ユースケース

  • オンプレミスや別クラウドのデータベースをAWSへ移行する。
  • 移行中も業務を続けるために、初期ロード後の変更を継続同期する。
  • 分析用データベースへ業務DBの変更をレプリケーションする。

4. 料金の考え方

レプリケーションに使うインスタンスやサーバーレスの処理能力、ストレージ、ログ、データ転送などが課金要因です。移行作業に必要な期間・容量を見積もり、完了後に不要なレプリケーション資源を停止・削除します。

5. 関連サービス

  • Amazon RDS/Amazon Aurora:移行先データベース
  • Amazon Redshift:分析用ウェアハウス
  • AWS Glue:移行後のETLとData Catalog
  • Amazon CloudWatch:タスクのログ・メトリクス監視

6. 試験・実務でのポイント

  • 異なるデータベース間のデータ移行や継続同期 → AWS DMS。
  • 全件ロード後も変更を追従させる → CDCタスク。
  • データの移行とスキーマ・コードの変換は別の作業として計画する。
  • レプリケーション遅延、エラー、データ整合性を切り替え前に確認する。

7. まとめ

  • AWS DMSはデータベースなどの移行と継続レプリケーションを行う。
  • スキーマ変換、ネットワーク、データ整合性の確認は移行計画に含める。
