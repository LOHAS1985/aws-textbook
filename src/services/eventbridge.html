1. サービス概要

Amazon EventBridgeは、サーバーレスなイベント駆動型の統合サービスです。AWSサービスやアプリで発生したイベントを、条件に応じてさまざまなターゲットへ届けます。

  • 複数のターゲットに送信できる
  • API Destination:外部のHTTPSエンドポイントへイベントを送信
  • アカウント間・リージョン間のイベント転送も可能

2. 主な機能・特徴

用語

  • イベントバス:イベントを送受信する仕組み。
    • デフォルト:AWSサービス同士の連携
    • カスタム:独自アプリのイベント
    • パートナー:AWS以外(SaaS)のアプリのイベント
  • イベントソース:イベントの送信元となるサービスやアプリ
  • ルール:イベントパターンやスケジュールに基づいて実行
  • ターゲット:送信先

EventBridge Rules

イベントバス上のイベントをフィルタリングし、複数のターゲットへファンアウト配信します。

  1. ルールを作成
  2. イベントバスを選択(デフォルト/カスタム)
  3. イベントパターンを定義(例:S3からのイベントだけに絞る)
  4. ターゲットを選択(SNSトピック、Lambda関数、Step Functionsなど)。送信前にイベントデータを変換・拡張できる
  5. ルールを保存

EventBridge Pipes

イベントソースとターゲットを1対1で接続するサービスです。

  1. ソース:DynamoDB Streams、Kinesis Data Streams、SQS、Amazon MSK、Amazon MQ
  2. フィルタリング:条件に一致するイベントだけを通す
  3. エンリッチメント:送る前に内容を補完・変換(Lambda、Step Functions、API Gateway、API Destinations)
  4. ターゲット:Lambda、Step Functions、SNS、SQS、API Gatewayなど

Systems Manager Automationによる自動修復

ターゲットとしてSSM Automation(ランブック)を指定できます。例:異常なEC2の修復

  1. CloudWatchアラームがEC2のステータスチェック失敗を検出
  2. EventBridgeルールがアラームの状態変化を検出
  3. SSM Automationのランブックを起動
  4. EC2インスタンスを再起動
  5. CloudWatchが状態を再評価

トラブルシューティング

チェック項目内容
イベントが実際に発生しているか発生元サービスやCloudTrailのイベント履歴を確認
イベントパターンが一致しているかコンソールのパターンテスト機能やサンプルイベントで確認
ルールが有効かルールが ENABLED か確認
ターゲットの権限ターゲットを呼び出すためのIAM権限を確認
ターゲットの実行結果ターゲットごとのログや実行履歴を確認
CloudWatchメトリクスとDLQDLQで配信できなかったイベントを後から調査
ArchiveとReplayArchiveでイベントを保存し、Replayで後から再送

3. ユースケース

  • EC2の状態変化やConfigの非準拠をトリガーに自動修復
  • cron式などのスケジュールでLambdaを定期実行
  • SaaS(パートナー)のイベントをAWSで処理
  • イベントをアーカイブしておき、障害後にリプレイ

4. 料金の考え方

カスタムイベント・パートナーイベントの発行数に応じて課金されます(AWSサービスからのデフォルトバスのイベントは無料)。Pipes、API Destinations、Archive/Replay、スケジューラーはそれぞれ別の料金です。

5. 関連サービス

  • AWS Health Dashboard:AWS Healthのイベント(aws.health)の送信元
  • Amazon SNS:シンプルなファンアウト通知
  • AWS Lambda/AWS Step Functions:代表的なターゲット
  • AWS Systems Manager:Automationによる自動修復
  • AWS CloudTrail:API操作をイベント化
  • Amazon SQS/Amazon DynamoDB/Amazon Kinesis:Pipesのソース
  • 関連する用語:イベント駆動の自動修復、cron式とrate式

6. 試験・実務でのポイント

  • 条件付きルーティング・変換・SaaS連携・アーカイブ/リプレイ → EventBridge。
  • イベントをトリガーに自動修復 → EventBridgeルール+SSM Automation。
  • ソースとターゲットを1対1でつなぎ、途中で加工 → Pipes。
  • ルールが発火しない → パターン一致・ENABLED・ターゲットの権限を確認。
  • 外部のHTTPS APIへ送信 → API Destination。
  • SQS・SNS・EventBridge・Kinesisの使い分け → メッセージングサービスの選び方。

7. まとめ

  • EventBridgeはイベントバス・ルール・ターゲットで構成されるイベント駆動の統合サービス。
  • Rulesはファンアウト、Pipesは1対1の加工付き接続。
