1. サービス概要

AWS Trusted Advisorは、AWS環境を自動でチェックし、ベストプラクティスに沿った改善を提案するサービスです。

2. 主な機能・特徴

チェックの観点

観点チェック例
コスト最適化使用率の低いEC2インスタンス、アイドル状態のELB、未使用のEBSボリューム
パフォーマンス高使用率のEC2インスタンス、EBSのプロビジョンドIOPSの過不足
セキュリティルートユーザーのMFA、セキュリティグループの無制限アクセス、S3バケットのパブリックアクセス
耐障害性RDSのマルチAZ未設定、EBSスナップショットの未取得
サービスクォータ上限に近づいているリソース(VPC、Elastic IP、EC2など)
オペレーショナルエクセレンスログ設定など運用面のベストプラクティス

コスト最適化のチェックにはCompute Optimizerの推奨が、セキュリティのチェックにはSecurity Hub CSPMのコントロールの結果も取り込まれます。公開されたリポジトリなどでアクセスキーが見つかったことを知らせる「漏洩したアクセスキー」のチェックもあります。

チェックの結果と更新

状態意味
緑(問題なし)問題は見つからなかった
黄(調査を推奨)確認したほうがよい(例:サービスクォータの80%以上を使っている)
赤(対応を推奨)すぐに対応したほうがよい(例:セキュリティグループで重要なポートが0.0.0.0/0に開いている)
  • チェックは自動で更新されるほか、コンソールから手動で更新(リフレッシュ)できる。
  • 意図して残しているリソースは、チェックの対象から除外できる。
  • 週1回、結果の要約をメールで受け取れる(通知先の連絡先を設定する)。

自動化と監視

チェックの状態の変化は、EventBridgeのイベントやCloudWatchのメトリクスになります。どちらも米国東部(バージニア北部)リージョンに出るため、ルールやアラームはそのリージョンで作ります。

  • 例:サービスクォータのチェックが黄になったらSNSで通知し、Service Quotasで上限の引き上げを申請する。
  • 例:漏洩したアクセスキーが見つかったら、Lambdaでそのキーを無効にする。
  • チェックの結果は、AWS Support API・Trusted Advisor APIから取得することもできる(使えるのはBusiness Support+ 以上)。

組織での利用

Organizationsと連携すると、管理アカウントから組織ビューで、全アカウントのチェック結果をまとめたレポートを作れます。Enterprise Supportでは、アカウントチームが優先順位を付けた推奨を届けるTrusted Advisor Priorityも使えます。

Service Quotasとの違い

Trusted Advisorのサービスクォータのチェックは、主なクォータの使用率をまとめて確認するものです。個々のクォータを確認し、上限の引き上げを申請したり、使用率にCloudWatchアラームを設定したりするにはService Quotasを使います(サービスクォータ)。

3. ユースケース

  • 無駄なリソースを洗い出してコスト削減
  • サービスクォータの上限到達を事前に検知
  • セキュリティの基本設定(MFA、公開設定)の確認

4. 料金の考え方

Trusted Advisor自体は無料で使えますが、利用できるチェック項目はサポートプランによって異なります。Basicサポートでは一部のコアチェックのみで、Business Support+ 以上のサポートプラン(2026年までの旧プランではBusiness以上)ですべてのチェックが使えます(サポートプラン)。

5. 関連サービス

  • AWS Health Dashboard:AWS側の障害・メンテナンスの影響を確認
  • AWS Compute Optimizer:機械学習によるリソースサイズの推奨
  • AWS Security Hub:セキュリティチェックの集約
  • Amazon EventBridge/Amazon SNS/AWS Lambda:チェック結果の変化の通知と自動対応
  • AWS Organizations:組織ビュー
  • 関連する用語:サービスクォータ、サポートプラン、AWS Well-Architected フレームワーク

6. 試験・実務でのポイント

  • 「サービスクォータの上限に近い」→ Trusted Advisorのサービスクォータチェック(使用率80%以上で黄)。
  • 「未使用・低使用率のリソースでコスト削減」→ Trusted Advisorのコスト最適化。
  • より詳細なサイズ推奨(機械学習)→ Compute Optimizer。
  • チェックの結果が変わったら通知・自動対応したい → EventBridgeのルールを米国東部(バージニア北部)に作る。
  • すべてのチェックを使いたい・APIで結果を取りたい → Business Support+ 以上のサポートプラン。
  • 全アカウントの結果をまとめて見たい → 組織ビュー。
  • 漏洩したアクセスキーの検出 → 「漏洩したアクセスキー」のチェックとEventBridgeで、キーを自動で無効にする。
  • GuardDuty・Inspector・Macie・Security Hub CSPMの使い分け → セキュリティ検出のサービスの選び方。

7. まとめ

  • Trusted Advisorはコスト・パフォーマンス・セキュリティ・耐障害性・クォータ・運用の観点でAWS環境をチェックする。
  • 結果は緑・黄・赤で示され、EventBridge(米国東部(バージニア北部))で通知・自動対応につなげられる。
  • 使えるチェックの数とAPIはサポートプランで変わる。
