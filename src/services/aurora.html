1. サービス概要

Amazon Auroraは、MySQL/PostgreSQL互換のリレーショナルデータベースです。RDSのDBエンジンの1つで、AWSが独自に設計したストレージにより高い性能と可用性を持ちます。

2. 主な機能・特徴

アーキテクチャの特徴

  • 共有クラスターボリューム:データは3つのAZにまたがって6コピー保持される。
  • インスタンス構成:1つのプライマリ(書き込み)と最大15のレプリカ(読み取り)。全インスタンスがボリュームを共有するため、レプリカのラグは通常ミリ秒レベル。
  • 自己修復:ストレージ側でディスク障害を自動検出して修復する。

エンドポイント

エンドポイント向き先
クラスターエンドポイント常にプライマリ(書き込み用)
リーダーエンドポイントレプリカへ負荷分散(読み取り用)
カスタムエンドポイント任意のインスタンスの組み合わせ
インスタンスエンドポイント特定のインスタンス

可用性とフェイルオーバー

  • プライマリに障害が起きると、レプリカが自動で昇格する。
  • レプリカがない場合は新しいインスタンスを作成するため、復旧に時間がかかる。可用性を重視するなら別AZにレプリカを置く。
  • 通常のRDS Multi-AZと違い、スタンバイ専用インスタンスはなく、レプリカが読み取りとフェイルオーバーを兼ねる。

主な機能

機能概要
レプリカのオートスケーリング負荷に応じてレプリカ数を増減する
Aurora Serverless v2負荷に応じてACU(Auroraキャパシティーユニット)を細かく自動調整する。変動の大きいワークロード向け
Auroraグローバルデータベース複数リージョンにレプリケートする。通常は1秒未満の遅延で、DRやグローバルな読み取りに使う
バックトラックAurora MySQLのみ。スナップショットから復元せず、クラスターを過去の時点へ巻き戻せる
クローンコピーオンライトで短時間に複製する。本番データを使ったテスト環境の作成に便利
RDS Proxy接続をプールし、フェイルオーバー時間の短縮と接続数の抑制に有効。Lambdaからの接続にも向く
Database Activity Streamsデータベースアクティビティをほぼリアルタイムでストリーミングする(監査用)

バックアップと復元

  • 継続的バックアップ:自動バックアップはS3に保存され、保持期間は1〜35日。ポイントインタイムリカバリが使える。
  • 復元は常に新しいクラスターとして作成される(既存クラスターは上書きされない)。
  • 手動スナップショットは削除するまで残り、リージョン間でコピーできる。

3. ユースケース

  • 高い可用性・性能が必要な業務システムのDB
  • 読み取りが多いWebサービス(最大15レプリカ+リーダーエンドポイント)
  • 負荷の変動が大きいアプリ(Serverless v2)
  • 複数リージョンでの災害対策・グローバル読み取り(グローバルデータベース)

4. 料金の考え方

インスタンスの稼働時間(Serverless v2ではACUの使用量)、ストレージの使用量、I/Oリクエスト、バックアップ容量で課金されます。ストレージは使った分だけ自動で拡張されます。

5. 関連サービス

  • Amazon RDS:Auroraを含むマネージドDBサービス
  • AWS Lambda:RDS Proxy経由での接続
  • Amazon ElastiCache:前段のキャッシュ
  • AWS Backup:バックアップの一元管理

6. 試験・実務でのポイント

  • データは3AZに6コピー。レプリカは最大15。
  • 書き込み → クラスターエンドポイント、読み取り → リーダーエンドポイント。
  • フェイルオーバーを速くしたい → 別AZにレプリカを置く。
  • 誤操作をすばやく戻したい(MySQL)→ バックトラック。
  • 本番データでテスト環境を素早く作る → クローン。
  • リージョン障害対策 → グローバルデータベース。
  • PITRやスナップショットからの復元は新しいクラスターになる(接続先の切り替えが必要)。

7. まとめ

  • AuroraはMySQL/PostgreSQL互換の高性能DB。共有ストレージで3AZ・6コピー。
  • エンドポイントで書き込み・読み取りを使い分ける。
  • Serverless v2、グローバルDB、バックトラック、クローンなど独自機能が豊富。
