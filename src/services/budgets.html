1. サービス概要

AWS Budgetsは、AWSの費用や使用量に予算(目標の上限)を決めて、実績や予測が予算に近づいたとき・超えそうなときに通知するサービスです。通知だけでなく、超えたときは予算アクションで、IAMポリシーやSCPの適用、EC2・RDSインスタンスの停止を自動で行えます。

予算を作って通知を受けるだけなら料金はかかりません。予算アクションを使う場合の料金は4章で説明します。

2. 主な機能・特徴

  • 期間は、毎月・四半期・毎年・毎日(使用率・カバレッジ予算)から選べる。開始日と終了日を決めるカスタム期間(年度や案件期間に合わせる)も作れる。カスタム期間は自動では更新されず、終了日は開始日から3年以内にする。
  • コスト予算では、費用の計算方法(ブレンデッド、アンブレンデッド、償却など)を選べる。割引・返金・クレジット・税・サポート料金を含めるかも選べる。

通知

  • 通知の基準は、実績(課金が発生した後)と予測(発生する前)から選べる。予測の通知なら、予算を超えそうなことを先に知らせられる。
  • 送り先は、1つの通知あたりメールアドレス最大10件と、Amazon SNSトピック1つ。
  • 予測の通知を計算するには、約5週間分の利用データが必要。データがそろうまでは、予測のアラートは発動しない。
  • 課金から通知までには遅れがある。請求データの更新に合わせて計算されるため、通知を受けたあとも費用が増えることがある。
  • 実績の通知は、予算期間ごとに1回だけ送られる。予測の通知は、予測値が予算を上下した場合に期間内で何度か送られることがある。

予算アクション

予算を超えた(または予測で超えそう)ときに、設定したアクションを自動で実行するか、承認したあとに実行するかを選べます。アクションの種類は次のとおりです。

  • IAMポリシーの適用:ユーザー・グループ・ロールに、EC2の新規作成を拒否するポリシーなどを付ける。
  • SCP(サービスコントロールポリシー)の適用:組織のメンバーアカウントに、管理アカウントからSCPを付ける。
  • EC2・RDSインスタンスの停止:対象のインスタンスを指定して停止する。

Budgets Reports(予算レポート)

複数の予算の状況を、日次・週次・月次のレポートとしてメールで受け取る機能です。予算の数が多いときに、どの予算が危ないかを一覧で確認できます。レポートは1通ごとに料金がかかります(4章)。

3. ユースケース

  • 月の費用が予算の一定割合を超えそうになったら、担当者にメールとSNSで知らせる
  • 開発用のアカウントで、予算を超えたら新しいEC2インスタンスを作れないようにする
  • Savings Plansの使用率が目標を下回ったら通知を受け、購入量を見直す
  • 年度末や案件期間に合わせたカスタム期間の予算で、期間全体の費用を管理する

4. 料金の考え方

予算の作成・監視・通知は無料です。予算アクションは、アクションを設定した予算のうち最初の2つまで無料です。3つ目以降は1つにつき1日$0.10かかります。1つの予算にアクションをいくつ設定しても、無料の枠の数は変わりません。

Budgets Reportsは、レポート1通ごとに$0.01かかります。

5. 関連サービス

  • AWS Cost Explorer:費用の内訳と推移の分析。どこで費用が増えているかを調べる
  • AWS Cost and Usage Reports:詳細な請求データの出力
  • Savings Plans:使用率・カバレッジの予算で、購入量が適切かを監視
  • AWS Organizations:管理アカウントから、メンバーアカウントの予算やSCPを使う
  • AWS IAM:予算アクションで適用するポリシー。Budgetsがアクションを実行するためのロール
  • Amazon EC2/Amazon RDS:予算アクションで停止できるインスタンス
  • Amazon SNS:予算の通知の送り先になるトピック
  • Amazon CloudWatch:請求額のアラーム。予算とは別に用意する監視の仕組み
  • 関連する用語:コスト管理ツールの選び方、料金の基本

6. 試験・実務でのポイント

通知と予測

  • 「費用が予算を超えそうなら、先に知らせたい」→ 予測の通知。実績の通知は、課金が発生したあとに送られる。
  • 予測の通知が出ない → 利用データが約5週間分そろっていない(使い始めたばかりのアカウントなど)。
  • 通知が遅れる → 請求データは1日1回以上更新され、予算の状況は最大で1日3回更新される。リアルタイムの監視ではない。
  • 通知の送り先は、メール最大10件と、SNSトピック1つ(1通知につき)。SNSを使うと、SMSなど別の方法でも受け取れる。

予算アクション

  • 「超えたら新しいEC2を作れないようにしたい」→ 予算アクションでIAMポリシーまたはSCPを適用する。
  • 「超えたらインスタンスを止めたい」→ EC2・RDSを対象に指定する。Auto Scalingグループの中のインスタンスは、停止しても再起動や新規の起動が行われるため、起動の権限を外す2つ目のアクションを組み合わせる。
  • 管理アカウントから、別のアカウントのEC2・RDSを停止の対象にはできない(SCPは別のアカウントに適用できる)。

使い分け・組織

  • 費用の内訳や推移を見る → Cost Explorer。目標との差を知らせる・制限する → Budgets。詳しくはコスト管理ツールの選び方。
  • RI・Savings Plansの使用率やカバレッジが下がったら知らせたい → 使用率予算・カバレッジ予算。
  • 管理アカウントは、メンバーアカウントの費用を追う予算を作れる。ただし、メンバーアカウントが同じ予算を見るには、管理アカウントへのアクセス権が必要。

SOA-C03での位置づけ

  • 費用の監視(通知)と自動の制限(アクション)を組み合わせた運用の例として扱う。
  • Cost Explorerとの違い(分析するか、目標を監視するか)を区別できることが基本。

7. まとめ

  • AWS Budgetsは、費用や使用量の予算に対して、実績と予測を監視して通知する。
  • 予算アクションで、IAMポリシー・SCPの適用やEC2・RDSの停止を、自動または承認後に行える。
  • 分析はCost Explorer、目標との比較と制限はBudgetsと使い分ける。
