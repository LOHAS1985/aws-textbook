1. サービス概要

AWS Certificate Manager(ACM)は、SSL/TLS証明書の発行・管理・自動更新を行うサービスです。

  • SSL/TLS証明書:HTTPS通信で「そのサーバーが本物である」ことを証明する電子証明書(SSLは旧規格)。
  • ACM証明書:ACMで使われるTLS証明書。

2. 主な機能・特徴

  • リージョンサービス:証明書はリージョンごとに発行が必要。
  • CloudFrontはus-east-1のACM証明書のみ参照可能。

証明書の発行・管理

  • 発行:パブリック証明書は無料
  • 配布:対応サービスにアタッチ
  • 更新:期限前に自動で更新
  • 失効・状態管理

証明書の配置

証明書はTLS終端に配置します。ALBやCloudFrontなど、クライアントからアクセスされるサーバー側の入り口に置くことが多く、通信開始時に証明書がクライアントに送られます。

SSL/TLS証明書の役割

  1. サーバーの身元証明(認証):なりすまし対策。接続先が正当なサーバーかを証明する(証明書にはドメイン名や発行者が含まれる)。
  2. 通信の暗号化(機密性)
  3. 改ざん検知(完全性)

HTTPS通信が始まるまでの流れ

  1. クライアントがサーバーに接続要求を送信(ClientHello)
  2. サーバーがクライアントに証明書を送信
  3. クライアントが証明書を検証
  4. クライアントとサーバーがセッション鍵(データの暗号化・復号に使う鍵)を安全に共有
  5. 暗号化通信の開始

イベント

Certificate Approaching Expiration:証明書の有効期限が近いことを通知するイベントです(EventBridgeで受け取れる)。

3. ユースケース

  • ALBでHTTPS終端し、Webサイトを独自ドメインで公開
  • CloudFrontでの独自ドメインHTTPS配信(us-east-1で発行)
  • API Gatewayのカスタムドメイン

4. 料金の考え方

ACMのパブリック証明書は無料です。

プライベート証明書を発行する場合は、AWS Private CAの料金がかかります。

5. 関連サービス

  • Elastic Load Balancing:HTTPS終端
  • Amazon CloudFront:us-east-1の証明書を使用
  • Amazon API Gateway:カスタムドメイン
  • AWS Private CA:プライベート証明書の発行
  • Amazon EventBridge:期限切れ間近の通知

6. 試験・実務でのポイント

  • CloudFrontで使う証明書はus-east-1で発行。
  • ALBで使う証明書はALBと同じリージョンで発行(リージョンサービス)。
  • パブリック証明書は無料で自動更新。
  • 有効期限の監視 → Certificate Approaching Expirationイベント。

7. まとめ

  • ACMはSSL/TLS証明書の発行・管理・自動更新サービス。
  • 証明書はTLS終端(ALB・CloudFrontなど)に配置する。
  • リージョンサービスで、CloudFront用はus-east-1。
