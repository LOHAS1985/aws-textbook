1. サービス概要

AWS Resource Access Manager(RAM)は、自アカウントのリソースを他のAWSアカウントや、Organizationsの組織・OUと共有するサービスです。共有したリソースの管理は共有元が行います。

2. 主な機能・特徴

共有の仕組み

RAMでは、リソース共有(Resource Share)という単位で、次の3つを決めます。

要素内容
リソース共有したいもの(サブネット、Transit Gatewayなど)
プリンシパル共有する相手。AWSアカウント、Organizationsの組織全体やOU、一部のリソースではIAMロール・ユーザー
マネージド型アクセス許可共有先が、そのリソースに何をしてよいか(AWSが用意したものか、自分で作ったもの)
  • 組織内での共有:管理アカウントで「AWS Organizationsとの共有を有効化」しておくと、組織やOUを相手に指定でき、相手は招待を承認しなくてもすぐに使える。OUに後から入ったアカウントにも自動で共有される。
  • 組織外のアカウントとの共有:相手に招待が送られ、相手が承認すると使えるようになる(承認しないと使えない)。リソース共有の設定で「外部のプリンシパルを許可する」が必要。
  • 共有されたリソースは、相手のアカウントでも同じリージョンで見える。RAMの共有はリージョンごと(グローバルなリソースを除く)。
  • 共有元がリソースを削除したり、共有をやめたりすると、相手は使えなくなる。

共有できる主なリソース

  • VPCサブネット
  • Transit Gateway
  • Route 53 Resolverルール

VPCサブネットを共有すると、共有先のアカウントはそのサブネットにEC2やRDSなどを起動できます(VPCの共有)。ただし、VPCやサブネット自体の変更は共有元(所有者)しかできません。この他にもLicense Managerの設定、Aurora DBクラスター、プレフィックスリストなど多くのリソースを共有できます。

リソース共有するとできること
VPCのサブネット共有先が、そのサブネットにEC2・RDS・Lambdaなどを起動する(VPCの共有)
Transit Gateway共有先が、自分のVPCをTransit Gatewayにアタッチする
Route 53 Resolverのルール共有先のVPCでも、オンプレミスのドメインを同じ転送ルールで名前解決する
マネージドプレフィックスリスト共有先のセキュリティグループやルートテーブルで、同じIPアドレスの一覧を参照する
IPAMのプール共有先がVPCを作るときに、重ならないCIDRを払い出してもらう
License Managerのライセンス設定組織全体で商用ソフトウェアのライセンス数を管理する
Aurora DBクラスター共有先がクラスターのクローンを作る
EC2のキャパシティ予約・Dedicated Hosts予約した容量や専有ホストを、ほかのアカウントでも使う
Network Firewallのポリシー、Image Builderのコンポーネント・レシピなど共通の設定やビルド部品を各アカウントで再利用する

RAMでは共有しないものも、試験ではひっかけとして出ます。

  • AMI・EBSスナップショット:それぞれの起動許可・作成ボリューム許可でアカウントを指定して共有する(RAMは使わない)。
  • S3バケット・KMSキー・SQSキューなど:リソースベースのポリシーで別アカウントを許可する。
  • VPCそのもの・セキュリティグループ:VPCは共有できず、共有するのはサブネット。共有先は自分のセキュリティグループを作る(所有者のセキュリティグループは参照できる)。

VPCの共有では、共有先(参加者)は自分が作ったリソースだけを管理でき、ほかの参加者や所有者のリソースは変更できません。また、AZの名前(ap-northeast-1a など)はアカウントごとに実際のAZとの対応が違うため、アカウントをまたいで同じAZを指すときはAZ ID(apne1-az1 など)を使います。

3. ユースケース

  • ネットワーク管理アカウントでVPCを一元管理し、各アプリアカウントにサブネットを共有
  • Transit Gatewayを組織全体で共有して、アカウント間のネットワークを接続
  • Route 53 Resolverルールを共有し、全アカウントでオンプレミスのDNSを名前解決

4. 料金の考え方

RAM自体は追加料金なしで利用できます。共有したリソースの料金は、それぞれのサービスの料金体系に従います。

5. 関連サービス

  • AWS Organizations:組織・OU単位での共有
  • Amazon VPC:サブネットの共有
  • AWS Transit Gateway:アカウント間で共有する代表的なリソース
  • Amazon Route 53:Resolverルールの共有

6. 試験・実務でのポイント

  • 「他アカウントとサブネット・Transit Gatewayを共有」→ RAM。
  • 共有したリソースの管理は共有元。
  • Organizations内で共有すると、招待の承認なしで共有できる(組織での共有を有効化した場合)。
  • 組織外のアカウントと共有 → 相手が招待を承認すると使える。RAMの共有はリージョンごと。
  • AMI・EBSスナップショットの共有はRAMではなく起動許可・作成ボリューム許可。S3・KMSはリソースベースのポリシー。
  • 共有したサブネットのAZをアカウント間で正しく合わせる → AZ名ではなくAZ IDで確認する。
  • VPCピアリング・Transit Gateway・PrivateLinkの使い分け → VPC同士をつなぐ方法の選び方。

7. まとめ

  • RAMはリソースをアカウント間・組織内で共有するサービス。管理は共有元が行う。
  • 共有は「リソース+相手(プリンシパル)+アクセス許可」のリソース共有で設定する。組織内なら承認不要、組織外は招待の承認が必要。
