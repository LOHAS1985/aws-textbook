1. サービス概要

AWS WAFは、Webアプリケーションに届くHTTP/HTTPSのリクエストの中身を検査して、許可・ブロック・カウントするWebアプリケーションファイアウォール(WAF)です。

セキュリティグループやネットワークACLはIPアドレスとポートしか見ませんが、WAFはURL・ヘッダー・クエリ文字列・本文まで見て判断できます。SQLインジェクション・クロスサイトスクリプティング(XSS)・ボット・大量アクセスなど、アプリケーション層(レイヤー7)の攻撃を防ぐのに使います。

2. 主な機能・特徴

保護できるリソース

  • CloudFrontディストリビューション
  • ALB(Application Load Balancer)
  • API GatewayのREST API
  • AppSyncのGraphQL API、Cognitoユーザープール、App Runner、Verified Access、Amplify など

NLBやEC2には直接付けられません。CloudFront用のWeb ACLはグローバル(us-east-1で作成)、ALBなど用はリージョンごとに作成します。

Web ACL とルール

要素説明
Web ACL(保護パック)ルールをまとめたもの。保護したいリソースに関連付ける。どのルールにも一致しないときの既定のアクション(許可/ブロック)を決める
ルール検査の条件とアクション。上から優先順位の順に評価される
ルールグループルールをまとめて再利用できるようにしたもの
マネージドルールAWSやベンダーが用意したルールグループ。SQLインジェクション・既知の悪い入力・悪意のあるIPリストなど
IPセット/正規表現パターンセットルールから参照する、IPアドレスや文字列パターンの一覧

主なルールの種類

  • IPアドレス(IPセット)での許可・拒否
  • 地域(国)での制限(ジオマッチ)
  • 文字列・正規表現・サイズ制限・SQLインジェクション・XSSの検査
  • レートベースルール:同じIPなどから一定時間内にリクエストが多すぎるとブロック(HTTPフラッドへの対策)
  • Bot Control(ボットの識別)、不正アカウント作成・乗っ取りの防止、CAPTCHA・チャレンジ

アクション

Allow(許可)・Block(ブロック)・Count(数えるだけ)・CAPTCHA・Challenge があります。新しいルールはまず Count で動かし、正常な通信を止めないことを確かめてから Block にするのが定番です。

ログと監視

  • Web ACLのログを CloudWatch Logs・S3・Data Firehose に出力できる(ロググループ名は aws-waf-logs- で始める必要がある)。
  • CloudWatchメトリクスで、ルールごとの許可・ブロック件数を確認できる。
  • 複数アカウントのWeb ACLを一括で配布・管理するには AWS Firewall Manager(Organizationsが前提)を使う。

3. ユースケース

  • CloudFront+ALBのWebサイトをSQLインジェクションやXSSから守る
  • 特定の国からのアクセスや、社外IPからの管理画面へのアクセスをブロックする
  • レートベースルールで、ログイン画面への総当たりやHTTPフラッドを抑える
  • 組織内の全アカウントのALBに同じWeb ACLを適用する(Firewall Manager)

4. 料金の考え方

Web ACLの数、ルールの数(いずれも月額)と、処理したリクエスト数に応じて課金されます。Bot Controlや不正防止のマネージドルールには追加料金がかかります。Shield Advancedの契約者は、保護対象リソースのWAF料金が含まれます。

5. 関連サービス

  • Amazon CloudFront/Elastic Load Balancing/Amazon API Gateway:保護する対象
  • AWS Shield:DDoS対策(WAFと組み合わせる)
  • AWS Network Firewall:VPC全体の通信を検査するファイアウォール
  • Amazon CloudWatch:ログ・メトリクス
  • AWS Organizations:Firewall Managerでの一括管理
  • ネットワークACLとセキュリティグループ:IP・ポート単位の制御

6. 試験・実務でのポイント

  • 「SQLインジェクション」「XSS」「HTTPヘッダーの検査」→ WAF。
  • 「特定IPからの大量リクエスト」→ レートベースルール。「特定の国をブロック」→ ジオマッチ(CloudFrontの地理的制限でも可)。
  • 付けられるのは CloudFront・ALB・API Gateway など。NLB・EC2には付けられない。
  • 新しいルールは Count で影響を確かめてから Block にする。
  • 複数アカウントへの一括適用 → Firewall Manager。
  • 大規模なDDoS対策とDDoS対応チームの支援 → Shield Advanced。

7. まとめ

  • WAFはHTTP/HTTPSのリクエストの中身を検査して、アプリケーション層の攻撃を防ぐ。
  • Web ACLにマネージドルールや独自ルールを入れて、CloudFront・ALB・API Gatewayに関連付ける。
