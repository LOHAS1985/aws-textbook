AWS Trusted Advisor

AWS環境を自動チェックし、ベストプラクティスに沿った改善を提案

最終更新:2026-10-26

1. サービス概要#

AWS Trusted Advisorは、AWS環境を自動でチェックし、ベストプラクティスに沿った改善を提案するサービスです。

2. 主な機能・特徴#

チェックの観点#

観点チェック例
コスト最適化使用率の低いEC2インスタンス、アイドル状態のELB、未使用のEBSボリューム
パフォーマンス高使用率のEC2インスタンス、EBSのプロビジョンドIOPSの過不足
セキュリティルートユーザーのMFA、セキュリティグループの無制限アクセス、S3バケットのパブリックアクセス
耐障害性RDSのマルチAZ未設定、EBSスナップショットの未取得
サービスクォータ上限に近づいているリソース(VPC、Elastic IP、EC2など)
オペレーショナルエクセレンスログ設定など運用面のベストプラクティス

3. ユースケース#

  • 無駄なリソースを洗い出してコスト削減
  • サービスクォータの上限到達を事前に検知
  • セキュリティの基本設定(MFA、公開設定)の確認

4. 料金の考え方#

Trusted Advisor自体は無料で使えますが、利用できるチェック項目はサポートプランによって異なります。Basicサポートでは一部のコアチェックのみで、Business Support+ 以上のサポートプラン(2026年までの旧プランではBusiness以上)ですべてのチェックが使えます(サポートプラン)。

5. 関連サービス#

  • AWS Health Dashboard:AWS側の障害・メンテナンスの影響を確認
  • AWS Compute Optimizer:機械学習によるリソースサイズの推奨
  • AWS Security Hub:セキュリティチェックの集約
  • Amazon EventBridge:チェック結果の変化を通知
  • 関連する用語:サービスクォータ、サポートプラン、AWS Well-Architected フレームワーク

6. 試験・実務でのポイント#

  • 「サービスクォータの上限に近い」→ Trusted Advisorのサービスクォータチェック。
  • 「未使用・低使用率のリソースでコスト削減」→ Trusted Advisorのコスト最適化。
  • より詳細なサイズ推奨(機械学習)→ Compute Optimizer。
  • GuardDuty・Inspector・Macie・Security Hub CSPMの使い分け → セキュリティ検出のサービスの選び方。

7. まとめ#

  • Trusted Advisorはコスト・パフォーマンス・セキュリティ・耐障害性・クォータ・運用の観点でAWS環境をチェックする。
