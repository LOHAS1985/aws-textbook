1. サービス概要#

AWS Elastic Disaster Recovery(略称はAWS DRS)は、オンプレミスや他のクラウドのサーバーを、AWSに継続的に複製しておき、障害のときにAWS上でサーバーを起動して業務を再開する災害復旧(DR)のサービスです。

本番と同じ規模の待機環境をAWSに常に置いておく必要はありません。複製先には、ステージングエリアと呼ばれる小さな領域だけを保っておき、障害のときに必要なEC2を起動します。待機のコストを抑えながら、RTOとRPOを短くできる点が特徴です。

2. 主な機能・特徴#

レプリケーションの仕組み#

  • レプリケーションエージェント(AWS Replication Agent)を、複製する本番サーバーにインストールする。ディスクへの変更を、ブロック単位で複製先へ送る。
  • 複製先は、選んだリージョンのAWSアカウント内にあるステージングエリア(専用のサブネット)。本番のディスクごとに、同じ容量のEBSボリューム(ステージングディスク)が作られる。
  • ステージングエリアには、複製サーバー(EC2)とステージングディスクがあり、待機中のコストを小さく抑えている。
  • 最初に初期同期を行い、その後は変更を継続的に送る(継続的データ保護、CDP)。CDPの状態から外れてからの経過時間がLag、まだ複製していないデータ量がBacklog。
  • 通信中のデータは暗号化される。復旧のときは、最新の状態か、過去の時点(ポイントインタイム)のどちらかで起動できる。ポイントインタイムは、EBSスナップショットで保持する。

ネットワークと準備#

  • 本番サーバーから、ステージングエリアの複製サーバーへ TCP 1500 番で送る。
  • 複製サーバーと本番サーバーは、DRSのAPIエンドポイント(HTTPS・TCP 443)へ送る。
  • ドリルと復旧のインスタンスは、サーバーごとの起動テンプレートで指定したサブネットに起動する。

ドリル(Recovery Drill)と復旧(Recovery)の違い#

ドリル(Recovery Drill)復旧(Recovery)
目的復旧の手順と起動の確認を、本番に影響させずに試す本番が障害になったときに、AWS上で業務を再開する
本番サーバーと複製影響を受けない。複製は続く業務を本番からAWSへ切り替える。切り替えはDRSの外で行う
起動するインスタンスドリルインスタンス(テストが終わったら削除する)復旧インスタンス(業務を続ける)
行う頻度の目安少なくとも四半期に1回障害のときだけ
  • 切り替え(フェイルオーバー)は、DRSの外で行う。Route 53などのDNSやトラフィック管理の仕組みで、通信の向き先を復旧インスタンスに変える。
  • 復旧後に、AWS上の業務を元の環境へ戻すのがフェイルバック。オンプレミスへ戻すときは、フェイルバック用のクライアントを使う。

RTOとRPO#

  • RPO(目標復旧時点):通常は1秒未満(sub-second)。障害の直前までのデータを復旧できる。ただし、Lagが続いてCDPの状態から外れたままだと、RPOは悪くなる。
  • RTO(目標復旧時間):通常は数分。OSの起動時間に左右される。起動するインスタンスタイプの在庫が不足すると、起動に時間がかかり、RTOに影響する。
  • RTOは、ドリルで実際の起動時間を測って、目標と比べる。

運用の流れ#

  1. 復旧先のリージョンでDRSを初期化する
  2. 本番サーバーにレプリケーションエージェントをインストールする
  3. 初期同期が終わり、Lagが増えていないことを確認する
  4. ドリルを行い、ドリルインスタンスの動作を確かめたら、削除する
  5. 障害のときは、復旧インスタンスを起動し、通信を切り替える
  6. 復旧後は、フェイルバックして元の環境へ戻す

台数の上限#

1つのAWSアカウントで複製できるサーバーは最大300台です。これを超えるときは、アカウントやリージョンを分けてDRSを設定します。

3. ユースケース#

  • オンプレミスのデータセンターの障害に備えて、AWSを復旧先にする
  • 他のクラウドで動かしているサーバーを、AWSに複製して復旧先にする
  • リージョン全体の障害に備えて、AWSの別のリージョンを復旧先にする
  • 定期的にドリルを行い、復旧の手順と起動時間を確かめて、DR計画を更新する

4. 料金の考え方#

DRSの料金は、複製しているサーバーの台数と時間で決まります。ソースサーバー1台あたり1時間$0.028で、最低料金も前払いもありません。この料金には、継続的な複製、テストの起動(ドリル)、復旧の起動、ポイントインタイムの復旧が含まれます。

これとは別に、AWS側のリソースの料金がかかります。主なものは、ステージングエリアのEBSボリューム(本番のディスクと同じ容量)、複製サーバーのEC2、ドリルや復旧で起動したEC2とEBSです。ドリルのインスタンスは、テストが終わったら削除しないと、通常のEC2の料金がかかり続けます。

5. 関連サービス#

  • Amazon EC2:複製サーバーと、ドリル・復旧で起動するインスタンス
  • Amazon EBS:ステージングディスク、ポイントインタイムを保持するスナップショット
  • Amazon Route 53:障害時に通信の向き先をAWSへ切り替える(DRSの外で行う)
  • AWS Application Recovery Controller:切り替えの準備と制御
  • AWS Backup:決めた時点の復旧ポイントを保管する。誤削除やランサムウェアへの備えとして併用する
  • Amazon EventBridge:DRSが出すイベント(レプリケーションの状態の変化)を検知する
  • 関連する用語:DR戦略、リージョンとアベイラビリティーゾーン

6. 試験・実務でのポイント#

仕組みと数字

  • 「オンプレミスや他のクラウドのサーバーを、AWSの災害復旧先に継続的に複製したい」→ AWS Elastic Disaster Recovery。
  • RPOは通常1秒未満、RTOは通常数分。RTOはOSの起動時間に左右される。
  • 複製先は、ステージングエリアの複製サーバーとEBSボリューム。障害のときにだけ、EC2を起動する。

ドリルと切り替え

  • 「本番に影響させず、復旧の手順と起動時間を確かめたい」→ Recovery Drill(ドリル)。少なくとも四半期に1回。
  • 通信の切り替え(フェイルオーバー)は、DRSの外で行う。Route 53などで向き先を変える。
  • ドリルで起動したEC2は、テストが終わったら削除する。残すと料金がかかり続ける。

ほかのバックアップ・DRとの違い

  • AWS Backupは、決めた時点の復旧ポイントを保管する。DRSは、サーバーを継続的に複製し、起動して復旧する。
  • 複製は、誤った変更やランサムウェアによる暗号化もそのまま複製する。誤削除やランサムウェアには、AWS Backupと併用する。
  • DR戦略の比較では、待機コストを小さく抑えたまま、RTOとRPOを短くできる仕組みとして位置づけられる。

制限と試験での位置づけ

  • 1つのAWSアカウントで複製できるサーバーは最大300台。
  • SOA-C03では、信頼性・事業継続の文脈で、RTOとRPOの違い、ドリル(テスト)と復旧の違いを区別することが基本。

7. まとめ#

  • AWS DRSは、サーバーを継続的に複製し、障害のときにAWSで数分で起動する災害復旧サービス。
  • 複製先は低コストのステージングエリアに保ち、RTOとRPOを短くできる。
  • ドリルで復旧を定期的に試し、切り替え(Route 53など)とフェイルバックはDRSの外で扱う。
