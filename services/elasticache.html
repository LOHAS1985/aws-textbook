Amazon ElastiCache

アプリのデータをインメモリでキャッシュするサービス

1. サービス概要

Amazon ElastiCacheは、アプリケーションで利用するデータをインメモリでキャッシュするサービスです。よく使うデータをメモリに置くことで、DBの負荷を下げ、応答を高速化します。

2. 主な機能・特徴

キャッシュする対象

  • DBのキャッシュ:RDS、Aurora、DynamoDB
  • API呼び出しの結果:外部APIやマイクロサービスのレスポンス
  • セッションデータ:Webアプリのユーザーセッション情報
  • 計算結果:重い計算処理やクエリ集計の結果(再計算を回避)

エンジンの種類

項目Valkey / Redis OSSMemcached
機能高機能シンプル
レプリケーション・自動フェイルオーバー○×
バックアップ(スナップショット)○×(ノードを自分で選ぶ構成の場合)
コマンドの処理1本のスレッドで順に処理(通信の処理は複数スレッドで並列化される)複数スレッドで並列に処理
複雑性高低

エンジンは、Redisと互換のオープンソースValkey、Redis OSS、Memcachedから選びます。ValkeyとRedis OSSは同じように使え、レプリケーション・自動フェイルオーバー・バックアップに対応し、ソート済みセット(ランキング)などのデータ構造も使えます。

キャッシュ戦略

  • リードスルー:アプリがキャッシュを読む → なければキャッシュがソースから読み込み、キャッシュに書き込む。
  • レイジーローディング:アプリがキャッシュを読む → なければアプリがソースから読み込み、キャッシュに書き込む。
  • ライトスルー(同期):アプリがキャッシュに書き込み → キャッシュがソースに書き込む。
  • ライトビハインド(非同期):アプリがキャッシュに書き込み → キャッシュが後からソースに書き込む。
戦略読み込み書き込みDB同期特徴
リードスルー自動取得-即キャッシュ主導
レイジーローディング必要時に取得-即アプリ主導
ライトスルー高速同期即整合性重視
ライトビハインド高速非同期遅延性能重視

3. ユースケース

  • RDSの読み取り負荷の軽減
  • 複数のWebサーバー間でのセッション共有
  • ランキングや集計結果のキャッシュ

4. 料金の考え方

キャッシュノードのタイプと稼働時間で課金されます(サーバーレス版はデータ保存量と処理量で課金)。リザーブドノードで割引も可能です。

5. 関連サービス

  • Amazon RDS/Amazon Aurora/Amazon DynamoDB:キャッシュ対象のDB
  • Amazon MemoryDB:Redis互換の永続的なインメモリDB
  • DynamoDB DAX:DynamoDB専用のキャッシュ

6. 試験・実務でのポイント

  • レプリケーション・フェイルオーバー・バックアップ・高機能なデータ構造 → Valkey/Redis OSS、シンプル・マルチスレッド → Memcached。
  • 必要なデータだけをキャッシュ(アプリ主導)→ レイジーローディング。ただし初回はキャッシュミスで遅く、古いデータが残る可能性がある。
  • キャッシュとDBの整合性重視 → ライトスルー。
  • 書き込み性能重視 → ライトビハインド(DBへの反映は遅延)。

7. まとめ

  • ElastiCacheはインメモリキャッシュ。DB負荷の軽減と高速化に使う。
  • エンジンはValkey・Redis OSS・Memcached。
  • キャッシュ戦略は読み込み2種・書き込み2種の特徴を押さえる。
