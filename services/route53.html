Amazon Route 53

マネージドDNSサービス

最終更新:2026-10-25

1. サービス概要#

Amazon Route 53は、マネージドDNSサービスです。ドメイン名とIPアドレスを結びつける名前解決のほか、ドメイン登録やヘルスチェックもできます。

2. 主な機能・特徴#

  • DNS解決(仕組みは用語「DNS」、レコードの種類は「DNSレコードタイプ」を参照)
  • ドメイン登録
  • ヘルスチェック/可用性モニタリング

ホストゾーン#

DNSレコードを管理するコンテナです。

  • パブリックホストゾーン:インターネット上での名前解決
  • プライベートホストゾーン:指定したVPC内でのみ有効な名前解決

ルーティングポリシー#

種類概要主な用途
シンプル複数の値を返せる基本的なルーティング単純な名前解決
加重(Weighted)重みを指定してトラフィックを分散A/Bテスト、段階的なリリース、負荷分散
レイテンシー最もレイテンシーが低いリージョンのリソースへルーティンググローバルなWebサービスの高速化
フェイルオーバープライマリが利用できない場合にセカンダリへ切り替え可用性向上、DR構成
位置情報(Geolocation)ユーザーの地理的位置に基づいてルーティング国・地域ごとのコンテンツ配信
地理的近接性(Geoproximity)ユーザーとリソースの地理的位置に基づく。バイアスで調整可能地理的なトラフィック配分
IPベースクライアントのIPアドレスとCIDRの対応付けに基づく特定ネットワーク・IP範囲からのトラフィック制御
複数値回答複数の正常なリソースの値を返し、クライアント側で選ぶシンプルな可用性向上
トラフィックフロー複数のポリシーを組み合わせた複雑な制御複雑なグローバルルーティング

Application Recovery Controller(ARC)#

アプリケーションの可用性と復旧を安全・確実に行うための機能です。

項目概要
ルーティングコントロールルーティングをスイッチで切り替える
セーフティルールルールを決めて誤操作を防ぐ
ゾーンシフト単一AZ障害に対し、そのAZへのトラフィックを数分で止める
準備状況チェック切り替え先が動く状態かを確認する
リージョンスイッチ複数リージョン間のフェイルオーバーを計画に沿って実行する

3. ユースケース#

  • 独自ドメインでWebサイトを公開
  • フェイルオーバーで障害時に待機系サイトへ切り替え
  • 新バージョンへ10%だけトラフィックを流す(加重)
  • VPC内の社内システムの名前解決(プライベートホストゾーン)

4. 料金の考え方#

ホストゾーンごとの月額料金、DNSクエリ数、ヘルスチェック数、ドメイン登録料で課金されます。AWSリソース(ELB・CloudFrontなど)を指すエイリアスレコードへのクエリは無料です。

5. 関連サービス#

  • Elastic Load Balancing/Amazon CloudFront:エイリアスレコードの向き先
  • Amazon VPC:プライベートホストゾーンの関連付け先
  • AWS Global Accelerator:DNSに依存しないグローバルなトラフィック制御
  • Amazon CloudWatch:ヘルスチェックのアラーム
  • Route 53 Resolver DNS Firewall:VPCからのDNS問い合わせのフィルタリング
  • Amazon Application Recovery Controller:確実なリージョンのフェイルオーバー

6. 試験・実務でのポイント#

  • A/Bテスト・段階リリース → 加重。DR → フェイルオーバー。速いリージョンへ → レイテンシー。
  • 国ごとにコンテンツを分ける(法規制など)→ 位置情報。
  • VPC内だけで使う名前 → プライベートホストゾーン。
  • AZ障害時にすばやくトラフィックを外す → ARCのゾーンシフト。

7. まとめ#

  • Route 53はDNS・ドメイン登録・ヘルスチェックを提供する。
  • ホストゾーンはパブリックとプライベートの2種類。
  • ルーティングポリシーを目的に応じて選び分ける。

このサービスが登場するユースケース#

  • 誤操作したRDSのデータを特定の時点に戻す自動バックアップのポイントインタイムリカバリ(PITR)で、誤操作の直前の状態のDBを作り直す
  • リージョン障害に備えて別リージョンへ切り替えるRoute 53のフェイルオーバーとAuroraグローバルデータベースで、ウォームスタンバイを構成する
  • オンプレミスとVPCで互いの名前を解決するRoute 53 Resolverのインバウンド・アウトバウンドエンドポイントと転送ルールで、ハイブリッド環境の名前解決をつなぐ
  • 利用者の場所や割合でアクセスを振り分けるRoute 53のルーティングポリシーとヘルスチェックで、レイテンシー・地域・重み付けによる振り分けと切り替えを行う
  • S3とCloudFrontで静的サイトを安全に配信する独自ドメイン・HTTPS・OACで、S3を公開せずに高速配信する
