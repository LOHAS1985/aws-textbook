AWS Transit Gateway

多数のVPCとオンプレミスをハブ&スポークでつなぐ中継ルーター

最終更新:2026-10-24

1. サービス概要#

AWS Transit Gateway(TGW)は、複数のVPCやオンプレミスのネットワークを1か所に集めて接続する、リージョン単位の中継ルーターです。各ネットワークをTransit Gatewayにつなぐだけで、つながったネットワーク同士が通信できるようになります(ハブ&スポーク型)。

VPCピアリングは「1対1」の接続で、VPCが増えると接続の数が急に増えます。Transit Gatewayなら、接続はVPCの数だけで済みます。

2. 主な機能・特徴#

アタッチメント(つなぐもの)#

アタッチメント内容
VPCVPCの各AZのサブネットにTGW用のネットワークインターフェイスを置いて接続する
Site-to-Site VPNオンプレミスとIPsec VPNで接続する
Direct Connect ゲートウェイ専用線(トランジットVIF)で接続する
ピアリング別のTransit Gateway(別リージョンも可)と接続する
ConnectSD-WANなどのネットワーク機器とGRE+BGPで接続する

Transit Gatewayのルートテーブル#

Transit Gatewayにも専用のルートテーブルがあり、「どのアタッチメントから来た通信を、どのアタッチメントへ送るか」を決めます。

  • 関連付け(Association):アタッチメントから入ってきた通信を、どのルートテーブルで判断するか。
  • 伝播(Propagation):アタッチメントのCIDRを、ルートテーブルに自動で登録するか。

ルートテーブルを複数に分けると、「本番VPCと開発VPCは通信させない。どちらも共有サービスVPCとオンプレミスにはつなぐ」のようなネットワークの分離(セグメンテーション)ができます。

あわせて、各VPCのサブネットのルートテーブルにも「相手のCIDR → Transit Gateway」の経路を追加する必要があります。

そのほかの特徴#

  • 推移的なルーティング:A→TGW→B のように中継できる(VPCピアリングはできない)。
  • アカウント間の共有:AWS RAMでTransit Gatewayを他アカウントと共有し、各アカウントのVPCをつなげる。
  • VPNのECMP:複数のVPN接続に通信を分散し、帯域を増やせる(VGWではできない)。
  • アプライアンスモード:ファイアウォールなどの検査用VPCを通すとき、行きと帰りの通信が同じAZの機器を通るようにする。
  • フローログ:Transit Gatewayを通る通信を記録できる(VPCフローログと同じ仕組み)。
  • CIDRが重複しているVPC同士は、そのままではルーティングできない。

3. ユースケース#

  • 数十〜数百のVPCとオンプレミスをまとめて接続する
  • マルチアカウント環境で、共有サービス(認証・監視など)のVPCに各アカウントからつなぐ
  • インターネットへの出口(NAT・ファイアウォール)を1つのVPCに集約する
  • リージョン間ピアリングで、複数リージョンのネットワークをつなぐ

4. 料金の考え方#

アタッチメントごとの時間料金と、Transit Gatewayを通ったデータ量(GB)に応じた処理料金がかかります。VPCが2〜3個で通信量が多い場合は、データ処理料金のかからないVPCピアリングの方が安くなることがあります。

5. 関連サービス#

  • Amazon VPC:接続するネットワーク。少数の接続ならVPCピアリング
  • AWS Site-to-Site VPN/AWS Direct Connect:オンプレミスとの接続
  • AWS Resource Access Manager:Transit Gatewayのアカウント間共有
  • Amazon CloudWatch:通信量などのメトリクス

6. 試験・実務でのポイント#

  • 「多数のVPC」「オンプレミスも含めて」「推移的に接続」→ Transit Gateway。2つのVPCだけならVPCピアリング。
  • 他アカウントのVPCをつなぐ → RAMで共有する。
  • 通信できない → TGWのルートテーブル(関連付け・伝播)と、VPC側のルートテーブルの両方を確認する。セキュリティグループ・ネットワークACLも確認。
  • VPNの帯域を増やしたい → TGW+複数VPN+ECMP。
  • 本番と開発を分離したい → TGWのルートテーブルを分ける。

7. まとめ#

  • リージョン単位の中継ルーターで、VPC・VPN・Direct Connectをハブ&スポークでつなぐ。
  • ルートテーブルの関連付け・伝播で経路を管理し、分離もできる。
  • RAMでアカウント間共有、ピアリングでリージョン間接続。
  • 料金はアタッチメント時間+データ処理量。

このサービスが登場するユースケース#

  • 複数のVPCとオンプレミスを接続するTransit Gatewayをハブにして、多数のVPCと社内ネットワークをつなぐ
  • 社員の端末からVPCの社内システムに安全に接続するClient VPNとSAML認証で、テレワーク中の社員を部署ごとの権限でVPCやオンプレミスにつなぐ
