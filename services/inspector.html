Amazon Inspector

EC2・コンテナイメージ・Lambdaのソフトウェアの脆弱性とネットワークの露出を継続的にスキャン

最終更新:2026-10-31

1. サービス概要#

Amazon Inspectorは、EC2インスタンス・ECRのコンテナイメージ・Lambda関数を自動で見つけ、ソフトウェアの脆弱性(CVE)や意図しないネットワークの露出を継続的にスキャンする脆弱性管理サービスです。

スキャンの予定を組む必要はありません。パッケージのインストールやパッチの適用、新しいCVEの公開などをきっかけに、自動で再スキャンします。

2. 主な機能・特徴#

スキャンの種類#

対象調べる内容しくみ
EC2インスタンスOS・パッケージの脆弱性、インターネットから到達できるポートSSMエージェントで情報を集める方式と、EBSスナップショットを読むエージェントレス方式がある
ECRのコンテナイメージイメージ内のOS・言語パッケージの脆弱性プッシュ時と、新しいCVEの公開時に再スキャン
Lambda関数依存パッケージの脆弱性(標準)、コード自体の欠陥(コードスキャン)関数のデプロイ・更新時にスキャン

EC2のエージェント方式では、インスタンスがSystems Managerのマネージドノードになっている必要があります(SSMエージェントとIAMロールが必要)。

Inspectorリスクスコア#

公開されている脆弱性の基本スコア(CVSS)を、実際の環境に合わせて調整したスコアです。例えば、ネットワーク経由で悪用される脆弱性でも、インターネットへの経路がないインスタンスではスコアが下がります。

そのほかの機能#

  • ソフトウェア部品表(SBOM)の出力
  • CISベンチマークに沿ったOS設定のチェック(EC2)
  • 抑制ルールで対象外の検出結果を非表示にする
  • Organizations の委任管理者で組織全体を一括で有効化し、新しいアカウントにも自動で有効化できる

似たサービスとの違い#

サービス見つけるもの
Inspectorソフトウェアの脆弱性、ネットワークの露出
GuardDuty実際に起きている不審な動き(脅威)
MacieS3の機密データ
Systems Manager Patch Manager(見つけるのではなく)パッチを適用する

3. ユースケース#

  • 全EC2インスタンスの脆弱性を継続的に把握し、重大なものから対応する
  • ECRにプッシュしたイメージに重大な脆弱性があれば、EventBridge経由で通知してデプロイを止める
  • 検出結果をもとに Patch Manager でパッチを適用し、修正されたことをInspectorで確認する

4. 料金の考え方#

スキャン対象の数で課金されます。EC2はスキャンしたインスタンス数(月平均)、ECRはスキャンしたイメージ数、Lambdaはスキャンした関数数が基準です。新しいアカウントには15日間の無料試用があります。

5. 関連サービス#

  • Amazon EC2/Amazon ECR/AWS Lambda:スキャン対象
  • AWS Systems Manager:EC2の情報収集(SSMエージェント)とパッチ適用
  • AWS Security Hub:検出結果の集約
  • Amazon EventBridge:検出結果をトリガーにした自動対応
  • Amazon GuardDuty:脅威の検出

6. 試験・実務でのポイント#

  • 「脆弱性」「CVE」「コンテナイメージのスキャン」→ Inspector。
  • EC2のエージェント方式は SSMエージェントが前提。スキャンされないときは、マネージドノードになっているかを確認する。
  • スキャンは自動・継続的。手動でスケジュールを組む必要はない。
  • 見つけるのはInspector、直すのは Patch Manager。
  • GuardDuty・Inspector・Macie・Security Hub CSPMの使い分け → セキュリティ検出のサービスの選び方。

7. まとめ#

  • InspectorはEC2・ECR・Lambdaの脆弱性を継続的にスキャンするサービス。
  • 環境に合わせたリスクスコアで、優先して直すべきものが分かる。

このサービスが登場する運用シナリオ#

  • 多数のEC2に定期的にパッチを適用する
  • パッチ適用済みのAMIを定期的に作り、Auto Scalingに反映する
  • 脆弱性を継続的に検出し、パッチ適用まで自動化する
