AWS Service Catalog

承認済みの構成を「製品」としてカタログから起動させる

最終更新:2026-10-25

1. サービス概要#

AWS Service Catalogは、構成(CloudFormationテンプレート)を製品としてカタログにまとめ、利用者がそこから起動できるようにするサービスです。

2. 主な機能・特徴#

  • 製品:CloudFormationテンプレートで定義した構成。
  • ポートフォリオ:関連する製品をまとめたもの。他のアカウントから共有(インポート)されたポートフォリオでは、製品や制約を変更できない。受け取った側の管理者ができるのは、利用者(IAMユーザー/グループ/ロール)へのアクセス許可の付与と、製品を自分のアカウントのローカルポートフォリオに追加すること。ローカルポートフォリオでは制約を追加できるが、共有元から引き継いだ制約は外せない。

管理者は、ポートフォリオに対して「誰が使えるか(IAMユーザー/グループ/ロール)」と「制約」を設定します。起動制約を使うと、利用者本人には強い権限がなくても、指定したIAMロールの権限で製品を起動できます。ポートフォリオは他のアカウントやOrganizations全体と共有できます。

3. ユースケース#

  • 社内で承認済みの構成(暗号化済みS3、標準VPCなど)だけを開発者に使わせる
  • 開発者にEC2の作成権限を直接与えずに、決められた構成のサーバーだけを起動させる
  • 複数アカウントへ標準構成を配布

4. 料金の考え方#

APIの呼び出し回数に応じて課金されます(無料枠あり)。製品として起動したリソースには、それぞれの料金がかかります。

5. 関連サービス#

  • AWS CloudFormation:製品の実体となるテンプレート
  • AWS Organizations:ポートフォリオの共有先
  • AWS IAM:利用者の制御、起動制約

6. 試験・実務でのポイント#

  • 「承認済みの構成だけをセルフサービスで起動させたい」→ Service Catalog。
  • 共有されたポートフォリオの製品・制約は変更できない。別の起動制約を使いたいときは、製品をローカルポートフォリオに追加して設定する。
  • 利用者に広い権限を与えずに起動させる → 起動制約。

7. まとめ#

  • Service CatalogはCloudFormationテンプレートを製品として配布・起動させるサービス。
  • 製品はポートフォリオにまとめて共有する。
