Amazon ECR

コンテナイメージを保存・管理するレジストリ

最終更新:2026-10-24

1. サービス概要#

Amazon ECR(Elastic Container Registry)は、コンテナイメージを保存・管理するためのサービスです。ECSやEKS、Lambdaはここからイメージを取得(プル)して起動します。

2. 主な機能・特徴#

  • イメージの保存と管理:Dockerイメージをリポジトリ単位で管理し、バージョン管理ができる。
  • セキュリティ:IAMと統合し、プッシュ/プルを制御する。

コンテナ運用の流れ#

  1. ビルド:アプリをコンテナ化
  2. 保管:ECRにイメージをプッシュ
  3. 実行:ECRからプルして起動

タグ管理#

タグはコンテナイメージの識別名です。

  • 形式:リポジトリ:タグ(例:myapp:v1 = myappのv1版)
  • 保存の構造:リポジトリ → タグ → イメージダイジェスト(イメージ実体のハッシュ値)
  • タグの例:latest(最新版)、v1.0.0(固定版)、dev(開発環境)、staging(ステージング)

ECRには、プッシュ時のイメージの脆弱性スキャン、古いイメージを自動削除するライフサイクルポリシー、他リージョン・他アカウントへのレプリケーションなどの機能もあります。

3. ユースケース#

  • ECS/EKSで動かすアプリのイメージ置き場
  • 250MBを超えるLambda関数をコンテナイメージとしてデプロイ
  • CI/CDパイプライン(CodeBuild)でビルドしたイメージの保管

4. 料金の考え方#

保存しているイメージのストレージ容量と、データ転送量に応じて課金されます。不要なイメージはライフサイクルポリシーで削除するとコストを抑えられます。

5. 関連サービス#

  • Amazon ECS/Amazon EKS:イメージをプルして実行
  • AWS Lambda:コンテナイメージによるデプロイ
  • AWS IAM:プッシュ/プルの権限制御
  • AWS CodeBuild:イメージのビルドとプッシュ

6. 試験・実務でのポイント#

  • プッシュ/プルの権限はIAMで制御する。
  • latest タグは中身が変わるため、本番では固定のバージョンタグやダイジェストで指定すると安全。
  • イメージの実体はダイジェスト(ハッシュ値)で一意に識別される。

7. まとめ#

  • ECRはコンテナイメージのレジストリ。ビルド → プッシュ → プルの流れで使う。
  • イメージは「リポジトリ:タグ」で識別し、実体はダイジェストで管理される。

このサービスが登場する運用シナリオ#

  • ECSのサービスを止めずに更新し、失敗したら自動で戻すローリング更新の割合を調整し、デプロイサーキットブレーカーとアラームで失敗時に自動ロールバックする
  • 脆弱性を継続的に検出し、パッチ適用まで自動化するInspectorで脆弱性を見つけ、重大なものはEventBridgeから通知・Patch Managerでの修正につなげる
