1. サービス概要#

Route 53 Resolver DNS Firewallは、VPC内のリソースが Route 53 Resolver(VPCのDNS)に送る問い合わせを、ドメイン名で許可・ブロックする機能です。

マルウェアの指令サーバーや、データを持ち出すために使われるドメインの名前解決を止めることで、不正なドメインへの通信を入口で防ぎます。DNSの問い合わせを使ってデータを外に送る攻撃(DNSトンネリング・DNS経由のデータ持ち出し)への対策にもなります。

2. 主な機能・特徴#

構成要素#

要素説明
ドメインリスト対象にするドメインの一覧。自分で作るものと、AWSが管理するもの(マルウェア・ボットネットの指令サーバーなど)がある
ルールドメインリストと、一致したときのアクション(許可・アラート・ブロック)の組み合わせ。優先順位の順に評価される
ルールグループルールをまとめたもの。VPCに関連付けて使う。RAMで他のアカウントと共有できる

ブロックしたときの応答#

  • NODATA(該当するレコードがない)
  • NXDOMAIN(ドメインが存在しない)
  • OVERRIDE(指定したドメイン名に向ける。警告用ページなど)

許可リスト方式とブロックリスト方式#

  • ブロックリスト方式:危険なドメインだけをブロックする(AWS管理のドメインリストを使うと手軽)。
  • 許可リスト方式:使ってよいドメインだけを許可し、最後に「すべてのドメイン(*)をブロック」するルールを置く。

フェイルオープン/フェイルクローズ#

DNS Firewallが応答できない状態になったとき、問い合わせを通すか(フェイルオープン=可用性重視)止めるか(フェイルクローズ=セキュリティ重視)をVPCごとに設定できます。既定はフェイルクローズです。

注意点#

  • 対象はRoute 53 Resolverへの問い合わせだけ。インスタンスが外部のDNSサーバー(8.8.8.8など)を直接使うと防げない。この抜け道はセキュリティグループ・ネットワークACL・Network Firewallで塞ぐ。
  • ドメイン名で判定するので、IPアドレスを直接指定した通信は防げない。
  • 問い合わせの記録は Resolverクエリログ(CloudWatch Logs・S3・Data Firehoseへ出力)で確認する。
  • Firewall Managerで組織全体のVPCに一括で関連付けられる。

3. ユースケース#

  • マルウェアに感染したインスタンスが指令サーバーと通信できないようにする
  • 閉じた環境のVPCで、業務に必要なドメインだけ名前解決できるようにする
  • DNSを使ったデータ持ち出しの防止

4. 料金の考え方#

ルールグループに含めたドメインの数(月額)と、処理したDNSの問い合わせ数に応じて課金されます。

5. 関連サービス#

  • Amazon Route 53:Resolver(VPCのDNS)
  • AWS Network Firewall:DNS以外も含めた通信全体の検査
  • Amazon GuardDuty:DNSログから不審な問い合わせを検出
  • AWS RAM:ルールグループの共有
  • DNS

6. 試験・実務でのポイント#

  • 「VPCから悪意のあるドメインへの名前解決をブロック」「DNS経由のデータ持ち出し」→ DNS Firewall。
  • 許可リスト方式は、許可ルールの後に全ドメインをブロックするルールを置く。
  • 可用性を優先するならフェイルオープン、セキュリティを優先するならフェイルクローズ。
  • GuardDutyは「検出」、DNS Firewallは「ブロック」。

7. まとめ#

  • DNS Firewallは、VPCのDNS問い合わせをドメイン名でフィルタリングする機能。
  • 不正なドメインへの通信を、名前解決の段階で止められる。

このサービスが登場するユースケース#

  • 外向きの通信を許可したドメインだけに制限するNetwork FirewallとRoute 53 Resolver DNS Firewallで、サーバーから不正な宛先への通信と名前解決を止める
