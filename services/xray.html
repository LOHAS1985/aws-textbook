1. サービス概要#

AWS X-Rayは、分散アプリケーションの処理の流れを可視化・分析し、性能問題やエラーの原因を特定するためのトレーシングサービスです。

2. 主な機能・特徴#

用語#

  • トレース:1つのユーザーリクエスト全体(例:API Gateway → Lambda → DynamoDB)。複数サービスをまたぐ流れを追跡するのが分散トレース。各サービスでアクティブトレースを有効にする。
  • セグメント:各AWSサービス単位の処理(例:Lambdaの処理、EC2の処理)
  • サブセグメント:アプリ内部の処理(例:DBクエリ、外部API呼び出し)
  • アノテーション:検索・フィルターできる情報(ユーザーID、リージョンなど)
  • メタデータ:検索できない詳細データ(インデックス化されない。デバッグメモ、リクエスト本文など)
  • サービスマップ:トレースデータを視覚的に表したもの
Trace(1つのリクエスト全体)
├─ Segment(API Gateway)
│    ├─ Annotations: customerId=12345, plan=premium
│    └─ Metadata:    requestBody, responseBody
├─ Segment(Lambda)
│    ├─ Annotations: customerId=12345, region=tokyo
│    └─ Metadata:    debugInfo
└─ Segment(RDS)
     ├─ Annotations: db=mysql
     └─ Metadata:    SQL文の詳細

トレースの実装の流れ#

  1. アプリにX-Ray SDKを組み込む(Java、Node.js、Pythonなどに対応)
  2. サーバーやコンテナでX-Rayデーモンを起動
  3. リクエストにトレースIDを付け、各サービス呼び出しでセグメント/サブセグメントを記録
    • トレースID:1-<エポック秒(16進8桁)>-<ランダム(16進24桁)>
    • セグメントID:16進16桁(64ビット)
    • サービス間の伝搬には X-Amzn-Trace-Id ヘッダーを使う
  4. データがX-Rayに送信され、コンソールで可視化

サンプリング#

すべてではなく一部のリクエストだけをトレースします。デフォルトでは、1秒ごとに最初の1リクエストは必ずトレースし、それ以降は5%をトレースします。

X-Rayデーモン#

アプリのトレースデータをX-Rayへ送る中継プロセスです。アプリからUDP 2000番で受け取り、HTTPSでX-Ray APIへ送ります。Lambdaでは不要です。

X-Ray SDK(OpenTelemetryへの移行が推奨)#

EC2上のアプリなどに組み込んでトレースデータを生成し、デーモンへ送るためのライブラリです(SDK → デーモン → X-Ray)。

  • AWS_XRAY_TRACING_NAME:X-Ray上で表示されるサービス名
  • AWS_XRAY_DAEMON_ADDRESS:トレースデータの送信先

他サービスとの連携#

サービス統合内容
Lambdaアクティブトレースを有効にするだけで収集可能(デーモン不要)
API GatewayAPI呼び出しのトレースを有効化
ELBトレーシングヘッダー(X-Amzn-Trace-Id)を伝搬し、各サービスのトレースを関連付ける

3. ユースケース#

  • マイクロサービスのどこで遅延が起きているかの特定
  • エラーが発生しているサービスをサービスマップで発見
  • 特定ユーザー(アノテーション)のリクエストだけを検索して調査

4. 料金の考え方#

記録したトレースの数と、取得・スキャンしたトレースの数に応じて課金されます(毎月の無料枠あり)。サンプリング率を調整するとコストを抑えられます。

5. 関連サービス#

  • AWS Lambda/Amazon API Gateway/Elastic Load Balancing:トレースの連携先
  • Amazon CloudWatch:Application Signalsなどの監視
  • Amazon Managed Grafana:トレースの可視化
  • Amazon EC2/Amazon ECS:デーモンを動かす環境

6. 試験・実務でのポイント#

  • トレースを検索・フィルターしたい値 → アノテーション。検索不要の詳細 → メタデータ。
  • EC2/ECSではX-Rayデーモン(UDP 2000)が必要。Lambdaはアクティブトレースを有効化するだけ。
  • デーモンにデータが届かない → AWS_XRAY_DAEMON_ADDRESS やIAM権限を確認。
  • サービス間の追跡は X-Amzn-Trace-Id ヘッダー。
  • デフォルトのサンプリング:毎秒1件+5%。
  • CloudWatch・CloudTrail・Config・X-Rayの使い分け → 監視・記録のサービスの選び方。

7. まとめ#

  • X-Rayはトレース・セグメント・サブセグメントで処理の流れを可視化する。
  • アノテーションは検索可能、メタデータは検索不可。
  • EC2などはSDK+デーモン、Lambdaは設定だけで使える。

このサービスが登場する運用シナリオ#

  • マイクロサービスの遅延の原因をトレースで特定するX-Rayのトレースで、どのサービス・どの処理が遅いか・エラーを出しているかを突き止める
