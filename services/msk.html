Amazon MSK

Apache Kafka互換のストリーミング基盤をマネージドで利用するサービス

最終更新:2026-11-07

内容の確認:2026年11月7日

1. サービス概要#

Amazon Managed Streaming for Apache Kafka (Amazon MSK)は、Apache Kafkaを使ったストリーミングアプリケーションのためのマネージドサービスです。AWSがクラスターの作成・管理を担い、既存のKafkaプロデューサーやコンシューマーを利用できます。

2. 主な機能・特徴#

Kafkaの基本構成#

  • プロデューサーがイベントをトピックへ書き込む。
  • トピックは複数のパーティションに分かれ、ブローカーに分散して保存される。
  • コンシューマーグループの各コンシューマーがパーティションを分担して読み取る。
  • オフセットで読み取り位置を管理し、保持期間内のレコードを再読込できる。

利用形態と連携#

MSK Provisionedはブローカーの種類や数を選びます。MSK Serverlessはブローカーの容量管理をAWSに任せます。MSK ConnectでKafka Connectコネクターを実行し、外部システムとのデータ連携もできます。MSK Replicatorはクラスター間のレプリケーションに使います。

ストリーム処理サービスとの違い#

MSKはKafka互換のイベントストリームを提供します。Kinesis Data StreamsはAWSネイティブなストリーム基盤で、Data Firehoseは処理済みデータを保存先へ配送するサービスです。Apache Flinkなどの処理エンジンは、ストリーム上のイベントを変換・集計する役割を担います。

3. ユースケース#

  • Kafkaを利用する既存アプリケーションのストリーミング処理。
  • イベントを複数のコンシューマーへ配信し、それぞれで独立して処理する。
  • Kafka Connectを使ったデータソース・保存先との連携。
  • 保持期間内のイベントを再生して、障害後の処理をやり直す。

4. 料金の考え方#

Provisionedはブローカーとストレージなどの稼働、Serverlessは利用量などが課金要因です。データ転送、MSK ConnectやReplicator、連携先サービスの料金も考慮します。保持期間・パーティション数・複製数がストレージ量や処理能力に影響します。

5. 関連サービス#

  • Amazon Kinesis:AWSネイティブなストリーミングデータ処理
  • Amazon Data Firehose:ストリームを保存先へ管理不要で配送
  • AWS Glue:ストリームETLとData Catalog
  • Amazon EMR:Sparkなどによる大規模分散処理
  • Amazon MWAA:データパイプラインのオーケストレーション

6. 試験・実務でのポイント#

  • Apache Kafka互換性を保ったマネージドストリーミング → Amazon MSK。
  • 保持期間内にオフセットを戻して再読込できる。再処理時の重複や冪等性も設計する。
  • スループットを高めるにはパーティション数とコンシューマー並列度を検討する。
  • 運用するKafkaクラスター → Provisioned。ブローカー管理を任せる → Serverless。
  • MSKはストリーム基盤、Data Firehoseは配送、Glue/Flinkは変換処理という役割を区別する。

7. まとめ#

  • MSKはApache Kafka互換のストリーミングサービス。
  • トピック・パーティション・オフセットでイベントを保持し、複数のコンシューマーが処理する。
  • ProvisionedとServerless、Kafka Connect、Replicatorを要件に合わせて使う。
