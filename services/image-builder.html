Amazon EC2 Image Builder

パッチ適用済みのAMIやコンテナイメージの作成・テスト・配布を自動化

最終更新:2026-10-25

1. サービス概要#

Amazon EC2 Image Builderは、AMI(EC2の起動用イメージ)やコンテナイメージの作成・テスト・配布を自動化するサービスです。

手作業でインスタンスを設定してAMIを取る方法では、手順のばらつきやパッチの適用漏れが起きます。Image Builderでは手順をパイプラインとして定義し、スケジュールや新しいパッチの公開をきっかけに、最新の状態の「ゴールデンイメージ」を作り続けられます。

2. 主な機能・特徴#

構成要素#

要素説明
コンポーネントソフトウェアのインストールや設定(ビルド用)と、確認の手順(テスト用)をYAMLで書いたもの。AWSが用意したもの(パッチ適用・CISの強化など)も使える
イメージレシピ元にするイメージ(ベースイメージ)と、適用するコンポーネントの組み合わせ。バージョンで管理する
インフラストラクチャ設定ビルド用のインスタンスのタイプ・サブネット・セキュリティグループ・IAMインスタンスプロファイル・ログの出力先(S3)
ディストリビューション設定できたAMIをコピーするリージョンや共有するアカウント、起動テンプレートの更新
パイプライン上の設定をまとめ、実行のスケジュールを決めたもの

主な機能#

  • パイプラインの実行は手動・スケジュール(cron)・ベースイメージや依存するコンポーネントの更新時から選べる。
  • ビルド用インスタンスはSSMエージェントを使って操作される。インスタンスプロファイルに AmazonSSMManagedInstanceCore と EC2InstanceProfileForImageBuilder のポリシーが必要。
  • Inspectorと連携して、作ったイメージの脆弱性をスキャンできる。
  • ディストリビューション設定で起動テンプレートの新しいバージョンを自動で作れる。Auto Scalingグループのインスタンスの更新と組み合わせると、新しいAMIへの入れ替えまで自動化できる。
  • ライフサイクルポリシーで、古いイメージやスナップショットを自動で削除できる。
  • 完了・失敗の通知をSNSやEventBridgeで受け取れる。

3. ユースケース#

  • 毎月、最新のOSパッチとセキュリティ設定を適用したゴールデンAMIを作り、全リージョンに配布する
  • 組織の各アカウントに、承認済みのAMIだけを共有する
  • 新しいAMIができたら起動テンプレートを更新し、Auto Scalingグループのインスタンスを順に入れ替える

4. 料金の考え方#

Image Builder自体は無料です。ビルド・テストに使うEC2インスタンス、作ったAMIのEBSスナップショット、S3のログなど、使ったリソースの料金がかかります。

5. 関連サービス#

  • Amazon EC2:AMIの利用先
  • Amazon EC2 Auto Scaling:起動テンプレートの更新とインスタンスの入れ替え
  • AWS Systems Manager:ビルド用インスタンスの操作、Parameter StoreへのAMI IDの保存
  • Amazon Inspector:イメージの脆弱性スキャン
  • Amazon ECR:コンテナイメージの保存先
  • AWS RAM:コンポーネントやレシピの共有

6. 試験・実務でのポイント#

  • 「パッチ適用済みのAMIを定期的に自動作成」「ゴールデンイメージ」→ EC2 Image Builder。
  • 他のリージョン・アカウントへの配布はディストリビューション設定で行う。
  • ビルドが失敗する → インスタンスプロファイルの権限、SSMエージェント、サブネットからSSMやS3への経路を確認する。ログはS3に出力される。
  • 新しいAMIへの切り替え → 起動テンプレートの更新+Auto Scalingのインスタンスの更新。

7. まとめ#

  • Image Builderは、イメージの作成・テスト・配布をパイプラインで自動化する。
  • サービス自体は無料で、使ったEC2などの料金だけがかかる。

このサービスが登場する運用シナリオ#

  • パッチ適用済みのAMIを定期的に作り、Auto Scalingに反映するImage Builderでゴールデンイメージを自動作成し、起動テンプレートの更新とインスタンスの更新で入れ替える
