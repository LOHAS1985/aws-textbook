AWS CodeDeploy

アプリを安全に各環境へ配布・更新するデプロイ自動化サービス

最終更新:2026-10-26

1. サービス概要#

AWS CodeDeployは、アプリケーションを安全に各種環境へ配布・更新するためのデプロイ自動化サービスです。EC2・オンプレミス・ECS・Lambdaにデプロイできます。

2. 主な機能・特徴#

構成要素#

  • アプリケーション:デプロイ対象の論理単位
  • デプロイグループ:デプロイ先
  • フック(ライフサイクルイベントフック):デプロイの各段階(アプリの停止・インストール後・起動後など)で、任意のスクリプトや処理を実行する仕組み。順番は後述の「デプロイの流れ」を参照。
  • AppSpecファイル:インスタンスごとのデプロイ手順を定義するファイル。アプリのソースのルートディレクトリに置く。
version: 0.0
os: linux
files:
  - source: /
    destination: /var/www/html
hooks:
  AfterInstall:
    - location: scripts/start.sh

デプロイ設定(Deployment Configuration)#

複数のインスタンスやトラフィックに対して、どう進めるかを決めます。

対象設定内容
EC2/オンプレミスOneAtATimeインスタンスを1台ずつデプロイ
HalfAtATimeインスタンスの半分ずつデプロイ
AllAtOnce全インスタンスに同時にデプロイ
ECS/LambdaAllAtOnce全トラフィックを一度に新バージョンへ移行
Linear指定した割合のトラフィックを、指定した時間ごとに新バージョンへ移行
Canary最初に指定した割合を新バージョンへ移し、指定時間後に残りをすべて移行

デプロイの流れ(In-Placeデプロイ)#

  1. ApplicationStop:既存アプリの停止
  2. BeforeInstall:インストール前処理
  3. Install:アプリの配置
  4. AfterInstall:インストール後処理
  5. ApplicationStart:アプリの起動
  6. ValidateService:動作確認

デプロイ方式には、既存のインスタンスを更新するIn-Placeと、新しい環境を用意してトラフィックを切り替えるBlue/Greenがあります。EC2/オンプレミスで使うには、各インスタンスにCodeDeployエージェントが必要です。CloudWatchアラームと連携した自動ロールバックも設定できます。

3. ユースケース#

  • EC2のWebサーバー群へ1台ずつ安全にリリース
  • Lambdaの新バージョンへ10%ずつトラフィックを移行(Canary/Linear)
  • ECSサービスのBlue/Greenデプロイ

4. 料金の考え方#

EC2・Lambda・ECSへのデプロイは追加料金なしで使えます。オンプレミスのサーバーへのデプロイは、更新するインスタンス数に応じて課金されます。

5. 関連サービス#

  • AWS CodePipeline:Deployステージ
  • AWS CodeBuild:デプロイ前のビルド
  • Amazon EC2/Amazon ECS/AWS Lambda:デプロイ先
  • Amazon CloudWatch:アラームによる自動ロールバック

6. 試験・実務でのポイント#

  • デプロイ手順の定義 → appspec.yml(ルートに配置)。
  • フックの順序:ApplicationStop → BeforeInstall → Install → AfterInstall → ApplicationStart → ValidateService。
  • Lambda/ECSで少しずつ移行 → Canary(2段階)/Linear(一定間隔)。
  • EC2で1台ずつ → OneAtATime。

7. まとめ#

  • CodeDeployはEC2・オンプレミス・ECS・Lambdaへのデプロイを自動化する。
  • 手順はappspec、進め方はデプロイ設定(OneAtATime/Canary/Linearなど)で決める。

このサービスが登場する運用シナリオ#

  • EC2のアプリをCI/CDでBlue/GreenデプロイするCodePipelineで自動化し、CodeDeployのBlue/Greenで安全に切り替える
  • Lambdaを段階的にリリースするSAMとCodeDeployのCanaryで、新バージョンへ少しずつトラフィックを移す
