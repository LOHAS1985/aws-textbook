AWS Backup

AWSサービスのバックアップを一元管理

最終更新:2026-10-26

1. サービス概要#

AWS Backupは、さまざまなAWSサービスのバックアップを一元管理するサービスです。サービスごとに別々に設定していたバックアップを、1つのプランでまとめて管理できます。

2. 主な機能・特徴#

対象サービス#

  • EC2
  • EBS/EFS/FSx/S3
  • RDS/Aurora/DynamoDB
  • DocumentDB/Neptune
  • Storage Gateway

構成要素#

  • バックアッププラン:スケジュール、バックアップウィンドウ、保持期間、ライフサイクル、コピー先を定義する。
  • リソースの割り当て:対象リソースをタグまたはARNで指定する。
  • バックアップボールト:バックアップの保管場所。

コピー先に別リージョンや別アカウントのボールトを指定することで、災害対策(DR)にも使えます。バックアップボールトロックを使うと、バックアップの削除を防ぐ(WORM)設定ができます。

3. ユースケース#

  • 複数サービスのバックアップを1つのポリシーで統一したい
  • タグ(例:Backup=daily)を付けたリソースを自動でバックアップ対象にしたい
  • 別リージョンにバックアップをコピーして災害対策をしたい

4. 料金の考え方#

保存しているバックアップの容量、復元したデータ量、リージョン間のコピーのデータ転送量に応じて課金されます。ライフサイクルでコールドストレージに移すとコストを下げられます。

5. 関連サービス#

  • Amazon EC2/Amazon EBS/Amazon EFS/Amazon FSx/Amazon S3
  • Amazon RDS/Amazon Aurora/Amazon DynamoDB
  • AWS Organizations:複数アカウントへのバックアップポリシー適用
  • AWS Storage Gateway:ボリュームゲートウェイのバックアップ
  • 関連する用語:タグ

6. 試験・実務でのポイント#

  • 「複数サービスのバックアップを一元管理」→ AWS Backup。
  • 対象リソースはタグで指定すると、新しいリソースも自動で対象になる。
  • 保持期間・スケジュール・コピー先はバックアッププランで定義する。

7. まとめ#

  • AWS Backupは「プラン(いつ・どれだけ)」「割り当て(何を)」「ボールト(どこに)」で構成される。

このサービスが登場する運用シナリオ#

  • DynamoDBを負荷に合わせてスケールし、誤操作から復旧するキャパシティモードと自動スケーリングでスロットリングを防ぎ、PITRで任意の時点に戻せるようにする
  • 誤操作したRDSのデータを特定の時点に戻す自動バックアップのポイントインタイムリカバリ(PITR)で、誤操作の直前の状態のDBを作り直す
  • S3のデータを誤削除やリージョン障害から守るバージョニング・レプリケーション・Object Lock・ライフサイクルを組み合わせてデータを守る
  • バックアップを一元管理して別リージョンに保管するAWS Backupのプランとタグで自動バックアップし、別リージョンへコピーする
