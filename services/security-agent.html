AWS Security Agent

設計書・コードのセキュリティレビューやペネトレーションテストをAIエージェントが行う

最終更新:2026-10-25

1. サービス概要#

AWS Security Agentは、アプリケーションの設計から本番前まで、セキュリティの確認をAIエージェントが行うサービスです。設計書のレビュー・ソースコードのレビュー・脅威モデリング・ペネトレーションテスト(侵入テスト)を、必要なときにすぐ実行できます。

AWSのセキュリティ関連のエージェント群をまとめた AWS Continuum の一部と位置づけられています。ペネトレーションテストは2026年3月に一般提供が始まり、設計レビュー・コードレビュー・脅威モデリングはプレビューとして提供されています。

2. 主な機能・特徴#

機能内容
ペネトレーションテスト対象のURL・認証情報・ソースコード・ドキュメントを渡すと、アプリの仕組みを理解したうえで複数の手順からなる攻撃を試し、実際に悪用できる脆弱性を見つける。再現手順・影響の分析・修正コードのプルリクエストまで作る
コードのセキュリティレビューGitHub・GitLab・Bitbucket・S3にあるソースコード全体をスキャンする。プルリクエストごとの自動レビューでは、指摘をコメントとして投稿する
設計のセキュリティレビューコードを書く前に、設計書が組織のセキュリティ要件を満たしているかを確認する
脅威モデリング設計書やコードから、構成要素・信頼の境界・データの流れをまとめ、STRIDEの分類で想定される脅威と対策を示す

組織のセキュリティ要件#

セキュリティチームは、承認済みの認証ライブラリ・ログの基準・データへのアクセスの方針などを一度コンソールで定義します。以降の設計・コードのレビューでは、一般的なチェックリストではなく、その要件に沿って自動で確認されます。

ほかのセキュリティサービスとの違い#

サービス主な役割
Security Agent開発中のアプリの設計・コードのレビューと、侵入テスト
Inspectorデプロイ済みのEC2・イメージ・Lambdaの既知の脆弱性(CVE)のスキャン
GuardDuty本番環境で起きている脅威の検出

AWS環境に対するペネトレーションテストは、一部の禁止された行為(DoS攻撃など)を除き、事前の申請なしで実施できます。Security Agentのテストは、AWSのほか、オンプレミスや他のクラウドのアプリにも使えます。

3. ユースケース#

  • 年1回の外部委託の侵入テストを、リリースごとのオンデマンドのテストに置き換える
  • プルリクエストの段階でセキュリティの問題を指摘し、修正案まで受け取る
  • セキュリティチームの人数が少なくても、全チームの設計レビューを一定の基準で回す

4. 料金の考え方#

ペネトレーションテストは従量課金で、エージェントがテストに使った時間(タスク時間)に応じて課金されます。新規の利用者には2か月の無料試用があります。プレビュー中の設計レビュー・コードレビュー・脅威モデリングは課金されません(1か月あたりの回数に上限があります)。

5. 関連サービス#

  • Amazon Inspector:既知の脆弱性のスキャン
  • Amazon GuardDuty:本番環境の脅威の検出
  • AWS DevOps Agent:運用・障害調査のAIエージェント
  • Kiro:AIエージェントを使った開発環境

6. 試験・実務でのポイント#

  • 「AIエージェントによるペネトレーションテスト」「設計書・コードのセキュリティレビュー」→ Security Agent。
  • デプロイ済みリソースのCVEスキャンは Inspector、実際の攻撃の検知は GuardDuty と区別する。
  • 組織の要件を一度定義すれば、全チームのレビューに同じ基準が使われる。

7. まとめ#

  • Security Agentは、開発の各段階でセキュリティのレビューと侵入テストを行うAIエージェント。
  • 見つけた問題について、再現手順と修正コードまで示す。
