AWS CodePipeline

ソース取得からデプロイまでを自動化するCI/CDサービス

最終更新:2026-10-26

1. サービス概要#

AWS CodePipelineは、CI/CD(継続的インテグレーション/継続的デリバリー)のサービスです。ソースコードの変更から、ビルド・テスト・デプロイまでを自動化します。

2. 主な機能・特徴#

ステージ(パイプラインの工程)#

ステージ内容例
Sourceソースコードの取得GitHub、GitLab、CodeCommit
BuildコードのビルドCodeBuild
Test自動テスト-
Approval手動承認(Manual Approval Action)-
DeployデプロイCodeDeploy、ECS、Lambda、CloudFormation

デプロイ先の比較#

項目CodeDeployECSLambdaCloudFormation
主な用途EC2/オンプレミスへのアプリ配置ECSサービスの更新Lambda関数の更新AWSインフラの構築・更新
デプロイ対象EC2、オンプレミスサーバーECSタスク・コンテナLambda関数VPC・ALB・RDS・ECS・Lambdaなど
管理対象アプリケーションコンテナ関数コードインフラリソース
Blue/Green○○(CodeDeploy連携時)○(エイリアス利用)×
ローリング更新○○××
自動ロールバック○○○○

3. ユースケース#

  • GitHubへのプッシュをきっかけに、ビルド・テスト・本番デプロイを自動実行
  • 本番デプロイの前に責任者の手動承認を挟む
  • CloudFormationでインフラ変更も含めて自動デプロイ

4. 料金の考え方#

V1タイプはアクティブなパイプラインの数(月額)、V2タイプはアクションの実行時間(分)で課金されます。CodeBuildなど各ステージで使うサービスの料金は別途かかります。

5. 関連サービス#

  • AWS CodeBuild:ビルド・テスト
  • AWS CodeDeploy:デプロイ
  • AWS CloudFormation:インフラのデプロイ
  • Amazon ECS/AWS Lambda:デプロイ先
  • Amazon SNS:承認依頼・結果の通知
  • 関連する用語:TerraformとGit

6. 試験・実務でのポイント#

  • 本番前に人の確認を挟む → Manual Approval Action。
  • EC2/オンプレミスへのBlue/Green → CodeDeploy。インフラ → CloudFormation。
  • Lambdaの段階的な切り替え → エイリアスを使ったBlue/Green(CodeDeploy)。

7. まとめ#

  • CodePipelineはSource→Build→Test→Approval→Deployを自動化するCI/CDサービス。
  • デプロイ先に応じてCodeDeploy・ECS・Lambda・CloudFormationを使い分ける。

このサービスが登場する運用シナリオ#

  • EC2のアプリをCI/CDでBlue/Greenデプロイする
  • ECSのサービスを止めずに更新し、失敗したら自動で戻す
