1. サービス概要#

AWS CodePipelineは、CI/CD(継続的インテグレーション/継続的デリバリー)のサービスです。ソースコードの変更から、ビルド・テスト・デプロイまでを自動化します。

2. 主な機能・特徴#

ステージ(パイプラインの工程)#

ステージ内容例
Sourceソースコードの取得GitHub、GitLab、CodeCommit
BuildコードのビルドCodeBuild
Test自動テスト-
Approval手動承認(Manual Approval Action)-
DeployデプロイCodeDeploy、ECS、Lambda、CloudFormation、Elastic Beanstalk

実行とアクション#

変更が1回入るたびに、パイプラインは実行(execution)として進みます。ステージの中のアクションは、順番に(直列)実行することも、同時に(並列)実行することもできます。アクションの種類は、Source・Build・Test・Deploy・Approval・Invokeの6つです。

アクションどうしは、ソースコードやビルドの成果物をアーティファクトとして受け渡します。CodePipelineは、アーティファクトをS3のアーティファクトストアにコピーし、次のアクションが取り出せるようにします。各アクションは、パイプラインのサービスロールの権限で動きます。権限の仕組みは用語ページ「iam:PassRoleとサービスにリンクされたロール」を参照してください。

同じステージには、同時に1つの実行しか入れません。前の実行がステージを使っている間、次の実行は待機します。

パイプラインの種類と実行モード#

パイプラインにはV1とV2の2種類があります。V2は、V1と同じ構造に、リリースの安全性(実行モードやロールバックの条件)とトリガーの設定が加わったものです。QUEUEDとPARALLELの実行モード、トリガーのフィルターはV2だけで使えます。

待機中の実行の扱いは実行モードで決まります。既定のSUPERSEDEDでは、待機中の古い実行を、より新しい実行が追い越して置き換えます。V2では、待機中の実行を順番に流すQUEUEDや、複数の実行を同時に流すPARALLELも選べます。PARALLELでは、ステージのロールバックは使えません。

手動承認(Manual Approval Action)#

承認アクションに着くと、パイプラインは止まって承認を待ちます。承認依頼は、設定したSNSトピックに通知できます。承認されると次のステージへ進みます。却下されるか、7日以内に誰も承認も却下もしなければ、アクションは失敗となり、実行は先へ進みません。

トリガーとソースの取得#

GitHub・GitLab・BitbucketなどのリポジトリはCodeConnectionsの接続を使ってソースを取得し、変更をきっかけにパイプラインを開始します。CodeCommitやS3のソースは、Amazon EventBridgeによる変更の検出でパイプラインを開始します。V2のトリガーでは、Gitのタグ・ブランチ・ファイルパスによるフィルターを付けられます。特定のブランチやタグへのプッシュだけを本番用のパイプラインに流す、といった使い分けができます。

ロールバックと再試行#

失敗したステージは再試行(retry)できます。また、ステージを以前に成功した実行の状態へ戻すステージのロールバックもあります。ステージには、失敗時や成功時の条件を満たしたときに自動でロールバックする設定もできます。デプロイの方式の違いは用語ページ「デプロイ戦略」を参照してください。

制限(クォータ)#

次の上限はリージョンごとの既定値です。

項目既定の上限
パイプラインの数1,000(引き上げを申請できる)
1パイプラインのステージ数2〜50
1パイプラインのアクション数1,000
1ステージの直列アクション数・並列アクション数それぞれ100
PARALLELモードでのアクティブな実行数50

3. ユースケース#

  • GitHubへのプッシュをきっかけに、ビルド・テスト・本番デプロイを自動実行
  • 本番デプロイの前に責任者の手動承認を挟む
  • CloudFormationでインフラ変更も含めて自動デプロイ

4. 料金の考え方#

V1タイプは、1か月の間に変更が流れたアクティブなパイプラインごとに、月額1.00 USDかかります(作成から30日間は無料)。V2タイプは、アクションの実行時間(分単位で切り上げ)に対して、1分あたり0.002 USDかかります。手動承認とカスタムアクションは、実行時間に含まれません。無料利用枠は、V1で1パイプライン、V2で月100分です。CodeBuildなど各ステージで使うサービスの料金は別途かかります。

5. 関連サービス#

  • AWS CodeBuild:ビルド・テスト
  • AWS CodeDeploy:デプロイ
  • AWS CloudFormation:インフラのデプロイ
  • Amazon ECS/AWS Lambda:デプロイ先
  • AWS Elastic Beanstalk:デプロイ先
  • Amazon SNS:承認依頼・結果の通知
  • Amazon EventBridge:S3・CodeCommitなどの変更の検出
  • 関連する用語:TerraformとGit、デプロイ戦略、iam:PassRoleとサービスにリンクされたロール

6. 試験・実務でのポイント#

  • 本番前に人の確認を挟む → Manual Approval Action(7日以内に応答がないと失敗する)。
  • EC2/オンプレミスへのBlue/Green → CodeDeploy。インフラ → CloudFormation。
  • Lambdaの段階的な切り替え → エイリアスを使ったBlue/Green(CodeDeploy)。
  • 新しい変更を優先し、待機中の古い実行を置き換えたい → 実行モードのSUPERSEDED(既定)。
  • 特定のブランチやタグへのプッシュだけでパイプラインを起動したい → V2のトリガーのフィルター。
  • 失敗したステージを以前の成功した実行へ戻したい → ステージのロールバック(PARALLELモードでは使えない)。
  • 料金 → V1はアクティブなパイプライン数、V2はアクションの実行時間(分)で課金される。手動承認は実行時間に含まれない。

7. まとめ#

  • CodePipelineはSource→Build→Test→Approval→Deployを自動化するCI/CDサービス。
  • デプロイ先に応じてCodeDeploy・ECS・Lambda・CloudFormationを使い分ける。

このサービスが登場する運用シナリオ#

  • EC2のアプリをCI/CDでBlue/Greenデプロイする
  • ECSのサービスを止めずに更新し、失敗したら自動で戻す
