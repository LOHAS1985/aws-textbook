Amazon Athena

S3上のデータを標準SQLで直接分析するサーバーレスなクエリサービス

最終更新:2026-11-07

内容の確認:2026年11月3日

1. サービス概要#

Amazon Athenaは、S3に保存されたデータを標準SQLで直接分析できるサーバーレスなクエリサービスです。データベースにデータを読み込む必要がなく、サーバーの管理も不要です。

2. 主な機能・特徴#

  • CSV、JSON、Parquet、ORC、Avroなどの形式に対応。
  • テーブル定義(スキーマ)はAWS Glue データカタログで管理する。
  • クエリ結果はS3に出力される。

仕組み#

Athenaは、Glueデータカタログに登録したテーブル定義(データの場所・形式・列)をもとに、S3のオブジェクトを読みながらSQLを実行します。サーバーの準備は不要で、クエリは並列に実行されて自動で拡張されます。料金はスキャンしたデータ量で決まるため、読むデータを減らすことが費用の削減につながります。

SQLのほかに、Apache SparkのPythonコードをノートブックからAthenaで実行できます。S3以外のデータも、フェデレーテッドクエリでLambda関数のコネクタを経由して分析できます。

スキャン量を減らす#

パーティションは、日付などの値ごとにS3のフォルダを分けておく仕組みです。WHERE句でパーティションのキーを指定すると、Athenaはその値のフォルダだけを読みます。

データを列指向形式(Parquet・ORC)にすると、クエリに必要な列だけを読めます。圧縮(GZIP・SNAPPY・ZSTDなど)をかけると、S3上の容量と読み取る量も減ります。既存のCSVなどは、CTAS(CREATE TABLE AS SELECT)でParquetやORCに変換できます。公式ドキュメントでは、圧縮・パーティション・列指向形式の組み合わせで、クエリあたりのコストを最大90%減らせるとされています。

設定の要点#

  • テーブルの作成:CREATE TABLEで、データの場所(LOCATION・S3のプレフィックス)、形式、パーティションのキー(PARTITIONED BY)を指定する。
  • パーティションの追加:dt=2026-10-01のようなHive形式ならMSCK REPAIR TABLEで登録する。それ以外の形式はALTER TABLE ... ADD PARTITIONで追加する。
  • ワークグループ:チームや用途ごとに、クエリ結果の保存先、暗号化の設定、IAMによるアクセス制御を分けて管理する。暗号化はワークグループ単位で決まるため、暗号化が必要な結果と不要な結果は別のワークグループにする。
  • データ使用量の制御:クエリ単位とワークグループ単位で、スキャンするデータ量のしきい値を設定する。しきい値を超えたときの動作を決められ、CloudWatchアラームで通知もできる。

制限#

  • 1回のクエリの文字列は256KBまで(変更できない)。長いクエリは分けて実行する。
  • 1回のスキャンで読めるパーティションは100万個まで。
  • DMLクエリ(SELECT・CTAS・INSERT INTO)には、同時に実行できる数の上限(リージョンにより異なる)と実行時間の上限がある。実行時間は申請により最長240分まで延ばせる。
  • キャンセルや失敗したクエリの途中までの結果が、S3に残ることがある。S3のライフサイクルルールで削除する。

3. ユースケース#

  • S3に出力されたCloudTrail・ALB・VPCフローログのアドホックな分析
  • データレイク(S3)に対する集計クエリ
  • BIツール(Amazon QuickのQuick Sightなど)のデータソース

4. 料金の考え方#

クエリでスキャンしたデータ量に応じて課金されます。スキャン量は1MB単位で切り上げられ、1クエリあたり最低10MBで計算されます。CREATE・ALTER・DROPなどのDDLと、失敗したクエリは無料です。キャンセルしたクエリは、キャンセルまでにスキャンした分が課金されます。パーティション分割・列指向形式・圧縮でスキャン量を減らすと、コストを大きく下げられます。料金の考え方は用語ページ「料金の基本」を参照してください。

6. 試験・実務でのポイント#

  • 「S3のデータ」「SQL」「サーバーレス」「アドホック分析」→ Athena。
  • コスト削減 → パーティション+Parquet/ORC+圧縮でスキャン量を減らす。
  • 特定の期間だけを分析したい → WHEREでパーティションのキーを指定する(読むのはその範囲だけ)。
  • Hive形式でないパーティションを追加したい → MSCK REPAIR TABLEは使えず、ALTER TABLE ... ADD PARTITIONで追加する。
  • 誤って大量のデータをスキャンして高額になるのを防ぎたい → クエリ単位・ワークグループ単位のデータ使用量の制御とCloudWatchアラーム。
  • テーブルの定義を一元管理したい → AWS Glue データカタログ。

7. まとめ#

  • AthenaはS3のデータをSQLで直接分析するサーバーレスサービス。料金はスキャン量で決まる。

このサービスが登場する運用シナリオ#

  • 複数アカウントのログを集約して分析する
