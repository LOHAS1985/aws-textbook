ストレージ

Amazon FSx

市販・オープンソースのファイルシステムをマネージドで提供

最終更新:2026-11-03

内容の確認:2026年11月3日

1. サービス概要#

Amazon FSxは、Windowsファイルサーバーや Lustre など、市販・オープンソースのファイルシステムをマネージドで提供するサービスです。用途に合わせて4種類から選びます。

2. 主な機能・特徴#

種類プロトコル特徴
FSx for Windows File ServerSMBActive Directory連携(利用者の認証とアクセス制御)。NTFSを使ったファイル管理
FSx for LustreLustreビッグデータ分析向け。高スループット・ミリ秒未満のレイテンシー。Linux向け
FSx for NetApp ONTAPNFS、SMB、iSCSI、NVMeオンプレミスのNetApp環境を拡張
FSx for OpenZFSNFSOpenZFSファイルシステムをマネージドで提供。スナップショットやデータ圧縮に対応

FSx for LustreはS3バケットと連携でき、S3上のデータを高速なファイルシステムとして処理できます。HPCや機械学習で使われます。

可用性:Single-AZとMulti-AZ#

Windows・ONTAP・OpenZFSは、1つのAZの中で完結するSingle-AZと、別のAZにも待機用のファイルサーバーを置くMulti-AZから選べます。Single-AZでも部品の故障は自動で検知・対処されますが、AZ全体の障害には耐えられません。Windows(Single-AZ)は、障害からの復旧時に約30分止まることがあります。高可用性の考え方は用語ページ「高可用性とスケーリング」を参照してください。

Multi-AZでは、待機用のファイルサーバーに変更を同期しておき、障害時はフェイルオーバーで切り替えます。Windowsでは通常30秒未満で切り替わり、ファイルシステムのDNS名は変わりません。OpenZFSのMulti-AZは通常60秒以内に切り替わります。Windowsの Multi-AZ では、Linuxクライアントは DNS名による自動の切り替えに対応していないため、待機側へ自動では接続し直されません。

容量と性能の設定#

FSx for Windowsでは、ストレージ容量・SSDのIOPS・スループット容量を作成時に指定し、あとから変更できます。ストレージはSSDかHDDを選びます。IOPSとスループットの違いは用語ページ「IOPS・スループット・レイテンシー」を参照してください。主な上限は次のとおりです。

項目(FSx for Windows)上限・下限
SSDの最小ストレージ容量32 GiB
HDDの最小ストレージ容量2,000 GiB
最大ストレージ容量(SSD・HDD)64 TiB
スループット容量8〜12,288 MBps

Lustreには、SSD・Intelligent-Tiering・HDDの3つのストレージクラスがあります。小さなファイルのランダムな読み書きが多い用途はSSD、全体に一定の低レイテンシーが不要な用途はIntelligent-Tieringが向いています。HDDは、1桁ミリ秒の一定のレイテンシーと大きなスループットが必要な用途向けです。

バックアップと暗号化#

FSx for Windowsは、作成時に自動の日次バックアップが既定で有効になります。バックアップはVSS(Volume Shadow Copy Service)を使ってファイルシステムの整合性を保ち、2回目以降は増分で保存されます。手動のバックアップはいつでも取れ、自動バックアップの保持期間は最大90日です。

作成時にMicrosoft Active Directoryに参加させ、利用者の認証とアクセス制御をADで行います。保存データはAWS KMSの鍵で暗号化され、通信中のデータはSMBのKerberosセッションキーで暗号化されます。

Lustreの種類とS3との連携#

FSx for Lustreには、一時的な処理向けのScratchと、長期的な保存やスループット重視のPersistentがあります。Scratchはデータを複製しないため、ファイルサーバーが故障するとそのデータは残りません。Persistentはデータを複製し、故障したファイルサーバーは交換されます。

S3バケットをデータリポジトリとして関連付けると、S3のオブジェクトがファイルとして見えるようになります。ファイルシステムの作成時にS3上のファイル一覧を取り込み、自動インポート・自動エクスポートを設定すると、変更がS3との間で同期されます。S3のバケットが、データの永続的な保管先になります。

3. ユースケース#

  • Windowsアプリのファイル共有(Active Directoryでアクセス制御)→ for Windows File Server
  • HPC・ビッグデータ分析・機械学習 → for Lustre
  • オンプレミスのNetAppストレージをAWSへ拡張 → for NetApp ONTAP

4. 料金の考え方#

種類ごとに、ストレージ容量・スループット容量・バックアップ容量に応じて課金されます。

5. 関連サービス#

  • Amazon EFS:Linux向けの共有ファイルストレージ
  • AWS Directory Service:FSx for WindowsのActive Directory連携
  • Amazon S3:FSx for Lustreのデータ連携先
  • Amazon EC2:ファイルシステムにアクセスするクライアント
  • AWS DataSync:オンプレミスからのデータ移行
  • AWS Backup:バックアップの一元管理
  • AWS KMS:保存データの暗号化に使う鍵
  • 関連する用語:ブロック・ファイル・オブジェクトストレージ、リージョンとアベイラビリティーゾーン

6. 試験・実務でのポイント#

  • Windows・SMB・Active Directory → FSx for Windows File Server。
  • HPC・高スループット・ミリ秒未満のレイテンシー → FSx for Lustre。
  • NetApp・iSCSI → FSx for NetApp ONTAP。
  • LinuxでNFS共有だけなら → EFSも候補。
  • Lustreで一時的な処理に使う → Scratch(データは複製されない)。長期の保存には Persistent(データを複製する)。
  • Windowsのファイル共有を高可用性にしたい → Multi-AZ(通常30秒未満で切り替え)。Linuxクライアントは DNS名による自動の切り替えに対応しない点に注意。
  • S3上のデータを高速に処理したい → FSx for LustreとS3のデータリポジトリ。

7. まとめ#

  • FSxは4種類のファイルシステムをマネージドで提供する。
  • キーワード(Windows/AD、HPC、NetApp)で種類を選び分ける。
