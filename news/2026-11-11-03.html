STS:パーティションをまたぐフェデレーション

アクセスキーを使わずに、別のパーティションのIAMロールへ一時的な認証情報で切り替えられるようになりました。

最終更新:2026-11-11

1. 発表の内容#

AWSのリージョンは「パーティション」というグループに分かれています(通常の商用リージョン、AWS GovCloud (US)、中国リージョン、欧州ソブリンクラウドなど)。パーティションごとにIAMが独立しているため、別のパーティションのリソースを操作するには、有効期限のないIAMユーザーのアクセスキーを使うことが多くありました。今回、AWS STS が、パーティションをまたぐフェデレーション(外部のIDを信頼して一時的な権限を渡す仕組み)に対応しました。ワークロードは、自分のパーティションのSTSで GetWebIdentityToken API を使って短期のトークンを受け取り、そのトークンを AssumeRoleWithWebIdentity API に渡して、相手のパーティションのロールの一時認証情報を得ます。どちらも既存のAPIです。

説明の中心 成功・推奨・正常 利用者・外部・送信元

何がうれしいか
期限のないアクセスキーを持ち回る必要がなくなり、認証情報の漏えいリスクと管理の手間が減ります。トークンの利用は両方のパーティションの CloudTrail で追跡できます。統合したセキュリティ報告や、運用ツールの一元化などに向きます。追加料金はなく、商用・GovCloud (US)・中国・欧州ソブリンクラウドのリージョンで使えます。
試験・実務への影響
「長期の認証情報を使わずにアクセスを許可する」というセキュリティの原則を、パーティション間にも適用できます。PKI(公開鍵基盤)を使っている場合は IAM Roles Anywhere という別の方法もあります。
