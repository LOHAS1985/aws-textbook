Systems Manager Parameter Store:API のスループット上限が引き上げ

高スループット設定を有効にしている Parameter Store で、パラメータの取得・登録・削除などの API の秒間リクエスト上限が約5〜10倍になりました。

最終更新:2026-11-20

1. 発表の内容#

Parameter Store は、設定値やパスワードなどを保存しておく Systems Manager の機能です。API には1秒あたりに受け付けられる回数(TPS)の上限があり、上限を超えるとスロットリング(受け付け拒否)のエラーになります。今回、高スループット設定(上限を引き上げる設定)を有効にしているアカウントで、5つの API の既定の上限が上がりました。追加料金はなく、すべてのリージョンが対象です。

自分で上限を決めていた場合は、その値がそのまま保たれます。

成功・推奨・正常 その他の構成要素

ほかに、DescribeParameters が10から100、GetParameterHistory が10から100になっています。多数の Lambda 関数が同時に起動して設定を読み込む場面や、大量のパラメータを一括で作成・削除する場面で、スロットリングが起きにくくなります。

何がうれしいか
スロットリングへの対策(リトライ処理や起動時間をずらす工夫)を減らせます。
試験・実務への影響
「Parameter Store の API がスロットリングされる」という場面では、高スループット設定の有効化が対策の1つです。上限の数字そのものより、設定の有無で上限が変わることを押さえましょう。
