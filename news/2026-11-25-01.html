AWS Sign-In:サインインの有効期間を最大90日まで設定可能に

AWS CLI などの OAuth 対応ツールで、IAM ユーザーやロールごとにサインインの有効期間を最大90日まで延ばせるようになりました。

最終更新:2026-11-25

1. 発表の内容#

AWS Sign-In に、「サインインの有効期間(Sign-in duration)」の設定が加わりました。これは、OAuth(アプリに自分の代わりの操作を許可する仕組み)で開始したサインインのセッションが、どれだけ有効なままでいられるかを決める値で、IAM ユーザーや IAM ロールごとに最大90日まで設定できます。対象は AWS CLI の aws login、AWS MCP Server など OAuth に対応したツールです。マネジメントコンソールのセッションには影響しません。

長時間動き続ける開発作業や AI エージェントは、サインインや同意の確認が何度も挟まると止まってしまいます。そこで固定のアクセスキーを使いがちですが、アクセスキーは漏れると長く悪用されます。今回の設定なら、短命で更新される認証情報のまま中断を減らせます。管理者が明示的に設定しない限り、既存の有効期間は変わりません。

成功・推奨・正常 失敗・非推奨・障害 その他の構成要素 点線の矢印(使われない・切り替え前・補足)

何がうれしいか
長時間の作業やエージェントが、再サインインで止まりにくくなります。静的なアクセスキーを発行せずに済み、設定は IAM コンソール・AWS CLI・IAM API から行えます。
試験・実務への影響
認証情報は長期のアクセスキーより、期限付きの一時的なものを使うのが基本です。有効期間はユーザーやロールごとに管理者が決める点と、コンソールのセッションとは別の設定である点を押さえましょう。
