Aurora:クラスターを別の VPC へ移動できるように

Aurora MySQL と PostgreSQL のクラスターを、データを移行せずに API 1回で別の VPC へ移せるようになりました。

最終更新:2026-11-21

1. 発表の内容#

データベースを置く VPC は、IP アドレスの空きが足りなくなったり、ネットワークを整理し直したりする場面で変えたくなります。これまでは、移動先の VPC に新しいクラスターを作ってデータを移行し、アプリの接続先も変える必要がありました。

今回、ModifyDBCluster API を1回呼ぶ(RDS コンソールの変更操作でも可)だけで、既存のクラスターを別の VPC へ移せます。データはそのまま、クラスターのエンドポイントも変わらず、接続が切れるのは短い時間だけです。移動の前に、元の VPC に結びついた機能(Aurora グローバルデータベース、RDS Proxy、Blue/Green デプロイ)をオフにし、移動後に設定し直します。

説明の中心 成功・推奨・正常 失敗・非推奨・障害 その他の構成要素

何がうれしいか
CIDR の重複や IP 不足への対応、ネットワークの統合を、移行作業なしで行えます。
試験・実務への影響
「データベースを別の VPC へ移したい」という問いで、スナップショットの復元以外の選択肢が増えました。移動前に Global Database や RDS Proxy をオフにする条件が落とし穴です。
