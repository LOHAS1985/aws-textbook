1. AWS AppConfig と AWS Config の違い#

  • AWS Config:リソースの設定の変更履歴を記録し、ルールで基準に合っているか(準拠)を評価する
  • AWS AppConfig:アプリの設定値や機能フラグを段階的に配布し、アラームが鳴ったら自動で元に戻す
  • 見分け方:設定の履歴・準拠チェック → Config / 設定の段階的な配布・即時の切り戻し → AppConfig
  • 詳しくは 機密情報・設定値の保存先の選び方

2. デプロイ戦略#

  • Blue/Green:新旧2つの環境を用意し、一括で切り替える。ダウンタイムなし・すぐに元に戻せる
  • Canary:少量(例:10%)で試してから残りを切り替える(2段階)。Linear:一定の割合ずつ増やす(例:1分ごとに10%)
  • Rolling:既存のインスタンスを少しずつ更新する(追加コストなし・容量が一時的に減る)。容量を減らしたくない → Rolling with additional batch
  • Immutable:新しいインスタンスを作ってから入れ替える。失敗しても既存のインスタンスに影響しない(Elastic Beanstalk)
  • All at once(In-place):最も速いが停止する。開発環境向け
  • サービスごとの設定名:CodeDeploy(EC2)は AllAtOnce/HalfAtATime/OneAtATime、Lambda・ECSは Canary10Percent5Minutes/Linear10PercentEvery1Minute、Auto Scalingはインスタンスの更新、CloudFormationはUpdatePolicy、Elastic BeanstalkのBlue/GreenはCNAME swap
  • 失敗を自動で戻す → CloudWatchアラームと連携した自動ロールバック(CodeDeploy・ECSのサーキットブレーカー・AppConfig)
  • 詳しくは デプロイ戦略

3. EC2 Instance Connect#

  • 一時的な公開鍵(有効期間60秒)でSSH接続。IAMで鍵の送信を制御するが、通常はSSH(22番ポート)の許可が必要
  • プライベートサブネットのEC2にはEC2 Instance Connect Endpointを使う。インターネットに22番ポートを公開せずに接続するならSession Manager
  • 詳しくは Amazon EC2

4. Amazon Inspector#

  • EC2・ECR・Lambdaの脆弱性(CVE)などを継続的にスキャン。Inspectorで検出、Patch Managerで修正
  • 詳しくは Amazon Inspector

5. AWS Trusted Advisor#

  • コスト・性能・セキュリティ・耐障害性・サービスクォータ・運用の6観点から改善を提案
  • 詳しくは AWS Trusted Advisor
