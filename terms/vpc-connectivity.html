VPC同士をつなぐ方法の選び方

VPCピアリング・Transit Gateway・PrivateLink・VPCの共有の違いと使い分け

最終更新:2026-10-26

1. 詳しい説明#

別々のVPC(別アカウント・別リージョンを含む)を通信させる方法は、主に3つあります。違いは「何本の接続が必要か」と「ネットワーク全体をつなぐか、特定のサービスだけを公開するか」です。

比較表#

PrivateLinkはネットワークではなくサービスをつなぐ#

PrivateLinkでは、提供側がNetwork Load Balancerの後ろにサービスを置いて「エンドポイントサービス」として公開し、利用側は自分のVPCにインターフェイスエンドポイント(ENI)を作ります。利用側から見えるのは自分のVPCの中のENIだけなので、両方のVPCのCIDRが重なっていても使えます。また、提供側から利用側のVPCへは通信できません。

S3やDynamoDBなどAWSのサービスへの接続に使うVPCエンドポイントも、インターフェイス型は同じPrivateLinkの仕組みです。

VPCをつながずに共有する#

同じ組織の複数アカウントで1つのネットワークを使いたいなら、AWS RAMでVPCのサブネットを他のアカウントと共有する方法もあります(VPCの共有)。各アカウントは共有されたサブネットに自分のリソースを作るので、VPCどうしをつなぐ必要がありません。ネットワークは所有者のアカウントがまとめて管理します。

選び方のポイント#

  • 2〜3個のVPCを、低コストでつなぎたい → VPCピアリング。
  • ピアリングでA–B、B–CをつないだのにAとCが通信できない → ピアリングは推移的でない。A–Cにもピアリングを作るか、Transit Gatewayに移る。
  • 多数のVPCやオンプレミスとの接続をまとめて管理したい → Transit Gateway。ルートテーブルを分けると、本番と開発のVPCを通信させないこともできる。
  • CIDRが重なるVPC、または他社のVPCに、特定のサービスだけを提供したい → PrivateLink。
  • 別リージョンのVPCどうし → リージョン間のVPCピアリング、またはTransit Gatewayどうしのピアリング。
  • ピアリングを作っただけでは通信できない。両方のVPCのルートテーブルに相手のCIDRへの経路を追加し、セキュリティグループでも許可する。
  • VPCのCIDRが重ならないように、組織全体でIPアドレスを払い出す → IPAM(運用シナリオ「組織全体のVPCのIPアドレスを重ならないように払い出す」)。
  • Transit Gatewayを他のアカウントのVPCにつなぐときは、RAMでTransit Gatewayを共有する。

2. 関連する用語#

  • VPCピアリング:VPC同士を1対1でつなぐ仕組みの詳細
  • VPCエンドポイント:VPCからAWSのサービスへのプライベートな接続
  • ルートテーブル:接続先への経路を設定する
  • CIDR:VPCのアドレス範囲。重なると接続できない方法がある
  • オンプレミスとAWSをつなぐ方法の選び方:VPN・Direct Connect・Client VPN

3. 関連サービス#

  • Amazon VPC:VPCピアリング・PrivateLink
  • AWS Transit Gateway:多数のVPCをつなぐハブ
  • Elastic Load Balancing:PrivateLinkで公開するサービスの前に置くNLB
  • AWS RAM:サブネットやTransit Gatewayを他のアカウントと共有する
  • Amazon VPC IPAM:VPCのIPアドレスの計画と払い出し

この用語が出てくるページ#

  • Amazon VPCサービスAWS上に論理的に分離された仮想ネットワークを作るサービス
  • AWS Transit Gatewayサービス多数のVPCとオンプレミスをハブ&スポークでつなぐ中継ルーター
  • AWS Resource Access Managerサービス自アカウントのリソースを他アカウントや組織と共有
