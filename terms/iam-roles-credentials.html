IAMロールと一時的な認証情報

長期のアクセスキーの代わりに、ロールを引き受けて期限付きの認証情報で操作する仕組みと、EC2・Lambda・別アカウントでの使い方

1. 詳しい説明#

IAMロールは、パスワードやアクセスキーを持たない「権限の入れ物」です。人・アプリ・AWSのサービスがロールを引き受ける(AssumeRole)と、STSが期限付きの認証情報を発行し、その間だけロールの権限で操作できます。AWSでは、プログラムからの操作に長期のアクセスキーを使わず、ロールを使うのが基本です。

ロールを決める2つのポリシー#

ポリシー決めること例
信頼ポリシー誰がこのロールを引き受けられるか(Principal)"Service": "ec2.amazonaws.com"、別アカウントのARN、IDプロバイダー
アクセス許可ポリシー引き受けた後に何ができるかS3の読み取り、DynamoDBへの書き込み

権限エラーのとき、「引き受けられない」なら信頼ポリシー、「引き受けたが操作できない」ならアクセス許可ポリシーを確認します。

一時的な認証情報#

ロールを引き受けると、アクセスキーID・シークレットアクセスキー・セッショントークンの3つと有効期限が発行されます。

  • 有効期限は既定で1時間。ロールの最大セッション時間は12時間まで延ばせる
  • ロールから別のロールを引き受ける(ロールの連鎖)と、セッションは最大1時間に制限される
  • 期限が来れば自動で使えなくなるので、漏れても被害の期間が限られる

使い方のパターン#

使う場面仕組みポイント
EC2上のアプリインスタンスプロファイル(ロールの入れ物)をインスタンスに付ける。認証情報はインスタンスメタデータ(IMDS)から取得され、自動で更新されるアクセスキーをインスタンスに置かない。ロールは起動中でも付け替えられる
Lambda関数実行ロールを関数に設定するCloudWatch Logsへの書き込み権限も必要
ECSのタスクタスクロール(アプリが使う)とタスク実行ロール(イメージの取得・ログの送信にECSが使う)2つを混同しない
別アカウントの操作相手のアカウントのロールの信頼ポリシーで自アカウントを許可し、自分側には sts:AssumeRole の権限を与える外部の会社に引き受けさせるときは外部IDを条件にする
人のログインIAM Identity Center、または外部のIDプロバイダーとのフェデレーション(SAML・OIDC)でロールを引き受けるIAMユーザーを人数分作らない
AWS外のCI/CD(GitHub Actionsなど)OIDCで AssumeRoleWithWebIdentity を呼ぶ長期のアクセスキーをCIに保存しない
オンプレミスのサーバーIAM Roles Anywhere(X.509証明書で引き受ける)、またはSSMのハイブリッドアクティベーション

認証情報が使われる順番#

AWS CLIやSDKは、認証情報を決まった順番で探し、最初に見つかったものを使います。

  1. コマンドやコードで直接指定したもの(--profile など)
  2. 環境変数(AWS_ACCESS_KEY_ID など)
  3. 共有の設定ファイル(~/.aws/credentials・~/.aws/config のプロファイル。IAM Identity Centerのログインもここ)
  4. コンテナの認証情報(ECSのタスクロール)
  5. インスタンスメタデータ(EC2のインスタンスプロファイル)

EC2にロールを付けたのに「別の権限で動いている」ときは、環境変数や ~/.aws/credentials に古いアクセスキーが残っていないかを確認します。そちらが先に使われるためです。今どの権限で動いているかは aws sts get-caller-identity で確認できます。

サービスロールとサービスにリンクされたロール#

AWSのサービスが利用者の代わりに操作するときもロールを使います。自分で作って権限を決めるサービスロールと、サービスが決めた内容で自動的に作られるサービスにリンクされたロールがあります。違いと、ロールをサービスに渡すときの権限(iam:PassRole)は「iam:PassRoleとサービスにリンクされたロール」で説明します。

2. 関連する用語#

  • iam:PassRoleとサービスにリンクされたロール:ロールをサービスに渡すときの権限
  • IAMポリシーと評価ロジック:信頼ポリシー・アクセス許可ポリシーの書き方と評価の順番
  • OIDC(OpenID Connect):外部のIDでロールを引き受ける
  • ARN:信頼ポリシーやリソースの指定に使う

3. 関連サービス#

  • AWS IAM:ロールとポリシーを作る

  • Amazon EC2:インスタンスプロファイルとIMDS
  • AWS Lambda:実行ロール
  • Amazon ECS:タスクロールとタスク実行ロール
