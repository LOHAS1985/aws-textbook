VPC内のリソースから外へ出ていく通信と、その4つのパターン

1. 詳しい説明#

アウトバウンド通信は、VPC内のリソースから外部へ出ていく通信です。経路は、サブネットに関連付けられたルートテーブルのターゲットで決まります。インスタンスは宛先に最も具体的に一致するルート(ロンゲストマッチ)を選び、そのターゲットを経由して宛先へ到達します。

1. パブリックサブネット(IGW)#

  • 経路:インスタンス → IGW → インターネット
  • ルート:0.0.0.0/0(IPv6は ::/0)→ IGW
  • 条件:IPv4ではパブリックIPv4アドレスまたはElastic IPが必要。IPv6ではグローバルに一意なIPv6アドレスで通信できる。
  • 特徴:アウトバウンドに加え、インターネットからのインバウンドも可能(SGとNACLで制御)。

2. プライベートサブネット(IPv4):NAT Gateway#

  • 経路:インスタンス → NAT Gateway → IGW → インターネット
  • ルート(プライベートサブネット):0.0.0.0/0 → NAT Gateway
  • ルート(NAT Gatewayを置くパブリックサブネット):0.0.0.0/0 → IGW
  • 特徴:インターネットからの新規のインバウンドは受け付けない。NAT Gatewayはパブリックサブネットに配置する。

3. プライベートサブネット(IPv6):Egress-only IGW#

  • 経路:インスタンス → Egress-only IGW → インターネット
  • ルート:::/0 → Egress-only IGW
  • 特徴:アウトバウンドのみ許可し、インターネットからの新規インバウンドは遮断する。IPv6専用でIPv4には使えない。IPv6ではNATによる変換は不要。

4. AWSサービス宛て:VPCエンドポイント#

  • 経路:インスタンス → VPCエンドポイント → AWSサービス(インターネットを経由しない)
  • ゲートウェイ型:S3とDynamoDBが対象。ルートテーブルにエントリを追加する。
  • インターフェイス型:多くのAWSサービスが対象。サブネットにENIが作成される。
  • 特徴:NAT Gatewayのデータ処理料金を削減でき、セキュリティ面でも有利。

比較#

パターン経路インターネットからのインバウンド主な用途
IGWインスタンス → IGW → インターネット可パブリックサブネットのリソース
NAT Gatewayインスタンス → NAT Gateway → IGW → インターネット不可プライベートサブネットのIPv4アウトバウンド
Egress-only IGWインスタンス → Egress-only IGW → インターネット不可プライベートサブネットのIPv6アウトバウンド
VPCエンドポイントインスタンス → VPCエンドポイント → AWSサービス該当なしAWSサービスへのプライベート接続

押さえておきたいポイント#

  • 戻りの通信は、SGがステートフルなため自動で許可される。NACLはステートレスなため、戻りの通信(エフェメラルポート)も明示的な許可が必要。
  • 通信できない場合の確認順:ルートテーブル → IGW/NAT Gatewayの状態 → セキュリティグループ → NACL → パブリックIPの有無。

2. 関連する用語#

  • インバウンド通信:外からVPC内へ入ってくる通信
  • ルートテーブル:ターゲットで経路が決まる
  • ネットワークACLとセキュリティグループ:戻りの通信の扱いが異なる
