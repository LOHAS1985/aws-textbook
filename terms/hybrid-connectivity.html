オンプレミスとAWSをつなぐ方法の選び方

Site-to-Site VPN・Direct Connect・Client VPNの違いと、冗長化の組み合わせ

最終更新:2026-10-26

1. 詳しい説明#

社内のデータセンターや拠点、社員の端末からVPCに接続する方法は、大きく3つあります。選ぶときに見るのは、「何をつなぐか(拠点か、個人の端末か)」と「帯域・遅延の安定性がどれだけ必要か」です。

選び方の流れ#

冗長化と組み合わせ#

Direct Connectは1本の回線だけだと、回線やDXロケーションの障害で通信が止まります。そこで次の組み合わせを使います。

  • DX+Site-to-Site VPNの予備:普段はDXを使い、DXが切れたらVPNに切り替える。同じ宛先の経路がDXとVPNの両方から届くと、AWSはDXの経路を優先する。
  • DXを2本以上:重要な接続は、別々のDXロケーションに回線を用意して、ロケーション単位の障害にも備える。
  • DXの上にVPN:専用線の安定性に加えて、IPsecで暗号化したいとき。

つなぐVPCが多いときは、VPCごとに接続を作るのではなく、Transit Gatewayを中心に置いてVPN・DX(Direct Connectゲートウェイ経由)をまとめます(VPC同士をつなぐ方法の選び方、運用シナリオ「複数のVPCとオンプレミスを接続する」)。

選び方のポイント#

  • 今すぐ・低コストで拠点とつなぎたい → Site-to-Site VPN。
  • 大量のデータを安定した帯域・遅延で送りたい → Direct Connect。開通までに時間がかかるので、それまではVPNでつなぐ。
  • DXの障害に備えて安く冗長化したい → DXの予備にSite-to-Site VPN。
  • DXの通信を暗号化したい → MACsec、またはDXの上にSite-to-Site VPN。
  • 在宅勤務の社員がVPCの社内システムを使いたい → Client VPN(運用シナリオ「社員の端末からVPCの社内システムに安全に接続する」)。
  • Site-to-Site VPNは1つの接続に2本のトンネルがある。両方を使えるように、カスタマーゲートウェイ側も2本とも設定する。
  • VPNのトンネルが切れたことに気づきたい → CloudWatchのメトリクス TunnelState にアラームを設定する。
  • オンプレミスとVPCで互いの名前を引きたい → Route 53 Resolverのエンドポイント(運用シナリオ「オンプレミスとVPCで互いの名前を解決する」)。
  • オンプレミスとVPCのCIDRが重なるとルーティングできない。つなぐ前にIPアドレスを計画する(CIDR)。

3. 関連サービス#

  • AWS Site-to-Site VPN:インターネット経由の拠点間VPN
  • AWS Direct Connect:専用線での接続
  • AWS Client VPN:個人の端末からのリモートアクセス
  • AWS Transit Gateway:多数のVPCとVPN・DXをまとめるハブ
  • AWS Systems Manager:Session Managerでのサーバー操作
  • Amazon Route 53:Resolverエンドポイントでのハイブリッドな名前解決
