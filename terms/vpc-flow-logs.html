VPCフローログ

VPC内のネットワークインターフェイスを通る通信の記録(誰から誰へ・許可か拒否か)

最終更新:2026-10-31

1. 詳しい説明#

VPCフローログ(VPC Flow Logs)は、Amazon VPCの機能の1つで、ネットワークインターフェイス(ENI)を通るIP通信の情報を記録します。「どこから・どこへ・どのポートで・どれだけ通信し、それが許可(ACCEPT)されたか拒否(REJECT)されたか」が分かるため、通信トラブルの調査やセキュリティの監査に使います。

記録されるのは通信のメタデータ(ヘッダーの情報)だけで、通信の中身(パケットの内容)は記録されません。中身まで必要な場合はトラフィックミラーリングを使います。

記録する範囲と送信先#

フローログは次の単位で作成できます。上の単位で作ると、その中のすべてのENIが対象になります。

  • VPC → その中のすべてのサブネット・ENI
  • サブネット → その中のすべてのENI
  • ネットワークインターフェイス(ENI) → そのENIだけ

Transit Gatewayを通る通信も、同じ仕組みのフローログで記録できます。

レコードの見方#

標準の形式では、1行に次の項目がスペース区切りで並びます。

2 123456789012 eni-0a1b2c3d 203.0.113.10 10.0.1.25 49152 22 6 10 840 1700000000 1700000060 REJECT OK
項目例意味
version / account-id2 / 123456789012形式のバージョン / AWSアカウントID
interface-ideni-0a1b2c3d通信したENI
srcaddr / dstaddr203.0.113.10 / 10.0.1.25送信元IP / 宛先IP
srcport / dstport49152 / 22送信元ポート / 宛先ポート(22はSSH)
protocol6プロトコル番号(6=TCP、17=UDP、1=ICMP)
packets / bytes10 / 840パケット数 / バイト数
start / end1700000000 / 1700000060集計期間の開始・終了(UNIX時間)
actionREJECTセキュリティグループ・ネットワークACLで許可(ACCEPT)されたか拒否(REJECT)されたか
log-statusOK記録の状態(NODATA=通信なし、SKIPDATA=一部記録できず)

この例は「外部の 203.0.113.10 から 10.0.1.25 へのSSH(22番)が拒否された」ことを表します。カスタム形式にすると、vpc-id、subnet-id、tcp-flags、flow-direction(通信の向き)、pkt-srcaddr(NATなどを経由する前の送信元)なども記録できます。

セキュリティグループとネットワークACLの切り分け#

セキュリティグループはステートフル(戻りの通信は自動で許可)、ネットワークACLはステートレス(戻りの通信も個別に許可が必要)です。この違いを使って、フローログから原因を絞り込めます。

注意点#

  • リアルタイムではない:通信を一定期間(既定10分、または1分)ごとに集計して記録するため、反映まで数分かかる。
  • 作成後に設定を変更できない:形式などを変えたいときは、削除して作り直す。
  • 記録されない通信がある:Amazonが提供するDNSサーバー(Route 53 Resolver)への問い合わせ、インスタンスメタデータ(169.254.169.254)、Amazon Time Sync、DHCPなど。
  • CloudWatch Logsへの送信量やS3の保存量に応じて料金がかかるため、必要な範囲・期間に絞る。

2. 関連する用語#
