コンプライアンスとAWS Artifact

法令や業界の基準を守っていることを示すための、AWSの第三者認証・監査レポートの入手方法と、利用者側の確認の仕組み

最終更新:2026-10-26

1. 詳しい説明#

コンプライアンスは、法令や業界の基準(クレジットカード情報の扱い、個人情報の保護、内部統制など)を守ることです。責任共有モデルのとおり、AWSを使うシステムでは、AWS側(データセンター・基盤)の証明はAWSが、利用者側(設定・データ・権限)の証明は利用者が用意します。

AWS Artifact#

AWS Artifactは、AWS自身が受けた監査のレポートや認証の証明書を、コンソールから無料でダウンロードできるサービスです。監査人に「AWS側はこの基準を満たしている」と示すときに使います。

種類内容例
Artifact Reports第三者の監査人によるAWSの監査レポート・認証SOC 1・SOC 2・SOC 3レポート、ISO 27001などの認証、PCI DSSの準拠証明
Artifact AgreementsAWSとの契約(同意書)の確認・締結BAA(米国の医療情報の取り扱い)、NDA
  • 新しいレポートが公開されたときに通知を受け取れる
  • Organizationsの管理アカウントで、組織全体の契約をまとめて結べる
  • ダウンロードには、IAMで Artifact の権限が必要

利用者側の準拠を確かめる仕組み#

AWSが認証を受けていても、利用者の設定が基準を満たしているとは限りません。利用者側は、次のサービスで設定を継続的にチェックし、証拠を集めます。

サービス役割
AWS Configリソースの設定の履歴を記録し、ルールに違反していないかを評価する。基準ごとのルールの組み合わせ(コンフォーマンスパック)も使える
AWS Security HubCIS AWS Foundations Benchmark・PCI DSS・AWS基礎セキュリティのベストプラクティスなどの基準に照らして、アカウントの設定をスコア化する
AWS Audit Manager監査の枠組み(PCI DSS・GDPRなど)に合わせて、Config・Security Hub・CloudTrailから証拠を自動で集めて報告書にする
AWS CloudTrail誰がいつ何をしたかの記録。ログファイルの整合性の検証で、改ざんされていないことを示せる
AWS Control Tower複数のアカウントに予防・検出のコントロール(ガードレール)を適用する

試験では「監査人にAWSのSOCレポートやPCIの準拠証明を提出したい」には AWS Artifact、「自社のリソースが基準を満たしているかを継続的に確認したい」には Config や Security Hub が答えになります。どちらの側の証明かを見分けます。
