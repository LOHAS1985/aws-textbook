1. 詳しい説明#

インフラをコードで管理する(IaC)ツールには、AWSのCloudFormation・CDKのほかに、HashiCorp社のTerraformがあります。また、テンプレートやコードはGitで変更履歴を管理し、レビューしてから反映するのが一般的です。SOA-C03では、CloudFormation・CDKに加えて、こうしたサードパーティのツールを使った運用も出題範囲に含まれます。

Terraformの仕組み#

Terraformは、作りたいリソースをHCLという書き方で記述し、コマンドで実際の環境に反映します。

provider "aws" {
  region = "ap-northeast-1"
}

resource "aws_s3_bucket" "logs" {
  bucket = "example-logs-bucket"
}
用語・コマンド意味
プロバイダー操作する相手(AWS・他のクラウド・SaaS)ごとのプラグイン。AWSは aws プロバイダー
リソース作るもの(aws_s3_bucket、aws_instance など)
terraform initプロバイダーのダウンロードなど、作業の準備
terraform plan実行すると何が作られ・変わり・消されるかを確認する(CloudFormationの変更セットにあたる)
terraform apply変更を反映する
terraform destroy管理しているリソースをすべて削除する
terraform import手で作った既存のリソースを、Terraformの管理下に取り込む

ステートファイル#

Terraformは、自分が作ったリソースと実際のIDの対応をステートファイル(terraform.tfstate)に記録します。CloudFormationではこの記録をAWSが持ちますが、Terraformでは利用者が保管します。

  • チームで使うときは、ステートをS3バケットに置く(リモートバックエンド)。バケットはバージョニングと暗号化を有効にし、アクセスを絞る
  • 同時に2人が反映して壊れないように、ロックをかける。S3のロックファイル(use_lockfile)を使うのが現在の方法で、以前はDynamoDBのテーブルを使っていた
  • ステートにはパスワードなどの値がそのまま入ることがあるので、Gitには入れない

CloudFormationとの違い#

CloudFormationTerraform
提供元AWSHashiCorp(サードパーティ)
対象AWSAWS・他のクラウド・SaaSなど
書き方JSON・YAML(CDKならプログラミング言語)HCL
状態の管理AWSがスタックとして管理利用者がステートファイルを管理
変更の確認変更セットterraform plan
手作業の変更の検出ドリフト検出terraform plan で差分として出る
失敗時自動でロールバック途中まで反映された状態で止まる(直して再実行)

AWS Control Towerでは、アカウントの払い出しをTerraformで行う Account Factory for Terraform(AFT)も使えます。

Gitの基本#

用語意味
リポジトリコードとその変更履歴の保管場所(GitHub・GitLab・Bitbucketなど)
コミット変更を1つの単位として履歴に記録すること
ブランチ本流(main)から分けた作業用の流れ。本番に影響を与えずに変更を進める
プルリクエストブランチの変更を本流に取り込むよう依頼し、レビューを受ける仕組み
マージブランチの変更を本流に取り込むこと
.gitignoreリポジトリに入れないファイルの指定(ステートファイル・認証情報など)

GitとAWSをつなぐ流れ#

  1. 開発者がブランチで変更し、プルリクエストを作る
  2. CI(CodeBuildやGitHub Actions)が terraform plan や cfn-lint・変更セットの作成を行い、結果をレビューする
  3. 承認されたら本流にマージし、CodePipelineなどが自動で反映する

CodePipelineは、CodeConnections(旧CodeStar Connections)でGitHub・GitLab・Bitbucketのリポジトリとつなぎ、マージをきっかけにパイプラインを動かせます。CloudFormationにも、Gitリポジトリのテンプレートの変更を自動でスタックに反映するGit同期があります。

Gitを使う運用では、手作業で本番を変更しないのが原則です(変更の履歴・レビュー・やり直しがすべてGitに残るため)。アクセスキーやパスワードをリポジトリに入れてしまう事故が多いので、認証にはIAMロールを使い、機密情報はSecrets ManagerやParameter Storeに置きます。
