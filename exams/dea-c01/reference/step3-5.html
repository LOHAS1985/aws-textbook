AWS Glue

データの発見・カタログ化・ETLをサーバーレスで行うデータ統合サービス

1. サービス概要#

AWS Glueは、複数のデータソースを発見・接続し、データカタログに登録して、分析用に抽出・変換・ロード(ETL)するマネージドサービスです。サーバーを管理せずに、バッチとストリーミングのデータ統合を行えます。

2. 主な機能・特徴#

AWS Glue Data Catalog#

データベース、テーブル、列、形式、S3上の場所などのメタデータを一元管理します。データそのものを保存する場所ではなく、データをどう読むかを記録するカタログです。Athena、Redshift Spectrum、EMRなどが同じテーブル定義を参照できます。

クローラーと接続#

クローラーはS3やJDBC接続先などのデータを調べ、形式やスキーマを推測してData Catalogにテーブルを作成・更新します。スキーマ変更の検出にも使えます。既知のスキーマを厳密に管理したいときは、クローラー任せにせずテーブル定義を明示します。

ETLジョブ#

  • AWS Glue Studioのビジュアルエディター、ノートブック、スクリプトでジョブを作成する。
  • Apache SparkまたはRayを実行エンジンとして、データの結合・整形・形式変換などを行う。
  • ジョブブックマークで処理済みデータを追跡し、再実行時に新しいデータだけを処理できる。ソースや変換の種類によって対応範囲が異なる。
  • トリガーやワークフローでジョブ・クローラーの順序や依存関係を管理する。

データ品質と準備#

AWS Glue Data Qualityでは、ルールを定義して欠損・重複・値の範囲などを評価し、結果を確認できます。AWS Glue DataBrewはビジュアル操作でデータのプロファイル確認や変換レシピ作成を行うデータ準備機能です。詳細はデータ品質を参照してください。

ストリーミングETL#

Kinesis Data StreamsやAmazon MSKなどのストリームを継続的に読み取り、変換して保存先へ書き込めます。リアルタイム処理にはチェックポイントや重複処理への考慮が必要です。

3. ユースケース#

  • 複数形式のデータをS3に集め、Parquetに変換して分析しやすくする。
  • データカタログとクローラーで、Athenaから検索できるテーブルを作る。
  • データ品質ルールをETLパイプラインに組み込み、不正なデータを検出する。
  • ストリーミングデータを変換してデータレイクへ取り込む。

4. 料金の考え方#

ジョブやクローラーの実行に使う処理能力と実行時間などに応じて課金されます。実行エンジンや機能によって料金体系が異なるため、ジョブの規模・頻度・ワーカー設定を見直します。S3、CloudWatch Logs、データ転送などの利用料は別途発生します。

5. 関連サービス#

  • Amazon S3:データレイクの保存先
  • Amazon Athena:Data Catalogを参照してS3をSQL分析
  • AWS Lake Formation:Data Catalogとデータレイクのアクセス制御
  • Amazon Redshift:データウェアハウスへのロード・分析
  • Amazon Kinesis/Amazon MSK:ストリーミングデータの取り込み
  • Amazon MWAA:複数ジョブを含むパイプラインのオーケストレーション

6. 試験・実務でのポイント#

  • データの場所・形式・スキーマを共有するメタデータの保管先 → AWS Glue Data Catalog。
  • S3上のデータを調べてスキーマを推測し、カタログ登録 → クローラー。
  • 大規模なデータ変換 → GlueのSparkジョブ。画面上で変換処理を作る → Glue Studio。
  • ルールに基づく品質評価 → Glue Data Quality。対話的なプロファイル・レシピ作成 → Glue DataBrew。
  • データカタログはメタデータであり、実データはS3やデータベースに存在する。

7. まとめ#

  • AWS Glueは、データのカタログ化・ETL・品質評価を統合するマネージドサービス。
  • Data Catalogがテーブル定義を保持し、クローラーがスキーマを検出する。
  • ジョブ・トリガー・ワークフローでバッチやストリーミングの処理を構成できる。

Amazon SageMaker Unified Studio

データ・分析・AIの作業をプロジェクト単位でまとめる統合開発環境

1. サービス概要#

Amazon SageMaker Unified Studioは、データ、分析、AI・機械学習の作業を共通の環境にまとめる開発体験です。管理者が設定するドメインの中で、チームはプロジェクトを作成し、データの発見・準備・分析・共有を行います。

2. 主な機能・特徴#

ドメイン・ドメインユニット・プロジェクト#

  • ドメイン:組織のユーザー、認証、共有環境などをまとめる管理境界。
  • ドメインユニット:ドメイン内を部門やチームに分け、委任管理や設定の適用範囲を整理する単位。
  • プロジェクト:データ、メンバー、処理資源、アクセス権をユースケースごとにまとめる作業領域。

カタログとデータ準備#

カタログを使ってデータ資産を発見し、アクセスを申請・共有できます。ビジネス向けカタログは、データの意味や所有者などの情報を利用者が理解しやすい形で示します。データ準備にはビジュアルな操作やノートブックなどを使い、データの来歴を追跡する機能と組み合わせます。

データ準備機能にはAmazon SageMaker Data Wranglerがあります。現在のData Wrangler体験はSageMaker Canvasに統合されており、視覚的な変換やデータ品質の確認、フローの出力を行います。試験ガイドにある名称と、現行の提供形態を区別して押さえます。

プロジェクトがデータを発見できることと、実データを読み取れることは別です。カタログ上の共有・承認と、Lake Formation、IAM、基盤サービス側の権限を確認します。

データリネージ#

データリネージは、データがどのソースから取り込まれ、どの処理を経て、どの出力や利用者につながるかを追跡する考え方です。変更の影響調査、品質問題の原因特定、監査に役立ちます。

3. ユースケース#

  • 部門ごとにプロジェクトとデータアクセスを分けた共同分析。
  • カタログから必要なデータを発見し、所有者にアクセスを申請する。
  • データの加工履歴や依存関係を追跡して、変更の影響を調べる。
  • データ準備、SQL分析、AI開発を共通の作業環境から行う。

4. 料金の考え方#

Unified Studioの利用に加え、プロジェクトから利用する計算資源、ストレージ、データカタログ、分析・AIサービスなどに料金が発生します。ドメインやプロジェクトの数そのものだけでなく、実行した処理と保存データの料金を確認します。

5. 関連サービス#

  • AWS Glue:技術メタデータとETL
  • AWS Lake Formation:データレイクの権限・共有
  • Amazon S3:データレイクの保存先
  • Amazon Athena:SQLでの探索・分析
  • Amazon Macie:個人情報を含む機密データの検出
  • 関連する用語:データガバナンス

6. 試験・実務でのポイント#

  • 組織の作業環境を構成する順序は、ドメイン → ドメインユニット → プロジェクト。
  • プロジェクトは作業と共有の境界であり、基盤データの権限も別途必要。
  • カタログはデータを見つける入口、Lake FormationやIAMは実データへのアクセス制御を担う。
  • ソース・処理・出力のつながりを調査する → データリネージ。

7. まとめ#

  • SageMaker Unified Studioは、データ・分析・AIの共同作業環境。
  • ドメイン、ドメインユニット、プロジェクトで組織と作業を分ける。
  • カタログでの発見・共有と、実データのアクセス権を区別する。
