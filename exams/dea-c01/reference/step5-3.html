セキュリティ、アイデンティティ、コンプライアンス

Amazon Macie

S3の機密データや個人情報(PII)を検出・分類

1. サービス概要#

Amazon Macieは、S3に保存された機密データや個人情報(PII)を検出・分類するサービスです。

2. 主な機能・特徴#

機能概要主な用途
機密データ検出S3オブジェクトを分析し、クレジットカード番号・個人情報・認証情報などを検出S3内の機密情報の発見・分類
データ検出結果検出した機密データの種類や場所を確認どのオブジェクトに機密情報が含まれるかを把握
バケットのセキュリティ・アクセス分析バケットの設定やアクセス状況を分析し、リスクを検出意図しない公開や過剰なアクセス権限の確認
自動検出S3のデータを継続的に分析定期的なデータセキュリティ監視
カスタムデータ識別子独自のパターン(正規表現など)を定義して検出社内固有のIDや顧客番号の検出

GuardDutyとの違い#

サービス主な対象主な目的
Amazon MacieS3のデータ機密データやS3のデータセキュリティリスクを検出
Amazon GuardDutyAWSアカウント・ワークロード不正アクセスやマルウェアなどの脅威を検出

自動検出とジョブ#

自動検出は、MacieがS3バケットの一覧を継続的に確認し、サンプリングでオブジェクトを選んで分析する機能です。アカウント全体で、機密データがありそうな場所を広く把握するために使います。

特定の対象を指定して詳しく調べるにはジョブを作ります。ジョブは1回だけ実行することも、定期的に繰り返すこともできます。対象は、バケットの指定や、タグ・プレフィックス・最終更新日などの条件で絞り込めます。

説明の中心 成功・推奨・正常 利用者・外部・送信元 その他の構成要素

検出する対象は、マネージドデータ識別子(AWSのシークレットアクセスキー、クレジットカード番号、パスポート番号など)で決まります。社員番号や顧客番号などの独自形式は、正規表現に、近くにあるキーワードや除外する語を組み合わせたカスタムデータ識別子で検出します。検出させたくない文字列は許可リストに登録します。

検出結果と連携#

Macieの検出結果には、機密データの検出結果(個々のS3オブジェクトに機密データが含まれていた)と、ポリシーの検出結果(バケットが公開されている、他のアカウントと共有されているなど、設定上のリスク)の2種類があります。

検出結果はEventBridgeにイベントとして送られ、AWS Security Hub CSPMにも連携できます。EventBridgeのルールと組み合わせて、通知や自動対応につなげられます。

コンソールのダッシュボードでは、S3バケットのインベントリ(一覧)と、公開されているバケットや他のアカウントと共有されているバケットの数などの統計を確認できます。自動検出では、バケットごとに機密度スコアが付くため、どのバケットを優先して確認するかを決められます。

設定の要点#

  • 複数アカウントの場合は、AWS Organizationsと連携してMacie管理者アカウントを指定する。管理者は、メンバーアカウントのバケットやポリシーの検出結果をまとめて確認できる。
  • ログ保存用のバケットなど、分析が不要なバケットは自動検出の対象から除外できる。
  • 自動検出とジョブは、マネージドデータ識別子・カスタムデータ識別子・許可リストを組み合わせて分析内容を絞り込める。

制限#

  • 分析の対象は、S3の汎用バケットにあるオブジェクト。ディレクトリバケットのオブジェクトは分析されない。
  • S3 Glacier Deep ArchiveやS3 Express One Zoneのオブジェクトは分析されず、対象外として扱われる。
  • DynamoDBやRDSのデータは、S3にエクスポートしてから分析する。
  • 検出結果は90日間保持される。それより長く残す場合は、EventBridgeで別の保存先に転送するか、検出結果をS3バケットに保存する。

3. ユースケース#

  • S3に個人情報が保存されていないかの定期チェック
  • 公開されているバケットや過剰な権限の発見
  • 社員番号・顧客番号など独自形式のデータの検出

4. 料金の考え方#

評価するS3バケットの数、自動検出で監視するS3オブジェクトの数、機密データ検出で検査したデータ量(GB)に応じて課金されます。ジョブで検査したデータ量も課金の対象ですが、ジョブは無料トライアルに含まれません。新しく有効にしたアカウントには30日間の無料トライアルがあり、自動検出は最大150GBまで検査されます。

5. 関連サービス#

  • Amazon S3:検査の対象
  • AWS Security Hub CSPM:検出結果の集約
  • Amazon EventBridge:検出結果をトリガーに自動対応
  • AWS Organizations:複数アカウントのMacieを一括管理
  • Amazon GuardDuty:脅威の検出
  • Amazon Inspector:脆弱性の検出
  • 関連する用語:セキュリティ検出のサービスの選び方、責任共有モデル

6. 試験・実務でのポイント#

  • 「S3」「個人情報(PII)」「機密データの検出」→ Macie。
  • 「不正アクセス」「マルウェア」「脅威検出」→ GuardDuty。
  • 独自形式のデータ → カスタムデータ識別子。
  • 公開されているバケットや過剰な共有の発見 → Macieのポリシーの検出結果。
  • 複数アカウントのS3を一括で確認 → AWS Organizationsと連携したMacie管理者アカウント。
  • 検出結果を90日を超えて残したい → EventBridgeで転送するか、S3に保存する。
  • GuardDuty・Inspector・Macie・Security Hub CSPMの使い分け → セキュリティ検出のサービスの選び方。

7. まとめ#

  • MacieはS3の機密データ検出サービス。GuardDutyは脅威検出サービス。

データガバナンス

データの所有者・意味・利用権限・保護・ライフサイクルを組織的に管理する枠組み

1. 詳しい説明#

データガバナンスは、組織がデータを安全かつ適切に発見・共有・利用するための役割、規則、管理方法です。所有者、用途、機密区分、品質、保持期間、アクセス条件を明らかにし、ルールをシステムに反映します。

カタログ・分類・来歴#

  • 技術カタログ:データベース、列、型、場所など、機械処理に必要なメタデータ。
  • ビジネスカタログ:意味、所有者、機密区分、利用条件など、利用者の判断を助ける情報。
  • データリネージ:データの取得元、変換、出力先、利用先のつながり。
  • データ品質:完全性や妥当性など、利用目的を満たすかの評価。

アクセス制御と共有#

IAMのロールベース制御(RBAC)は利用者の役割で権限を決め、タグベース制御(TBAC)は資産や主体に付けたタグで権限を管理します。属性ベース制御(ABAC)は利用者・資産・環境の属性を組み合わせて判断します。いずれも最小権限、明確な所有者、アクセスの定期レビューが重要です。

データ共有では、共有先の用途・期間・利用可能な列や行を定めます。Redshiftのデータ共有やLake Formationの共有を使う場合も、共有の設定だけでなく、IAM・データベース権限・基盤側のアクセス制御を合わせて確認します。

プライバシー・暗号化・データ主権#

  • 個人情報や機密情報を検出し、マスキング・匿名化・削除などの扱いを定める。
  • 保存時と転送時の暗号化、キー管理、職務分離を構成する。
  • 法令や契約で許可されたリージョンにデータを保存・処理し、複製・バックアップ先も制御する。
  • 保持期限、S3 Lifecycle、バージョニング、DynamoDB TTL、法的削除要件を組み合わせる。

説明の中心 成功・推奨・正常 利用者・外部・送信元 その他の構成要素 点線の矢印(使われない・切り替え前・補足)

2. 関連する用語#

  • 暗号化:保存時・転送時のデータ保護
  • IAMポリシーの評価:権限の許可・明示的な拒否
  • オープンテーブル形式:スキーマ変更とデータ管理
  • データ品質:データの信頼性を評価する

3. 関連サービス#

  • AWS Lake Formation:データレイクの権限・共有
  • AWS Glue:技術メタデータとETL
  • Amazon SageMaker Unified Studio:プロジェクト・ビジネスカタログ・来歴
  • Amazon Macie:S3内の機密データ検出
  • AWS Key Management Service (AWS KMS):暗号化キーの管理
  • AWS CloudTrail/AWS Config:監査と構成変更の記録
分析

AWS Data Exchange

外部組織とのデータセットの検索・共有・利用権限を管理するサービス

1. サービス概要#

AWS Data Exchangeは、AWS上でデータセットの提供・共有・利用権限を管理するサービスです。利用者はサードパーティーや社内提供者のデータ製品を検索・購読し、提供者はデータの配布基盤を個別に構築せずにデータを共有できます。

2. 主な機能・特徴#

提供者と利用者#

  • 提供者はデータ製品にデータセットと利用条件を設定し、AWS Marketplaceで公開する。
  • 利用者は利用条件に同意して購読し、許可されたデータ資産を利用する。
  • データ共有の単位には、データセット、データ資産、データグラント、製品の購読などがある。

データの種類と更新#

データセットはファイル、API、Redshiftデータ共有、S3データアクセスなど複数の形を取れます。提供者はデータの更新をリビジョンとして公開し、利用者の権利に応じて過去・将来の版を提供します。

説明の中心 成功・推奨・正常 利用者・外部・送信元 その他の構成要素

利用権限はデータの利用方法や期間を規定します。購読やグラントを取得しても、データの内容や品質が保証されるわけではないため、利用条件・更新頻度・ライセンス・地域制約を確認します。

3. ユースケース#

  • 市場・気象・位置情報などの外部データを分析に取り込む。
  • 提供者が新しいデータリビジョンを公開し、購読者が更新分を利用する。
  • 組織内外で共有するデータの権利や利用期間を管理する。

4. 料金の考え方#

公開製品や購読データには、提供者が定めた価格・契約条件が適用される場合があります。データ転送、S3・Redshiftなどの保存・分析サービスの料金も別途発生します。購読費用とAWS上での利用料金を分けて確認します。

5. 関連サービス#

  • Amazon S3:ファイルデータセットの保存・利用
  • Amazon Redshift:データ共有形式のデータセット利用
  • AWS Lake Formation:データレイク内のアクセス権
  • Amazon Athena:共有されたS3データのSQL分析
  • Amazon SageMaker Unified Studio:データの検索・分析・共同利用

6. 試験・実務でのポイント#

  • 外部データセットを発見・購読し、提供者と利用者の権利を管理 → AWS Data Exchange。
  • 購読・データグラントは利用権限であり、データの品質や正確性の保証とは異なる。
  • データ製品の契約条件と、S3・Redshiftなどの保存・分析料金を分けて見積もる。

7. まとめ#

  • AWS Data Exchangeはデータ製品の共有・購読とアクセス権を管理する。
  • データセットの形式・更新・利用条件を確認して、分析サービスと連携する。
